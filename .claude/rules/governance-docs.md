# ガバナンス文書の参照と命名のルール

**書く約束（面積の一次規範・`ADR-doc-promise-over-area-ratchet`）**: 文書へ書き足すとき・書き換えるときは、(1) **かぶりなく**——同じ主張が別の場所に無いか grep で確かめ、あれば正本 1 か所に寄せて他は参照にする。(2) **必要なことだけ**——推論で辿り着ける事柄・その場限りの事情は書かない。(3) **古い情報を残さない**——触った節の隣にある主張が今も真か見る。面積に合否は無い——`governance:check` は実測値を報告するだけで、判定はこの約束が持つ（`ADR-retire-area-budget`）。

`AGENTS.md` / ルート `CLAUDE.md` / `docs/adr/` / `governance:check` は互いに参照し合う。**他を指すときは正準形 `` `<対象>`「<見出し>」 `` で書く**（**対象として認める綴りの正本は `scripts/governance/lib.mjs` の `isRefTargetSpelling` である**——ここへ写さない。同 doc が、綴りごとに何が着地先になるかも持つ）。この形だけが `governance:check` の G-heading-refs で照合され、見出しの改名・消滅は参照元を名指しして CI が落とす。**走査元は `.md` だけではない——コード（`.rs`）とスクリプト（コメント記法を持つファイル）のコメントに書いた参照も同じ検査に載る**（#925・#1138）。

- **序数で他を指してはならない。** 見出しの序数だけでなく、**ファイル名の連番・検査 ID・その他の引用される識別子すべて**が対象である——番号は構造を凍らせ、ずれても誰も気づかない。**連番はさらに並行作業で衝突する**: 値が確定するのはマージの瞬間なので、2 本の PR が同じ値を見る（ADR の連番で 3 回・#812）。
- **機構の実装の詳細（述語の種類・件数・分岐の列挙）を散文へ写さない。** 連番と同じ理由が、値でなく**記述**にも当たる——確定するのはマージの瞬間である。#984 は `governance-check.mjs` を読んで「判定する識別子の形は camelCase と SCREAMING_SNAKE だけ」と**正確に**書いたが、並行して入った #989 が 3 つ目の述語を足し（照合 70 → 285 件）、squash で両者が同じ木に載った時点で偽になった。**自分の branch の CI も main の CI も緑で、どちらもこの嘘を検知していない**。書くのは帰結（「型で修飾したトークンには当たらない」）だけにして、機序は正本を指す。
- **名前はテーマ・目的が決まった時点で、何を指すか分かる形で付ける。** 「いま空いている最大値 + 1」という操作を持たない名前には、衝突する余地が無い。ADR は `docs/adr/ADR-<slug>.md`（引用は `ADR-<slug>`）、`governance:check` の検査は `G-<name>` とする（#812。全 ADR 移行済み・連番への回帰は G-adr-file-names が落とす）。
- **G-heading-refs が見るのは正準形だけであり、かつ 1 物理行に収まったものだけである。** 散文形（「ルート `CLAUDE.md` のフック節」）・節を移動したときの意味の変化は検知されない（助詞が挟まった近傍形は G-near-heading-refs が拾う）。**物理改行を跨いだ参照は一致すら生成されない**——G-folded-heading-refs が別途これを赤にするが、**その射程と死角は同検査のヘッダが正本である**（ここで数え上げると腐る）。ゆえに**移動・圧縮・分割の完全性は依然として機構の外**にあり、`/plan-review`「Step 2b」相当の**独立再導出**（旧内容を SSOT に、全命題の着地を作者と別枠組みで確認）で裏取りする。
- **ADR 本文内の参照は照合されない**——凍結された歴史であり腐るに任せる（`ADR-adr-frozen-history`）。ADR を消すときは生きた層の引用を散文化してから。**G-adr-citations は助けになるが全経路は見ない**——照合する母集団の外に残った引用は沈黙で壊れる（母集団の正本は同検査の `adrCitationDocs`・2026-08-09 実測 #1008）。
- **既に消滅した節の名前を正準形で書かない。** 正準形は「今ある場所への指し」であって過去の名前の記録ではない（G-heading-refs 導入時に `PERFORMANCE.md` で実例 1 件）。歴史を書くならバッククォートを外して散文にする。
- **これらの編集に PostToolUse hook 検査は走らない**（`selectChecks` がガバナンス文書に検査を割り当てず空集合を返す。`CLAUDE.md`「フック」）。**検査ではない reminder は出る**——依存を持つ節の本文を変えるとその節を指す参照が並び（#1140）、実在しない参照を書くとその文書の分が並ぶ（#1139）。一覧と射程の穴は `docs/hooks.md`「検査ではない reminder」が正本。**鳴ったときにだけ意味がある合図**であって、沈黙は依然として「何も走らなかった」である。G-heading-refs を含む決定的な検査は PR CI の governance-check job が事後に走る（#587）。**`.rs` では逆に hook が走って沈黙するが、その沈黙は fmt / clippy / test の合格であって見出し参照の着地を含まない**（#925。#1139 の索引 reminder も見出し参照は見ない）。
