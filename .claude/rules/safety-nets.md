# セーフティネット（hook / CI / githooks / 規範）を新設・変更するときのルール

このファイルは、セーフティネットそのもの（対象はフロントマターの `paths` が SSOT）を触ると自動配送される——**rules 自身を含むため、本ファイルの編集でも配送される**（この手順は自分自身にも適用される）。規範文書（ルート `CLAUDE.md` / `AGENTS.md` 等）もセーフティネットだが `paths` 外＝自動配送されない（誤配送を避けるため。必要時に手動参照する）。**設計哲学**（検出は構造化信号で行い、fail-closed を既定値に埋める）は `docs/development-principles.md`「構造的設計原則と強制の階梯」が SSOT。ここに置くのは、そのセーフティネットが**本当に効いているか**を確かめる運用手順である。

## 効いていることは、フォールトインジェクションで一度は実測する

- **「hook が自動実行する」「CI が担保する」に依拠して手順を省く前に、故意に壊して検知されることを 1 度確かめる。** それらは書かれた時点の期待であって、測定結果ではない（#471: hook の出力が一度も届いていないのに「届く」という記述の上に PR が積まれていた）。
- **「一度測った」は将来の母集団の下界を保証しない——機構自身の配置を変えたら、その母集団を食う述語を測り直す。** #837 が置いた「マッチ 0 件」検知は出生時には効いていたが、3 日後の #1093（判定を `scripts/governance/` 配下へ分割）が対象を**ゼロにはせず部分的に落とした**ため、**緑のまま保護が失効した**（#1143 で発覚・未被覆 106 件・失効期間 3 日 21 時間）。引き金は通常の作業ではなく**機構自身の再編**である——判定ファイルの移動・母集団の切り出しの変更・走査元の追加。**これを見張る新しい機構を足すのではなく、この引き金で測り直す**（足す側の判断規準は `docs/adr/ADR-governance-meta-demotion.md`）。
- **赤くなったことを「検出できる証拠」として扱う前に、変異が「実際に起きた回帰の姿」と同じかを確かめる。** 注入したことと、注入が正しい強さであることは別である——変異が本来の回帰より強いと、検査が縛れていなくても赤くなる（#872 で同じ型を 3 回）。**発火しないときも同じである**（#1004）。**どちらの向きも本文は `docs/development-principles.md`「構造的設計原則と強制の階梯」が持つ。**

## フォールトインジェクションでは、稼働中のガードを弱めない——複製に変異を当てる

- **変異対象は「他所から逐語で名指されていないもの」を選ぶ。** 名指されていると、変異がその名指し側を別の理由で赤くし、**「この層は黙っている」という当の観測ができなくなる**（#1094 で `G-ci-table` を選びかけた——`governance-manifest.test.mjs` がその id を逐語で持つため、消すと `npm test` が母集団とは無関係に落ちる）。これは `.claude/rules/safety-nets.md`「効いていることは、フォールトインジェクションで一度は実測する」が言う、変異が本来の回帰より強い場合の一形である。
- **複製で `npm test` を走らせるなら `node_modules` を junction で張る**（`New-Item -ItemType Junction`。symlink と違い開発者モード不要）。張らないと vitest は**起動前**にモジュール解決の失敗で exit 1 を返し、**変異を検知した場合と終了コードが同じ**になる（#1094 で 2 度踏んだ）。モジュール解決の失敗を見たら**どのモジュールが解決できなかったかを必ず読む**——vitest 本体なら測定環境の欠陥、変異先のファイルなら検知である。終了コードをパイプ越しに読まないこと（`| tail` の後の `$?` は tail の値）。
- 判定がソース述語でも実 git 操作でも規則は同じで、**変わるのは複製の作り方だけ**である。述語はメモリ上へコピーして変異させ、git 操作は hook を一時ディレクトリへコピーして使い捨て repo の `core.hooksPath` をそこへ向ける（手本は `.githooks/githooks.test.mjs`）。「判定が〜なら」のような条件節を免除と読んではならない（#504: 条件節を免除と読み、ライブの `pre-commit` を無害化して main 保護が数十秒消えた）。意図的に規則違反となる操作を行い、拒否されることを確認する類はガードの**行使**であり、弱めていないので対象外（#482）。

## 規範（ドキュメント・スキル・チェックリスト）を足すとき

- **規範そのものへフォールトインジェクションを当てる専用手順は置かない。** かつて `/norm-review` が担ったが、判別力がゼロと測れたため 2026-08-07 に廃止した（経緯と却下案は `docs/adr/ADR-retire-norm-review.md`）。規範の妥当性は、条項を実際に使う作業と独立レビュー（`code-reviewer`・`/plan-review`「Step 2b — 独立導出による網羅性レビュー」）が事後に暴くものとして扱う。
- **check 系スキルを新設するときは、母集団と費用対称性を書く——必須はこの 2 つだけである**（証拠・停止・接続は書けるなら 1 文で）。定義と、必須を 4 つから 2 つへ減らした実測は `docs/check-skill-skeleton-design.md`

- 条項を足す前にその節のスコープ宣言を見る（検算の母集団は規範が名乗る範囲）: `docs/development-principles.md`「構造的設計原則と強制の階梯」

## 検査の入力集合を、具体対象で検算する

- 一覧・索引・サブエージェントの報告を根拠に「全部」「一致した」と言うときは、(1) 守りたい対象を 1 件名指しし、それが実際に読む入力に現れることを示し、(2) 判定対象外が同じ入力に混じらないことを示す（両方向）。**正常時に一覧へ出ない対象は、その一覧だけを見る検査からは永遠に見えず**（#488, #489）、余計なものが入れば誤爆する（#482）。母集団は**派生した参照集合ではなく、起きた事実**から取り（`gh pr view <PR> --json closingIssuesReferences` ではなく `gh issue list --search "closed:>=<mergedAt>"`）、派生集合（`description` 等の要約）で関連性を判断しない。

## 検出器のカバー範囲は、欠落のパターンごとに検算する

- **「既存の機構が捕まえるから新しい検査は要らない」と言う前に、足ごとに壊して測り、捕まらない足は機構へ載せる。** この理屈はそれ自体が検査を書かない理由として使われる——検出器が守る対象が複数の足を持つとき（id → 予算 → 実装 の組など）、どの足が欠けても赤くなるとは限らない（#858: カナリアが捕まえるのは 3 本中 1 本だけで、残りは手書きの列挙が唯一の検知点だった）。
- **新設する検出器は、設計を確定する前に「注入する変異」を先に書く。** 守りたい退行を変異の形へ書き下ろすと、**その配置では発火しない**ことが計画段階で見つかる（#878: 「show 直後に位置クランプが動いたか」を見る案は、`WorkArea::clamp` が矩形の境界越えでしか座標を変えないため、**窓が作業領域の内側にいる限り導出の誤りに沈黙する**——実装前に気づき、位置に依存しない矩形の突き合わせへ替えた）。**変異は実装が終わってからでないと書けない、と思わないこと**——先に書くのは「何を壊すか」であってコードではない。
- **CI の実測は計画の検証項目に置かず、PR 本文のチェックリストへ送る**（#858）。**CI の実測は PR が在って初めて行える**——`ci.yml` は `pull_request` でのみ起動し、`gh pr create` は `workspace/plan.md` の未チェック `- [ ]` で block される（#749）。計画に置くと循環して閉じられない。
- **`workflow_dispatch` だけを持つ workflow を新設したら、実験用の枝接頭辞へ `push:` を一時的に張って測り、役目を終えたら workflow ごと外す**（#872 の pester-flake-repro.yml が先例。撤去済み）。**それ以外に main へ入る前に実測する手段が無い**——dispatch は既定ブランチに在るものしか起動できない（実測）。PR 本文のチェックリストは「PR ができてから走る `ci.yml`」には効くが、**起動手段そのものが無い workflow には届かない**。
- **回復機構（fail-safe・自己修復・リトライ）を足したら、その機構が隠す退行を誰が見るかを同時に決める**。#755/#801 では、show の導出が退行しても次のフレームが 1 フレームで補正するため、**外から窓を測る検査は緑のまま通る**（観測できる差は約 16ms の過渡だけで、200ms ポーリング + 100ms 間隔のサンプリングには写らない）。**故障注入は回復機構ごと巻き戻して行う**——実測では、導出をバグらせても外部の矩形測定は正しい値を返し、in-process の信号だけが発火した。外から見えない退行には、プロセス内で不変条件を突き合わせる信号を用意する（形は「起きてはならないことが起きていないか」・`src-tauri/CLAUDE.md`「モジュール構成」）。

## これまで無意味だった状態に意味を与える変更は、その状態に到達する全経路を列挙する

- 「無出力 = 合格」「空 = 未設定」のような意味づけは、同じ状態を無害なノイズから**誤った合格判定の原因**に変える——意味が成り立たない経路をすべて塞ぐ（#471: hook の沈黙に「合格」を与えたとき、タイムアウト・起動失敗・出力溢れが沈黙経路として残っていた）。**分類を 1 つ足したときは、隣接分類への到達経路も再列挙する**——逃げ道は塞いだ扉の隣に現れる（#489）。
