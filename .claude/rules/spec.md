# SPEC.md ルール

- セクションを追加・削除したら、子セクションの番号（`### N.x`）と、後ろに続くセクション（`## N+1.`〜）の番号がずれていないかを確かめる。
- SPEC には as-built を書く。計画で「任意（流用可）」とした sub-feature は、実装がそれを採用したかを確かめてから SPEC に書く。実装と別のタスク（特にサイクルの終わり）で書くと、計画の楽観的な全体像をそのまま書いてしまい、実装とずれる（#394）。
- 外部ツールが生成する成果物について「受容する残余」を書くときは、その成果物を一度生成して読んでから書く。残余は「直さない」という宣言なので、後から誰も確かめない。#1210 は Tauri のアンインストーラの挙動を測らずに「アンインストールしても値が残る」と書いたが、テンプレートは既にその値を消していた（#1211 で `tauri build` が生成した `installer.nsi` を読んで分かった）。偽の残余は、「対処予定」に見える issue を生む。それを訂正するだけで、調査のサイクルが 1 本要る。
