# SPEC.md ルール

- **セクションを追加・削除したら、子セクション番号（`### N.x`）と以降のセクション（`## N+1.`〜）の番号がずれていないか確認する**
- **as-built を記述する**: 計画で「任意（流用可）」とした sub-feature は、実装がそれを採用したか確認してから SPEC に書く。実装と別タスク（特にサイクル末）で書くと、計画の楽観的な全体像をそのまま記述して乖離する（#394）
- **外部ツールが生成する成果物についての「受容する残余」は、その成果物を一度生成して読んでから書く**: 残余は「直さない」という宣言ゆえ、後から誰も検算しない。#1210 は Tauri のアンインストーラの挙動を測らずに「アンインストールしても値が残る」と書いたが、テンプレートは既にその値を消していた（#1211 で `tauri build` が生成した `installer.nsi` を読んで判明）。**偽の残余は「対処予定」の見た目を持つ issue を生む**——訂正だけで調査サイクルが 1 本要る
