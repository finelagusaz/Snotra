規範が捕まえると主張する欠陥を実際に蒔き、規範なし／ありの差を測る。

対象: $ARGUMENTS

新設する条項の置き場は、先に `/retrospective`「Step 3 — 教訓の配置（トリガーに括り付ける）」で確かめる。

## Step 1 — 母集団と種

母集団は、この変更で足した／書き換えた**独立した判定**である。同じ作業状況・欠陥・期待結果を扱う複数の文は1件に束ねる。変更していない判定の欠陥は母集団へ混ぜず、issueへ回す。

判定ごとに、issue・`RETROSPECTIVE.md`・`docs/adr/` に実在する失敗から種を1件書く。想像上の種は、自分が捕まえられる答えへ寄るため使わない。

> **種**: `<作業状況>` / `<紛れ込む欠陥>` / `<規範が効いたときの観測可能な結果>`

種が書けない判定は削除候補とし、エージェントへ渡さない。母集団が空なら起動せず終了する。

禁止・義務の形で、破る方が速い／楽になる判定は通常モードへ混ぜず、`--pressure` が必要な対象として報告する。`--pressure` が指定された場合だけ `pressure-scenario.md` を読み、そちらの手順を使う。

### 起動予算を先に出す

起動前に、判定と種の対応、対象ファイル、予定エージェント数を表で出す。通常モードの初回は、種の数によらず**対照1体＋本番1体の計2体**である。種が互いに無関係で1つの作業として渡せないなら、呼び出しを分ける。

## Step 2 — 対照（規範なし）

全種を1つの対照バッチとして、通常の作業を1体のサブエージェントへ渡す。変更前の版を使えるなら `git show <base>:<path>` を基準にする。新設ファイルなら、変更した判定を除いた本文を指示に含める。稼働中の規範は弱めない。

対照エージェントには各種を独立に実行させ、指定した1つの絶対パスへ種ごとの結果を書かせる。別の条項が同じ答えを運んでいないかも記録させる。対照が欠陥を捕まえた種は「条項不要」候補である。

## Step 3 — 本番（規範あり）

同じ全種を1つの本番バッチとして、対照とは別の1体へ渡す。変更後の規範を読ませ、指定した別の絶対パスへ種ごとの結果を書かせる。同じエージェントを対照と本番に使わない。

各成果物には母集団の全種が1回ずつ現れることを呼び出し側が数える。不着または種の欠落があれば、そのバッチだけ同じ指示で1度再起動する。再び届かなければ不成立とする。

## Step 4 — 記録と、素通りした種の修正

種ごとに、**捕まえた** / **素通りした** / **対照も捕まえた（条項不要）** / **不成立**を割り当てる。

素通りした種だけを、様態に合う形で1文を目安に修正する。

| 素通りの様態 | 採る形 |
|---|---|
| 出力の形が違う | 出力を順序付きで述べる |
| 要る要素が落ちた | 既存様式へ埋める枠を置く |
| 条件で振る舞いが変わる | 観測可能な述語へ紐づける |
| 知っていて破った | 通常モードの射程外。`--pressure` で別に測る |

免除句では規則の射程を限定できない。一部を除外するなら、その対象へ規則が届かない構造に変える。

修正後は、素通りした種だけを**新しい本番エージェント1体**で再実行する。種・変更前の基準・期待結果が変わらない限り、対照結果を再利用する。2度目の修正でも素通りしたら `BLOCKED` として人へ返す。

修正は呼び出し側が行う。本スキルは測る側と書く側を分けるため `Edit` を持たない。

## 出力

```markdown
## norm-review — <対象>

### 母集団と費用
- 独立した判定: <N>件 / 種あり: <K>件 / 削除候補: <N-K>件
- エージェント: 予定 <2または0>体 / 実績 <起動数>体（再試行 <N>体）
- 対照: 新規取得 / 再利用

### 種ごとの結果
- 種1 <要約>: 捕まえた / 素通りした → <修正> / 対照も捕まえた（条項不要） / 不成立

### 受容する残余
- 網羅性: 種が通った経路だけを検査した
- <不成立・削除候補・BLOCKED>
```

`K = 捕まえた + 素通りした + 対照も捕まえた + 不成立` を満たすこと。
