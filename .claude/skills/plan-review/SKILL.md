`workspace/plan.md` を読み、内容に基づいてサブエージェントを並列起動して検証する。

## Step 1 -- plan.md の読み込み

`workspace/plan.md` を読み、以下を把握する:

- 変更対象ファイルと変更内容
- 実装フェーズ構成
- 不変条件の記述
- テスト方針

## Step 2 -- 並列サブエージェントで検証

変更対象のレイヤー（Rust / TypeScript / 設定 など）ごとにサブエージェントを分割して並列起動する。

各サブエージェントへの指示に含めるもの:

1. **担当レイヤーと対象ファイル**: plan.md に記載の変更ファイルを起点にする
2. **検証観点**（担当レイヤーに関係するものを全て確認）:

   **影響範囲**
   - 変更する関数・シグナル・イベントの呼び出し元を grep し、plan.md に漏れた影響先がないか
   - 変更するコードパスと対称ペア（`show`/`hide`、`enter`/`exit`、`start`/`stop` 等）が存在し、同様の変更が必要でないか

   **不変条件**
   - plan.md に記載の不変条件が実際のコードで成立するか
   - 新規に導入する状態フラグ・プロセス・リソースについて「失敗・異常終了時にどうなるか」が記述されているか
   - `false` に戻す経路のない `AtomicBool`、`unlisten` のない `listen()`、`kill` のない子プロセスが生まれないか

   **スコープ**
   - plan.md の変更範囲が issue の要求に対して過不足ないか（YAGNI 違反・要求未達の両方を確認）
   - 既存の類似パターンで実現できるものを新規実装していないか

3. **出力形式**: 「問題なし」「軽微な懸念」「要対処」の3分類で列挙

サブエージェントは `Explore` タイプを使用する。

## Step 3 -- 結果の統合と報告

各サブエージェントの結果を統合し、以下の形式で報告する:

```
## plan-review 結果

### 問題なし
- ...

### 軽微な懸念（実装時に注意すべき点）
- ...

### 要対処（実装前に plan.md の修正が必要）
- ...

### 総評
計画の completeness: [高 / 中 / 低]
実装着手可否: [可 / 要修正後に着手]
```

「要対処」事項がある場合、具体的な修正案を提示し `workspace/plan.md` の更新を提案する。
