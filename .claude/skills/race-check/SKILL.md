$ARGUMENTS の変更が、別スレッド・別フレーム・別ウィンドウへ何かを渡しているかを見る。渡していれば、送信してから適用されるまでの間に、周りの状態が変わりうる。このプロダクトの状態競合は、すべてこの 1 点から生じる。`await` の数を数える検査は、これを捉えない。

計画の段階では起動しない（経緯は `#784`）。`$ARGUMENTS` は対象の説明であって、母集団の定義ではない。両者が食い違ったら、差分の側を採る。

不変条件の正本は `src-tauri/CLAUDE.md`「イベント駆動 wake の不変条件」・`snotra-egui-runtime/CLAUDE.md`・`snotra-core/CLAUDE.md`「engine.rs のロック最小化パターン」である。ここには、最も見落とされやすい直観に反する事実だけを写す。`listen` のコールバックは、emit した呼び出し元のスレッド上で同期的に実行される。そのため listener を追加すると、emit 元のスレッドから UI 状態を触るコードを追加したことになりうる。

## 母集団

`npm run race:boundaries` を走らせる（コマンド本体と `--base` / `--include-removed` の指定の SSOT は `docs/build-commands.md`「Windows/macOS/Linux で実行可能」である。二重にメンテしないため、ここには書かない）。

母集団はこのツールが決める（種別 ①〜⑧ の定義・検出パターン・0 件の明示を含む出力仕様の SSOT は `scripts/race-boundaries.mjs` である）。

ツールが出す手がかりは調べ始める入口であって、網羅ではない。0 件は「この手がかりでは見つからなかった」という意味であり、「無い」という意味ではない。候補から先は、コードを読んで判定する。1 つの worker が複数の種別を持つなら、種別ごとに境界を立てる。たどるのは、状態を 1 段・呼び出し元を 1 ホップ・呼び出し先を 1 段である。純粋関数でも、staleness の判定・表示ゲートの述語・世代の照合に使われるなら、境界の要になる。位置を行番号で断定しない。参照はシンボル名で行う。

## 境界ごとに 5 つ答える

答えられない項目があれば、それが指摘である。

- a. 何が誰へ渡るか — 種別・シンボル・渡る値
- b. 送信〜適用の間に周りの状態が変わったとき、古い結果はどう捨てられるか — 判定の軸は「送信路が view 寿命の共有か、per-request か」である。共有なら世代 token が要る。per-request なら `Receiver` の所有権を破棄すれば足りる。この 2 つを混ぜない。既知の型は 4 つある: 世代 token・チャネルの所有権・重複 spawn ガード・level-triggered 状態（網羅ではない。5 つ目の型を見つけたら、そう報告する）。特定した機構が実際に適用されているかまで見る。照合・破棄・remove・フラグの復帰が、すべての終わり方（成功・timeout・異常終了・リセット）にあるかを確かめる
- c. 状態を変えたあと、次のフレームを起こすものはあるか — フレームは自動では回らない。回数ではなく、起こす呼び出しに到達するかを問う。自ウィンドウからは `ctx.request_repaint()` を使う。外部スレッド・別ウィンドウ・listener からは wake handle を使う。managed state へ `egui::Context` の clone を置かない（worker の停止を妨げる）
- d. 送信〜適用の間に、何が届きうるか — 打鍵・起動・モード離脱・hide/show（reset-on-show による一括クリア）・config の適用・index build の完了・他の worker。到達しないと結論するなら、そのガードの条件式を `file:シンボル` か grep 結果で示す。hide をまたいで処理中のまま残る状態には、reset-on-show による後始末が組になっているかを確かめる。クリアする対象は view-local の範囲に限らない。managed state 側の共有スロットも見る
- e. 順序と live-read — この処理を別の位置へ動かすと壊れるか（壊れるなら順序を明文化する。壊れないなら、読み書きする集合が重ならないことを示す）。live-read について 3 点を確かめる: フレームの冒頭で読んだ値を後段で読み直さない。その値を `self.` へ保持しない。逆に、フレームをまたぐキャッシュによって hot-reload を効かなくしない

## 出力

境界ごとに a〜e と [安全] / [要修正] を書く（[要修正] には修正案を付ける。適用するかは呼び出し元が判断する）。判定には `file:シンボル` を添える。境界が 1 つも無ければ [非該当] と明示し、[安全] と書き分ける。検査を実行したことと、検査の対象があったことは別だからである。

仕事量は境界の数で決まる。境界が無ければ、母集団を取得して終わる。境界があれば、その数だけ 5 つの問いに答える。結論がどちらに向かうかで、仕事量を増減させない。
