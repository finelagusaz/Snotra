# Snotra Review Checklist

## 使い方

変更内容を次の観点に分類し、該当する節だけを読む。
レビューでは常に `正しさ -> 回帰 -> 保守性` の順で判定する。
所見を書くときは、壊れた不変条件とユーザー影響を先に書く。

## 1. 検索の正しさ

- 逐次入力で false negative / false positive が起きないか
- 前方一致、部分一致、kana、migemo、履歴ブースト、ソートの責務が混ざっていないか
- slash command と instant command への切り替えで通常検索の結果を誤再利用していないか
- 絞り込み最適化は「今回の述語が前回の部分集合である」と証明できるか
- `snotra-core` に UI 用文言を持ち込んでいないか

## 2. 検索状態遷移

- 入力文字列の変化だけでなく、検索モードの変化を追えているか
- `migemo_min_chars` の閾値跨ぎで fresh scan が必要にならないか
- `kana_query` が今回初めて生成される遷移をキャッシュ無効化条件に含めているか
- インデックス更新中、入力クリア、Escape、window 再表示で状態が破綻しないか
- `prev_*` キャッシュは正常系・空結果・early return の全パスで更新されるか

## 3. フォルダ展開

- 開始時スナップショットを保持し、`Escape` で一括復帰する不変条件が守られるか
- 展開中に検索結果が再計算されても、復帰先の基準がぶれないか
- 一部だけ展開状態が残る経路がないか

## 4. 起動結果と通知ライフサイクル

- `launch_item` の `LaunchResult(status/code/message)` 契約を壊していないか
- 失敗通知の自動クリアは単一タイマーで管理されているか
- 連続起動・連続失敗で前回タイマーを破棄しているか
- エラー意味は `is_error: true` で伝え、表示文字列は UI 側で決めているか

## 5. ウィンドウ・ホットキー・トレイ

- リスナー登録より前にホットキーやトレイを有効化していないか
- `show/hide`、focus、always-on-top の状態が整合しているか
- `show_main_and_emit` と UI 側の高さ再計算が競合しないか
- 起動直後の初期化スレッドとイベント購読順の不変条件を壊していないか

## 6. 設定反映

- `config.toml` 変更が本体と設定 GUI に一貫して反映されるか
- ホットキー、言語、テーマ、instant prefix、検索設定の反映タイミングが揃っているか
- watcher の多重登録、取りこぼし、二重反映がないか

## 7. 多言語対応

- フロントエンド、バックエンド、設定 GUI の3層で用語がずれていないか
- OS 言語からの初期判定ロジックを層ごとに重複実装していないか
- 言語切り替えイベントがトレイ・UI・設定画面へ揃って伝播するか

## 8. 子プロセス管理

- 子プロセス spawn に対して exit 時 kill が必ず対になっているか
- `Mutex<Option<Child>>` の重複起動防止を壊していないか
- 終了検知後の alwaysOnTop 復元が漏れていないか
- 隣接バイナリ追加時に release workflow のビルド対象を確認したか

## 9. 永続化と破損耐性

- 履歴、インデックス、アイコンキャッシュの書き込みは `.tmp` 経由で原子的か
- 読み込み側が壊れたファイルに対して安全側に倒れるか
- キャッシュ保存失敗が検索や起動の主要フローを止めないか

## 10. Windows 固有境界

- Win32 / Tauri 固有制約を UI 層に漏らしていないか
- Windows 非対応設定を `tauri.conf.json` 等へ入れていないか
- E2E で観測できない native window を WebDriver で直接検証しようとしていないか
- 可視判定の真実源を `plugin:window|is_visible` に寄せているか

## 11. テストと観測性

- 主要な状態遷移ごとに最小再現テストがあるか
- スモーク、E2E、ユニットのどこで守る不変条件か明確か
- ログや trace から「どのモードで失敗したか」を追えるか
- 壊れたときに「遅い」だけか「結果が欠ける」かを区別できるか

## 12. 回帰範囲

- 同じパターンが `snotra-core`、`src-tauri`、`ui`、`snotra-settings` の他所にないか検索したか
- API 境界をまたぐ修正で、呼び出し側パッチだけに寄っていないか
- 変更なしと判断した対称コードパスについて根拠を書けるか
