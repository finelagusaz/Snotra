# ADR-0009: コマンドの形で判定する規範を PreToolUse へ吸収し、platform は第 4 位置引数で注入する

ルート `CLAUDE.md` の常時ロード面に置いていた規範 5 件（bash HEREDOC 禁止・`\` パス区切り・Python の `PYTHONIOENCODING`・`--no-verify` 人間専用・`git pull --ff-only`）を `.claude/hooks/pre-bash.mjs` の判定へ移した（#768）。**この ADR が残すのは、そのとき `decide` の注入面をどう広げるかで却下した案である**——採った形とその理由は `docs/hooks.md`「PreToolUse（pre-bash.mjs）の実装契約」とコードが持つ。

## 文脈

5 件はいずれも「エージェントが打ちうるコマンドの形」で判定できる。だが前 3 件は Windows 固有の失敗様態（シェルが `\` を食う・cp932 コンソールが非 ASCII で落ちる）にしか当たらず、**`pre-bash.mjs` には platform を注入する面が無かった**。

`decide(payload, readGitState, readPlanState)` は外部状態をすべて注入で読む設計である。ゆえに第 4 の入力を足すことは「規範を hook へ移すだけ」では済まず、判定の骨格そのものへの手入れになる。既存の `decide` 呼び出し点は 23 箇所（テスト 22 + `main()` 1）だった。

## 決定

1. **`platform` を第 4 位置引数として、reader ではなく素の値で受ける。**
2. **`platform` が渡されないときは Windows 専用判定を発火させない**（非 Windows と同じ扱い）。
3. 配線（`main()` が `process.platform` を渡すこと）を**ソースカナリアと process 級 e2e の二重**で固定する。

## 検討した代替案と却下理由

- **`readPlatform()` reader 形にする（既存 2 つの注入と揃える）**: 却下。既存の 2 つが `{ ok: false, reason }` を持つのは**失敗しうる I/O** だからである（`git` の起動失敗・ファイルの読み取り失敗）。`process.platform` は失敗しない。失敗しえないものへ失敗の表現を与えると、`ok` が常に true な分岐がテストと読者に「ここは失敗しうる」と嘘をつく。形の統一より、**表現が事実に対応していること**を採った。

- **options オブジェクトへ改修する（`decide(payload, deps)`）**: 却下。位置引数の増加を止められる正しい終着点ではあるが、**今の利益が既存 23 呼び出し点を機械的に書き換える差分に見合わない**。位置引数 4 本は読める範囲であり、既存テストを 1 行も触らずに済むことは「I7: 既存呼び出しの意味を変えない」の確認を容易にする（書き換えた 22 箇所が緑であることは、書き換えなかった 22 箇所が緑であることより弱い証拠である）。**5 本目を足すときに再検討する**——そのときは足す判定と同じサイクルで改修する。

- **`platform === undefined` を Windows へ倒す（fail-closed）**: 却下。**この判断は plan-review の独立導出と割れた**（相手は Windows へ倒すべきと結論した）ため、理由を残す。`docs/hooks.md` の fail-closed 契約が「判定不能はすべて block へ倒す」と言うのは**「何が実行されるか分からない」場合**である。platform が分からないのは「その規範がここで効くのか分からない」ことであって、実行内容は完全に見えている。前者と後者を同じに扱うと、非 Windows で heredoc という**正しい操作**が止まる。
  - **とはいえ相手の要求（配線が切れたら気づけること）は正しい。** 倒す向きは維持したまま、求められたソースカナリアを process 級 e2e に**追加**して両方置いた。`npm test` は ubuntu と windows の双方で走るため（`.github/workflows/ci.yml`）、e2e は両分岐をそれぞれの OS で一度は実行する。
  - **受容する残余**: `decide` を `main()` 以外から第 4 引数なしで呼ぶ新しい実行経路が生まれた場合、Windows 専用 3 判定はそこで沈黙する。カナリアは `main()` の 1 行しか見ていない。

- **`\` 判定に `node_modules` 等の免除を彫る**（`post-edit.mjs` の再現コマンドが自判定に当たる問題への対処）: 却下。免除句は名指しした対象しか守らず、逃げ道は列挙の隣へ移る（`/norm-review`「Step 3」）。**根本は「エージェントへ渡す文字列が規範を破っていること」**であり、直す先は判定ではなく `post-edit.mjs` の `repro` である。

- **`\` を広く検出する（`\` の後ろにパスらしい文字が続く形すべて）**: 却下。`grep -E "\d+"` の正規表現エスケープや `find . -exec rm {} \;` を巻き込む。ドライブレターと環境変数展開に続く区切りの 3 形に絞り、**過小検出を意図的に受け入れた**（`\` 判定はこの 5 件の中で唯一、検出漏れ側へ倒している）。

- **引用を認識してセグメントを分割する**: 却下。`git commit -m "a;b" --no-verify` を捕まえられる代わりに shell パーサ相当へ近づき、#482 が根治した payload 全体 grep の誤爆を作り直す。残る漏れは `sh -c` と同格の意図的迂回として扱う。

- **`git pull` の判定で現在のブランチを見る**（main 以外の pull は通す）: 却下。規範の文面（「main の同期は」）には忠実になるが、`readGitState` の責務を「upstream と未 push の有無」から広げる。過剰検出の代償（feature ブランチでの `git pull` も止まる）は、`--ff-only` を付けるだけで解けるため軽い。

## 帰結

- 常時ロード規範の面積が下がり、`AREA_BUDGET.alwaysLoaded` を実測 + 100 字へ引き下げた。**知識は消えていない**——事故の理由と代替手段は拒否文言（`SHAPE_REMEDY`）が実行時に運ぶ。
- **`docs/hooks.md`:12 の「コマンド位置だけを見る」が全称表現として偽になったため是正した。** heredoc・`\`・非 ASCII の 3 判定はコマンド全体を見る。`docs/development-principles.md` §6 の一般則は正しいまま置き、逸脱は具体の側（`docs/hooks.md`）に理由付きで記した——narrow な例外を広い原則文書へ書き戻すと原則が弱まる。
- `git commit -n` を `--no-verify` と同義として検出する。**issue の文言より広い**が、commit では実際に同義である。`git push -n`（= `--dry-run`）を巻き込まないよう、短縮形の判定は commit セグメントに限定した。
