# ADR-0010: `/implement`「出力」へ Step 4 の報告項目を新設するとき、母集団を閉じる形以外を却下した

`/implement`「出力」に Step 4（4a の check スキル・4b の `code-reviewer`）の受け口が無く、レビューを実施した回と素通りした回が報告から区別できなかった（#765）。**この ADR が残すのは、そのとき却下した案である**——採った形（三値 + 閉じた母集団）は `/implement`「出力」自身とコミットが持つ。

## 文脈

同じ PR（#764）で「出力を軽くする」較正を入れた直後であり、項目を足す方向が正しいかが自明でなかった。加えて `/health-check`「Check 7 — MEMORY.md 参照の実在性」と `/plan-review`「Step 3 — 結果の統合と報告」が既に同じ失敗様態（実施の有無が会話にしか無い）へ答えを持っており、新規発明と既存形の流用のどちらを採るかが論点だった。

## 検討した代替案と却下理由

- **4b の結果をコミットメッセージ側へ寄せる**（会話の「出力」節は増やさない）: 却下。git に残る利点はあるが、**#765 が述べる失敗面は意思決定時に読む会話面であって永続性ではない**。報告面を git へ移しても、その場で「実施した回と素通りした回」を区別する手立ては増えない。**どの面で失敗が起きているかが、対策を置く面を決める。**

- **項目 2（最終検証結果）と項目 3（Step 4 のレビュー結果）を 1 項目に畳む**（項目数を増やさない）: 却下。検証（カテゴリ A〜F）とレビュー（check スキル・エージェント）は**別の失敗様態**であり、同じ項目に混ぜると片方が沈黙する。#764 の総括パターン 3（記録テンプレートの有無が実施の有無の唯一の観測点）が言うとおり、テンプレートを持たない側へ責務を寄せるとその責務は消える。

- **項目 3 の母集団を `AGENTS.md`「条件別チェック（トリガー → 参照先）」表へ直接指す**（写しを作らない）: 却下。表は check スキル以外の行（rules 参照・grep 指示・skill でない手順）を含む混成表であり、忠実な読者が非スキル行まで 1 行ずつ書こうとする経路が開く。**写しであることを名指ししたうえで受容した**——`/implement`「4a. check スキルの実行」の列挙が表と同期している間だけ母集団が一致するという前提条件を、全称表現と同じ場所に書いた（`AGENTS.md`「検証の作法（全タスク共通）」の全称表現規則）。乖離を検知する機構は置いていない。

- **停止時の免除を、経路を名前で列挙して直す**（「Step 1 で止まった場合」に「Step 3 の中止」を足す）: 却下。免除句は名指しした対象しか守らず、逃げ道は列挙の隣へ移る（`/norm-review`「Step 4 — 記録と、素通りした種の修正」）。「到達しなかった Step に対応する項目は書かない」という**原理**へ書き換えたことで、**既存の「コミット」項目が Step 3 中止経路で充足不能だった先行欠陥も同時に消えた**——列挙で直していれば、その先行欠陥は列挙に載らないまま残っていた。

- **`npm run governance:check` に、本変更の遵守を測る検出器を足す**: 却下。`docs/development-principles.md`「構造的設計原則と強制の階梯」が「検知手段が無いと書きかけたら、検知可能になる設計へ変えられないか先に問う」と述べるのに従って (a) 責務を検査可能な層へ移す・(b) 観測点を作る の 2 種を検討したが、**報告そのものは会話にしか存在せず git にもディスクにも残らない**。検出器が測れるのは「規範文が書かれているか」までであり、それは #765 が塞ごうとしている当のものではない。**受容する残余として記録した。**

## 帰結

- 「出力」は 3 項目から 4 項目になった。**面積 ratchet（G10）は掛からない**——skills 本文は `AREA_BUDGET.alwaysLoaded` の母集団外であり（`scripts/governance-check.mjs`）、課税されるのは frontmatter の `description` だけである。「出力を軽くしたばかりで項目を足してよいか」という #765 の懸念は、**面積予算の問題ではなかった**。
- `/norm-review` を 2 巡回し、8 件を 1 文ずつで塞いだ。**2 巡目の 3 件のうち 1 件は 1 巡目の塞ぎ自身が作った過剰な全称表現**であり、修正は縮める方向だった（分量予算が塞ぎの膨張を止めた実例）。
- **`/norm-review` 自身は新設した項目 3 の母集団の外にある**——`AGENTS.md` 表 → `.claude/rules/safety-nets.md` の 2 段間接で到達し、4a が名指しする 6 スキルに含まれない。本変更自身がその実例であり、名前を挙げた残余として残した。
