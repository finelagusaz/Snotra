# ADR-0018: G14 / G15 を置いたとき、窓幅だけで判定する案と規範側へ義務を足す案を却下した

`governance:check` に **G14**（正準形に見えて隣接していない見出し参照・#727）と **G15**（`/implement`「4a. check スキルの実行」の列挙 ↔ `AGENTS.md`「条件別チェック」表・#778）を置いた。**この ADR が残すのは、そのとき却下した案である**——採った述語と理由は `scripts/governance-check.mjs` の G14 / G15 節が持つ。

## 検討した代替案と却下理由

### 却下 1: G14 を窓幅だけで判定する（#727 が提案した形）

#727 は「バッククォートで閉じた `<path>.md` / `/skill-name` の近傍（数文字以内）に `「…」` があるのに隣接していない箇所を finding にする」「窓幅を狭く（例: 4 文字以内）取れば実用上は分けられるはず」と書いていた。**実測したら分けられなかった。**

| 窓幅 | 非隣接で `「…」` が近傍にある | うち引用が着地する |
|---|---|---|
| 2 | 13 | 5 |
| 4 | 19 | 7 |
| 8 | 36 | **8** |
| 12 | 42 | 8 |

窓幅を絞っても、参照でない散文（「`SPEC.md`（…）は「何を実現すべきか」を記す」「`docs/adr/0005-*.md`（…）。「承知の上で受容した」」）が混じり続ける。**分ける軸は距離ではなく「引用が実際に見出しへ着地するか」だった。**

着地条件を課すと、窓を広げても真の参照は 8 件で頭打ちになり、増えるのは無視する側だけになる。ゆえに**窓幅 8・着地必須**とした。窓幅は「頭打ちになる値」であって、誤爆を絞るための値ではない。

### 却下 2: 着地しない非隣接参照も finding にする

腐った参照（消滅した節を指す散文形）を拾えるように見えるが、**歴史記述と区別できない**。`docs/check-skill-skeleton-design.md` は「`/race-check` の「非該当と結論してよい条件」節を書き換える試みを行い」と書いており、この節は `docs/adr/0013-race-check-simplification.md` で実際に消滅している——**正しい歴史記述である**。

`.claude/rules/governance-docs.md`「既に消滅した節の名前を正準形で書かない」（歴史を書くならバッククォートを外して散文にする、と定める）が規範として担う領域であり、機構では分けられない。**受容する残余**とする。

### 却下 3: `§` に節番号を許さないまま G14 を置く

G11 の正準形は `§` の直後に `「` が来る形しか許していなかった。この状態で G14 を置くと、下の 1 行目に対して「助詞を外せ」と指摘しながら、外した 2 行目も G11 の視界に入らない——**直せない指摘**になる（実測 2 件）。

```
`SPEC.md` §11 の「見た目の規範」   ← G14 が指摘する
`SPEC.md` §11「見た目の規範」      ← 直した先。番号を許さないと G11 も見ない
```

G11 の `HEADING_REF` を `§\s*[\d.]*\s*` へ広げた。#727 の射程は「G11 の死角」であり、死角の一部が G11 自身の正準形の狭さに由来するなら、そちらを広げるのが筋である。副作用として G14 の finding は 8 → 7 件になった。

### 却下 4: #778 を (a)（`AGENTS.md` の表側へ同期義務を 1 行置く）で解く

#778 は (a) を「行為者の視界に入る唯一の面」と評価しており、**劣化案ではない**。しかし `AGENTS.md` は G10 の常時ロード面で余裕が小さく（実測 13248/13338 字）、`AREA_BUDGET` の引き上げを伴う。

**(b)（機械照合）の述語が書けたので、そちらを採った。** #778 は「表は rules 参照・grep 指示を含む混成表であり、`/plan-review` も現れるため、判定を機械で書けるかが論点」としていた。着手前に現行コーパスへ当てて実測した結果:

- 表の `/…-check` = {cache, dry, persistence, race, state, symmetric}（6 件）
- 4a の `/…-check` = 同じ 6 件
- `/plan-review` `/norm-review` は `-check` で終わらないため**構造的に外れる**
- `/health-check` は表に現れない（ルート `CLAUDE.md` のスキル表に在り、そちらは G8 が見る）

規範を 1 行も足さずに済み、常時ロード面も増えない。

### 却下 5: `-check` で終わらない check スキルを名前以外の方法で判定する

将来 `-check` で終わらない check スキルが増えると G15 の母集団から落ちる。frontmatter に印を足す案・スキル一覧から導出する案を検討したが、**印を足す案は「印を付ける義務」が行為者の視界の外にあるという #778 の当の問題を再生産する**。

命名規約に乗せるほうが、行為者（スキルを新設する人）の視界に入る。**受容する残余**とし、G15 節に明記した。

## 帰結

- **`SPEC.md` §11 のような節番号つき参照が G11 の照合対象になった**（照合件数 175 → 183 件）
- **#778 の (a) は不要になった。** `AGENTS.md` の面積を消費せずに済んだ
- 非正準形だった 7 件を正準形へ直した。うち 1 件（`docs/adr/0005-*.md`）は ADR だが、**参照の書式を整えることは記録された決定を書き換えることではない**（`docs/adr/0015-norm-review-seeding.md` 却下 3 が禁じたのは、参照先の**名前**が変わって過去の事実が消えることである）

## 受容する残余

- **着地しない非隣接参照**（却下 2）。歴史記述と区別できない
- **`-check` で終わらない check スキル**（却下 5）。命名規約に依存する
- **G14 の窓幅 8 の外にある参照**。実測では頭打ちだが、将来より長い挿入が現れれば見えない
