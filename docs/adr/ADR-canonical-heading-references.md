# ADR-canonical-heading-references: 文書間の参照に正準形を与えて機械照合し、序数参照をやめる

## 文脈

`.claude/rules/governance-docs.md` は、ガバナンス文書の構造を改変する前に「参照側を名前と序数の両方で数え上げよ」と要求していた。これは人手の列挙であり、`governance:check` は参照**先のファイルの実在**は見ても、参照**先の見出しの実在**は見ていなかった。

帰結として 2 つの害が同時に出ていた。

1. **構造が凍る** — `AGENTS.md` のワークフローは `ステップ 0` / `Step 8` という序数で 7 箇所から参照されており、番号をずらすと静かに壊れる。壊れても失敗として現れないため、**中身が古びても直せない文書**になっていた。
2. **実際に腐っていた** — G-heading-refs 導入時の初回実行で、`PERFORMANCE.md` が src-tauri の「TrySuspend / Resume パターン」節を指したまま残っているのを検出した。この節は WebView2 層ごと #532 SU7 で消滅している（本 ADR がこの死んだ名前を正準形で書かないのは `.claude/rules/governance-docs.md`「既に消滅した節の名前を正準形で書かない」に従うためである——初稿は従っておらず、G-heading-refs が自分を導入した ADR を落とした）。人手の列挙規範は、この 1 件を見つけられないまま運用されていた。

## 決定

1. **参照の正準形を `` `<対象>`「<見出し>」 `` と定める**（対象は `<path>.md` または `/skill-name`）。
2. **G-heading-refs で正準形の着地を機械照合する** — アンカーは ATX 見出し・番号付きリスト項目・太字リードの 3 種、照合は正規化（`**`・バッククォート・「」・空白の除去）後の前方一致。
3. **他文書を序数で指さない**。既存の 7 箇所は名前参照へ移した。

## 検討した代替案と却下理由

- **マッチャを緩めて（部分一致で）既存の全参照を着地させる**: 却下。**これが最も危険な選択肢である**——現状に合わせて調整した検査は現状の写像になり、ドリフトを検出しない。34 件中 3 件が着地しなかったとき、直すべきは検査ではなく参照側だった（`.claude/rules/safety-nets.md`「検査の入力集合を、具体対象で検算する」の適用）。前方一致に留め、規約に沿わない参照 2 件を書き換えた。
- **序数参照も機械照合できるようにする**（「ステップ N」→ N 番目の項目の実在を見る）: 却下。着地はするが「N 番目が今も同じ意味か」は見ないため、**凍結が解けない**。番号がずれた瞬間に検査は緑のまま意味だけが壊れる。名前で指させる方が、機構としても人の読みとしても本質的である。
- **散文形（「ルート `CLAUDE.md` のフック節」）も検出する**: 却下。「言及」と「指し」を構文で区別できず誤爆する。判定を構文位置に限る点は、PreToolUse 判定をコマンド位置に限った #482 の教訓と同型である。正準形へ書き換えたものだけが検査される、という非対称を受容する。
- **人手の列挙規範を維持したまま検査を足さない**: 却下。`docs/development-principles.md`「構造的設計原則と強制の階梯」の上段（機構が吸収できるなら規範にしない）に反する。実際、規範だけの運用下で 1 件腐っていた。

## 帰結

- `.claude/rules/governance-docs.md` から手作業の列挙手順が消え、代わりに正準形の規約が入る（12 行 → 13 行。**面積は減っていない**——変わったのは中身であり、「数え上げよ」という実行不能に近い義務が「この形で書け」という書式規約になった）。
- **序数参照の解消は `AGENTS.md` を指すものに限る**（7 箇所）。**他文書から skill の Step を指す形は残っている**——`/plan-review`「Step 2b」（`AGENTS.md`・`start-issue`・`governance-docs.md`）、`/retrospective`「Step 6」（`health-check`）、および ルート `CLAUDE.md` から `/implement`「4b. code-reviewer エージェント」。多くの skill は見出しが `## Step 2b — 独立導出 + 差分` のように**番号を見出し語の一部として持つ**ため、正準形に書けば G-heading-refs が着地を照合できる。**ただし形は揃っていない**——`/implement` だけは `### 4b. …` であり「Step 4b」では着地しない（この段落の初稿が実際に G-heading-refs で落ちた）。移行は本サイクルの範囲外。
  - **2026-07-26 追記**: 上に「残っている」と書いた 3 群は #720 で正準形へ移行済みであり、この残余は解消している。さらに同日、`/implement` の責務境界の変更（計画フェーズの除去）で Step が繰り上がったため、本文中の `5b.` を `4b.` へ追随させた（正準形のまま保ち、G-heading-refs の照合対象に留める）。
- **受容する残余**: 正準形でない参照（散文形・skill 内部の自己参照・上記の未移行分）は G-heading-refs の視界外である。**節の移動・圧縮・分割の完全性も機構では担保されない**——旧内容の全命題が新構造のどこへ着地したかは `/plan-review`「Step 2b」の独立再導出で裏取りする。
- 母集団は追跡下の全 `*.md` から `docs/superpowers/`（履歴資料）と `workspace/`（`/implement` が削除する作業バッファ）を除いたもの。ガバナンス文書に限らないのは、腐っていた 1 件が `PERFORMANCE.md` にあったためである。
  - **2026-08-04 追記（#925）**: 母集団へ **Rust ソース（`.rs`）の腕**を足した（`docs/adr/` の除外はその後 `ADR-adr-frozen-history` が加えている）。#921 で SPEC の節の中身を移したとき `.rs` 側の参照は手で直す必要があり、検査は緑のままだった——`.rs` には正準形が 27 件あり、そのすべてが改題・移動・削除に対して沈黙していた。腕を 2 本に分けたのは 0 件検知が母集団ごとに 1 本ずつ要るためで、`.rs` の腕は md の腕の除外接頭辞を共有しない（凍結の契約は ADR **本文**についてのものであり、コードについては何も決めていない）。
  - 却下した案: (1) **`.mjs` / `.ps1` へも広げる**——実測した `.mjs` の finding 9 件は、6 件が検出器のテストフィクスチャ、残り 3 件が検出器自身のコメント（正準形の例示 1・切り詰め表記 1・本物の腐り 1）で、入れれば検出器の説明が検出器を赤にする（腐り 1 件は母集団に入れないまま #925 で直した）。(2) **SPEC の本文 bullet へ太字リードを足し、本文の言明を指す引用を着地させる**——SPEC の見出し構造がコードコメントの引用文言に従属し、「本文の言明には太字リードを与える」という規範条項の新設も要る。(3) **検出器で見出し名の引用と本文の引用を記法で分ける**——正準形が 2 系統になり、既存の全参照に新しい判定が要る。(2)(3) の代わりに**参照側の記法を直した**（`「」` の中身は見出し名だけとし、本文の言明は `「」` の外に散文で書く）。
  - **2026-08-19 追記（#1138）— 上の却下 (1) を覆した**。母集団へ **スクリプトの腕**（コメント記法を持つファイル。述語は `scripts/governance/lib.mjs` の `commentFamilyOf`）を足し、走査はコメント行に限る（`linesOfComments`）。覆した根拠は 2 つある。
    - **却下の実測が射程の半分を見ていなかった**。#925 が数えた finding 9 件はすべて `.mjs` のものであり、`.ps1` / `.psm1` は 1 件も測られていない。今回リポジトリ全体を数えたところ、そこに本物の腐りが 2 件あった（読点と強調を落とした言い換え・アンカーでない段落頭の太字リードを指す参照）。**却下の理由が `.mjs` にしか当たらないのに、結論は `.ps1` まで及んでいた。**
    - **却下の理由そのものが、走査をコメント行へ限ると消える**。負の fixture が赤くなるのは「テストファイルだから」ではなく**文字列リテラルに書かれたデータだから**で、参照はコメント＝散文に書かれる。実測（拡張前の作業ツリー・`.md`/`.rs` 以外の全件）: コメント行の参照はすべて実参照、非コメント行はすべて `*.test.mjs` の fixture だった。検出器自身のコメント（正準形の例示）は、対象の形に当たらないプレースホルダへ替えて解いた。
    - **非対称の向きが `.rs` と逆だった**ことも根拠に数える。正準形の規範は `paths` に `scripts/*.mjs` / `scripts/*.ps1` / `scripts/lib/**` を持つ——**この形で書けと配送しながら、検めていなかった**。
    - 拡張の初回実行は近傍形 1 件（`scripts/manual-smoke.ps1`）を名指しした。**この 1 件は #1138 の調査で対照群として先に測ってあり、機構が同じものを独立に見つけた**。
    - **受容する残余**: `.json` はコメント記法を持たないので入らない。文字列リテラルの中の参照・PR 本文・凍結層も従来どおり視界の外である。コメント判定は字句解析ではないので、**テンプレートリテラルの中で `//` から始まる行はコメントと誤判定される**——赤に倒れる誤りなので沈黙しない。
  - **2026-08-20 追記（#1155）— 却下 (1) の残り半分（対象の綴り）も覆した**。#1138 が覆したのは**走査元**であり、**対象として認める綴り**は `.md` と `/skill-name` のままだった。この非対称の下では、スクリプトを対象に置いた正準形は**照合そのものが生成されない**（`isRefTargetSpelling` が弾き、`checked` にも数えられない）——#1152 が撤去したファイルを指す参照が生きた層に残り、緑のまま推移していた。対象綴りへ `.mjs` を足し、着地先として `ANCHOR_SPECS` に**テスト名の腕**（`describe` / `it` の第 1 引数）を足した。
    - **腕は必須である。** `.mjs` には ATX 見出しが無く、`//! - **…**` は行頭が `//!` なので太字リードにも当たらない。腕を持たずに対象綴りだけ広げると、**実在するファイルを指す参照が「着地しない」で恒久的に赤くなる**（拡張前の写しで独立導出が実測・2 件）。
    - **`.ps1` / `.psm1` / `.rs` は入れない。** 対象に置いた正準形が 0 件で、足しても照合が 1 件も生まれない（宣言する死角。書かれ始めたら足す）。
    - **効果は今日の検知数ではない。** 導入時に赤くなった既存の腐りは #1155 が直す 1 件で、それを閉じれば新しい検知は 0 になる（もう 1 件は下に書くとおり、この差分が自分で持ち込んだ例示である）。足す根拠は `AGENTS.md`「条件別チェック（トリガー → 参照先）」の「壊れたとき緑が緑のまま推移するか」であり、この形は現に推移した実績を持つ。
    - **#925 の却下理由「検出器の説明が検出器を赤にする」は、対象綴りの側でも起きた**——導入と同じ差分で、`isRefTargetSpelling` の doc に書いた例示のプレースホルダ自身が赤になった。例示を散文へ替え、その禁止を同 doc の宣言として残した（走査元の側で #1138 が採ったのと同じ解き方である）。
    - **受容する残余**: `docs/adr/` は走査元から外れているため（`ADR-adr-frozen-history`）、ADR 内から `.mjs` を指す参照は今も照合されない（実測 1 件）。
  - **受容する残余**: 正準形の規範（`.claude/rules/governance-docs.md`）は `paths` に `.rs` を持たず、Rust の書き手へ配送されない（2026-08-04 の裁定——全 Rust 編集へこの rule 1 本ぶん（裁定時の実測 1677 字）を配送する費用を避けた）。実際 #925 が見つけた腐り 1 件は、改題への追随漏れではなく**規範を知らないまま記憶で言い換えた**ものだった。事前には防がれず、CI の赤が事後に捕まえる。
- `AGENTS.md` のワークフロー番号は外部参照から解放された。**構造の改変自体は本 ADR の範囲外**（検査対象を変更しながら検査を検証しない・#489）。
