# ADR-canonical-source-without-pointer-indirection: 正本を定めても、他所をポインタへ倒さない

## 文脈

#825 は「`CLEAR_COLOR` と config 既定背景色の一致に落ちる検査は無い」という**主張の写し**が 6 箇所に残っていた事案である（検査は #802 で追加済みだった）。`AGENTS.md`「条件別チェック（トリガー → 参照先）」の「文書に事実の写しを増やす変更 → 正本を 1 か所に定め他は参照へ」が当たる形として起票された。

計画の第 1 版は、この規範を素直に読んで「正本 = `renderer.rs` の `CLEAR_COLOR` の doc（値を変える人が必ず開く場所）／他所 = そこへのポインタ」という構造を採った。

## 決定

**正本は定める。ただし他所をポインタへ倒さない——各所が事実を正しく述べ、`.md` は被参照の実体（テストのパス）を直接書く。**

「正本」が意味するのは「**由来と理由を最も詳しく書く場所**」であって「他所が指す先」ではない——`AGENTS.md`「条件別チェック（トリガー → 参照先）」の「他は参照へ」は、参照の**形**を指定していない。

## 検討した代替案と却下理由

- **他所を「正本を見よ」というポインタへ倒す（計画第 1 版）**: 却下。**照合の向きが逆になる。**

  | 書く場所 | 書く内容 | 機械照合 |
  |---|---|---|
  | rustdoc（正本） | テストのパス | **無い**（`governanceDocs` は `.md` のみ） |
  | `.md`（参照側） | 「あの doc を見よ」 | `renderer.rs` の**実在**のみ。doc の**中身**は誰も見ない |

  機械照合される場所（`.md`）に照合されないポインタを書き、照合されない場所（rustdoc）に照合されうる情報（パス）を書くことになる。`.md` からテストのパスを直接書けば、パスの実在は G-references が守り（`REF_EXTENSIONS` に `.rs` を含む）、**その `.rs` ファイルが消えた・改名された瞬間に** CI が名指しで落ちる——ポインタ構造が一切与えない保証である（**保証はそこまでである**——同じファイルの中でテストを動かしても緑のままで、それは下の受容する残余が引き受ける）。**腐りを消す変更が、新しい未照合の腐り面を増やしていた。**

  加えて、読者は答えを得るのに 1 ホップ余計に払い、その 1 ホップは機械が守らない。

- **写しをそのまま許容し、各所を個別に直すだけ（正本を定めない）**: 却下。値を変える人が最初に開く場所（定数の定義位置）に由来が無いと、次の変更者が同じ調査をやり直す。正本を定める価値は「指す先を作ること」ではなく「**探さなくてよい場所を 1 つ約束すること**」にある。

## 帰結

- **判定基準は「その参照を機械が照合するか」である。** 照合される形（`.md` 内のパス・正準形の見出し参照）があるなら、それを書く。無い形（rustdoc・`.ps1` からのパス、シンボル名一般）しか選べないなら、**規範で補ったうえで受容する残余として明記する**。
- **同じ事実が 2 箇所で正しく述べられることは、この規範の違反ではない。** #825 が消そうとした欠陥は「**事実が古くなったこと**」であって「事実が 2 箇所にあること」ではない。`CLEAR_COLOR` の一致は同じ**判断**を 2 度書いたものではなく、**同じ機構を 2 つの読者層**（crate の実装者と crate の利用者）へ告げたものである。
- **不在の主張は、書いた瞬間から腐り始める。** 「検査は無い」「受容する残余」は**照合すべき実体が存在しないと述べている**ため原理的に機械照合できず、**誰かが機構を足した日に偽になる**——足した本人はその散文を通らない。#825 はまさにこの形で、#802 がテストを足した日に 6 箇所が一斉に偽になった。ゆえに (a) 残余を書くときは、それを固定しうる機構の名前（肯定形）へ倒せないか先に問い、(b) **検出器・テストを新設したときは、その不在を述べた散文を grep する**。対照が同じ変更の中にある——同じ事実を中立形で書いた `scripts/visual-check-colors.ps1` の 1 箇所だけが腐らずに済み、否定形で書いた側が全滅した。
- **受容する残余**: テスト名 `runtime_fallback_matches_config_default_background` の実在はどの検査も見ない。**拘束しているのは述語ではなく母集団である**——名前を書いた `.md` 2 箇所は `snotra-egui-runtime/CLAUDE.md`（モジュール `CLAUDE.md`。#891 が測定のうえ「足さない」と決めた面）と本 ADR（`docs/adr/` は #891 が明示的に除外）で、`.rs` 側 2 箇所は rustdoc ゆえどの `.md` 母集団にも入らない。**G-stale-identifiers の述語に snake_case を足しても、4 箇所のうち 1 つも検査対象にならない。** ゆえにテストを改名・削除すると**生きた 2 箇所**（`renderer.rs` の doc と `snotra-egui-runtime/CLAUDE.md`）が緑のまま stale になる（ADR 自身は当時の決定文脈ゆえ旧名のままでよい・`docs/development-principles.md`「撤去（消す変更）の作法」）。テスト側の doc に「テスト名で grep して数え上げる」と規範で補った。
- **#891（G-stale-identifiers の射程拡大）は本件のクラスを閉じない。** #825 が腐らせたのは**識別子ではなく命題**である——`CLEAR_COLOR` も `default_background_color()` も現存しており、偽になったのは「その一致に検査は無い」という主張の方である。同検出器はどれだけ射程を広げても命題の真偽を見ない。**follow-up が在ることを、このクラスの再発防止が済んだと読まないこと。**
