# ADR-comment-pointer-trim-scope: コードのコメントの参照を減らしたときに、消さなかった形と、却下した確かめ方

2026-11-08、#1408 で `.rs` のコメントから「（`X` の doc）」と添えるだけの出所の印と、「`X` の doc を見よ」の道案内を消した（判定した候補 175 件のうち 32 件）。消したのは、その参照が効いているブロックのコードが X を実際に使い、読者が定義へジャンプできるものだけである。**この ADR が持つのは、同じ見た目の参照のうち消さなかった形と、その理由である。** 次に同じ整理をする人が、残った参照を消し漏れと読まないために置く。

## 消さなかった形

- **doc コメント（`///` `//!`）のリンク形 `` [`X`] の doc ``**: `cargo doc` が着地を確かめる名指しであり、`docs/comment-guidelines.md`「名指しと正本の指名」が精密事実の第一の道具に置く形である。`//` の行のリンク形は `cargo doc` が見ないので、この理由では残さない（ほかの形と同じ基準で判定した）
- **「理由は／根拠は／経緯は／帰結は `X` の doc」型（所在の宣言）**: 「（`X` の doc）」と違い、手元に主張を書かず、中身の所在だけを言う形である。消すなら、理由を隣へ書くか、要らないと判断するかを 1 件ずつ決める必要があり、参照を削るだけの変更では閉じない。規約（「第一原則: コメントは理由を書く」）はこの形を「遠くを指すだけで済ませない」と名指ししているので、規約に沿って触ったときに直す扱いにした
- **正本・契約の指名**（「正本は `X` の doc」）: 1 か所にしか置けない精密事実を指す形で、規約が残すとしている
- **doc の文言の逐語引用**（「`X` の doc が宣言する『…』」）: 出所を消すと、出所の無い引用になる
- **名前は同じファイルに出るが、ブロックのコードが X を使わないもの**: ファイル単位の名前の一致は、呼び出しの関係を示さなかった（例: `window_coordinator.rs` の `window_width` は config のフィールドで、指された `view.rs` の関数ではない。`read_config` も同名の別の関数を呼んでいた）
- **外部 crate の doc・テストが何を固定するかの宣言・文字列リテラルの中**

## 却下した確かめ方

- **「変更行がすべて `//` で始まる」ことで、コメントだけの変更と見なす**: 却下。文字列の継続行（`"abc\` の次行が `// x";`）を変えても `//` で始まる行の変更に見え、実行結果は変わる（反証の調査で実験した）。コードの純削除も、追加行だけを見る実装では見逃す。代わりに、コメントを落とした Rust のトークン列を変更の前後で比べた（文字列・raw 文字列・char とライフタイム・入れ子のブロックコメントを区別する字句解析。リポジトリには置いていない）
- **`cargo doc` で、doc コメントのバッククォートの欠けを捕まえる**: 当てにならない。`rustdoc::unescaped_backticks` は既定で allow で、欠けた結果 `<…>` や `[…]` がコードスパンの外に出たときだけ別の lint が赤にする（変異で確かめた）。`#[cfg(test)]` の下の doc は `cargo doc` がそもそも見ない。追加した行のバッククォートの数が偶数であることで確かめた

## 受容する残余

- 抽出は正規表現の近似であり、母集団の外の書き方（「`X` を参照」など）は判定していない
- 所在の宣言の型は残っている。規約の「遠くを指すだけで済ませない」と食い違う形が、既存のコメントに残っている
