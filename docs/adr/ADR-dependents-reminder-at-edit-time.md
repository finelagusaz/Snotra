# ADR-dependents-reminder-at-edit-time: 節の中身が変わったことを、編集直後に reminder として知らせる

## 文脈

`G-heading-refs` が保証するのは「ラベルが見出しに着地するか」だけで、**見出しの名前が変わらないまま本文が入れ替わっても緑のままである**。`ADR-canonical-heading-references.md` は「節の移動・圧縮・分割の完全性も機構では担保されない」と明記し、裏取りを `/plan-review`「Step 2b」の独立再導出へ委ねていたが、**委ねた先が実際に走ったかを誰も見ていなかった**。

実測（2026-08-19・`git blame` による上限値）: 生きた層で着地している正準形の参照 271 件のうち、**81 件（30%）が「参照が書かれたあとに指し先の節が変更された」状態**にあった。ずれの日数は中央値 6 日。この 81 件に対して検査は一度も鳴っておらず、鳴る仕組みも無かった。

## 決定

`.md` の編集直後に、PostToolUse hook が「変更された節に依存する参照」を **reminder** として出す。**合否は持たない**（`ADR-retire-area-budget` が面積で採った形と同型で、判定は人が持つ）。判定は `scripts/governance/dependents.mjs` が持ち、hook は **subprocess** で呼ぶ。

## 検討した代替案と却下理由

- **安定アンカー ID（`{#slug}`）へ移し、改名で参照が壊れないようにする**: 却下。`ADR-canonical-heading-references.md` が序数参照を却下した理由がそのまま当たる——「着地はするが N 番目が今も同じ意味かは見ない」。**ID は改名を生き延びるが、意味の変質も生き延びて検査は緑のままになる**。壊れやすさは欠陥ではなく、改名のたびに参照側へ再読を強制する機構の一部である。
- **見出し参照の機構ごと廃止し、必要なときにスキルで矛盾を探す**: 却下。main の履歴で**週 2 回**（3 か月で 48 コミット）参照ラベルの追随が起きており、押し出す機構を引き出す機構へ替えると実行漏れが戻る（#629 / #630 が同型の実測）。`G-near-heading-refs` も導入後 3 週間で CI が 1 件捕まえている。
- **PR CI の `governance-check` へ報告行として混ぜる**: 却下（ユーザー裁定 2026-08-19）。CI 時点では編集者が既に離れており、**直せる時点で出る**という reminder の主な価値を失う。
- **hook が判定モジュールを静的 import する**: 却下。**import 文は `post-edit.mjs` の `try { main() } catch` の外で走る**ため、解決に失敗すると JSON エンベロープを出さずにプロセスごと落ちる。この hook は全 `Edit|Write` で発火するので、`.rs` の fmt / clippy / test まで含めて**全編集が沈黙する**（使い捨て repo で再現）。加えて相対 import は importer の所在（`${CLAUDE_PROJECT_DIR}`）基準で解決し、`resolveRoot` が求める「編集されたファイルのツリー」とずれる（`docs/hooks.md`「PostToolUse（post-edit.mjs）の機構と保守」が既に持っていた非対称）。**代償は node 起動 109〜130 ms**（実測）で、これを払う。
- **純粋な追記でも報告する**: 却下。行が足されただけでは既存の参照を偽にしない。実測（`.md` を触った直近 80 コミット）: 外すと発火が 41〜46% から 24〜25% へ半減し、報告件数は 26% しか減らない——**消えるのは小さな発火ばかり**だった。
- **索引を組む前に「対象文書か」を安く判定する前段を置く**: 却下。判定には参照側を全部読む必要があり、全文を読んで `「` の有無だけ見る前段でも 88 ms 掛かる。全索引構築（プロセス内 129 ms）との差は 41 ms しかない。
- **節の切り出しに `sectionOf` を使う**: 却下。契約が「見出しの正規表現を 1 本渡して**その 1 節の body を返す**」形で、複数一致は finding になる。全節の列挙という用途に合わない。
- **節の境界でフェンスをマスクする**: 却下。着地判定の `collectAnchors` がマスクしないため、参照はフェンス内の見出しへも着地しうる。**境界だけマスクすると索引と境界が食い違う**ので、両方マスクしない側へ揃えた（フェンス内のアンカーは 1371 本中 27 本＝2.0%）。

## 帰結

- **`.md` の沈黙の意味が変わった。** 従来「何も走らなかった」だけを意味していたところへ、検査ではない reminder が 1 つ入る。**その不在は「依存が無い」を意味しない**——純追記では出ず、判定スクリプトが無いツリーでも出ない。この訂正は ルート `CLAUDE.md`・`docs/build-commands.md`（2 か所）・`docs/hooks.md`（2 か所）・`.claude/rules/governance-docs.md`・`post-edit.mjs` の契約コメントへ同時に入れた。
- **発火頻度の見積もりは実装後に訂正された。** 計画段階の 24〜25% は、節を入れ子にしていなかった当時の数字であり、`## 節` が最初の箇条書きの手前で切れる欠陥による**過小評価**だった。実装で測り直した値は **44/80（55%）・重複を除いた参照は中央 6 件・最大 37 件**。**コミット単位の値なので、編集 1 回あたりの発火はこれより低い。**
  - この欠陥は**実物で走らせて初めて出た**——合成フィクスチャは見出し直下の行しか触っておらず、`CLAUDE.md`「フック」節の箇条書きを編集して初めて沈黙が観測された。
- **費用の実測**（2026-08-19・`.md` を 1 回編集したときの hook 全体）: reminder が出る場合 **約 386 ms**、出ない場合 **330〜351 ms**。**差はノイズである**——subprocess の起動と索引構築の費用は、鳴っても鳴らなくても掛かる。
- **配線は統合テストでしか守れない。** `dependentsReminder` 自体は spy で試験できるが、**その戻り値を `warnings` へ積む 2 行**は誰も見ておらず、消してもユニットテストは 96/96 緑のままだった（委譲レビューが変異注入で実測）。一時 git リポジトリへ最小の木を作り、hook をプロセス起動して固定してある。**この変異が赤になる形も確かめた**——`buildEnvelope` が `context` も `systemMessage` も空なら `null` を返すため、`JSON.parse` が落ちる。一時リポジトリの作成失敗・git の不在・タイムアウトとは**落ち方が違う**ので、赤の理由を取り違えない。
- **受容する残余**: 文字列リテラル内の参照・PR 本文・凍結層は従来どおり視界の外である。テンプレート塊（フェンス内の見出し）が節を分断する形も残る。**「参照そのものが書き換えられた」場合**（対象文書の中身は変わっていない）は本機構の射程外である。
