# ADR-doc-minimization-cap-enforcement: 恒久規範の面積 cap を機構で担保し、二面を独立に ratchet する

## 文脈

#593「文書をなるべく必要としない開発システム」の具体化にあたり、恒久規範（毎セッション課税される文書）の面積を今後拡張しないという上限（cap）をどう据えるかを決める必要があった。#593 自身の思想は「規範をなるべく機構へ吸収する」であり、cap の据え方がこの思想と一貫している必要があった。

面積の代理指標は行数とし、対象面は「常時ロード（`CLAUDE.md` + `AGENTS.md`）」と「rules 配送（`.claude/rules/*.md`）」の 2 つがある。

## 決定

1. cap は**規範宣言ではなく機構で担保する** — `governance:check` に行数ゲートを追加し、基準値超過で赤にする ratchet。
2. **二面（常時ロード・rules）を独立の上限で ratchet する** — 合計ではなく別々に監視する。

## 検討した代替案と却下理由

- **cap を規範として宣言するだけ（機構なし）**: 却下。#593 の思想「規範を機構へ吸収する」に自己矛盾する。セーフティネットの不在を人の規律だけに委ねると、面積は気づかれないまま増える。
- **指標の可視化のみ（報告するがゲートしない）**: 却下。burn-down の推移は見えるが、拡張を止める力が無い。ratchet の本質は「増やすには明示的な合意が要る」摩擦であり、報告だけではこの摩擦が生まれない。
- **常時ロードと rules を合計して単一 ratchet**: 却下。総額が不変なら通るため、常時ロード→rules への**面替えだけで数字を下げられ**、読む量が減っていないのに削減したように見える。二面独立なら、面替えは移動先の上限に当たり、真の削減（機構吸収または履歴退去）だけが両面を下げられる。
- **常時ロードのみを ratchet（rules は自由）**: 却下。同じく rules へ押し込む逃げ道を残す。

行数が粗い代理指標である（密度で誤魔化す余地が残る）ことは承知の上で受容した。ratchet は精密なメーターではなく方向を守る道具であり、この粗さは費用に見合う。

> **2026-07-26 追記**: この受容は実測で覆り、指標は文字数へ替えた（`docs/adr/ADR-area-metric-characters.md`）。「承知の上で受容した」粗さが、削減していないのに数字を下げる行動を実際に誘発した。**骨格（機構で担保する・二面を独立に ratchet する）は本 ADR のまま有効**であり、替えたのは代理指標だけである。

## 帰結

- `scripts/governance-check.mjs` に二面独立の行数チェックと基準定数が加わる（実装は #593 配下の別 issue）。
- 恒久規範を増やす変更は基準定数の明示的な引き上げ（理由コメント付きコミット）を伴わない限り CI で止まる。
- ADR・spec・issue は履歴側ゆえ ratchet の対象外。決定理由の散文は課税面（`CLAUDE.md`）から ADR へ退去でき、burn-down が前進する。
