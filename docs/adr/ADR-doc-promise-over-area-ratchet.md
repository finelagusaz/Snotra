# ADR-doc-promise-over-area-ratchet: 面積の一次規範を「書く約束」にし、数字は火災報知器へ退く

日付: 2026-08-03 ／ 状態: 承認

## 決定

恒久規範の面積管理を 2 層に分ける:

1. **一次規範は質的な「書く約束」**（`.claude/rules/governance-docs.md`）——(1) かぶりなく（正本 1 か所・他は参照）、(2) 必要なことだけ、(3) 古い情報を残さない
2. **`AREA_BUDGET` は火災報知器**——実測の約 1.3 倍へ丸めた粗い上限とし、「気づかないうちの大幅な肥大」だけを捕まえる。±100 字の許容差で毎追記に鳴らす ratchet 運用と、引き上げごとの台帳記録は廃止する（旧台帳は git 履歴にある）

## 経緯（実測）

2026-08-03 の実績調査で、G-area-budget の稼働後発火 3 件は**すべて正当な追記**に対するもので、欠陥を指した記録は 0 件だった。さらに RETROSPECTIVE には「数字に押されて規範を正しい場所に置かない回避が生まれた」という逆効果の記録があり、同日の作業でも、系全体で 6.7KB 縮む変更（スキル廃止＋rules へ 53 字吸収）が局所の数字に咎められ、基準更新の儀式を要した。文字数は「かぶりなく・必要なことだけ・古くない」の代理指標であり、代理指標が本物と乖離したとき行動を歪める側に回っていた。

前提の変化も大きい。ratchet 導入時（#593）に質的検出器は無かったが、今日では約束の 3 観点のうち 2 つを機構が受けている——「古い情報」は G-stale-identifiers（#893 で docs/** へ拡大）と G-heading-refs が、「かぶり」は SSOT 規範と写しの数え上げの作法が守る。数字のゲートが独自に守るものは暴走の検知だけになった。

## 却下した代替案

1. **現状維持（±100 字 ratchet）**: 却下。上記の実測——正当な追記にしか鳴らず、置き場の歪みを生む
2. **AREA_BUDGET の完全撤去**: 保留（様子見）。火災報知器としての運用を 1〜2 サイクル見てから再判断する。規範だけでは沈黙ドリフトが再発してきた歴史（#497 ほか）があり、暴走検知の網を先に捨てない
3. **合計 1 本の上限へ統合**: 却下。二面独立は面替え（常時ロード → rules）による片面の肥大隠しを可視にするために在り、火災報知器になっても同じ理由で保つ

## 受容する残余

- 上限までの間の漸進的な肥大は機構では捕まらない——「書く約束」と、レビュー・`/health-check` の意味判断が受ける（これが本 ADR の引き受けるトレードオフである）
- 部分的に覆される先行 ADR: `ADR-doc-minimization-cap-enforcement`（cap の常時強制）と `ADR-area-metric-characters` の運用節（±100 字の許容差・引き上げ台帳）。指標そのもの（文字数・二面独立・description 算入）は引き継ぐ。旧 ADR は凍結ゆえ編集しない（`ADR-adr-frozen-history`）
