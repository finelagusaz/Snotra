# ADR-edit-time-check-scope: 編集時に前倒しする検査を、書き方と命名の族に限る

## 文脈

`governance:check` の検査のうち、**編集直後に届いていたのは索引整合（`checkModuleIndex`）と参照実在（`checkReferences`）の 2 つだけ**だった（#1139）。残りは PR CI か手動実行でしか鳴らず、**書き方・記法の逸脱が「出来上がってから」指摘される**形になっていた。`ADR-dependents-reminder-at-edit-time` が「CI 時点では編集者が既に離れており、**直せる時点で出る**という reminder の主な価値を失う」として CI へ混ぜる案を却下しているにもかかわらず、その路線の射程が 2 つで止まっていた。

守る対象を読み直すと、**性質と時刻が逆に付いていた**——命名・語彙・参照の書き方は書いたその瞬間にしか安く直せないのに CI にしかなく、リポジトリ規約の実効性（lints・clippy 禁止集合）は編集時に要らないのに同じ扱いだった。

## 決定

**走査元（参照や識別子が書かれている側）を編集ファイル 1 枚へ絞れる判定**を `edit-findings.mjs` へ足す。着地先（アンカー・語彙・実ファイル）は snapshot 全体のままとし、**判定の強さは CI と同じで、違うのは報告する範囲だけ**とする。合否は持たない（`ADR-dependents-reminder-at-edit-time` と同じ契約）。

対象は見出し参照の 3 種・語彙の腐り・ADR の命名。**帰属は母集団の絞り込みで構造的に決まる**ので、索引側（finding のメッセージへ文字列で結合する `attributesTo`）と違い、メッセージ書式の変更で静かに 0 件へ倒れる経路を持たない。

## 検討した代替案と却下理由

- **全検査を編集時に走らせ、`HEAD` との差分だけ報告する**: 却下。射程は最大になるが、機構が 1 段複雑になる（ベースラインの取得と保持が要る）うえ、**費用が要らない**——痛みの中心は書き方と命名であり、それらは走査元を絞るだけで届く。差分の器を持つと「機構自身を守る層」が増える方向で、`ADR-governance-meta-demotion` の判断規準に反する。
- **21 本すべてを編集時に配線する**: 却下。表の双方向照合（索引・スキル表・CI 表・コマンド写像）は**「どこに書かれたか」が定まらない**ので帰属が作れず、リポジトリ規約の実効性（`G-workspace-lints` / `G-clippy-disallowed` / `G-module-linkage`）は編集頻度が低く CI で足りる。**さらに件数はノイズの危険を持つ**——`G-area-budget` は「数字に押されて規範を正しい場所に置かない回避を生んだ」実績があり、報告が増えるほど読まれなくなる。
- **reminder ではなくゲート（exit code を動かす）にする**: 却下。既存の 2 つが合否を持たない契約で運用されており、片方だけゲートにすると「編集時に赤が出る検査と出ない検査」が同じ表に並ぶ。判定は人が持つ（`ADR-retire-area-budget` と同型）。
- **`G-module-linkage`（`mod` 宣言の到達性）も足す**: 却下（今回は）。`.rs` を**追加**したときに効く判定であり、`Write` の直後には `mod` を書く編集がまだ来ていない——鳴っても正しい指摘にならない頻度が高い。`governance:check` が引き続き赤にする。

## 帰結

- **費用は既存の subprocess の内側に収まった。** `edit-findings.mjs` は `.rs` / `.md` で既に spawn されており、追加は判定の分だけである（実測 2026-08-20: 拡張前 59 ms → 拡張後 59〜109 ms。hook 全体は `ADR-dependents-reminder-at-edit-time` の実測で 330〜386 ms なのでノイズの内側）。
- **配線の検知は統合テストが持つ。** `post-edit.test.mjs` の一時リポジトリが `edit-findings.mjs` を実プロセスで起動する。**その fixture が `checks/` を手で列挙していたため、依存を足した瞬間に `ERR_MODULE_NOT_FOUND` で subprocess が非 0 になり、`editFindingsReminder` が空文字へ倒れて reminder ごと消えた**（実測）。列挙をディレクトリ走査へ置き換えてある——**沈黙で腐る写しだった**。
- **テストヘルパの `extraFiles` の意味を実ツリーへ寄せた。** 「列挙されているが読めない」は `makeSnapshot` の実経路に無い状態であり、本文を読む検査がそれを「母集団の欠落」と報告していた。空文字として読ませ、母集団欠落の試験は `docs` 引数へ直接渡す形に一本化した。
- **受容する残余**: **母集団が空になったとき、編集時の側は沈黙する**——絞り込みは `population(snapshot).includes(rel)` で判定するので、導出が `[]` を返せば分岐へ入らないまま何も報告しない。0 件検知は `runAll` にしかない。**ここに検知器を足さない**——合否を持たない層であり、同じ欠落は `governance:check` が母集団ごとの 0 件検知で赤にする。機構を守る機構を増やす判断は `ADR-governance-meta-demotion` の規準に照らして置かない側へ倒した。
- 削除は依然として見えない（`rm` は `Edit|Write` matcher に届かない）。表の双方向照合とリポジトリ規約の実効性は CI のみ。`docs/adr/**` で編集時に出るのはファイル名と冒頭見出しの形だけで、本文の参照は凍結された歴史として腐るに任せる（`ADR-adr-frozen-history`）。
