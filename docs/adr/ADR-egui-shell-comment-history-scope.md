# ADR-egui-shell-comment-history-scope: egui_shell のコメントから経緯を外したときに、残した形と、却下した確かめ方

2026-11-10、#1409 で `src-tauri/src/egui_shell/` の `.rs` 23 ファイルのコメントにあった経緯を、いま守っている約束の形へ書き直した。経緯とは、変化の語り（「〜へ移設」「以前は〜」「かつて〜」）と作業単位の名指し（「PR A′」「#646 PR2 決定 6」「SU5 要石」）である。正規表現で拾った候補は 676 行・443 ブロックで、ほかに読みながら見つけたものも足し、計 533 件を 1 件ずつ判定した。**この ADR が持つのは、経緯に見えて残した形と、その理由である。** 次に同じ整理をする人が、残った語を消し漏れと読まないために置く。`scripts/smoke-egui.ps1` の経緯は、別の issue で扱う。

## 残した形

- **「旧・段 14/34」**（`view.rs` の `read_pre_widget_input` の doc と段 16–17 のコメント・`hide_request.rs`・`lifecycle.rs`）: 段番号の欠番を説明している。`ADR-blur-grace-single-field-state-machine` は、段番号を振り直さない決定の根拠に、この語句を引いている
- **同じ処理の中の、前の値を指す「旧」**（旧 metrics・旧 state・旧 token・旧ホットキー・hide を跨いだ旧幅）: 経緯ではない
- **`回帰テスト:` が守る性質と、出自の `#NNN`**、**日付つきの実測**、**変異の説明**（「移した先でゲートが落ちる退行」）
- **今の制約を支える、過去の行為の 1 文**: `docs/comment-guidelines.md`「第一原則: コメントは理由を書く」が、古くならない根拠の形として認めている
- **文字列リテラルの中の副ラベル**（`view.rs` の `indexing_is_read_exactly_once_per_frame` の失敗文言の「#752 F2」・`icon_textures.rs` の assert の「#532 SU4」）: コードであり、コメントだけを変える範囲の外にある
- **外の見出しの逐語引用**（`src-tauri/CLAUDE.md`「イベント駆動 wake の不変条件（#532 SU5）」）: 見出し名で辿る参照なので、引く側だけを変えられない
- **`/code-review #637 finding N` のラベル**: 複数のコメントが「finding 0 の規律」のように、ラベルで互いを引き合っている。縮めるなら、引く側と一緒に直す必要がある
- **旧フロントエンド（SolidJS / WebView2）との parity**: 仕様の出所として理由を運んでいるものは残した。理由を運ばないものは消した。判定はファイルごとに行った

## 番号の引き方

`#NNN` の無いラベルは、`git log -S '<語句>' -- <file>` で語句を入れた最古のコミットを探し、その PR 番号へ置き換えた。ファイルを移して作ったもの（`results_window.rs`・`results_view.rs`）では、移した側のコミットが最古に見える。そのため、パスを付けずにもう一度引いた。#1409 では、`results_window.rs` の「SU6 spec 決定 2」を最初に #802（写した側）としてしまい、`view.rs` の同じ語句と突き合わせて #532 に直した。文脈の無い短いラベル（「Important 1」など）は、パスを付けて引いても、同じファイルの別のレビューの同名ラベルが最古に当たる。`view.rs` の `last_set_*` の注記は、SU4 の別の指摘（#532）を最初に当て、出所の #646 を独立の監査が引き当てた。こうしたラベルは、置き換えた番号のコミットで、同じ文が実際に入ったかを `git show` で確かめる。`SU<n>` と `codex #<n>` は親の #532 までしか引けない。`Task <n>` は計画書の中の番号で、issue ではない。

## 却下した確かめ方

- **コメントを落としたトークン列の一致だけで、コメント以外が変わっていないと見なす**: 却下した。egui_shell のテストのうち 3 群（`view.rs` の `assert_read_once_in_this_file`・`icon_textures.rs` の `include_str!` 検査・`launcher_controller/activation/tests.rs` の `sources()`）は、ソースの全文を読み、コメントも含めて綴りを数える。コメントに needle と同じ綴りを足すと、件数を見る検査は赤になる。`contains` で見る検査は、将来ゲートを消しても黙って緑のまま残る。トークン列の比較に加えて、needle の出現数がファイルごとに変わらないことを確かめ、`cargo test -p snotra` を実際に走らせた（比較器はリポジトリに置いていない。#1411 と同じく使い捨てにした）
- **式に当たった語を一括で置き換える**: 却下した。同じ「旧」が、経緯の場合と前の値の場合とに分かれる。「決定 3」も、どの spec の決定かが語句ごとに違う（`visual.rs` の「spec 決定 4」は #673 と #802 の 2 系統が混ざっていた）

## 受容する残余

- **候補の抽出は正規表現の近似である。** 式に無い語りは、読んでいる途中で見つけた分しか処理していない
- **外の文書は経緯の形のまま残る。** `SPEC.md`（§4.5 の「#835 で #675 を撤去」）・`ADR-show-path-derives-bar-rect`（「旧経路も同じで退行ではない」）・`src-tauri/src/config_watcher.rs` の tests 冒頭（テストを移した記録）は、コメント側の写しを書き直しても、外の文書は変えていない。ADR は凍結されている（`ADR-adr-frozen-history`）
- **経緯ではない規約違反は、見つけても直していない。** 呼び出し元の数え上げ・行番号での参照・指すだけの参照・`window_coordinator.rs` の `read_metrics` の doc の偽の呼び出し元（「`show_egui_main` だけ」）・`hide_egui_main` の中のコメントが doc を引いた文言の食い違い。ただし、経緯の段落の中で偽の現在形になっていた文は、同じ段落を書き直すときに直した
