# ADR-folded-canonical-reference-detector: 正準形の参照が物理改行で折れた形を赤にし、母集団を広げる案・件数の ratchet・数値の重複検知を却下した

## 文脈

#1128 が「実測値の写しを畳んで正本を 1 か所に定める」作業を終えたとき、**正本化そのものの逆行を止める機構が無い**ことが残った（`docs/adr/ADR-measurement-canon-in-code-doc.md`「帰結」の最終段が、判断を人へ返している）。#1154 はその判断を引き受ける issue である。

裁定に入る前に母集団を測ったところ、**折れた正準形の参照が今日 33 件実在していた**（照合母集団 318 のうち 10.4% が不可視）。#1128 のレビューが変異注入で示した「折れると照合件数が 285 → 284 へ静かに落ちる」は、将来の回帰の模擬ではなく**現に 33 回起きている事象の 34 回目**だった。うち 1 件（`snotra-core/tests/path_query_cost.rs` の `docs/development-principles.md` への参照）は繋いでも着地せず、**折れが本物の腐りを隠していた**。

## 決定

**`G-folded-heading-refs` を新設し、正準形の参照が物理改行で折れた形を赤にする。** 母集団は `G-heading-refs` と同一（`allHeadingRefDocs`）で、新しい母集団定義を作らない。

検知する形は 2 つ——対象綴りで行が終わりラベルが次行から始まる形と、`「` まで同一行に開いてラベル本文だけが次行へ流れる形。**片方だけでは足りない**——前者だけを実装すると出荷直後から 13 件の既知の見逃しを持つ。

## この層を足してよいと判断した理由

`AGENTS.md`「条件別チェック（トリガー → 参照先）」のセーフティネット行は「**足す前に『壊れたとき緑が緑のまま推移するか』を問う——推移しないなら置かない**」を要求する。答えは**推移する**である（#1128 の変異注入で `exit 0` のまま照合件数だけが落ちることを実測済み）。ゆえに「気づく契機が残るから機構は要らない」の側へは倒せない。

`docs/adr/ADR-governance-meta-demotion.md`「格下げの線 — 「メタかどうか」ではなく「止めたとき 21 本の合否が信用できなくなるか」」が引いた線に照らすと、**折れは母集団の部分的な欠落であり、ゲートに残す側に落ちる**。同 ADR が「母集団が空になれば 21 本は空虚に緑を返す。それは 21 本自身の故障であってメタ層の話ではない」として `runAll` の 0 件検知をゲートに残したのと同じ理由が、**部分的に縮んだ場合にも当たる**。主題は機構自身ではなく、既存の検査の入力である。

### 却下 3 の理由が陳腐化していたこと

`docs/adr/ADR-comment-guideline-delivery-by-pointer.md`「却下 3: 行またぎコードスパンの検知器を `governance:check` へ新設する」で、**同じ族の検知器が一度却下されている**。却下理由は「5 件は `.rs` のコメント 8030 行に対する事故率であり、**規範 1 行と現存違反の修正で足りる**」だった。同 ADR の「受容する残余」は帰結をこう書いている——「行またぎスパンの再発は誰も検知しない。次に誰かが grep で辿れないコメントを踏むまで分からない」。

**この却下理由は 2 つの実測で陳腐化している。**

- **規範 1 行では足りなかった。** `docs/comment-guidelines.md`「日本語の折返し」は 2026-08-08 に入ったが、折れ 33 件のうち少なくとも 4 件は**それより後**に生まれている（`git blame`: `4f5f4d3f` 2026-08-16 / `39a426a4` 2026-08-12 / `2dc987e1` 2026-08-12 / `db2093e5` 2026-08-13）。
- **害の種類が違う。** 却下 3 が扱ったのは「grep で辿れない」＝人間の検索性である。折れの害は**別の CI ゲートの母集団が黙って縮むこと**であり、実際に腐り 1 件を隠していた。

**射程も違う**——却下 3 はコードスパンの行またぎ一般を対象にしたが、本検査が見るのは正準形の指しだけである。

## 検討した代替案と却下理由

- **`HEADING_REF` を行跨ぎ対応にして吸収する**（赤にせず母集団へ取り込む）: **却下。** 照合件数は 318 へ増え腐り 1 件だけが赤になるので一見きれいだが、**`HEADING_REF` の 3 消費者すべての意味論を同時に変える**（`G-heading-refs` / `G-near-heading-refs` の `ADJACENT_REF` / `scripts/governance/dependents.mjs`）。finding の行番号の帰属も `dependents.mjs` の節境界計算も動く。加えて `docs/comment-guidelines.md`「日本語の折返し」が「文途中で物理改行を入れない」と規範化している向きと**逆を向く**——機構が折れを許容すれば、規範だけが折るなと言い続けることになる。
- **照合件数の ratchet（減少を赤にする）**: **却下。** 下界値の保存先という新しい状態が要り、他の PR の増減と混ざる。`docs/adr/ADR-doc-promise-over-area-ratchet.md` が文書の文字数について同型の運用を退けているが、**あちらは対象も却下理由も違うので同一の先例ではない**（あちらの理由は「正当な追記にしか鳴らない」）。本件を退ける理由は混ざることそのものである。
- **「この値の正本はここ」と宣言した doc に対し、同じ数値が他所に現れたら赤にする**: **却下。** issue が挙げた 3 候補のうち、正本化の逆行を最も直接に捕まえる案だが、**凍結 ADR と歴史記述を除く allowlist ＝新しい母集団定義**を要する。`docs/adr/ADR-governance-corpus-reduction-rejected.md`「前提の棚卸し（この 3 方向が立っていた土台）」の実測——検査の改修費用 21 件のうち 17 件の原因が母集団・メタ層の変更——が名指す費用の型に正面から当たる。加えて表現ゆらぎ（`40〜95` / `40-95` / `95ms`）に弱い。
- **`ANCHOR_SPECS` へ「段落先頭の太字」を足す**（腐り 1 件を着地させる案）: **却下。** `.md` 196 本のアンカーが 5,492 → 7,375（**+34.3%**）になり、増分のほぼ全部が節のリードではない強調文である。アンカーが薄まると前方一致で**無関係な太字文へ着地して緑になる側（沈黙）**へ倒れる。`docs/adr/ADR-canonical-heading-references.md`「検討した代替案と却下理由」が同型の 2 案（SPEC の本文へ太字リードを足す／記法を 2 系統に分ける）を既に却下し、**参照側の記法を直す**解き方を採っている。
- **腐り 1 件について、指し先を箱条書き化する / 参照を散文化する**: **却下。** 前者は規範文書の文章構造を検査器の都合で変える。後者は機構の射程から外れ、折れで隠れていた状態と実質同じになる。採ったのは参照側を包含する ATX 見出しへ指し替え、具体的な言明を `「」` の外へ散文で置く形である。

## 帰結

- **`HEADING_REF` の意味論は変わらない。** 3 消費者はすべて行単位のままで、新検査は入力の欠落を赤で告げるだけである。
- **射程はファイル種別に依らない。** 33 件のうち 9 件は `.rs` 以外（`.mjs` 4 / `.ps1`・`.psm1` 3 / `.md` 2）である一方、`docs/comment-guidelines.md` の配送は 4 crate の `**/*.rs` のみで、**`.ps1` / `.psm1` にはコメント作法の生きた規範が一つも無い**。ゆえに**検査ヘッダの射程宣言が、赤を受け取った者の唯一の拠り所になる**。
- **宣言する死角がある**（検査ヘッダが正本）: バッククォート自体が行を跨ぐ形（今日 0 件）・助詞を挟んで折れた近傍形・`refScanLines` が次行を供給しない形。
- **受容する残余 1**: 新検査の `checked` の evidence 供給が断たれた場合の検知は `metaFindings` 側に落ちる（`docs/adr/ADR-governance-meta-demotion.md` の格下げの内側）。実際に捕まえるのは `scripts/governance-check.test.mjs` の `?` カナリア＝`npm test` である。
- **受容する残余 2 — この検査自身の劣化を見張るのは `G-folded-heading-refs.test.mjs` である。** 継続行の剥がしを恒等写像へ変異させると、**継続行が記号（`///` / `//` / `#` / `>` / ` * `）を持つ形 A はすべて見えなくなる**（2026-08-20・複製での実測。fixture 11 件のうち 7 件が落ちた。記号を持たない継続行の形 A と、次行を見ない形 B は生き残る）。それでも折れが 0 件の定常状態では `governance:check` は**緑のまま**である。**evidence 行の「折れうる位置 N 件」はこの劣化に対して無効である**——`checked` は候補位置を数えた時点で加算され、剥がしを参照する前に確定するので、健全時と変異時で同じ値を返す（委譲レビューが指摘・実装で確認）。**発火するのは fixture のほうである。**
