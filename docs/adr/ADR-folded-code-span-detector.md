# ADR-folded-code-span-detector: 折返しの規範を実測された害へ縮め、差分ベースの検査・既製の lint・機構なしの 3 方向を却下した

## 文脈

#984 のサイクルで `docs/comment-guidelines.md`「日本語の折返し」の「1 段落 1 行」を**目視では守れなかった**——新規・touched の段落に 26 件の違反があり、**直す編集自身が 2 件持ち込んだ**。#992 はその機構化を求める issue である。

**裁定に入る前に母集団を測ったところ、提案どおりの検査は成立しないと分かった**（2026-08-22 実測）。

- `.rs` 全ツリーの折返しは **3151 件**（`.rs` + `.mjs` で 3758 件）
- 差分に絞っても、`.rs` を触った直近 60 コミットの **88% が発火し、1 コミットあたり中央 19 件・最大 167 件**。目視した範囲に偽陽性は無く、**すべて本物の折返しだった**
- 規約が根拠として挙げる 2 つの実測された害に当たるのは **0.1%**（害 1 コードスパンの行またぎ 2 件、害 2 正準形の参照の折れ 0 件＝#1156 が畳んだ後）

**規約が守られていないのであって、検出器が弱いのではない。** `G-folded-heading-refs` 自身のヘッダ（2026-08-20 に書かれた）が段落を折っており、機構を書く側が守っていない規約だった。

## 決定

**害 1 を `G-folded-code-spans` として新設し、規範を実測された害を持つ 2 形へ縮める。** 素の散文の折返しは禁じない。

母集団は `G-heading-refs` と同一（`allHeadingRefDocs`）で、新しい母集団定義を作らない（`ADR-folded-canonical-reference-detector`「決定」と同じ選択）。述語は折返しの意味を見ず、**単独のバッククォートを左から対応づけて「開いた行と閉じた行が違うか」だけ**を見る。実測で 262 文書・6 箇所・偽陽性 0・偽陰性 0。

編集時の reminder（`edit-findings.mjs`）へも配線する。`ADR-edit-time-check-scope`「決定」の前倒し条件（走査元を編集ファイル 1 枚へ絞れる判定）を、**着地先を持たないぶん既存 4 本より強く満たす**ためである。

### 却下 3 との関係

`ADR-comment-guideline-delivery-by-pointer`「却下 3」が、**ほぼ同じ検知器を 2026-08-08 に利用者の裁定で見送っている**（理由: 「5 件は `.rs` のコメント 8030 行に対する事故率であり、規範 1 行と現存違反の修正で足りる」）。同 ADR の「受容する残余」は帰結も明記した——「行またぎスパンの再発は誰も検知しない」「折返し・訳語の条項は 100% 規範であって機構ではない」。

**`ADR-folded-canonical-reference-detector` はこの却下理由を「陳腐化していた」と宣言したが、「射程も違う」として却下 3 の決定そのものは再考しなかった。** ゆえに「害 2 が機構を持ったのだから害 1 も持つべきだ」という対称性の議論は**先行 ADR には無く、この決定が独自に立てるもの**である。

**支える一次証拠は同一形で取った。** 却下 3 は現存 5 件を畳んで 0 件にしたが、`git blame` で今日の 6 箇所を辿ると、**規範が入った 2026-08-08 より後に `.rs` で 2 件が生まれている**（`view.rs` 2026-08-11 / `launcher_controller.rs` 2026-08-17）。あちらが「規範 1 行では足りなかった」を示すのに使ったのと同じ形の証拠であり、**母集団も期間も小さいので強さは及ばない**。

## 検討した代替案と却下理由

- **issue の原案——「1 段落 1 行」そのものを差分ベースの検査にする**: **却下。** 上の実測がそのまま費用である（毎 PR 中央 19〜20 件の赤）。加えて 3 つの構造的な難がある。(1) `checks/` は今日 snapshot 純粋で、**初の git 依存の検査になる**。(2) **CI に base が無い**——`governance-check` job は `actions/checkout@v7` を fetch-depth 指定なし（＝depth 1）で使い、`node scripts/governance-check.mjs` はその直後に走る。(3) **fail-open が「壊れたとき緑が緑のまま」に当たる**——差分ベースでは `checked: 0` が main 上の正常状態なので、`{findings, checked}` の証跡では「`git diff` が黙って失敗した」と「変更が無い」を区別できない。
  - **費用の見積もりは下限である。** 上の中央 19 件は `added.has(n) || added.has(n+1)` の行単位で測ったもので、規約が言う「触った**段落**」を文字通り取ると総計 1725 → 1804（+4.6%）・発火 88% → 92% へ**増える方向にしか動かない**（敵対的レビューの指摘で測り直した）。
- **「1 段落 1 行」を検査の代わりに編集時の reminder で鳴らす**: **却下。** 母集団（新規・touched）は構造的に一致するが、**中央 19 件はほぼ毎編集で鳴る**。`dependents.mjs` が `LISTED = 3` で切っているのと同じ問題がはるかに高い頻度で起き、**鳴っていることが「見た」を意味しなくなる**。縮めた 2 形を前倒しすることは却下していない——件数が 0 から始まるので同じ問題を持たない。
- **既製の lint / formatter へ委ねる**: **却下。固定版 1.98 で実測した。**
  - **rustfmt**: `rustfmt.toml` に wrap_comments を立てて折れたスパンへ当てると、`can't set ... unstable features are only available in nightly channel` を出して**無視され**、折れは 1 文字も直らない（exit 0）。仮に nightly へ移しても**向きが逆**である——指定幅へ**折り込む**オプションであり、8000 行超のコメントを一斉に折って害 1 を量産する
  - **clippy**: pedantic + doc 系の lint を全部有効にして折れたスパンへ当てて **0 件**。唯一鳴った doc_paragraphs_missing_punctuation は「。」を終端と認めない**誤検出 2 件**で、日本語 doc では使えない
  - **母集団が届かない**: 実在 6 箇所の内訳は `.md` 1 / `.rs` 2 / `.mjs` 1 / `.ps1` 2 で、**完璧な Rust lint でも 6 件中 2 件**しか覆わない
  - **理由は道具の欠落ではない**: 折れたスパンは**正しい CommonMark** であり rustdoc は soft line break を跨いで正しく描画する。害は `grep` にしか出ず、**整形器も lint も「人間が正規表現で検索する」ことをモデルに持たない**
- **機構を足さず、規範だけを縮める**: **却下。** 害 1 の再発が誰も検知しないまま残り、却下 3 の受容する残余がそのまま生き延びる。上の `git blame` が示すとおり、規範 1 行では実際に足りなかった。
- **「1 段落 1 行」を規範として残す**: **却下。** 実測 3151 件で、機構の書き手自身が守っていない。`ADR-folded-canonical-reference-detector`「検討した代替案と却下理由」が「機構と規範が逆を向く」形を退けた向きの、鏡像の適用である。
- **`COMMENT_FAMILY` へ `.rs` を足してコメント行を取る**: **却下。** `refScanLines` の意味論が変わり、`G-heading-refs` / `G-near-heading-refs` / `G-folded-heading-refs` の母集団が**同じ変更で動く**（`.rs` の走査対象が全行からコメント行へ縮む）。#925 以来の意図的な母集団であり、検査対象を変更しながら検査を検証しない（#489）。採ったのは `linesOfComments` へ既定引数の第 3 引数を足し、**既存の呼び出し点を 1 つも動かさない**形である。
- **`.rs` を全行走査したまま char リテラルを特別扱いする**: **却下。** 綴りに依存し、Rust の文字列中のバッククォートで再発する。そもそも規範の対象はコメントである。
- **行ごとの偶奇で判定する**: **却下。** 同じ折返しを開始行と終了行の **2 回**報告する（実測: 12 行 = 6 箇所）。走査行をまたいで「開いたまま」を持ち越し、**開始行だけを報告する**形を採った。

## 受容する残余

- **素の散文の折返し（3149 件）は今後も誰も見ない。** #984 型の見落とし——目視で 26 件を落とし、直す編集が 2 件持ち込んだ——は**再発しうる**。この決定は #992 の動機そのものには答えていない。
- **行末のインラインコメント**（`let x = 5; // 説明`）は走査しない。`linesOfComments` が行頭で判定するためである。
- **`.rs` の raw string の中で `//` から始まる行**をコメントと誤判定する。`linesOfComments` の js 族が自ら宣言している死角をそのまま継承する（**向きは赤＝沈黙ではない**ので人が解く）。
- **綴りの意味は見ない。** 非実在の例示コードも実在の識別子と同じ重みで赤にする。実例が `launcher_controller.rs` の doc で、そこはスパンを 2 つへ割って解いた——**この 1 件は「grep で辿れなくなる」実害の典型ではない**（敵対的レビューの ⚠ 所見。構文的には真陽性なので除外はしていない）。
- **凍結層の数は残る。** 生きた散文からは「21 本」という検査の本数を捨てたが、`ADR-governance-meta-demotion` の**見出し**は数を含んだまま残り、`ADR-folded-canonical-reference-detector` がそれを正準形で引用している。見出しは凍結された歴史なので触らない。
- **撤去した語彙は 2 か所に残る。** `docs/superpowers/plans/2026-08-10-search-worker.md` は「1 段落 1 行」を計画本文へ写しており、`ADR-folded-canonical-reference-detector` は「規範化している向きと逆を向く」と**一般則が在る前提**で書いている。どちらも凍結された歴史であり、`ADR-adr-frozen-history` のとおり腐るに任せる。生きた層に残った出現は、`docs/comment-guidelines.md` の「かつて課していた」という**撤去の描写だけ**である（撤去時に 4 つの綴りで `git grep` して確かめた。**別綴りの同義表現までは覆っていない**）。
