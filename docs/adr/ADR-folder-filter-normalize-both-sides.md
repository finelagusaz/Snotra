# ADR-folder-filter-normalize-both-sides: フォルダ絞り込みの正規化は照合の時点で、絞り込みと名前の両方へ掛ける

## 文脈

#1284 で、フォルダ展開の絞り込みが `SPEC.md`「4.2 クエリ正規化」の前後空白除去・連続空白の1文字化を行っていないと分かった。直すにあたり、どこで正規化するか（入力を状態へ書く時点か、照合の時点か）と、どちらの辺へ掛けるか（絞り込みだけか、エントリ名もか）を決める必要があった。

## 決定

1. 正規化は core の照合（`folder::matches_filter` とその呼び出し元）で行い、`SearchState::set_folder_filter` へ渡す入力文字列は生のまま保つ。
2. 絞り込みとエントリ名の両方へ同じ `query::normalize_query` を通す。

## 検討した代替案と却下理由

- **`set_folder_filter` で正規化してから状態へ書く**: 却下。`folder_filter` は入力欄の表示バッファでもあり（`view.rs` が読んで TextEdit へ戻す）、打鍵のたびに末尾空白が削られる。`my doc` のように途中に空白を含む語が打てなくなる。Escape 復帰の `saved_folder_filter` も生の文字列を戻す前提に立っている。
- **絞り込みの側だけ正規化する（本体検索と同じ形）**: 却下。名前の側を `to_lower_folded` のままにすると、連続空白を含む名前（`a  b.txt`）に対し、それまで一致していた絞り込み `a  b` が `a b` へ圧縮されて一致しなくなる退行が出る。全角空白（U+3000）や NBSP を含む名前も半角空白の絞り込みに一致しないまま残る。本体検索がこの形なのは、名前側の派生を `index.bin` に永続化しており、変えると意味の変更になるからであって（#1309）、事前正規化した列を持たないフォルダ側が同じ制約を負う理由は無い。要求判断としてユーザーが両側を選んだ（2026-10-29）。

## 帰結

- 空白だけの絞り込みは正規化後に空となり、空の絞り込みと同じく全件を表示する（本体検索は同じ入力で空結果を返し、両面の振る舞いは逆になる）。
- `normalize_query` の借用判定が titlecase 等の文字で所有側と割れる欠陥（#1310）が、名前の側にも及ぶ。両辺が `to_lower_folded` だった頃には一致していた組（名前 `Aǅx`・絞り込み `aǅ`）が一致しなくなる。
- 本体検索の名前側は空白を正規化しないまま残る（#1309）。SPEC §4.2 の「エントリ名も」は本体検索ではまだ満たされていない。
