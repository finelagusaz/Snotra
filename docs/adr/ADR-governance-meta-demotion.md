# ADR-governance-meta-demotion: メタ層をゲートから計器へ格下げしたとき、撤去する案と据え置く案を却下した

2026-08-20、ガバナンス機構のうち**主題が機構自身である層**（以下メタ層）を `governance:check` の exit code から外した。**この ADR が残すのは、そのとき却下した 2 案と、戻す条件である**——格下げ後の姿は `scripts/governance-check.mjs` の `META_CHECK_IDS` と `metaAuditEnabled` が持つ。

## 格下げの根拠

- **稼働実績が 1 日しか無い。** 錨の層は `e9bdf932`（2026-08-19）で生まれ、この決定は翌 8-20 である。実運用での発火はゼロで、「効いている」を支える観測点が存在しない。
- **費用は測れている。** 直近 8 日 50 コミットのうち機構コードに触れたものが 19、製品コード（`*/src`）に触れたものが同じく 19。Phase 1〜3（`e9bdf932` / `b154ad57` / `2f2c0a37`）は 2,065 行の追加で、`.rs` は 0 行だった。

  **訂正（2026-08-20・同日。凍結規約により書き換えず追記する）**: この「8 日」という窓は **#1148 の見直し作業そのもので埋まっていた**。機構の全生涯（2026-07-01〜08-20）で測り直すと全 438 コミット中、機構 83 / 製品 185 で **製品の方が 2.2 倍多い**。比率も 18%（07 月）→ 12%（08-01〜12）と下がっていたところへ、見直しが 40%（08-13〜20）へ押し戻したものである。**「機構と製品が同量」は成り立たない。** 一方、同じ広い窓で**「機構は製品と無関係に自分で動いている」は強まった**——83 のうち **65（78%）が `.rs` を 1 行も触っていない**。格下げの判断はこちら・稼働実績 1 日・#1143 の 45/51・「止めることが唯一の実験」に支えられており、**変わらない**。訂正の全文と前提の棚卸しは `docs/adr/ADR-governance-corpus-reduction-rejected.md`。
  **残余**: 同じ数字が squash commit message（`7506f093`）にも入っており、そちらは履歴なので直せない。
- **後追いは実装に対してではなく、機構自身に対して起きていた。** #1143 が「rules の `paths` が `scripts/governance/**` の 51 本を覆っていない」と見つけたその 51 本のうち **45 本は #1093（機構自身のディレクトリ分割）が 3 日前に生んだ**ものである（`git log --diff-filter=A` で実測）。積み残しの生産者と消費者が同一であり、「追い付く」状態が構造的に来ない。
- **止めることが唯一の実験である。** メタ層の壊れ方は沈黙なので、動かしている限り「効いているか」を外から測れない。片側だけ確からしいということはなく、**壊れても気づけない層は、効いていることも確かめられない**。

## 格下げの線 — 「メタかどうか」ではなく「止めたとき 21 本の合否が信用できなくなるか」

母集団が空になれば 21 本は空虚に緑を返す。それは**21 本自身の故障**であってメタ層の話ではない。ゆえに `runAll` の 0 件検知・`lib.mjs` の入力ガード・`registry.mjs` の走査と形式検証・`manifest` の `checks`/`docs`/`rules`/`skills` 列はゲートに残す。

格下げしたのは、倒れても 21 本の合否が動かないもの——`G-domain-anchors`、面積計器の入力ガード、evidence の供給断検知、`manifest` の `domains` 列、および `domains.test.mjs` の錨の総称反証テストである。

## 却下 1: いま撤去する（コードごと消す）

**消すと、廃止できる根拠が二度と取れない。** `ADR-retire-area-budget` は面積の判定を廃したとき計器を残し、そのおかげで「通算 4 観測点で欠陥検出ゼロ」という実績が積めた。消していればその 4 点は存在しない。**撤去は観測の後に来る**。

加えて、撤去は「効いていなかった」という主張を含むが、いまその主張を支える観測は 1 日分しか無い。**費用が測れていることは、価値がゼロであることの証拠ではない。**

## 却下 2: 据え置き、規範で「これ以上メタ層を足さない」とだけ約束する

`ADR-retire-norm-review` が測ったとおり、規範は機構の代わりにならない。加えて据え置きは**痛みを一切回収しない**——メタ層が赤で止める限り、#1143 型の後追い（機構が自分の開けた穴を塞ぐ作業）はそのまま発生し続ける。格下げの実体は「赤で止まらなくなること」であり、そこが回収点である。

## 却下 3: 実行ごと止める（コードを凍結して置く）

印字も出なくなるので読む対象は減るが、**「発火したはずだった回数」も同時に消える**。それは撤去と同じ情報損失を、撤去の利点（行数が減る）なしに引き受ける形になる。

## 実測（フォールトインジェクション・2026-08-20）

複製 worktree（`node_modules` は junction）に変異を当てた。**稼働中のガードは 1 バイトも触っていない**（測定後に worktree を撤去し、作業ツリーは `git status --porcelain` が空・HEAD 一致を確認）。

**変異 1 — 錨の消失。** `buildDomains` が 1 ドメイン（`ruleDocs`）へ空の `anchors` を返す形。**この姿は `G-domain-anchors` 自身のコメントが名指す回帰そのものである**（「`anchors: []` になっても holds ループは何もせず findings 0 件のまま緑になる」）ため、本来の回帰より強くない。

| 実行 | 結果 |
|---|---|
| 既定モード | **exit 0**。`格下げ中のメタ層に 1 件（合否には算入しない）` として印字 |
| `SNOTRA_GOV_META_AUDIT=1` | **exit 1** |
| `npm test`（既定） | **511 passed / 3 skipped** — 緑のまま |

**変異 2 — 逆向き（21 本のゲートを弱めていないか）。** `AGENTS.md` へ実在しない ADR 参照を 1 行足した。既定モードで **exit 1**（`G-adr-citations` と `G-references` が 2 件）。同じ実行で格下げ側の 1 件も並んで印字され、**両者が混ざらないことも確認した**。

**変異 1 の `npm test` が緑だったことは、受容する費用の実測である**——錨の消失を見ていた層は `G-domain-anchors` だけであり、格下げによってその 1 件は exit code から消えた。**これは格下げの副作用ではなく、格下げそのものである。**

## 追記（2026-08-20・同日）— 錨の層は観測を待たずに撤去した

**格下げの対象のうち、錨の層（`domains.mjs` / `G-domain-anchors` / 各検査の `domains` 宣言 / `manifest` の `domains` 列 / `duplicateDomains` / 未移行ラチェット）は、下の観測期間を待たずに撤去した**（`ADR-governance-anchor-layer-discarded`）。理由は「格下げは強制力を外しただけで面は残る」であり、**利用者が名指しした痛み（母集団の特定という認知作業）は面が在る限り消えない**からである。

**ゆえに下の「戻す条件・撤去する条件」が今も律するのは 2 件だけである**——面積計器の入力ガードと、evidence の供給断検知。

## 追記（2026-08-20・#1155）— `META_CHECK_IDS` は同じ撤去で消えた

上の撤去（#1152）は `META_CHECK_IDS` も落としている。**ゆえに冒頭の「格下げ後の姿は `META_CHECK_IDS` と `metaAuditEnabled` が持つ」と、下の「その項目だけを `META_CHECK_IDS` から外してゲートへ戻す」は、どちらも実在しない識別子を指している**（凍結規約により本文は書き換えず、ここで読み替えを与える）。

- **格下げ後の姿を持つのは `scripts/governance-check.mjs` の `metaAuditEnabled` と、同ファイルが `metaFindings` へ振り分ける 2 件である。** 検査 id の集合として持つ形は残っていない——格下げ対象が検査ではなくなり（`G-domain-anchors` の撤去で 0 本になり）、残る 2 件がどちらも検査ではない計器だからである。
- **「ゲートへ戻す」の実体**は、その項目を `metaFindings` ではなく `findings` へ積むことである。監査モードの合流（`if (metaAuditEnabled()) findings.push(...metaFindings)`）が既にその形を持つ。

**この腐りは #1155 で見つかるまで沈黙で推移した。** `.claude/skills/health-check/SKILL.md` が判定規則の正本として本 ADR のこの節へ委譲しているため、**復帰手順が実行不能なまま運用の入口だけが生きていた**——凍結された歴史であっても、生きた層から手順として委譲されている節は、指し先の実在が切れれば実害になる。

## 戻す条件・撤去する条件

**運用の正本は `/health-check`「Check 11 — 格下げ中のメタ層の発火計数」である**——何を走らせるか・赤をどう読み分けるか・「連続」をどう数えるかはあちらが持つ。以下は**決定時点の規則**であり、歴史として残す。**生きた層が凍結された歴史へ手順を委譲すると、指し先が腐ったときに運用の入口だけが生き残る**（この ADR 自身が上の節でその形を記録している）。

サイクル末の `/health-check` が `SNOTRA_GOV_META_AUDIT=1` を立てて **`governance:check` の exit code で発火件数を数える**（`npm test` は同じ問いには答えない——器が動くことの対照である。理由は運用の正本側）。

- **発火した** → その項目**だけ**を `META_CHECK_IDS` から外してゲートへ戻す。全部ではない。
- **2 サイクル連続で 0 件** → その項目を撤去する。撤去時はこの ADR へ観測点を追記する。

**この判定を機構で自動化しない。** 自動化すれば、それ自身が「メタ層を守るメタ層」になり、いま止めようとしている再帰をもう一段伸ばす。

### 観測点

| 日付 | 走らせたもの | 格下げ中のメタ層の発火 |
|---|---|---|
| 2026-08-21 | `SNOTRA_GOV_META_AUDIT=1` で `governance:check`（exit 0）と `npm test`（865 件 green） | **0 件** |
| 2026-08-25 | `SNOTRA_GOV_META_AUDIT=1` で `governance:check`（exit 0）と `npm test`（901 件 green） | **0 件** |
| 2026-08-27 | `SNOTRA_GOV_META_AUDIT=1` で `governance:check`（exit 0）と `npm test`（906 件 green） | **0 件** |

**まだ撤去は来ない——ただし理由が変わった。** 記録された観測はいずれもゼロだが、**その間に観測の無いサイクル末が挟まっている**（#1167・#1174 の振り返りに加え、2026-08-25 の行と 2026-08-27 の行のあいだにも `RETROSPECTIVE.md` の更新が 1 回ある——`73703a36`・2026-08-26 20:57）。上の規則が数えるのは連続する**サイクル**であって記録の行数ではないので、**これらの行から「連続 2 回」は導けない**。撤去が来るのは、サイクル末ごとに漏れなく観測した結果が連続 2 回ゼロになったときであり、**その時点で初めて「効いていなかった」と言える**（`ADR-retire-area-budget` が積んだ観測と同じ作法）。発火が出た項目は、その項目だけがゲートへ戻る。

**この空白そのものが、受容した残余が実際に発現した記録である**——下の「読む責任は `/health-check` の手順にある。手順を踏み損ねればメタ層の発火は誰にも数えられない」が、2 サイクルにわたって現実になっていた。**気づけたのは行数ではなく、行の日付とサイクル境界を突き合わせたからである。**

**2026-08-27 の行は `/retrospective` からではなく、利用者が直接起動した `/health-check` から出ている。** 次に数える者は、この行がサイクル末に立つのかを自分で判定すること——**観測が在ることと、それがサイクル末の観測であることは別である**。

## 受容する残余

- **格下げ中の印字は検出チャネルではない**（「検出は exit code、出力は証拠」・#471）。読まれないまま流れる前提で置いており、読む責任は `/health-check` の手順にある。手順を踏み損ねればメタ層の発火は誰にも数えられない。
- **止めたことによる害も沈黙する。** メタ層の失効は緑が緑のまま推移する形で起きるので、「何も起きていないように見えること」は無事の証拠にならない。監査モードの実行だけがその窓である。
