# ADR-heading-refs-headings-only: G-heading-refs の着地先を見出しに絞る

日付: 2026-11-03 ／ 状態: 承認

## 決定

`G-heading-refs` と `G-near-heading-refs` の着地先（`scripts/governance/lib.mjs` の `ANCHOR_SPECS`）から、番号付きリスト項目と箇条書きの太字リードを外す。着地先は ATX 見出しと、`.mjs` のテスト名（`describe` / `it` の第 1 引数）だけにする。

見出し以外を指していた参照は、その項目を含む節の見出しへ向け直し、項目名は散文で添える（例: `AGENTS.md`「開発ワークフロー」の「事前調査」）。

`ADR-canonical-heading-references` の決定 2（アンカーは ATX 見出し・番号付きリスト項目・太字リードの 3 種）を覆す。同 ADR は凍結された歴史なので編集しない。

## 経緯（実測）

常時ロードされる文書（ルート `CLAUDE.md`・`AGENTS.md`・`.claude/rules/`）を平易な文体へ書き直したとき（#1378・#1379）、太字リードを外した箇所と、番号付き項目の言い回しを変えた箇所で、他の文書からの参照が 11 件赤になった。本文の言い回しと太字が参照の ID を兼ねていたためである。そのため、参照されている箇条だけは太字と言い回しを固定して残すことになった。

生きた文書から正準形で指している参照を数えると、見出しへの参照が 289 件、見出し以外（番号付き項目 6 件・太字リード 11 件）が 17 件だった。この 17 件のために、文書の読みやすさを直すたびに地雷を避ける手間が生じていた。

## 却下した代替案

1. **現状のまま、参照される箇条の言い回しと太字だけを固定する**: 却下。どの箇条が参照されているかは、書き直す人から見えない。今回も書き直しの途中で赤になって初めて分かった。文体を直す作業のたびに同じ手間がかかる。
2. **明示的な ID を付ける**（`<!-- anchor: xxx -->` のような目印を置き、参照は ID で指す）: 却下。言い回しは完全に自由になるが、書く手間と照合の仕組みが増える。17 件のために機構を足すほどの価値は無い。
3. **太字リードだけ外し、番号付き項目は残す**: 却下。番号付き項目も本文の言い回しが ID になる点で同じであり、6 件の参照のために残す理由が無い。

## 受容する残余

- 参照の粒度が「項目」から「節」へ粗くなる。項目名は散文で添えるが、散文の部分は照合されないので、項目の言い回しが変わっても検査は緑のまま通る。
- `ANCHOR_SPECS` から `depth` も外した。読む消費者がいなかったため（節境界を読む `sectionsOf` は既に無い）。
