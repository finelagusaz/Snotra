# ADR-hook-fires-table-check: 発火一覧を代表パスで機械照合し、実在しない入力は機構の外へ残す

#863。`docs/hooks.md`「PostToolUse（post-edit.mjs）の発火一覧」は `selectChecks` の写しでありながら、内容を照合する機構を持たなかった。

## 文脈

この表は**退去先である**。同型のドリフトはルート `CLAUDE.md` の同じ表で一度起きており（#474〜#497）、常時ロード面から `docs/hooks.md` へ逃がすことで解決したことになっていた。表自身が「正本は `selectChecks` である」と自己申告していたが、索引が正本とずれても `npm run governance:check` は緑のままだった。

#858 で `selectChecks` へ `fmt` を足したとき、この行は実際に計画の変更ファイル一覧から漏れている（独立レビューが発見）。**避難させただけで、腐る性質は移動しただけだった。**

issue は「機構化する（案 A）」と「受容を明示的な判断として維持する（案 B）」の二択として書かれ、案 A の懸念として「表のセルが日本語散文を含むので、厳密照合には書式を機械可読へ寄せる代償がある」を挙げていた。

## 決定

`governance:check` へ `G-hook-fires` を新設する。表を 3 列（代表パス / 検査 id / 補足）にし、**代表パス列を `selectChecks` へ食わせて検査 id 列と順序込みで一致すること**と、**ソースの `checks.push("<id>")` 全件が表のどれかの行に現れること**を要求する。

## 検討した代替案と却下理由

- **案 B: 受容を維持し、機構を作らない**: 却下。issue では案 A と対等な選択肢に見えていた。しかし案 A の懸念は「**照合の対象がセル全体である**」という暗黙の前提から来ており、散文を別の列へ分離すると代償はほぼ消える（規約は「検査 id 列のバッククォートは検査 id だけ」の 1 本になり、補足列は無制約のまま残る）。代償が消えた以上、受容の根拠が残らない。加えて、ここは既に一度の退去先であり、**二度目の受容は「腐る場所を移し続ける」ことになる**。
- **`G-hook-commands` を `docs/hooks.md` へ広げる（issue の案 A 原形）**: 却下。あちらは `docs/build-commands.md` のコードブロックから cargo 行を取り、トークン列一致を見る形に特化している。表の列抽出はまったく別の抽出器であり、1 つの検査に 2 つの母集団と 2 つの抽出器を持たせると、finding が「**どちらの母集団が欠けたか**」を言えなくなる。母集団の欠落を明示的な赤にする既存の規律（各検査が自分の母集団を 1 つ持つ）を守るため、別検査として新設した。
- **ソーステキストから `selectChecks` の述語を抽出して照合する**: 却下。判定の再実装であり、**閉じたい写しを一段下で作り直す**。`selectChecks` は export 済みで、`post-edit.mjs` は I13 のガードにより import しても `main()` を走らせない（`pre-bash.test.mjs` が既に import している）。ゆえに関数そのものを呼べる。
  - **`G-hook-commands` がソース抽出なのは `cargoSpec` が非 export だからであって、import が危険だからではない。** この区別を書き残さないと、将来の読者が 2 つの検査の不一致を見て「一貫性の修正」として逆方向へ揃えうる（同検査のコメントにも同じ注記を置いた）。
- **代表パスの実在検査を G-references へ委ねる**: 却下（**当初は採用したが、レビューの実測で覆した**）。`docs/hooks.md` は `governanceDocs` の母集団に入るので、G-references が実在を要求してくれるから二重に持つ必要はない、と考えていた。しかし `checkReferences` の述語は「バッククォート内で **`/` を含み** かつ `REF_EXTENSIONS` に当たる」であり、実測すると現行 10 行のうち **`Cargo.toml`（`/` を持たない）と `.githooks/pre-commit`（拡張子を持たない）の 2 行が述語の外**にあった。委ねると 10 行中 8 行しか守られない。`checkHookFires` 側に `fileSet.has(rel)` を持つ形へ改めた。
  - **既存の機構が覆うから要らない、という判断そのものが検算を要する**（`.claude/rules/safety-nets.md`「検出器のカバー範囲は、欠落のパターンごとに検算する」）。#858 で同じ形の過大評価をしており、**それを教訓として書いた当のサイクルの次で再発した**。
- **母集団を `BUDGETS` のキーから取る**: 却下。`BUDGETS ⊇ 発行されうる id` である（予算は発行されうる id を覆うだけで、逆は保証しない）。どのパスも発火させない id が `BUDGETS` に入ったとき、表に「**決して走らない検査**」を書かせることになる。正しい母集団はソースの `checks.push` リテラルである。
- **glob 列のまま、id の集合だけを照合する**: 却下。捕まるのは id の追加・削除・改名だけで、issue の文言（「`*.rs` → clippy」が事実と合っているか）に答えない。**述語の変更と行の割り当て違い**を覆うには、glob ではなく具体パスを関数へ食わせる必要がある。読みやすさの損失は補足列（3 列目）が吸収する。
- **表の行を `selectChecks` の述語の分岐と 1 対 1 にする**: 却下（範囲）。`vitest.config.ts` / `package.json` / `.claude/hooks/**` / `.claude/settings.json` の各分岐は `post-edit.test.mjs` が既に 1 件ずつ固定している。**この検査の担当は「文書が腐らないこと」であって、述語の正しさではない。** 行を増やすと表が索引として読めなくなり、既存のカナリアと重複する。

## 受容する残余

**足ごとに名指しする**（`.claude/rules/safety-nets.md`「検出器のカバー範囲は、欠落のパターンごとに検算する」）。粗い粒度の「内容整合は機構の外」という書き方こそ、この行が一度腐った原因である。

1. **実在しないファイルは代表パスにできない。** 実在検査を持つ以上、4 crate の外に置いた `.rs`（現在 0 件）と `config.toml`（ランタイムのユーザー領域ファイル）は行にできず、**補足列の散文だけが記述する**。この 2 つが表れる変更では G-hook-fires は沈黙する。実在検査を外せばこの足は覆えるが、代わりに「改名で死んだ代表パスが接頭辞判定を通り続ける」足が開く——**どちらか一方しか閉じられない**ので、頻度の高い後者を採った。
2. **補足列の意味整合は見ない。** 「この順は報告の並びであって実行順の打ち切りではない」が事実かどうかは判定の外にある（この命題自体は #858 でフォールトインジェクションにより実測済み）。
3. **代表パスは標本であり、`selectChecks` の全域の等価性証明ではない。** 表が覆うのは 10 行 10 id であり、述語ごとの挙動は `post-edit.test.mjs` が別に固定している。

## 検出器自身のカバー範囲を検算して見つかった足（実装後のレビューで閉じた）

**この検査は「写しが黙って腐らないこと」を主張する。その主張自体を足ごとに壊して測ったところ、2 本の沈黙経路が残っていた。** どちらも「機構を入れた」ことに満足して検算を省けば、緑のまま残っていた。

- **行の脱落**: 行を消しても、その行が持つ id が他の行にもあれば母集団照合を通る。とくに**空集合の行（`docs/hooks.md` → `（なし）`）は id を 1 つも持たない**ので、消しても何も赤くならなかった——そしてその行こそ「割り当ての無いファイルの沈黙は合格ではない」という最上位の契約（#471/#497）を運ぶ。空集合の行が 1 本以上あることを要求して閉じた。
- **走査の打ち切り**: 終了条件が `startsWith("|")` だったため、表の途中に非表の行が 1 行紛れるだけで以降が照合されなかった。**同じ穴が `checkCiTable` にもあり、そこからコピーされていた**（この PR が `checkCiTable` の別の沈黙経路を塞いだ際、同じループのもう 1 つを見落としていた）。両者とも「最初の空行まで走査し、途中の非表行は finding にする」形へ揃えた。
