# ADR-hooks-doc-retired: フックの実装契約を文書から外し、テストとコードのコメントへ置く

## 文脈

#1334 で `docs/hooks.md` の条項を、置き場所の順（テスト・型 → 安いテスト → 該当箇所のコメント → 文書 → 消す）で振り分けた。PreToolUse 節の大半は `.claude/hooks/pre-bash.mjs` のコメントの写しで、テストが守っていた。

## 決定

`docs/hooks.md` を撤去した。PreToolUse の契約の正本は `pre-bash.mjs`（先頭コメントと各判定の doc）とそのテスト、RA の扱いの正本は `lsp-config.mjs` の先頭 doc である。テストが守っていなかった規則（git 判定のコマンド位置・要約ゲートの `workspace/` 接頭辞・git 上限の和と hook の timeout・拒否文言の代替手段）にはテストを足した。

## 検討した代替案と却下理由

- **hooks.md を小さく残す（RA の 3 項目と、外から参照されている見出しだけ）**: 却下。`AGENTS.md`「ドキュメント参照」と `docs/development-principles.md`「規範の書式は文書の役割から選ぶ」は、この文書の書式を「適用範囲の宣言と逸脱の明記の対」と定めていた。逸脱の明記をコードへ移すと、文書に残るのは対のどちらでもない 3 項目になり、書式の説明が中身を失う。しかも 3 項目は RA の設定を触る人にだけ要る内容で、その人が開くのは `lsp-config.mjs` である。
- **テストを足さず、規則をコメントへ残す**: 却下。敵対的調査で、規則を破る変異（コマンド位置のアンカーを緩める・接頭辞判定を緩める・上限を 40 秒にする・拒否文言から代替手段を消す）が全テスト緑のまま通ると分かった。どれも数行のテストで落とせるので、置き場所の順の「安くテストにできるならテストにする」に当たる。
