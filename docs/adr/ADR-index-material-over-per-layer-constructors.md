# ADR-index-material-over-per-layer-constructors: 木と派生データの組の不変条件を 1 つの型で持ち、層ごとのコンストラクタで捌かない

## 文脈

`rebuild_and_save` が保存の返す派生データを捨てていた（#984）。素直な修復は「返り値を広げ、呼び出し点で
`Option` を捌く」形だが、レビューで**同じ `Option` 分岐が `PrebuiltIndex` / `Engine` / `SearchEngine` の
3 層・5 呼び出し点へ写っている**ことが判明した。根は最下層の 2 コンストラクタで、上の 2 層はその写しである。

同時に、木とマスクの**長さが揃うこと**を守っていたのは `assemble` の `debug_assert` だけで、release
（このワークスペースは `panic = "abort"`）では何も守っていなかった。破綻はビルド時に沈黙し、索引を
入れ替えた後の初回検索で並列 Vec の添字外アクセスとしてプロセスごと落ちる形で初めて出る。

## 決定

**木と派生データを `indexer::IndexMaterial`（フィールド private）へ束ね、索引を建てる入口を
`from_material` の 1 つへまとめる。** マージ（マスクへ追記 ＋ 木へ根として追加）はその型のメソッドに
なり、ディスクから来た組は `from_untrusted` が列長を検証する。

このリポジトリが既に明文化している原理の 1 段上への適用である——`SearchEngine::new_with_cached_masks`
の doc が「組のまま受け取る……境界を跨ぐ手前でほどかない」、`DerivedColumns` が「タプルにしてはならない」
と書く。機序と受容残余は `IndexMaterial` の doc が正本。

## 検討した代替案と却下理由

- **`PrebuiltIndex` に集約用コンストラクタ（`from_parts`）を 1 本足す**（レビューの提案）: 却下。
  **5 呼び出し点のうち 1 か所しか直せない。** 分岐は 3 つの型の層に散っており、`PrebuiltIndex` を直しても
  `Engine` と `SearchEngine` の写しは残る。**「4 枚」と数えた指摘自体も実測では 5 枚だった**——数えた
  散文ではなく grep で母集団を取ってから射程を決める必要があった
- **`Option<&mut CachedMasks>` を取る自由関数で閉じる**（最初に採り、レビューで覆した）: 却下。
  **閉じていなかった。** `Option<&mut _>` は呼び出し側に `as_mut()` を書かせるため「`Some` を持ちながら
  `None` を渡す」形が型を通り、`&mut Option<_>` へ変えても `&mut None` が通る——**同じ差分の検知器が
  その反例を実演していた**。引数でマスクを受け取る形はどう書いても閉じない。閉じたのはフィールドを
  private にしてメソッドへ移したことである
- **drain 経路の額を独立に測る計測ハーネスの新設**: 却下。`IndexTree` / `CachedMasks` はどちらも `Clone`
  を持たないためフルスキャン 2 回か `Clone` の追加が要り、さらに `derive_columns` を `pub` へ開ける
  必要が生じる——**その関数を `pub(crate)` に留めている理由（検知器がファイルシステムと、型に無い
  ロック契約を巻き込まないこと）が形骸化する**取引になる。額は反復 11 の実測と同一の導出であり、かつ
  この枝は起動レイテンシではないので予算の判断材料にならない（`PERFORMANCE.md` の該当節が「未実測」と
  明記する形を採った）
- **`has_masks` を `pub(crate)` へ狭める**（レビューの提案）: 却下。crate 外の計測ハーネスが「どちらの
  枝を測ったか」を出力できなくなり、**その数値が読めない数字に戻る**。`#[doc(hidden)] pub` は
  `SearchEngine::footprint_rows` と同じ扱いで、製品が分岐に使わないことは doc が担う
- **`IndexTree::extend_with_roots` の可視性をさらに絞る**: 却下。A/B 検知器の A 側オラクルが crate 内で
  それを直接呼ぶ形に依存しており、絞ると**比較の独立性が失われる**（A と B が同じ経路を通ると不動点になる）
