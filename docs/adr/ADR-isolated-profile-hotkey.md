# ADR-isolated-profile-hotkey: 分離プロファイルの既定ホットキーを Alt+F12 にし、既定値へ戻る経路のうち初回起動と復旧だけを分ける

## 文脈

#1306 で、`SNOTRA_CONFIG_DIR` が実プロファイル以外を指す起動（分離プロファイル）を、普段使いの Snotra と同時に動かせるようにした。ホットキーが同じだと後から起動した側の登録が失敗するので、分離プロファイルが既定値を使うときのホットキーを実プロファイルの既定（`Alt+Q`）から分けることにした（ユーザー裁定・2026-11-07）。キーの選び方と、既定値へ戻る経路のどこまでを分けるかを決める必要があった。採用した形は `SPEC.md` §13 と `snotra-core/src/hotkey.rs` が持つ。

## 検討した代替案と却下理由

- **`Ctrl+Alt+Q`**: 却下。smoke-egui の Alt 解放の扱い（`ShowAfterAltRelease`）と「押しっぱなしの Z」の検査では、show が確定する時点で Ctrl がまだ押されている。`Ctrl+Alt` を AltGr として扱うキーボード配列もある。修飾は `Alt` 単独のまま保ち、キーだけを変えた。
- **`Alt+Shift+…`**: 却下。Windows の入力言語切り替えの既定の組み合わせで、注入すると IME やレイアウトが切り替わりうる。
- **修飾なしの `F12`**: 却下。デバッガ予約で `RegisterHotKey` が `ERROR_HOTKEY_ALREADY_REGISTERED` を返す（2026-11-07 実測）。`Alt` を付ければ登録できる。
- **不正なホットキーの自動修復（`fallback_invalid_hotkey`）も分離の既定へ直す**: 却下。読み込みの腕（初回起動・parse 失敗・非 UTF-8・読めない）は、書かれた config を丸ごと既定値で置き換える経路で、どれを通ったかは利用者に見えない。そのため、腕ごとに既定値を食い違わせない。一方、自動修復は読めた config の中の 1 値を直す移行であり、SPEC §7.5 が `Alt+Q` への修復を規定している。分けるには `apply_migrations()` の署名を変えることになり、呼び出し元（インポート・テスト）まで波及する。「初回起動を分ける」という裁定の範囲を超えるので、`[hotkey]` の欠落・「初期設定に戻す」・インポートと同じく、残余として SPEC §13 に書いた。
- **スタートアップ登録の結線（`autostart::enable` が `unless_isolated` を通ること・設定アプリの `run` が分離プロファイルではレジストリを読まないこと）に検知器を置く**: 却下。結線を測るテストは、変異したときに開発機の実 `HKCU\…\Run` を書く。守りは UI の分岐（kittest）と core の入口のガード（罠の閉包のテスト）の 2 層あり、片方だけが壊れても害は表示とエラーに留まる。

## 帰結

- 分離プロファイルでも、上の残余の経路を通ると `Alt+Q` が保存される。普段使いの Snotra が `Alt+Q` を握っていれば、既存の登録失敗の通知が出る。
- `Alt+F12` は Rust の定数が正本で、検証用プロファイルの seed（PowerShell）はその写しである。
