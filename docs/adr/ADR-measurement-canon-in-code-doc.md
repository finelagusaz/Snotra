# ADR-measurement-canon-in-code-doc: 寄せ先の無い実測値は `PERFORMANCE.md` へ足さず、コードの doc を正本にする

## 文脈

#1128 は「#1032 の実測値 `43,939 µs` が生きた層の 4 か所に実体で在り、再計測で同時に腐る」を解く issue で、
`PERFORMANCE.md` の当該節を正本とし残りを参照へ寄せる形を指定していた。

作業中に**同型の写しがもう 1 つ**見つかった——`40〜95 ms`（worker が `engine.search` の間じゅう
engine lock を握る時間）が生きた層の **8 か所 / 6 ファイル**に在る。ユーザーの裁定で今回に含めたが、
こちらは 43,939 と**形が 1 つ違っていた**。

**`PERFORMANCE.md` にこの値の記録が無い。** `git grep "40〜95\|40-95" -- PERFORMANCE.md` が 0 件で、
#1032 が使った計装は同 issue の完了時に撤去されている（`PERFORMANCE.md`「フレーム後半の帰属」が
「計器は #1032 の完了時に撤去した」と記録している）。**寄せ先の節そのものが存在しない。**

## 決定

**`Engine::config_handle` の doc（`snotra-core/src/engine.rs`）を `40〜95 ms` の正本とし、
残る 7 か所はそこを指す。** `PERFORMANCE.md` には何も足さない。

参照の形は在り処で分ける——`///` / `//!` からは intra-doc link（`cargo doc` の
`broken_intra_doc_links` deny が綴りを検算する）、`//`（非 doc）と `.md` からはバッククォートの散文。

## 検討した代替案と却下理由

- **`PERFORMANCE.md` の #1032 の節へ 1 行足して正本にする**（43,939 と形を揃える案）: **却下。**
  値の出所が**既存の写しそのもの**になる。計装は撤去済みで、書ける数字は 8 か所の写しから転記した
  ものしか無く、それを「測定記録」の顔で `PERFORMANCE.md` へ据えると
  `AGENTS.md`「照合は SSOT に対して行う。派生コピー同士の一致を完全性の証拠にしない」に正面から触れる。
  **機構は最も強くなる案だった**（`G-heading-refs` が 8 本すべてを検算できた）——それでも、
  裏取りできない数字に機構の権威を与えるほうが害が大きいと判断した。
- **計装を復元して測り直し、`PERFORMANCE.md` へ本物の記録を作る**: **却下。**
  #1032 の計器は `update()` を 8 区間へ切り、trace の書き込み時間を各区間から控除する規模のもので、
  実運用点（312k エントリ）の実 `index.bin` と 3 標本 × 2 巡を要する。
  **#1128 の「正本を定めて残りを寄せる」より 1 段も 2 段も大きい変更**であり、
  写しを畳む作業の中で決めてよい規模ではない。**将来この値が疑わしくなったときにやるべき作業として残す。**
- **数値を 8 か所すべてから落とし、害の説明だけ残す**: **却下。**
  正本を決める必要も腐る対象も消えるが、「どれくらい長いか」の規模感が失われる。
  `40〜95 ms` は 60fps の予算（16,700 µs）の 2.4〜5.7 倍であり、**この桁が「なぜ live-read を
  錠の外へ出したか」の説得力そのもの**である。数値ではなく寄せ先が問題なのだから、数値を消すのは筋が違う。
- **`docs/architecture.md` の #1032 の bullet を正本にする**: **却下。**
  同文書の 228 行が既に「実運用点の値は下の #1032 の bullet が持つ」と書いており、
  文書内の正本宣言としては先例が在った。しかし `docs/architecture.md` は横断パターンの解説であって
  `Engine` の契約の在り処ではなく、`snotra-core/src/engine.rs:7` と `snotra-core/CLAUDE.md`
  「engine.rs のロック最小化パターン」と `src-tauri/src/state.rs` の 3 つが既に
  「契約の正本は `config_handle` の doc」と名指していた。**既にある向きへ値を合流させるほうが、
  新しい向きを作るより参照の本数が減る。**

## 帰結

- **測定値の正本は `PERFORMANCE.md` に限らない。** `PERFORMANCE.md` は A/B と実測ログの置き場であり、
  そこに記録の無い値まで押し込む場所ではない。**寄せ先が無いときはコードの doc を正本にしてよい。**
- **機構は非対称になる。** `43,939` 側は `G-heading-refs` が 4 本すべての着地を検算するが、
  `40〜95 ms` 側で綴りの実在を見るのは 3 か所だけである（`docs/architecture.md` は
  `G-stale-identifiers`、`mod.rs` と `state.rs:18` の intra-doc link は `cargo doc`）。
  `src-tauri/CLAUDE.md` / `state.rs` のテスト doc / `view.rs` の行コメントには機構が無い
  （#1128 で 6 行すべてを対照変異で実測した）。**受容する残余である。**
- **どの機構も「指し先がその値を持つか」は見ない。** 見るのは綴りの実在だけで、
  正本から値が消える変更は沈黙で通る。
- **正本化そのものの逆行にも機構は無い。** `config_handle` の doc は「他の箇所はここを指す」と
  宣言するが、9 番目の写しが明日書かれても何も鳴らない。検知器を置くかは
  セーフティネットの新設ゆえ #1128 では決めず、判断を人へ返した。
