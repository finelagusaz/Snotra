# ADR-meta-harness-thinning: ハーネス自身を走査する層を撤去したとき、検査ごとの選別と形の判定の撤去を却下した

2026-09-29、利用者の「メタハーネス層をばっさり薄く」を受けて、**走査対象がハーネス自身である層**を 4 段に分けて撤去・圧縮した。**この ADR が残すのは、撤去の単位の決め方と、却下した案である。**

## 撤去したもの

1. 格下げ中だった計器（面積計器・evidence 行）と、その観測手続き（`/health-check` の Check 11）
2. ハーネスを照合する検査 7 本、編集時 reminder、manifest の差分検査（CI の step を含む）
3. 編集後の自動検証（PostToolUse フック）
4. 常時ロードされる規範の圧縮（ルート `CLAUDE.md` のフック節と委譲節・`AGENTS.md` の機構に関する行・`.claude/rules/safety-nets.md`）。規則は残し、事件の経緯を落とした

守ったもの: 参照の腐りを見る検査群・製品の設定を照合する検査群・`/plan-review` の Step 2b・`.githooks/` と GitHub ruleset・PreToolUse フック。

## 撤去の単位 — 検査の良し悪しではなく「何を走査しているか」

`ADR-governance-corpus-reduction-rejected` は、検査を 1 本ずつ選別する案を「取り戻す費用が測ると 0」として却下していた。今回はその却下を踏まないよう、**走査対象がハーネス自身かどうか**で層を切った。個々の検査が役に立ったかは問うていない。同 ADR が名指ししていた痛み（セッションの認知作業）に直接効くのは段 4 である。

## 却下 1: 格下げの観測規則（2 サイクル連続 0 件）を待つ

`ADR-governance-meta-demotion` の観測表は、小さな計器 2 件について約 50 行の議論を積んでいた。観測の抜けで連続が何度も切れ、規則どおりに撤去が来る見込みが立たなかった。**守る費用が守られる価値を上回っていた**ので、利用者の裁定で打ち切った。

## 却下 2: PreToolUse フックを `gh pr create` のガードだけにする

当初の提案はこの形だった。pre-bash.mjs を読むと、残りは I/O を伴わない形の判定 5 件（`--no-verify`・`--ff-only` なしの `pull`・HEREDOC・`\` 区切りのパス・Python の cp932）で、それぞれが復帰手順を文言に持っていた。**防いだ事故は git にも振り返りにも痕跡を残さないため、捕捉実績では裁けない。** 保守費が小さいこともあり、利用者の判断で残した。

## 却下 3: 主題が消えた ADR を削除する

段 2 で主題が消えた ADR 5 本は、他の凍結 ADR から連鎖して引かれていた。削除には凍結された本文の書き換えが要るため、歴史として残した。

## 受容する残余

- `.rs` を編集しても fmt / clippy / test は自動では走らない。手順 6 を飛ばせば、壊れた変更が CI まで届く
- ルート `CLAUDE.md` のスキル表・`/implement` 3a の check スキルの列挙・hook の cargo コマンドとカテゴリ A の一致は、機構の照合を失って手作業の写しに戻った
