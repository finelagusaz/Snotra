# ADR-module-index-reverse-scope: 逆方向の照合を節へ絞ったとき、所有関係のパースと死角の据え置きを却下した

2026-09-02、`G-module-index` の逆方向の照合（production ファイルの basename が `<crate>/CLAUDE.md` に現れるか）が見る範囲を、**文書全体から「モジュール構成」節へ絞った**（#1214）。**この ADR が残すのは、そのとき却下した案と、一度却下した案を覆した経緯である**——採った形は `scripts/governance/checks/G-module-index.mjs` が持つ。

## 文脈

#1210 で `snotra-core/src/autostart.rs` を足したとき、索引行のほかに開発ルールの散文と `win_registry.rs` の索引行でも同名に触れた。この状態で **`autostart.rs` の索引行だけを削る変異を入れても `governance:check` は exit 0** だった。逆方向が見ていたのは「索引行に載っているか」ではなく「文書のどこかにバッククォート付きで現れるか」だったためである。

この弱化は検査自身が宣言済みで、新しい欠陥ではない。#1214 は**宣言された死角へ実際に踏み込んだ**という報告だった。

## 却下 1: 索引行の所有関係をパースする（issue の案 B）

行ごとに「この行はどのファイルの索引行か」を決め、逆方向をその写像へ照合する形。**死角は閉じるが、費用が文書の性格を変える。**

実測（2026-09-02・実物の `moduleIndexSources` と `sectionOf` で導出）:

| crate | 実ファイル | 行頭が所有 | 集約行に載る | それ以外 |
|---|---|---|---|---|
| snotra-core | 59 | 31 | 0 | 28 |
| snotra-egui-runtime | 12 | 12 | 0 | 0 |
| src-tauri | 45 | 37 | 7（`commands/` `platform/`） | 1 |
| snotra-settings | 15 | 6 | 9（`tabs/`） | 0 |
| 合計 | 131 | 86 | 16 | 29 |

**「それ以外」29 件のうち 22 件はテストモジュール**（`tests.rs` 13 枚・`search/tests/*.rs` 9 枚）で、チームが意図して索引していないものである。案 B を素直に採ると、この 22 件へ索引行を新設するか、母集団から除外する規則を別途入れるかになる。**どちらも「索引とは何か」という文書の性格を変える判断**であり、#1214 が報告した欠陥の修復としては大きすぎる。

加えて、**basename 照合である限り閉じない天井が別にある**——`snotra-core` の `tests.rs` は 13 枚あり、節の中に `` `tests.rs` `` が 1 回あればその 13 枚が覆われる（crate 内で同名が複数ある basename は `snotra-core` に 2 種 15 件、`src-tauri` に 2 種 5 件）。案 B は行の所有を決めるだけなので、この天井には触れない。

## 却下 2: 死角のまま据え置き、宣言だけ更新する（issue の案 C）

issue はこれを素直な選択肢として挙げ、**案 A（節へ絞る）は「実測したが効かない」として既に却下していた**。当初はこの前提のまま案 C を選んだ。

**覆った。**——次節の実測による。

## 却下 3: 1 例の実測を根拠に案 A を却下したまま進む

**これが本 ADR の主眼である。**

issue の案 A 却下は `snotra-core/autostart.rs` **1 例**の実測だった。その 1 例では確かに現行も案 A も沈黙する——`win_registry.rs` の索引行が**同じ節の中**で `autostart.rs` に触れているため、節の内外という切り口では動かない。

**母集団を「索引行を持つ全ファイル」へ広げて測り直すと、結論が変わった**（2026-09-02・索引行 1 本ずつを削る変異を全数へ注入）:

| crate | 索引行 | 現行（`text`）赤/緑 | 案 A（`section`）赤/緑 |
|---|---|---|---|
| snotra-core | 34 | 15 / 19 | 23 / 11 |
| snotra-egui-runtime | 12 | 8 / 4 | 9 / 3 |
| src-tauri | 34 | 12 / 22 | 12 / 22 |
| snotra-settings | 6 | 3 / 3 | 6 / 0 |
| 合計 | 86 | 38 / 48 | **50 / 36** |

**案 A は現行より 12 件多く捕まえ、現行ツリーへ当てたときに新たに赤くなるファイルは 0 件だった**（掃除の費用ゼロ）。`src-tauri` だけ差が 0 なのは、そこでは言及が節の**中**にあるためで、#1210 が踏んだのはこの形である。

**1 例での却下が見落としたのは「差が出ない例を選んでいた」ことである。** 却下の根拠にした実測は正しく、機序の説明も正しかった——**足りなかったのは母集団だけ**だった。この形は `AGENTS.md`「検証の作法」の「照合は SSOT に対して行う」でも「全称表現」でもなく、**反例 1 件で一般命題を否定したときに起きる**。

## 実測（フォールトインジェクション・2026-09-02）

実物の `checkModuleIndex` / `checkModuleLinkage` を import し、`makeSnapshot` 由来の snapshot の `read` だけを差し替えたメモリ上の複製へ変異を当てた。**稼働中のガードは 1 バイトも触っていない。**

| 変異 | 結果 |
|---|---|
| 対照（変異なし） | 4 crate とも 0 件・`G-module-linkage` も 0 件 |
| `snotra-settings` の `style.rs` の索引行を削る | **赤 1 件**（節の外の言及に救われていた側。案 A で新たに捕まる） |
| `snotra-core` の `autostart.rs` の索引行を削る | **緑**（#1210 の形。同じ節の `win_registry.rs` の索引行が救う＝残る死角） |
| 索引行を残し `mod autostart;` だけ削る | `G-module-linkage` が**赤 2 件**（`autostart.rs` と `autostart/tests.rs`）。`G-module-index` は 0 件（担当外） |
| `snotra-settings` の集約行 `` `tabs/` `` を削る | **赤 8 件**（集約行が覆っていた全タブ） |
| `snotra-egui-runtime` の `raster.rs` の索引行を削る | **緑**（`renderer.rs` の索引行が言及している） |
| 同じく `renderer.rs` の索引行を削る | **緑**（`raster.rs` の索引行が言及している） |
| 上の 2 行を**両方**削る | **赤 2 件** |
| 節の中で 1 回しか現れない索引行を削る（`lib.rs` / `env.rs` / `input.rs`） | いずれも**赤 1 件** |

**赤の理由はいずれも検査の assert であり、実行時エラーではないことを出力で確かめた。**

**測り直しを 2 度要した。** 1 巡目は (a) `G-module-linkage` の finding がファイル名を `file` に入れ `message` に入れないのに `message` で絞ったため常に 0 件になり、(b) 対照に選んだ `renderer.rs` が `raster.rs` の索引行から逆に言及されており対照になっていなかった。**どちらも「沈黙」に見えたが、計器の欠陥と変異の選び損ないだった**（`.claude/rules/safety-nets.md`「発火しないときも同じである」）。

## 受容する残余

- **索引行の所有関係は今も見ない。** 同じ「モジュール構成」節の中にバッククォート付きで basename が現れれば、それが集約行でも別ファイルの索引行の説明文でも緑になる。**閉じるには却下 1 が要る。**
- **その死角は相互参照が残る間だけ続く**（`raster.rs` / `renderer.rs` の対で実測）。片方の索引行が消えても残る側が救うが、両方消えれば赤になる。**「索引行の消失は検知されない」は偽であり、「同じ節の中に他の言及が残っていれば検知されない」が正しい。**
- **basename 照合の天井は動いていない**——crate 内で同名のファイル群は、その crate の節での 1 回の言及で覆われる。
- **掃除の費用 0 件は 2026-09-02 の値であって将来の下界ではない。** 節の外の散文だけが同名に触れるファイルが現れれば、そのとき新たに赤くなる。向きは赤側（安全側）である。
- **編集時 reminder は同じ述語を共有する**（`scripts/governance/edit-findings.mjs` が `checkModuleIndex` をそのまま呼ぶ）。ゆえに上の残余はすべて reminder にも同じだけ当たる。
