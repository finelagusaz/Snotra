# ADR-nested-quote-heading-ref-labels: 見出し参照のラベルに 1 段の入れ子を許し、見出し側を縛る案・参照側の新検査・兄弟検査への同居を却下した

日付: 2026-08-26 ／ 状態: 承認

## 文脈

正準形の見出し参照 `` `<対象>`「<見出し>」 `` を照合する `HEADING_REF` は、ラベルの文字クラスが
`[^「」\n]` だった。**見出し名が鉤括弧を入れ子に含むとき、それを全形で指す参照は一致そのものが
生成されない**——`checked` にも `findings` にも現れないので、「照合していない」と「差分ゼロ」が
区別できない。#497 が閉じたはずの沈黙経路が、ラベルの形の側に 1 本残っていた。

**「今 0 件」は無害の証拠ではなかった。** 過去のコミットで測り直すと（読むだけ・作業ツリー不変）、
**18 日間・独立 2 エピソード・2 つの別の見出し・2 つの別の引用元**で不可視の参照が実在した。
うち 1 件は製品コードの rustdoc（`snotra-core/src/indexer.rs`）である。直前のサイクルは
1 見出しへ手で回避策を当てただけで、機構は無かった。

## 決定

**`HEADING_REF` のラベルを 1 段の入れ子まで受け入れる。** 検知器を新設して書き方を縛るのではなく、
**死角そのものを消して縛りを増やさない。**

## 検討した代替案と却下理由

- **見出し側を縛る**（見出し名に鉤括弧を入れ子で書かせない）: **却下。** ATX 見出しに絞れば
  他のアンカー種別（番号付きリスト・太字リード）に死角が残り、全アンカーへ広げれば
  **決定時点の実測で 249 件 / 65 ファイル**（アンカー総数 3282）の改名になる。加えて `ADR-canonical-heading-references` が既に「参照側の記法を直す」を採っており、
  **この案はその向きの反転**である。`docs/development-principles.md` が条項の太字リードを
  アンカーとして使う設計とも噛み合わない。
- **参照側を縛る新検査**（入れ子ラベルの参照を赤にする検査を足す）: **却下。** 誤検出 0 件で
  成立はするが、新規 2 ファイル + 配線 + ADR + 実行時間を要する。正規表現案が
  「**縛りを増やさず死角を消す**」ので上位互換である。加えて、昇格先の検出器は 1 本の正規表現では
  書けない——naive な形は**深さ 1 にも誤発火する**（`*` が 0 回に落ちるため、正規表現案が
  合法化する当の形を赤にする）。正しい形は否定判定になり、費用がさらに上がる。
- **兄弟の `G-folded-heading-refs` へ同居させる**: **却下。** 本体への追加行数は最小だが、
  検査 id が内容を偽る。折れ（物理改行）と入れ子（ラベルの形）は別の事象である。

## `ADR-folded-canonical-reference-detector` の却下 1 が本件に当たらない理由

同 ADR は「`HEADING_REF` を行跨ぎ対応にして吸収する」案を 3 つの理由で却下している。
**3 つとも本件には当たらない**（いずれも実測で裁定した）。

1. **「3 消費者の意味論が同時に動く」**——本件は `REF_HEAD`（正準形の頭）を 1 文字も触らない。
   `G-near-heading-refs` と `G-folded-heading-refs` はどちらも `HEADING_REF` を import していないので
   入力が変わらない（実測: 両者の `checked` が不動）。
2. **「行番号の帰属と `dependents` の節境界が動く」**——判定は行単位のままで、節境界は
   `ANCHOR_SPECS` 由来である。`dependents` の索引は全エントリが逐語一致した。
3. **「折返しの規範と逆を向く」**——全称否定なので探しに行った。入れ子や鉤括弧の書き方を
   縛る生きた条項は見つからず、正準形についての生きた条項はどれも**ラベルの中身を縛っていない**。

## 帰結

- **移行コストは 0 である。** 生きた母集団で新たに赤くなる参照は 1 件も無く、変更は純粋に加算的だった
  （歴史データでは、18 日間沈黙していた 2 件が**赤を 1 件も出さずに**「照合済み」へ上がる）。
- **性能は変わらない。** 2 つの選択肢が先頭 1 文字で排他なので曖昧さが無く、破滅的バックトラックは
  起きない（病的入力を独立に 2 度測って確認した）。**速くなるとは書かない**——実装時の初回測定は
  大きな改善を示したが、warmup を揃えた再測定では再現しなかった。向きは弱く支持される程度である。
- **宣言する死角がある**（正本は `lib.mjs` の `HEADING_REF` の doc・**ここへ写さない**）。
- **境界が見えにくくなる。** 線が「入れ子は照合されない」から「1 段までは照合される」へ動くので、
  深さ 2 を書いた者はより強く動くと期待する。数え上げではなく**宣言**で受け止める。

## 受容する残余

- **`G-near-heading-refs` の `NEAR_REF` は同じ形を独立に手書きしており、本件で広がらない。**
  ゆえに近傍形（助詞などを挟んだ形）で入れ子の見出しを指す参照について、同検査は**入れ子の内側で
  切れた別物のラベル**として一致を作る（「不可視」ではない——`checked` には数えられる）。
  今日そういう参照は 0 件で、広げる根拠が 1 件も無いので面積を増やさない。
  **重要なのは安全性の根拠の所在である**——`G-near` が本件で動かないのは「頭を共有しているから」
  ではなく「**`HEADING_REF` を import していないから**」である。次に `REF_HEAD` を触る者が
  前者を信じると、誤った安心を得る。
- **観測性の後退を作った。** 旧実装は「他の参照のラベルの内側に置かれた正準形参照」を独立に
  照合しており、それが失われる。**1 つではない**——外側の対象綴りが**有効**なときは
  **内側の `findings` がすべて消え**、**無効**なときは `checked` ごと消えて完全な沈黙になる
  （どちらも実測。入れ子の構造を持たない行は対照で不変を確認した）。後者は**本 ADR が消しに来た当の形の再生産**である。
  それでも受容するのは、露出が今日 0 件であり、塞ぐには 2 つの消費者が共有する新しい導出
  （弾いた外側のラベルを内側として再走査する）が要って、**その導出自身が `lib.mjs` の doc が
  警告する「片方だけ直す形」を作り直す**からである。無効綴りの頭を持つ一致は生きた母集団に
  現に在るので、露出は「起こりえない」ではなく「まだ書かれていない」である。
  死角の一覧の正本は `lib.mjs` の doc であり、fixture が形を固定している。
- **この変更自身の劣化を見張るのは `G-heading-refs.test.mjs` の fixture である。** 正規表現を
  元の形へ戻す変異を当てると、**入れ子の見出しを改名する赤の fixture が落ちる**。緑の fixture だけでは
  接地しない——一致が生成されなければ findings も 0 件になり、健全時と区別が付かないからである。
