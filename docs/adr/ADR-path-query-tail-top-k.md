# ADR-path-query-tail-top-k: パスクエリの裾のゲートを max から p90 へ改め、top-k の作り替えには踏み込まないことにした

2026-08-13、`#1070`（`#1067` から引き継いだ「実運用点で `c:\` の **max** が 1 フレーム
＝ 16,700 µs を下回る」）へ当てる手段を決めた。採ったのは
**incremental cache 用の全一致 index をパスクエリでは集めない**（C1）1 手だけである。
この ADR はそこで**却下した案・未測定のまま残した案・受け入れ条件そのものを改めた判断**の記録である。

**実測値の正本は `PERFORMANCE.md`「採用: パスクエリで再利用されえない候補を集めない」**であり、
ここには数字を最小限しか写さない（判断と、なぜ再訪しない／いつ再訪するかを残す）。

## 前提（測って分かっていたこと）

- 裾の帰属は本サイクルで初めて測った。`#1067` の ablation は **p50** の分解であり、しかも
  #1069（`sorted_prefix_len`）の適用**前**だった
- **C1 は本物だが、それだけでは max のゲートに届かない**（不足 1,600〜3,300 µs）
- **残る支配項は top-k 挿入である**。`c:\` は全件が同じ score（`3000 - 0`）で並び
  `last_launched` もほぼ全件 0 なので、`ScoredEntry::cmp` は毎回 `lower_name` の比較まで落ちる
- **max は同一機・同一構成の 4 回で ±20% 揺れる**（p50 は 3%）

## 判断: 受け入れ条件を max から p90 へ改める（2026-08-13 のユーザー決定）

`#1067` から**逐語で**引き継いだゲートは max だった。本サイクルの実測でこれを維持できないと判明し、
ユーザーが p90 へ改めることを決めた。**根拠は「届かなかったから」ではなく、次の 2 点である。**

1. **削るものを全部削ってもゲートを割りうる。** `local_matches` の収集と `top_k.push` を
   **両方殺し、検索結果が空になる天井**（`PERFORMANCE.md` の ablation 表の X2）ですら、
   max は 3 回中 1 回 16,700 を超えた。per-hit コストの削減で到達できる範囲の外にゲートが置かれている
2. **受け入れ条件が、最も不安定な統計量に乗っていた。** max は ±20% 揺れるので、同じ実装で
   合格と不合格の両方を引ける。**p90 は 3 回とも一致した向きを示す**（C1 適用で 1 フレームの内側）

**再訪する条件**: max を再びゲートに載せる決定が出たとき。そのときに最初に測るのは、下の
「未測定で残す候補」である。

### 境界ケースを「別セッションで取り直す」で解いた（**両セッションを残すことが条件**）

改めた p90 のゲートでも、**1 回目の交互測定は 3 本中 1 本が 68 µs（0.4%）超えた**。
判定規則は測定の**前に**書いてあり、「A が帯の内側で B だけ超えた → 不合格」「A 側も帯を超えて
膨れている → セッション不良・取り直し」の 2 つだった。**1 回目はどちらとも読める**——超過した
実行の直前の A は帯の内側だが、同じセッションの別の A（最初の 1 本）は帯の外だった。

**エージェントが自分で倒すと「緑が出るまで測る」になるので、ユーザーへ渡して取り直しを選んだ。**
2 回目は 3 本とも内側に入った。

**代償を打ち消す条件として、両方の実測を `PERFORMANCE.md` に残した。** 取り直しを選ぶ手続きは、
不利な標本が消える形で使うと検証を骨抜きにする。**残っていることだけが、この判断を後から検算
可能にする。**

## 却下: top-k の tie 比較を安くする 3 手（**「実装形が無い」とは書かない**）

`c:\` の top-200 は「312,208 件の `lower_name` のうち辞書順で最小の 200 件」そのものであり、
**これは定義上、全件を比較しないと決まらない。** その制約の下で検討した 3 手はどれも成立しない。

- **score の下限で枝刈りする**（`scored.score < worst_score` で即棄却）——
  **全件が同点なので発火しない**。パスマッチのスコアは `3000 - min(byte_pos, 500)` で、
  `c:\` は全キーの 0 バイト目で当たる
- **`k`（`result_limit`）を小さくする**——`docs/adr/ADR-sorted-prefix-over-reflagging.md`
  「却下 2」で**機能変更**と裁定済み。200 行はすべて UI へ渡りスクロールで到達できる。**再訪しない**
- **tie-break の規則を変える**——検索結果の順序が変わる。受け入れ条件「1 件も変わらない」に反する

**この 3 件は「検討した範囲」であって全称否定ではない。** 本サイクルの敵対的調査が
「**1 件ずつ heap へ push して都度フル比較する**というアルゴリズム自体を替える手を探索していない」と
指摘し、それは正しかった。その先は下の「未測定で残す候補」である。

## 未測定で残す候補（**捨てていない・再訪条件つき**）

**どれも `ScoredEntry::Ord` を変えないので、結果を保てる形でありうる。** 本サイクルで踏み込まなかった
理由は成立しないからではなく、**ユーザー決定で受け入れ条件が p90 へ移り、max を追うこと自体が
目的でなくなった**からである。

| 候補 | 何を替えるか | 未測定である点 |
|---|---|---|
| **バッチ選択** | 1 件ずつ heap へ push して都度フル比較する形をやめ、`select_nth_unstable_by` で上位 k を一括選択する | 全件ぶんの候補を実体化する費用（C1 で消したばかりの `Vec` が別の形で戻る）と、比較回数の削減が釣り合うか |
| **多段比較キー** | `(score, last_launched)` と `lower_name` の先頭数バイトを 1 語へ詰め、大半の比較を整数 1 回で決める | 詰めたキーの導出コストが per-hit に乗る。同点が先頭数バイトまで及ぶ実データの割合 |
| **rayon をより細かい分割へ** | `with_min_len` / task 粒度を**細かくする**方向 | C3 は**粗くする方向しか測っていない**（下の却下）。細かくする側は 1 度も測っていない |

**再訪する条件**: max を再びゲートに載せる決定が出たとき。

## 却下: rayon の task 粒度を粗くする（**対照行がゲート自体を超えた**）

fold の task 粒度を 24 分割へ寄せる変異（`PERFORMANCE.md` の ablation 表の X4）は `c:\` の min を下げるが、
**対照行が退行する**。生ログでは `\program files\` の max が **18,590**、`c:\users\` が 16,809、
`\zzz-no-such-path\` が 16,096 で、**issue が守れと言っている対照行のほうが 1 フレームを超えた。**
負荷分散が崩れて裾が伸びる向きであり、`c:\` だけを見ていると採ってしまう形である。

**再訪しない**（粗くする方向に限る。細かくする方向は上の未測定候補）。

## 却下: candidate index の `Vec` を実体化しない（C1 と区別できない）

C1 に加えて候補 index の `Vec` そのものを作らない変異（`PERFORMANCE.md` の ablation 表の X3）は、p50 も max も
**C1 単体と区別できなかった**（2 回の実行が C1 の帯の内側に収まる）。C1 で `push` を止めた時点で
その `Vec` は空のまま伸びないので、**削るものが残っていない**。

**再訪しない。**

## 判断: 安全性の論証を正規化器の挙動へ立脚させない

C1 が結果を変えないことは、次の形でだけ論証する——**収集を止めると `prev_candidates` が空になり、
`can_reuse` の `!is_empty()` が落ちて全件走査へ倒れる。全件走査は候補集合の上位集合ではなく
母集団そのものである。**

**却下したのはもう一つの論証経路である**: 「`has_path_sep`（生クエリ）と `norm_query_has_path_sep`
（正規化後）は外延的に一致するので、集めた候補を読む打鍵列は構成できない」。これは**今日は真である**
（敵対的調査が `nucleo-matcher` 0.3.1 の `src/chars/normalize.rs` を読み、`DATA1` の先頭が `U+00C0` で
`U+00A5`＝`¥` のエントリがどの表にも無いことを確認した）。しかし**外部クレートの版に依存する事実**であり、
安全性をここへ立脚させると**その挙動を永久に固定する義務**が生じる。

万一将来これが偽になっても、帰結は「再利用が成立しうる場面で全件走査へ倒れる」だけで、
**結果は変わらない。**
