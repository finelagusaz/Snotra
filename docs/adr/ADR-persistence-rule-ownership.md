# ADR-persistence-rule-ownership: 永続化の規則は snotra-core/CLAUDE.md、検証と失敗の型は /persistence-check が持つ

## 文脈

`/persistence-check` は「SSOT は `snotra-core/CLAUDE.md`「データ永続化の注意」」と宣言していたが、#1327 で CLAUDE.md の側を「編集の瞬間に守る指示」だけに縮めたため、宣言と中身の厚さが逆向きになった（#1328）。二つの面は届く時機が違う: CLAUDE.md は snotra-core を編集すると自動で注入され、スキルは起動されたときだけ読まれる。

## 決定

文書単位ではなく項目の役割で正本を分ける。規則（編集時に守る命令）は CLAUDE.md、満たしたかの検証の仕方と規則の根拠になった失敗の型はスキルが持ち、互いを指す。

## 検討した代替案と却下理由

- **スキルを丸ごと正本にし、CLAUDE.md はスキルを指す 1 行にする**: 却下。コードコメント（`config/tests.rs`・`indexer/cache/tests.rs`）と `PERFORMANCE.md` が「データ永続化の注意」を規則の出典として名指しており、節から規則が消えるとそれらが古くなる。さらに編集の瞬間に規則が届かなくなり、スキルを起動し忘れれば何も残らない。
- **CLAUDE.md を丸ごと正本にし、スキルは手順だけにする**: 却下。典型パターンやインシデント番号といった根拠の行き場が無くなる。CLAUDE.md へ戻せば、#1327 の「理由・経緯は書かない」に反する。
- **重複を許すと宣言だけ直す**: 却下。`AGENTS.md`「条件別チェック（トリガー → 参照先）」の「文書に事実の写しを増やす変更」に反する。実際、写しの側で 3 つ古くなっていた（見出しの誤り・IndexCache の項目要約の欠落・誤ったインシデント番号）。

## 帰結

- スキルから CLAUDE.md の規則を指すときは、``` フェンスの外に正準形で書く。フェンスの内側は `governance:check` の G-heading-refs に照合されず、#1328 以前の見出しの誤りはそこで緑のまま残っていた。
