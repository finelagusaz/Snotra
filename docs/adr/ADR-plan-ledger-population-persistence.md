# ADR-plan-ledger-population-persistence: 照合の母集団をファイルへ移すとき、契約の広い読みと 3 つの代替を却下した

`npm run plan:ledger -- verify` は照合の母集団を**呼び出し側が打ち直したスラグ**から再導出しており、`init --slug a --slug b` の後に `verify --slug a` を打つと母集団が黙って縮んだまま緑になった（#831）。`init` が母集団を `workspace/plan-review/ledger.json` へ書き、`verify` が引数を取らずにそれを読む形へ移した。**この ADR が残すのは、そのとき却下した読みと案である**——採った形はコードと `.claude/skills/plan-review/SKILL.md` が持つ。

## 文脈

`scripts/plan-review-ledger.mjs` の契約は「**呼び出し側が渡した内容を、このスクリプトは決して書かない**」だった。これは `/plan-review` のオーケストレーターが `Write` を持たない理由（返り値で受けた内容を成果物ファイルへ転記でき、実在確認も中身の検査も自作自演で通る）と対になっている。母集団をファイルへ書く案は、この一文の字面に触れる。

issue #831 自身が「**どちらを採るかが決定の中身であり、決めずに実装すると契約が黙って緩む**」と名指ししていた。

## 却下 1: 「スラグも呼び出し側が渡した内容だから書けない」という読み（＝穴を塞がない）

**これが本サイクルで最も価値のある否定の知識である。**

この読みを採ると #831 は塞げない。しかし契約が守ろうとしているのは「バイト列を預かって書き戻すこと」であって、識別子を書くことではない。区別は**書いたものが何の証拠になるか**にある——成果物ファイルは「レビューが行われた」ことの証拠であり、偽造されると検査そのものが無効になる。台帳は「何を検査すべきか」の宣言であって、縮めても残った成果物が命名逸脱として不着に落ちる（`classifyEntries` の双方向照合）。**偽造しても緑にならないものは、契約が守る対象ではない。**

加えて `docs/check-skill-skeleton-design.md`「必須 1 — 母集団」が既にこの軸で結論を出していた: 「母集団を得る手順が決定的でないなら、その検査は結論を持たない」、そして**列挙アンカーは「この型を母集団に採らない」**。会話上の列挙から母集団を取る旧実装は、規範上すでに非推奨の型だった。#831 はその実例である。

## 却下 2: 台帳を `workspace/plan-review/` の外へ置く

ディレクトリ外なら `init` の `rmSync` の射程を外れる。**却下**——外に置くと「母集団を書き換える唯一の口が `init`」という性質が消える。同居していれば、台帳を縮める操作は全成果物を消す `init` を通るか、手で書き換えて命名逸脱を出すかのどちらかになり、**どちらも赤くなる**。さらに `.claude/skills/start-issue/SKILL.md`「収束判定に要る状態はすべて `plan.md` に置く」が偽になる（持続する面が 2 つになる）。

## 却下 3: 時刻・mtime による staleness ガード

「`init` を打たずに `verify` だけ走らせると、前ラウンドの台帳と成果物が対で残って緑になりうる」という残余を、タイムスタンプで塞ぐ案。**却下**——スクリプトが冒頭で宣言している「決定的（ネットワーク・時刻に非依存）」を破る。ラウンド番号を台帳へ持たせる変種も、上記「収束判定に要る状態はすべて `plan.md` に置く」と衝突する。**残余として受容する。**

## 却下 4: `SKILL.md` のフェンス行を抽出して `parseArgs` に食わせるテスト

変更が必要な唯一の呼び出し文字列（`SKILL.md` の `verify` 行）には静的検出器が無い——`selectChecks` は `scripts/*.mjs` にも `.claude/skills/**` にも検査を割り当てず（実行して確認）、コードフェンス内ゆえ `G-references` の視界にも入らない。そこで規範の文字列に検出器を付ける案を立てた。

**却下**——計画に書いた抽出を**実装前に実データへ当てて破れた**。現行のフェンス行は末尾にプレースホルダ `...` を持ち、`parseArgs` は `{"error":"未知の引数: ..."}` を返す。通すにはプレースホルダを剥がす脆い正規表現を書くか、テストを通すために SKILL.md の散文を書き換えるかになり、後者は本末転倒である。

**決め手は、この検査が守る失敗が沈黙しないことだった**——`verify --slug` が残っていれば実行時に exit 2 と復帰手順が出る。#802 → #803 の沈黙バグとは性質が違い、検出器の不在を受容できる。

## 却下 5: `verify` が受け取った `--slug` を黙って無視する

拒否ではなく無視すれば後方互換になる。**却下**——古い手癖・古い写し・古いトランスクリプトが沈黙で通り、#831 の穴が「引数が効かないだけ」の形で生き延びる。`AGENTS.md`「検証の作法（全タスク共通）」の「これまで無意味だった状態に意味を与える変更は、その状態に到達する全経路を列挙する」と同じ理由で、**意味を持たなくなった入力は拒否して復帰手順を出す**。

## 帰結

- exit は 3 値になった: `0` 全件実在 / `1` 母集団に対する不着 / `2` 母集団を得られない。**`1` と `2` は行き先が違う**（再起動 / `init` からやり直し）ため、`.claude/skills/plan-review/SKILL.md`「Step 3 — 結果の統合と報告」に両方の行き先を書いた
- `/plan-review` の `allowed-tools` が `Write` を持たないことは、**成果物の偽造に加えて母集団の偽造も防ぐ**という 2 つ目の職務を負った。`Bash` を広げる編集はこの職務を黙って外す
- **受容する残余 2 件**: (a) 台帳の改竄と成果物削除の同時実行は塞がらない（スカウトは全ツール型ゆえプロンプト契約でしか縛れない・構造では表現不能）、(b) `init` を打たないセッション再開（却下 3）
- **`.claude/rules/safety-nets.md` の `paths` は `scripts/plan-review-ledger.mjs` を含まない**ため、次にこのスクリプトだけを直す人にフォールトインジェクション義務が配送されない。`paths` の変更はエージェント設定であり、本 PR の射程に入れずユーザーの判断へ回した
  - **2026-08-02 追記**: この残余は #837（`555cf7c`・2026-07-29＝本 ADR と同日）で解消している。「ユーザーの判断へ回した」当の裁定が「glob で足す」となり、`safety-nets.md` / `governance-docs.md` の両方が `scripts/governance-check.mjs` の名指しから `scripts/*.mjs` へ広がった——`plan-review-ledger.mjs` にもマッチするので、フォールトインジェクション義務は**配送される**。**上の記述は決定当時の事実であり書き換えない**（ADR の目的は当時の文脈を残すことである）
