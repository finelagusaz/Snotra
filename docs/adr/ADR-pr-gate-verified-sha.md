# ADR-pr-gate-verified-sha: PR 前ゲートは道具の要約だけを照合し、例外を設けない

## 文脈

`/implement` 3c は「Step を出るのは、いま HEAD にある差分がトリガーする検査をすべて通ったとき」と定めるが、照合は散文にしか無かった。最終巡のあとにコード変更が載ったまま PR になった例は、#1299 の起票時点で 9 件あった。#1302 自身も、最終巡のアンカーのあとに ADR の追記とコードの修正が載っている。

採った形の全文は `.claude/hooks/pre-bash.mjs` の `readVerifyState` / `judgeSummary` と `docs/hooks.md` の「要約ゲート」が持つ。**この ADR が残すのは却下した案である。** 次の 3 点は、2026-10-25 にユーザーが裁定した。

## 検討した代替案と却下理由

- **委譲のレビューが見た sha も照合する**: 却下（裁定）。委譲先の `align` が名乗る sha を記録する一手が要り、その一手を打ち忘れると、ゲートは記録の無いブランチとして扱うことになる。照合を道具の A〜F に限れば、記録は道具が自動で書く。
- **「手直しが小さいので再検証しない」を、理由の記録つきで例外にする**（issue の当初案の 3 項目目）: 却下（裁定）。道具の回し直しは warm の木で、E と F だけなら数十秒で済む。例外の口を開けると、何が「小さい」かを判断する場所がまた散文に戻る。記録の置き場として挙げた `workspace/plan.md` は、`/implement` Step 4 が PR を作る前に撤去するので、そもそも使えない。
- **要約の無いブランチは管轄外として通す**: 却下（裁定）。`/implement` で道具を回し忘れたとき、黙って通ってしまう。止める代わりに、`/deps-update` にも道具を回す手順を足した。
- **`docs/adr/` を除外のパスに足す**（`/implement` Step 4 の ADR の回収コミットが、最後の要約のあとに載るため）: 却下。例外の追加と同じである。代わりに Step 4 の順序を、ADR の回収 → 道具の回し直し → 木の片づけ → `workspace/` の撤去、に改めた。
- **`gh pr create` の検出を広げ、`gh.exe pr create`・`& '<path>/gh.exe' pr create`・`gh api …/pulls` も拾う**: 却下。検出の正規表現は push ゲートと plan.md ゲートも共有しており、この issue より広い面を動かす。「見ないコマンド形」として `docs/hooks.md` と hook の冒頭コメントに明記した。
- **要約の置き場の導出を hook の中に写し、道具との一致をテストで縛る**（独立レビューの推奨）: 却下。静的 import が失敗すると exit 1 で素通りするのはそのとおりである（独立レビューの実測）。ただ、`main()` を async にして `gh pr create` の検出後だけ動的 import し、失敗を reader の `{ ok: false }` で受ければ、写しを持つ理由が無くなる。
- **`decide` を位置引数のまま 5 本目を足す**: 却下。省略可能な `platform` の後ろに穴が開く。`ADR-command-shape-norms-in-hook` の「5 本目を足すときに再検討する」の予告どおり、options オブジェクトへ改めた。書き換えの前後で既存テストは 188 件 → 188 件、すべて緑であることを測ってから、新しい照合を足した。

## 受容した残余

- **要約は自己申告である。** `categories_run` が変更に見合っているかは見ない。要約を手で書けば通る——このゲートが防ぐのは事故であって改竄ではない。
- **PR を作ったあとに足したコミットは射程外である**（#1302 の Windows 向けの修正の形）。照合は `gh pr create` の時点だけで走る。
- **`--out` で既定の置き場の外へ出した要約は見ない。**
- **`gh pr create --head <別ブランチ>` は、今のブランチの要約で照合する。**
- **要約を消す側は置かない。** `verify-tree remove` は木とログを消し、要約（1 KB 前後の gitignore 済みの JSON）を残す。
- **rebase や main の取り込みのあとは、取り込んだ変更が `workspace/` の外を動かしていれば止まる。** 比べるのは 2 端点の木なので、メッセージだけを変える rebase や、`workspace/` の外を動かさない取り込みでは止まらない。止まるのは fail-closed の向きで、復帰は道具の回し直しである。
- **引数に `gh pr create` を含むだけのコマンド（grep など）も、要約が無ければ止まる。** 引用の内側を解釈しない設計（過剰検出は許容）のままにした。
- **linked worktree のセッションからは、道具を回せないので復帰できない。** PR は本体の作業ツリーから作る。
