# ADR-race-boundaries-git-plumbing: race:boundaries の追跡差分を plumbing で取り、patch の名前を -z の一覧と照合する

## 文脈

`scripts/race-boundaries.mjs` は追跡ファイルの差分行を porcelain の `git diff -U0 <mergeBase>` から解いていた。#1300 の作業中に、本物の git に設定を 1 つずつ注入した一時リポジトリ（日本語名ファイル・サブディレクトリ実行）で測ると、`core.quotePath=true`（git の既定）・`diff.relative`・`diff.mnemonicPrefix`・`diff.noprefix`・`color.ui=always`・`diff.external` の 6 形とも行が黙って落ち、多くは exit 0 で報告した。開発機の `~/.gitconfig` が `quotepath false` だったため表に出ず、fake と手書き diff のテストは git の実際を見ていなかった。

## 決定

追跡差分は `git -c core.quotePath=false diff-index -M -p -U0` で取る。patch から解いたファイル名がすべて `diff-index -M --name-only -z` の一覧にあることを確かめ、無ければ exit 3。hunk の本文は `@@` が宣言した行数だけ読む。削除されたファイルの行は `--- a/<path>` に帰属させ、入れるかは `--include-removed` だけが決める。本物の git に 6 設定を注入するテストを置く（global / system の設定は外して git の既定から始める）。

## 検討した代替案と却下理由

- **porcelain のまま、形を変える設定を引数で 1 つずつ打ち消す**（`--no-color --no-ext-diff --no-relative --src-prefix=a/ --dst-prefix=b/`）: 却下。塞いだ設定の列挙は git の版や新しい設定で古びる。plumbing は測った 6 形のうち quotePath 以外を性質として無視する。
- **git の設定を環境変数で隔離する**（`GIT_CONFIG_GLOBAL=/dev/null` + `GIT_CONFIG_NOSYSTEM=1`）: 却下。リポジトリ local の設定は残るうえ、global に置いた `safe.directory` も消え、所有者の異なるリポジトリでは git が拒む（git の仕様。この形は測っていない。テストでの隔離は、一時リポジトリが自分の所有ゆえ当たらない）。
- **numstat の追加・削除行数まで照合し、バイナリ扱いのソース（`-diff` 属性など）も止める**（一時期の実装）: 却下。照合の端のケース（削除されたファイル・削除されたバイナリ・`--include-removed` との相互作用・壊れた hunk）を塞ぐ部品が委譲レビューの巡ごとに増え、コードは 1.6 倍・テストは 2.7 倍になった。守った事態はこのリポジトリで起きていない（`-diff` 0 件・バイナリのソース 0 本・git は壊れた hunk を出さない）。観測した壊れ方はどれも名前が化ける形であり、名前の照合で止まる。`race:boundaries` は「手がかりは入口であって網羅ではない」と自ら書く grep の前段であり、行数の完全一致はその保証の水準を超えていた（ユーザーと合意）。
- **hunk の本文を接頭辞（`+++ ` / `--- `）で見分け続ける**: 却下。`++ ` で始まる追加行は patch で `+++ …` になり、ファイル名が切り替わった。`-- ` で始まる削除行も同じ形で落ちる。どちらも委譲レビューが本物の git で実測。
- **名前の照合の相手を porcelain の `git diff --name-only -z` にする**: 却下。`diff.relative` で patch と同じだけ狭まり、黙って一致した（`--numstat` で実測）。2 経路は同じ設定に引きずられないときだけ独立である。
- **`-M` を付けない**（rename を削除と追加に分ける）: 却下。移動しただけのファイルの全行が母集団へ入る。`-M` 付きの新から削除されたファイルの行を除くと、旧 `git diff -U0` と、このリポジトリの 4 基準（`main`〜`main~600`・作業ツリーを含む）で行の集合が完全一致した。
- **削除されたファイルの行を捨て続ける**（#806 の導入時からの形）: 却下。`--include-removed` は廃止の検査のための指定なのに、ファイルごと消した worker が映らず、削除だけのブランチは空の母集団として「基準が誤っている」と誤診された（セルフレビューが実測）。理由の記録は見つからなかった。

## 帰結

- patch の名前が化けると、母集団を欠いた報告の代わりに exit 3 と化けた名前が出る。quotePath を外しても `"` `\` 制御文字を含むパスは quote されたままであり、その形もここで止まる（Windows では作れないので本物の git では測っていない）。
- バイナリ扱いのソースの行は、以前と同じく黙って母集団に入らない。
- 空の母集団の判定（「基準が誤っている」）は、行の数ではなく変更されたファイルの数で行う。バイナリを消しただけ・中身の変わらない rename だけのブランチは行を生まない。
- `--include-removed` の母集団に、削除されたファイルの行が加わる（4 基準で最大 6978 行。既定の母集団は変わらない）。
