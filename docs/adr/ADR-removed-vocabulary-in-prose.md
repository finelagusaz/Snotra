# ADR-removed-vocabulary-in-prose: 撤去済み語彙が散文に残ったとき、遡及書き換え・注記の過去形化・検知器の新設を却下した

#1023（`ae3335df`）が背景再スキャンごと撤去した語彙が `PERFORMANCE.md` と `src-tauri/src/startup.rs` の散文に残っていた（#1180）。**この ADR が残すのは、そのとき却下した 3 案である**——採った振り分けと、直した 3 箇所の理由はコミット `f2ac33de` と `PERFORMANCE.md` の当該注記が持つ。

## 文脈

`digest_ms` は撤去済みのフィールドだが、散文には残る。**害は「読んだ人が実在しないフィールドを探す」ことである。**

振り分けは「その文を読んだ人が、その識別子を**今このリポジトリに在るもの**として探しに行くか」の 1 つに還元した。材料は 3 つ（時制 / 文中の役割が指示的か引き合いか / 直近に撤去注記が在るか）で、いずれも機械的に確かめられる。#1023 が撤去した語彙の全件へ当てた結果は「直す 3 件・直さない 8 群」だった。

**数え上げは手選びを挟むと落ちる。** 初稿は削除行から語を機械抽出しておきながら「主要語彙」を手で選んで grep に掛け、抽出済みの `measure_raw_path_rebuild_cost_over_real_index` を落とした（敵対的レビューが発見）。**誤りは「決め打ちのリスト」ではなく「機械抽出の後に手選びを挟んだこと」である。** その 1 件は最も害が大きい箇所でもあった——同じ表の 1 行上の計器が**現存する**ため、読者は 1 行目を検算できてしまい、2 行目が見つからないのを自分の探し方のせいだと思う。

## 検討した代替案と却下理由

### 却下 1: 撤去も改名と同じく遡及して反映する

`PERFORMANCE.md` は歴史記録の中の識別子を**遡及して書き換えた実績を持つ**——`1a405180` / `46386da6`（#1181 / #1182）が `total_ms` → `total`・`scan_ms` → `scan`・`cache_load_ms` → `cache_load`・`cache_read_ms` → `cache_read` を直している。「同じ扱いを撤去へも」は自然な類推に見える。

**却下した。改名の遡及反映が正当なのは指示対象が保たれるからである**——`total_ms` と `total` は同じものを指す。撤去にはその保証が無く、`digest_ms` に「現在の正しい名前」は存在しない。書き換え先が無いので、選べるのは (i) 注記を追記する (ii) 現在形をやめて散文化する (iii) 何もしない の 3 つだけである。

**この非対称には同じコミットの隣り合う行に一次証拠が在る。** `46386da6` は `digest_ms` の 1 行手前で `cache_load_ms` → `cache_load` を書き換え、`digest_ms` の直後に新しい注記文を追記しながら、`digest_ms` だけを素通りした。改名には遷移先の名前が在るので機械的に直せたが、撤去には無いので手が止まっている。

なお **#1027 に「散文へ改名を遡及反映する」という明文の裁定は無い**（実装 issue であり、受け入れ条件はコード変更と doc 反映のみ）。「裁定」の実体は上記 2 コミットの**観測された挙動**である。

### 却下 2: 腐った注記を過去形へ倒す（書き換える）

`PERFORMANCE.md` の「後日（#996）」注記は「残る 2 者は今もフルパスを要求する」と現在形で言うが、その 2 者（`entries_equal` / `try_background_rescan`）は #1001 で撤去済みである。**注記のほうが腐っている**ので、現在形を過去形へ倒すのが直接の解に見える。

**却下した。#996 の時点でこの注記は真だった**（当時 2 者は実在した）。過去形へ倒せば、**日付を持つスナップショットを偽にする**。同文書が撤去済み語彙に対して確立している作法は 6 例すべてが**追記**であり（`:70-72`, `:176`, `:1943`, `:1972`, `:2224`, `:2293`）、原文を書き換えたものは 1 件も無い。**兄弟の「後日（#1001）」注記を隣に置く**形を採った。

**結論そのものは生き残ったが、支える根拠が入れ替わっていた**——「`target_path` を落としても再構築が要る」を今要求するのは、同じ節の「再構築は 2 種類要る」が名指す消費者のほうである（実測で現存を確認）。**所見が正しくても、添えられた機序は独立に腐りうる。**

### 却下 3: 再発防止の検知器を新設する（`G-stale-identifiers` の母集団を広げる）

`PERFORMANCE.md` も `.rs` のコメントも `G-stale-identifiers` の母集団外なので、この腐りは構造的に射程の外にある。母集団を広げれば捕まえられる。

**却下した。** 理由は 3 つあり、いずれも一次資料で確認した。

- `.claude/rules/governance-docs.md`「書く約束」(3)「**古い情報を残さない——触った節の隣にある主張が今も真か見る**」が既にこの形を名指している。#1182 はその規範を守り損ねたのであって、規範が無かったのではない。**規範を 2 枚目へ書くのは `AGENTS.md`「文書に事実の写しを増やす変更」に当たる。**
- `ADR-measurement-record-provenance` が「**`PERFORMANCE.md` を `governanceDocs` へ足さない。穴は開いたまま残る**」と機構の不在を既に受容している。ここで足せばその決定を黙って覆すことになる。
- `AGENTS.md`「ガバナンス機構**自身**の配置を変える」の行が「**足す前に『壊れたとき緑が緑のまま推移するか』を問う——推移しないなら置かない**」と言う。ここは気づく契機（1 つ目の規範）が残るので、機構ではなく引き金で足りる。

**射程を広げた版を実データへ当てていない点は、この却下の弱いところである。** #992 では「述語がこの形の折れを見ない」という所見も機序も正しかったのに、射程を広げた版を当てると実ツリーの 7 行すべてが誤検出になった。**指摘の正しさは修正の正しさを含意しない**ので、将来この案を再検討するなら、まず広げた述語を現行コーパスへ当てて偽陽性を数えること（`ADR-stale-identifier-detector-scope` の表がその測り方の先例である）。

## 帰結

- **この修正を守る機構は存在しない。フォールトインジェクションで実測した**——`PERFORMANCE.md` へ実在しない識別子 `` `totally_fake_identifier_xyz` `` を書いても `governance:check` は緑のまま通り、「散文の識別子 421 件を 34 文書から照合」の計数も動かない（コードスパンの計数だけが 1 増える）。**スパンとしては見えているが実在は問われていない。** 対照として、コードスパンの行またぎと着地しない見出し参照はどちらも赤になる。
- **`src-tauri/src/startup.rs` の `digest_ms` は直していない**（人間が承認した受容する残余）。過去形の引き合いであり、「反復 6 が `digest_ms` を足して隙間を塞いだ」という文は永久に真である。
- **散文形の参照は誰も検算しない。** 「同じ節の『再構築は 2 種類要る』」は参照先が見出しではなく太字の散文なので正準形にできず、変異注入でも緑のままだった（`.claude/rules/governance-docs.md` が既知の残余クラスとして明示している）。
- **同じクラスの再発は、この振り分けを再実行すれば数え上げられる**——`git show <撤去コミット> -- '*.rs'` の削除行から機械抽出し、**手選びを挟まずに**現存判定と生きた層への照合を掛ける。散文の語（「背景再スキャン」等）は定義行を持たず抽出に乗らないので、別に走査する必要がある。
