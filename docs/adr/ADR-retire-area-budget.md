# ADR-retire-area-budget: 面積の上限判定を廃し、数字をゲートから計器へ格下げする

日付: 2026-08-11 ／ 状態: 承認

## 決定

恒久規範の面積について、**合否の判定を持たない**。

1. `AREA_BUDGET` と上限比較を廃止する。検査 `G-area-budget` は `G-area-instrument` へ改め、**母集団の欠落（入力が読めない・空）だけ**を判定する
2. 実測値は `governance:check` の成功行が報告し続ける（`恒久規範 常時ロード N 字・rules N 字`）。推移は git 履歴が持つ
3. 一次規範は `ADR-doc-promise-over-area-ratchet` のまま——「書く約束」（かぶりなく・必要なことだけ・古い情報を残さない）

## 経緯（実測）

`ADR-doc-promise-over-area-ratchet` は完全撤去を「保留（様子見）——火災報知器としての運用を 1〜2 サイクル見てから再判断する」とした。その様子見の結果が出た。

| 期 | 発火 | 内訳 |
|---|---|---|
| ±100 字 ratchet（〜2026-08-03） | 3 件 | #894 の実績調査で**全て正当な追記**・欠陥検出 0 |
| 火災報知器（2026-08-04〜08-11・30 コミット） | **0 件** | その間に両面が **+30%**（常時ロード 11961 → 15006・rules 9253 → 11654） |

**通算 4 観測点で、欠陥を指した発火はゼロである。** 火災報知器期に鳴らなかったのは肥大が無かったからではなく、閾値（実測の 1.3 倍）が 7 日ぶんの正当な蓄積より上に置かれていたためで、`ADR-doc-promise-over-area-ratchet` 自身が受容残余に書いた「上限までの間の漸進的な肥大は機構では捕まらない」が実際に起きた。残り余白は 494 字と 346 字（約 1 日ぶん）で、**次の発火は 4 度目の「正当な追記への発火」になる公算が高い。**

副作用も観測された。数字に押された書き手は「洗う」より**上限の無い面へ逃がす**方を選ぶ。`docs/development-principles.md` は 28,278 字まで肥大し（本文の 53% が 2 節・条項の平均 321 字・最長 1,389 字）、面積ではなく**到達性**が壊れた。`docs/` を課税面から外したのは意図的だが（「登ってほしい階梯を登る側が罰せられる」）、退去先が読めるままかを見る手段は誰も持っていなかった。

前提の変化は `ADR-doc-promise-over-area-ratchet` が既に記録している——「書く約束」3 観点のうち 2 つは機構が受けている（「古い情報」は G-stale-identifiers と G-heading-refs、「かぶり」は SSOT 規範と写しの数え上げ）。数字が独自に守るのは暴走検知だけで、それが 0/4 である。

## 却下した代替案

1. **再較正（現実測の 1.3 倍へ引き上げる）**: 却下。8 日で消費された余白をもう一度積むだけで、次の 8 日後に同じ判断へ戻る。`ADR-doc-promise-over-area-ratchet` が逃れようとした ratchet の周期を伸ばす操作にすぎない
2. **据え置いて鳴らせる（設計どおりの応答＝3 観点で洗う）**: 却下。過去 3 発火が全て正当だった以上 4 度目も同じで、そのとき人は洗うより逃がす方を選ぶ——上の副作用の再生産である
3. **完全撤去（計器も母集団判定も消す）**: 却下。合否を持たない道具でも、**読めない入力の上で出した数字は静かに誤り、判定が無いぶん誰も気づかない**（`check:colors` がロック画面を撮る形と同型）。母集団の欠落だけは判定に残す
4. **計器を `/health-check` へ移す**: 却下。既に測っている場所から数字を動かすと新しい配線が要り、見る頻度も落ちる。`check:input-metrics` と同じく「既にある場所で値を出し、合否は言わない」形を採る

## 帰結

- 面積を理由に PR が止まることは無くなる。**書き手は数字と交渉しない**
- 漸進的な肥大を捕まえる機構は無い。受け皿は「書く約束」・レビュー・`/health-check` の意味判断であり、これが本 ADR の引き受けるトレードオフである（`ADR-doc-promise-over-area-ratchet` の残余をそのまま継承する）
- 部分的に覆される先行 ADR: `ADR-doc-promise-over-area-ratchet`（火災報知器としての上限）・`ADR-doc-minimization-cap-enforcement`（cap の常時強制）・`ADR-area-metric-characters` の運用節。**指標そのもの（文字数・二面独立・description 算入）は計器として引き継ぐ**。旧 ADR は凍結ゆえ編集しない（`ADR-adr-frozen-history`）
- 廃止が戻ったことを検知する対照テストを 2 本置く（常時ロード面と rules 面がいくら大きくても finding を出さない）。上限判定を復活させればこの 2 本が落ちる
