# ADR-risk-tiered-plan-review: 計画レビューを常時fan-outしない

## 却下した案

### すべてのissueでレイヤー別スカウトと独立導出を起動する

却下する。#713 の実測では初回4体で約52万トークン、典型2ラウンドで約80万トークンを要した。直近サイクルでは3ラウンド目の指摘4件が計画の説明訂正に留まり、別の独立導出は参照できない添付画像を欠いたまま逆の結論を出した。レビューの配送成立は測れても、追加エージェントが実装判断を改善した量は測れていなかった。

### 計画が動くたびに全体を再導出する

却下する。同じissueからの再導出は非決定性の再抽選になるが、1回約18万トークンの費用に対する停止条件が「計画の任意の文字列が動いたか」では広すぎる。説明文の訂正と、要件・対象ファイル・インターフェース・不変条件・テスト期待値の変更を同じ再レビュー条件にしない。

### 独立レビューをすべて廃止する

却下する。網羅性が要件の変更、永続化、並行性、状態遷移、セーフティネットでは、作者と同じ分解だけでは盲点を共有する。通常リスクでは主エージェントの自己レビューに留め、高リスクでは観点を限定した1体を使う。

### 計画の承認をエージェントだけで完結させる

却下する。製品優先度・許容するトレードオフ・スコープはコードから再導出できない。元になった注釈型ワークフローの人間レビューを、同じモデル群の票数で代替しない。
