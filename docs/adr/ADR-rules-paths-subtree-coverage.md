# ADR-rules-paths-subtree-coverage: rules の `paths` は部分木ごと覆い、被覆はファイル側から検める

## 文脈

`.claude/rules/` の 2 本（`safety-nets.md` / `governance-docs.md`）の `paths` は `scripts/*.mjs` を持っていたが、
`*` は `/` を跨がない。#1088/#1093 の per-check 分割で `governance:check` の判定がディレクトリごと
`scripts/governance/` へ移った結果、**判定そのものを編集してもルールが配送されない**状態になった（#1143）。

これは #837 が塞いだ穴の再発である。ただし #837 が予見した形（スクリプトが 1 本増える）ではなく、
**ディレクトリが増えた**形だった。`scripts/*.mjs` は facade（`scripts/governance-check.mjs`）に今も当たるため、
**既存の `G-rules-globs`（マッチ 0 件の検知）は緑のまま**で、glob は壊れて見えなかった。#837 自身が
「その漏れを検出する機構は無い」と書いており、実際に無いまま再発した。

## 決定

1. **`paths` は部分木ごと覆う** — `scripts/*.mjs` / `scripts/*.ps1` / `scripts/lib/**` の 3 行を `scripts/**` 1 行へ畳む。
2. **被覆はファイル側から検める** — 新規検査 `G-rules-script-coverage` を置き、実在するスクリプト
   （`.mjs` / `.ps1` / `.psm1`）が rule の `paths` に覆われているかを判定する（`G-rules-globs` の逆向き）。

## 検討した代替案と却下理由

- **`scripts/governance/**` を 1 行足す（ディレクトリごとに足す）**: 却下。#837 が「1 件ずつ足す形では次に
  増えたとき再発する」と書いた形の、ディレクトリ版の反復にすぎない。判定関数へ直接問うた実測で、
  `scripts/**` は現行 3 glob の和の**真の上位集合**であり、**失うものが 0 件**（元の 3 glob が覆っていて
  `scripts/**` が覆わないファイルは存在しない）と分かったため、畳まない理由が無い。
  増える側の内訳はここに書かない——`scripts/` に何が在るかは動くので、書けば足すたびに腐る。
- **import 閉包（覆われたファイルの import 先も覆われていること）**: 却下。**このリポジトリの肝心な 2 辺を
  どちらも見ない** — hook から判定スクリプトへの辺は構成した文字列の `spawn` であり（静的 import は
  `post-edit.test.mjs` が「足すと全編集で hook が沈黙する」として禁じている）、`registry.mjs` から各検査への辺は
  `readdirSync` + 動的 `import()` である。静的な辺が無い所に閉包は張れない。
- **「深さ」形の検出器**（単一 `*` のパターンについて、同じディレクトリの深部に取りこぼしがあれば赤くする）:
  却下。**パターンが 1 本も無い相手を見ない** — 判定コードが新しいトップレベルへ出た場合、「浅すぎる glob」が
  存在しないので沈黙する。加えて、判定に手で維持するアンカー列挙を要する。ファイル側から見る形にはどちらの
  欠点も無い。ただし**発火件数が少なく読みやすい**という利点はこちらにあり、被覆形はその読みにくさ
  （再発時に未被覆を全件名指す）を引き受けている。
- **既存の `G-rules-globs` を拡張する（検査を増やさない）**: 却下。1 検査 1 ファイル（#1093）に反し、
  失敗の意味も違う（死んだ glob と、未被覆のファイルは別の事故である）。
- **検出器を置かず、死角として宣言する**: 却下。#837 が実際にその形で終えて再発した。今回は被覆形が
  実装可能と実測できたので、宣言で済ませる理由が無い。

## 帰結

- **誤配送を 1 件受け入れた** — `scripts/run-codex.sh` は `.sh` ゆえ従来どの glob にも当たらなかったが、
  `scripts/**` には当たる。#837 が `clean-worktrees.mjs` について引き受けたのと同型のトレードオフである。
- **`globToRegex` と `rulePathPatterns` は `lib.mjs` へ移った** — 2 検査が共有するため（同ファイル冒頭の掲載条件）。
  写しにすると glob の意味論が検査ごとに独立に腐る。
- **検査が言えるのは documented な glob 意味論での被覆までである** — harness が実際に配送するかは見ない。
  射程と死角の一覧は `scripts/governance/checks/G-rules-script-coverage.mjs` の `//!` が正本。
- **メインセッションの配送を対象にした保証である** — サブエージェントへの配送は 2 体で挙動が割れており
  （予算消費でも Read/Bash の取り違えでも説明が付かない）、機序は未解明のまま残る。`paths` を広げても
  委譲先へ届くとは限らない。
