# ADR-show-foreground-masked-alt: 表示時の前面化は tao の set_focus を置き換え、拒まれたら常にマスクした Alt で再試行する

## 文脈

#1470。tao 0.37.2 の `set_focus` は、`SetForegroundWindow` を拒まれるとマスクなしの Alt を注入して再試行する。まだ前面にいる元のアプリがその Alt を単独の Alt として受け、メニューを起動していた。

前面化が拒まれるのは、Alt を離してから前面が移るまでの間に、打鍵が元のアプリへ落ちたときである。起動して最初の表示で起きやすい。

## 決定

1. Windows では、`show_egui_main` の前面化を tao の `set_focus` から自前の関数へ**置き換える**。
2. 前面化を拒まれたら、vkE8 で包んだ Alt を注入して 1 回だけ再試行する。**修飾キーが押されていても注入を省かない。**

## 検討した代替案と却下理由

- **tao の `set_focus` を残し、その前に自前の前面化を置く**: 却下。自前の再試行も拒まれると、続く tao の `set_focus` がマスクなしの Alt を注入する。直したいメニュー起動の経路が残る。
- **修飾キー（Alt・Ctrl・Shift・Win）の押下中は注入を省く**: 却下（実測による）。
  - 検討の発端は 2 つの懸念である。注入した Alt up が、押されている Alt を論理的に離す。Shift との組で入力言語の切り替えを踏みうる。
  - 2026-11-17 に比べた（release・各 3 起動）。Alt+Q を離して 5 ms 後に Shift と A を押し、Shift を押したまま前面化を拒ませた。
  - 注入する版は 3/3 で前面化に成功した。元のアプリのメニュー起動も、入力言語の切り替え要求（`WM_INPUTLANGCHANGEREQUEST`）も 0 件だった。
  - 省く版は前面化を諦める。置き換えた後では、最前面に見えるのに前面でないウィンドウが残り、打鍵が元のアプリへ流れ続ける。この害のほうが大きい。
- **Alt の押下中だけ注入を省く**: 却下。Alt を論理的に離す害（その後の打鍵が Alt なしになる）より、前面にならないウィンドウが残る害のほうが大きい。置き換え前の tao の注入も、同じ Alt up を送っていた。

## 帰結

- 置き換えた後も、前面化より前に打った文字は元のアプリへ落ちる（Snotra は前面になる前に入力を受け取れない）。初回の表示が遅いことも残る（#1472）。どちらも #1470 の範囲外である。
- マスクした Alt は、実在のアプリでも Alt の押下による表示を残さなかった。
  - 2026-11-17 に測った。Word・メモ帳・VS Code・Edge・エクスプローラーを前面に置き、注入の前後でウィンドウの画像とフォーカスを比べた（各 3 回）。
  - tao と同じ素の Alt では、全アプリで 3/3 変化した。Word とメモ帳はキーヒントを出し、VS Code はメニューの File に、Edge とエクスプローラーはボタンにフォーカスを移した。
  - マスクした Alt では 15/15 で、何もしない対照と同じだった。
