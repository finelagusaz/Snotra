# ADR-show-path-derives-drawn-height: show 経路が実高を導出し、位置決定後に適用する（位置の畳み込み先はバー高のまま据え置く）

日付: 2026-08-04 ／ 状態: 承認

対象 issue: #755（hide 時に status/toast が出ていると再表示後に窓が伸びず案内が切り取られる）・#801（updater トースト表示中の show で高さが縮んでから伸びる）。両症状は 1 回の show では排他であり、同じ食い違い（畳む先と最初のフレームが描く高さの不一致）から出ている。

## 決定

show 経路（`show_egui_main`）に、位置決定後・`show()` の前に 2 回目の `set_size` を追加し、毎フレーム側と同じ述語（`status_row_present`）・同じ積算式（`main_window_height`）を通した実高を適用する。**位置決定に使う 1 回目の `set_size`（バー高固定）は変えない**——バーの位置はユーザーが決めるものであり、status 行・toast 行の出没（クランプでも、可視中の伸びでも）で動かしてはならない（確定仕様・2026-08-04）。入力は reset-on-show 後の状態を 3 つのリテラル引数として呼び出し点に置く（前提が変わったとき grep で見つかるようにするため）。

**この決定は、`ADR-results-presentation-two-stage` 却下 6 と `ADR-window-coordinator-split-rule` 決定 4・却下 5 が置いていた前提の一部を反転させる。** 3 か所とも「show 経路の畳み込みと毎フレームの動的高さは目的が違う」と読み、**導出式の統合そのもの**を恒久的に禁じていた。旧 ADR の却下 6 は「毎フレームの導出をそのまま使えば結果件数で伸びた高さでクランプする」と読んで統合を禁じたが、**実際に共有できるのは `main_window_height`（バー + status + toast のみで積算し、結果件数には伸びない）という積算式であり、これを位置決定後の 2 回目の `set_size`（クランプの対象外）に使うことは安全である**。反転したのは「導出式を共有できない」という前提だけである——**「位置クランプの対象を実高にできる」という意味ではない。位置クランプはバー高のまま据え置く**（確定仕様・2026-08-04）。両者は同じ入力（status 行の有無・toast の有無）から同じ高さを導いており、違っていたのは「その値をいつ・どこへ適用するか」である。

これは同じ ADR（`ADR-results-presentation-two-stage`）の却下 3 が残した教訓の適用例である: **禁止を恒久文書へ書く前に、その禁止が依存している前提を明示できるか確かめよ。** 明示できない禁止は、選択肢を隠す。

**旧 ADR は編集しない**（`ADR-adr-frozen-history`: ADR は凍結された歴史）。反転はここに記録する。

## 検討した代替案と却下理由

### 1. memo（サイズデルタガード）だけを直す

食い違いが無くなるので両 issue は消え、memo が stale でも撃たれる値が同値になって無害化される。**しかし失敗が沈黙する。** 導出が将来ずれた場合（reset-on-show が消すはずの状態を消さなくなる等）、memo と一致した瞬間に補正が握り潰され、#755 がそのまま再発する。沈黙する失敗を選ばない。

### 2. 継ぎ目 2（`position_on_target_monitor` の OS 読み戻し）まで踏み込む

サイズを引数で渡す形にできれば、show が窓を物理的に畳む必要そのものが消える。ただし同じ読み戻しは `position_results_below_main` にもあり、そちらは毎フレーム + `Moved` リスナーの 2 経路から呼ばれてフレームに閉じない。フレームに閉じない消費者を巻き込む（#738 / #760 の射程であり、ここでは触らない）。

### 3. show 側の導出をインラインで書き、一致条件をコメントで記録する

変更面積は最小になるが、導出の写しが 2 つになる。前提（reset-on-show が何を消すか）がコメントにしか無い形は、前提が変わったときに grep で見つからない。

### 4. 既定プロファイル（toast なし）の smoke へ高さの断言を足す

捕まえるはずのバグを 1 件も捕まえない。toast も status も無い状態では main は常にバー高であり、そこは一度も壊れていない。検出器は「toast あり」かつ「2 回目の show」でなければ両 issue の分岐を踏まない。

## 帰結

- show 経路と毎フレームは、`status_row_present` / `main_window_height` という同じ述語・同じ積算式を共有する 2 つの呼び出し点になった。共有するのは導出であって memo ではない（`main_size` を results の導出へ入れないという `ADR-results-presentation-two-stage` 却下 1 の境界は変わらない）
- reset-on-show で main のサイズ memo も 0 へ戻す（fail-safe）。導出が正しい限り 1 フレーム目は同値の再設定を 1 回撃つだけで見た目は変わらず、導出がずれた場合はその 1 フレームで実際に描く高さへ直る（固着せず、スナップとして現れる）
- **位置の意味論は不変である**——バーの位置は行の出没（show 時のクランプでも、可視中の伸びでも）では動かない。位置クランプが読み戻すサイズは 1 回目の `set_size`（バー高）のままで、実高は位置決定後にしか効かない
- #738（下端はみ出し時の再クランプ）とは無関係である——本決定は show 経路が導出する高さの値を変えるだけで、位置クランプが対象にする高さ（バー高）そのものは変えない
