# ADR-smoke-egui-not-split: `smoke-egui.ps1` を分けず、見出し行とスクリプト内の関数で境目を示す

## 文脈

#1404 は、`scripts/smoke-egui.ps1`（2026-11-08 時点で 958 行）に複数の検査が並んでいることをペインに挙げ、分けるか、`scripts/lib/` へ寄せるか、現状維持にするかを問うた。

2026-11-08 に main 692e8871 で測った事実:

- 起動は 2 回ある。既定のプロファイルで 1 プロセスに検査を順に当てるシナリオと、起動時に読む env が要る toast ありのシナリオである
- 前者の検査は、前の検査が残した状態を入力にする。`$failures` が 0 件のときだけ進むゲート、注入する VK 列、results 検査の実施、パスクエリの観測（Ctrl+H の起点になる）、入力欄の中身、ウィンドウの可視性である。コメントに書かれた順序の制約も 3 つある
- toast ありのシナリオは検査の結果には依存しないが、`$failures`・観測予算の引数・`Show-FailureEvidence` を共有し、不合格の発生源を後段の集計へ渡す
- 2026-08-01 以降の変更 16 件で、区画をまたいだ編集は数行にとどまった（末尾の成功文言・隣の検査の「検出しないもの」・受け渡す状態の前置・同じ機構の説明・集計への配線）。1 ファイルであることが変更を難しくした記録は見当たらなかった

## 決定

分けない。モジュールへも寄せない。境目は、シナリオと検査ごとの見出し行と、段取り（1 キー打鍵・増分の待ち・入力変化の読み取り）のスクリプト内関数で示す。

## 検討した代替案と却下理由

- **検査ごとに別のスクリプトへ分ける**: 却下。各スクリプトで起動と hotkey の待ち（CI のコールドスタートで最大 25s の予算）をやり直すか、プロセスと上の状態を受け渡す仕組みが要る。順序の制約は、ファイルをまたいだ暗黙の契約になる
- **toast ありのシナリオだけを別のファイルにする**: 却下。プロセスとしては切り出せるが、上の共有物と集計の受け渡しが残る。入口が 2 本になると、`smoke.yml` のステップと `paths`、`package.json`、`SnotraSmoke.Tests.ps1` の既定 ExePath と PositionalBinding の検査の母集団、文書の名指しが増える。費用に対し、変更履歴に益の実例が無い
- **段取りの関数を `SnotraSmoke.psm1` へ移す**: 却下。使うのはこのスクリプトだけである。移すと export・Pester・`Mock -ModuleName` の費用が出る（`ADR-smoke-module-not-split`）
- **末尾の成功文言を、走った検査の名前から組み立てる**: 却下。検査を足すたびに成功文言を 1 行直す編集は 3 回起きたが、名前を集める変数を足すと、検査をまたいで受け渡す状態が 1 つ増える。1 行の編集の費用より大きい

## 帰結

- 分割を再び検討するなら、上の共有物と順序の制約を先に数え直す。益の根拠は、1 ファイルであることが変更を難しくした実例で示す
- toast ありのシナリオの Escape は、関数へ寄せたことで down と up の間に 50ms が入った（既定のプロファイル側の Escape と同じ間隔）
