# ADR-smoke-module-not-split: `SnotraSmoke.psm1` を役割ごとに分けず、コメントを絞る

## 文脈

#1403 は、`scripts/lib/SnotraSmoke.psm1`（2026-11-07 時点で 1142 行・関数 29 本）に 5 つの役割（Win32 の相互運用・プロファイルと起動・本体の解決とプロセス・trace・注入とウィンドウ）が同居していることをペインに挙げ、分けるかどうかを問うた。

2026-11-07 に main 996db798 で測った事実:

- issue の前提「trace を読むだけの消費者も全体を import している」は、おおむね偽だった。`SnotraTraceInvariants.psm1` は import していない。`manual-smoke.ps1` は trace 以外にプロセスの役割も使う
- import の実行時の費用はほぼ無い。`Add-Type` は `Initialize-SnotraNativeInterop` を初めて呼んだときに行う
- 2026-08-01 以降の機能変更 16 件のうち 10 件は 1 つの役割で閉じていた。1 ファイルであることが変更を難しくした記録は見当たらなかった
- ファイルの中は、既に役割の順に並んでいる

## 決定

分けない。代わりに、コメントを呼び出し側の契約・前提・理由へ絞り、経緯は `#NNN` に委ねる。

## 検討した代替案と却下理由

- **役割ごとに独立したモジュールへ分ける**: 却下。
  - `SnotraSmoke.Tests.ps1` の `Mock -ModuleName SnotraSmoke` は、Mock の対象を呼ぶ関数が居るモジュールを名指す。関数を移すと、名指しを移し先へそろえる必要がある。そろえ損ねると Mock が効かず、実プロセスを止める・起動する
  - `smoke-egui.ps1` は `[SnotraSmokeInterop.Native]` 型を直接使い、モジュール内の関数が先に `Add-Type` していることに暗黙に依存している
  - `docs/build-commands.md` は「`scripts/lib/SnotraSmoke.psm1` の関数だけで組む」を、画面ロックの検出に守られる経路の定義として書いている
  - これらの費用に対し、上の実測からは益が見えなかった
- **モジュール名を保ったまま、役割ごとの `.ps1` を dot-source してファイルだけ分ける**: 却下。Mock と import は変わらないが、役割の境界は機構で守られず、影響範囲が読めるというペインへの効き目は、既に役割順に並んだ 1 ファイルと変わらない

## 帰結

- 分割を再び検討するなら、上の費用（Mock の名指し・Native 型への暗黙の依存・build-commands の経路の定義）を先に数え直す。益の根拠は、変更が役割をまたいで難しくなった実例で示す
- trace の関数群は他の役割を呼ばない（2026-11-07 に AST で確認）。分けるなら、最初の候補はこの群である
