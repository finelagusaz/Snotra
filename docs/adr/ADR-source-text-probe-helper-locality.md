# ADR-source-text-probe-helper-locality: ソーステキスト検査の母集団切り出しは、サイトごとに局所の helper を置く

## 文脈

`include_str!` で自分のソースを読み、目的の呼び出しが本体に在ることを assert する「ソーステキスト検査」がこの repo に複数ある。テスト席を作れない型の呼び出し点を守る唯一の手段になるため増えつつある。

#1077 のサイクルで、この形の母集団の切り出しが CI（CRLF checkout）でだけ壊れ、**もう 1 本は同じ理由で空虚に緑だった**。その是正として `src-tauri/src/egui_shell/launcher_controller.rs` の `mod tests` に `method_body` が生まれ、続く #1106 の振り返りが `docs/development-principles.md`「検証の層と、層と層の隙間」へ「ゆえに切り出しの helper は 1 つに閉じる」を置いた。

#1108 は `src-tauri/src/indexing.rs` に残っていた同型の欠陥（終端の錨が消えると母集団が EOF まで伸びて沈黙する）であり、是正にあたって**切り出しをどこへ置くか**を決める必要が生じた。

## 決定

**サイトごとに局所の helper を置く**（crate 共通の抽出モジュールを作らない）。

## 検討した代替案と却下理由

- **crate 共通の `#[cfg(test)]` helper へ抽出し、終端の形を引数化して 2 サイトが共有する**: 却下。理由は 2 つで、いずれも独立に成立する。
  1. **稼働中のガードへ爆風が及ぶ。** `method_body` を一般化すれば、それに依存する検査の変異注入を再実測する義務が生じる（`AGENTS.md`「条件別チェック（トリガー → 参照先）」の「レビュー指摘へ修正（fix-forward）を当てた」行）。#1108 が合意を求めた射程は `indexing.rs` である
  2. **新ファイルは統治コストを持つ**——`mod` 宣言・モジュール索引・`G-module-linkage` が別々に見る

- **却下理由として使わなかったもの**（記録として残す）: 「共通化しても実装は複数残るから削減にならない」という論証は**誤りであり、採らない**。統合しうるのはトップレベル関数の本体を切る形とメソッドの本体を切る形の 2 つで、**切り出しの構造と assert の並びは一致し、差は終端のリテラルと期待する字下げ幅の 2 値である**（回帰テストの構成はサイトごとの必要に応じて異なる）。`egui_shell/view.rs` の切り出しは production 部を取る別概念、`startup.rs` の切り出しは enum 宣言の走査であり、どちらも元より統合の候補ではない——**候補でないものを数えて「減らない」と言っていた**。達成可能な削減は 2 → 1 であり、上記の規範が対象とするのはまさにその 2 本である。この論証は #1108 のレビューで覆った。

## 受容した残余

**規範が予告した乖離は、この決定を下した当の差分で 2 度起きた。**

1. **散文の側**: `indexing.rs` 側に書いた doc が CRLF の機序（手元と Windows CI の `core.autocrlf` の非対称）を落とした形で書かれ、レビューの指摘で書き足した
2. **挙動の側**: アンカーの字下げを検査する assert を `top_level_fn_body` にだけ足し、`method_body` は同型の穴（アンカーの字下げがずれると母集団が黙って狭まる／広がる。両方向を実測）を持ったまま残りかけた。レビューが捕まえ、鏡像の assert と回帰テストを当てて閉じた

**写しは独立に腐る。硬化を片側にだけ入れる形は、写しが 2 つある限り毎回起こりうる**——却下理由 1・2 がそれを上回るという判断であって、費用が無いという主張ではない。

## 反転条件

次にソーステキスト検査を**新設する** issue が立ったら（＝3 つ目の局所実装が生まれるなら）、そこで共通化を再検討する。
