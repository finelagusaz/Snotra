# ADR-source-text-probe-population-not-concatenated: 母集団をディレクトリにするとき、子を連結しない

## 文脈

#1200 で `launcher_controller.rs` を子モジュールへ分割したとき、`activation/tests.rs` の 3 本のソーステキスト検査は `include_str!("../activation.rs")` で母集団を取っていた。そのため「**起動の入口を `activation.rs` の外へ出さない**」という制約を規範として置く必要が生じた（正本は `activation.rs` の `//!`）。守られ方は方向で違い、移動は赤になるが、**赤を消す最短手が `include_str!` のパス書き換えであり、そうすると射程が黙って狭まる**。

#1201 はこれを機構へ落とす。母集団をファイルではなくディレクトリにすれば、入口がどの子モジュールへ移っても検査が生き続け、規範そのものが要らなくなる。

issue 本文が示したスケッチは次だった。

```rust
let dir = concat!(env!("CARGO_MANIFEST_DIR"), "/src/egui_shell/launcher_controller");
// read_dir → 子 *.rs を連結して src とする
```

## 決定

**ディレクトリを母集団にする。ただし子を連結しない**——`Vec<(ファイル名, 中身)>` のまま配り、既存の helper へファイルごとに渡す。

- `sources()` — `read_dir` → `is_file() && ends_with(".rs")` → 名前順 → `read_to_string`
- `sole_file_with()` — アンカーを含むファイルが**ちょうど 1 枚**であることを assert し、その中身を返す
- `owners_of_all()` — `owners_of` を**ファイルごとに**呼んで連ねる

**`method_body` / `method_header` / `owners_of` の本体は 1 バイトも変えない**（main とのバイト一致を実測して確認した）。

## 検討した代替案と却下理由

### 子を連結して 1 本の `src` にする（issue のスケッチ）

**却下。** issue 自身が「測るべきこと」として挙げた 4 点のうち **3 点を、連結という手段が自分で作り出す**。

1. **`owners_of` の帰属がファイル境界を越える。** `current`（直前のヘッダ）は**ヘッダ行でしか更新されず、ファイル境界では戻らない**。当時 `activation.rs` の最後のヘッダは起動の入口 `on_enter` であり、後続ファイルの `//!` に禁止語が 1 語現れるだけで恒久的な偽陽性になる。**A/B で実測した**——連結形へ戻して `folder_nav.rs` の `//!` へ `read_config(` を植えると赤、ファイルごとに呼ぶ形なら緑
2. **`method_body` の `split_once` が並び順に依存する。** 先頭の出現を採るので、前のファイルの doc コメントにアンカーの綴りが先行すると、そこで割れて別ファイルの本体を切り出す。`read_dir` の順序は OS・ファイルシステム依存なので、**並べ替えただけで対象が変わる**
3. **連結の境目**が改行コードの新しい依存点になる

ファイルごとに配れば、この 3 つはいずれも起こりえない。**費用は関数 1 本（`owners_of_all`）である。**

### 母集団を `mod` 宣言と機械照合する検査を足す

**却下**（`/plan-review` の独立導出が「新しい子モジュールが黙って母集団の外に落ちる」として要対処で挙げた）。**所見が立つ前提が成立しない**——その導出は「`include_str!` はパスを計算できないので母集団はリテラルの配列にならざるをえない」を置いていたが、`read_dir` は母集団をファイルシステムから導くので、子を足せば `mod` を書かなくても自動で母集団へ入る。

**ずれの向きも逆である**: `mod` 宣言のある `.rs` の欠落は起こりえず（コンパイルエラー）、`mod` 宣言の無い `.rs` の混入は誤爆＝赤方向で `governance:check` の `G-module-linkage` が別に捕まえる。**足す前に「壊れたとき緑が緑のまま推移するか」を問うと、推移しない。**

### 母集団に下限の assert（「2 枚以上」等）を置く

**却下。** 数え上げは足すたびに腐る（`AGENTS.md`「検証の作法」）。空母集団は `sole_file_with` の「ちょうど 1 枚」assert が赤にする——**3 本の検査すべてで実測した**。

### 親モジュール `egui_shell/launcher_controller.rs` を母集団へ含める

**却下**（issue の「子 `*.rs`」に従う）。含めた場合との差は当時のツリーで無かった。**規範は消えるのではなく弱まる**——「1 ファイルへ集める」から「`launcher_controller/` の中に置く」へ。入口を親へ戻す形は 0 枚で**赤になる**（沈黙ではない）。

### `read_dir` を再帰させる

**却下。** 検査自身（`activation/tests.rs`）が母集団へ入り、**倒れ方が非対称になって気づけない**——`method_body` 側は字下げ 8 のアンカー文字列で assert が落ちて赤（安全側）だが、`owners_of` 側は当該ファイルの `fn` がすべて字下げ 0 でヘッダとして認識されないため、リテラルで綴った禁止語が帰属先を持たず**黙って捨てられて緑になる**。**非再帰は意図であって偶然ではない。**

### `ADR-source-text-probe-helper-locality` の反転条件に当たるか

**当たらない。** 反転条件は「次にソーステキスト検査を**新設する** issue が立ったら（＝3 つ目の局所実装が生まれるなら）」であり、#1201 は既存 3 本の**母集団の取り方**を変えるだけで、局所実装は 2 つ（`method_body` / `top_level_fn_body`）のまま。同 ADR の却下理由 2（新ファイルの統治コスト）も、新ファイルを作らないので不成立。

**却下理由 1（稼働中のガードへの爆風）は当たる。** それを最小化するために helper の本体を凍結した——合成 fixture 11 本が逐語で生き、再実測が要るのは母集団の配り方と 3 本の検査だけになる。

## 受容した残余

**塞がない死角を宣言する。正本は各シンボルの doc である**（ここへ写すと、あちらを直したときこの行だけが腐る）。

- **4 本目の入口の新設は沈黙する**——対象の正本が `entry_points` 配列で、母集団の側から導かれていない。**#1201 が消したのは「移動で射程が黙って狭まる」側だけである**
- **inline `#[cfg(test)] mod tests` の混入**——`read_to_string` は属性を解釈しない。曝露面が 1 枚から直下の子全部へ広がる
- ~~**`owners_of_all` を「ファイルごとに呼ぶ」ことに検知器は無い**（散文の契約）~~ — **`/simplify` の altitude 枠の指摘で閉じた**（合成 fixture の回帰テストを置いた。`owners_of_all` / `sole_file_with` は `&[(String, String)]` 上の純関数なので fixture が当たる——実ディレクトリを読む `sources` とは違う。この区別を当初せず 3 関数まとめて「fixture では測れない」と判じていた）
- **`file_type` の `Err` 枝は発火を実測していない**——Windows の `DirEntry::file_type` は `FindNextFileW` のデータから組み追加 I/O をしないため、壊れた junction を置いても `Ok` が返る

## 実測した機構（フォールトインジェクション）

`.claude/rules/safety-nets.md`「効いていることは、フォールトインジェクションで一度は実測する」に従い、**機構あり／なしの対照**を取った。

**便益の証拠は、緑になったことではなく差である**——`shift_activate` を丸ごと `folder_nav.rs` へ移すと、**この設計では 3 本とも緑**、**同じ移設を変更前の `include_str!` 版へ当てると赤 2 本**。そのうえで移した先でゲートを落とすと赤になる（射程が入口に付いていった）。

**変異が本来の回帰より強いと、検査が縛れていなくても赤くなる。** 当初書いた変異 3 件は綴りの差し替え・実定義の重複で、いずれも**コンパイルエラー**を返した——それは検知ではない。書き直して測り直した。**その過程で、アンカーが 2 枚に現れる状況は同じ型の inherent メソッドからは作れない**（rustc が E0592 で先に落とす）ことが分かった。
