# ADR-source-text-probe-predicate-polarity: ソーステキスト検査の母集団は、述語の極性で要求が裏返る

## 文脈

**母集団を持つ検査では、母集団そのものが壊れる。** ソーステキスト検査（自分の属する production のソースを読み、目的の呼び出しが在ることを assert する形。テスト席を作れない型の呼び出し点を守る唯一の手段になる）が典型である。**母集団の取り方は 1 ファイル（`include_str!`）とディレクトリ（実行時の `read_dir`）の両方が実在する**（後者は #1201）。**どちら向きの壊れ方で沈黙するかを決めるのは、切り出し器ではなく切り出した結果を食う述語である**——広がる側で沈黙する述語と、狭まる側で沈黙する述語がある。ゆえに切り出しの正しさを述語と切り離して問うことはできない。**この裏返りは Rust と `.mjs` の双方で観測した**——母集団を切り出して述語へ渡す形であることが共通点で、言語ではない（2 実例からそれ以上は言えない）。

この記録は、`docs/development-principles.md`「検証の層と、層と層の隙間」に置いていた本文を移したものである（原則集の条項を「命令 1 文 ＋ 観点」へそろえるため）。

## 述語の極性と、母集団への要求

切り出した母集団 P と、本来見るべき本体 B を分けて書くと、要求は述語の向きで裏返る。**以下は観測された実例であって、述語の形はこれで尽きない**——新しい形を足すときは「どちら向きの誤りで、この述語は真の側へ誤るか」を自分で問う。

- **存在形（`P.contains(x)`）は `P ⊆ B` を要求する。** P が B を越えて広がると他所の文字列で真になり沈黙する。**探す綴りが同じファイルに逐語で実在する**（assert のリテラルがまさにそれである）ことに加えて、**その綴りが飲み込まれる側に在る**という位置の前提が要る——アンカーより後ろに `mod tests` が在る現在の並びがそれで、テストモジュールを前へ置けば、**本体の呼び出しが消えた状態で** EOF まで伸びても綴りは飲み込まれず赤になる（呼び出しが在るうちは、どちらの並びでも真であってよい）。**上界を縛る assert がこれを塞ぐ**: 終端が実際に見つかったこと・アンカーが期待どおりの字下げから始まっていること
- **否定形（`!P.contains(x)`）は逆に `P ⊇ B` を要求する。** 切り捨てた領域に禁止語が在っても真になるので、**狭まる側で沈黙する**。**目印（canary）はこの下界のごく弱い版（`|P| > 0`）にすぎず、「P が途中で切れていない」は言わない**——2026-08-17 に rustc で対照を取り、canary の後・禁止語の前で切断した母集団に対して否定形は緑、同じ切り方で存在形は赤だった（#1112）
- **一致形（数え上げが宣言側と一致すること）は、広がった領域が要素を 1 つでも足せば赤になる。** 偽陰性が残るのは増減が釣り合うときである——`egui_shell/view.rs` の `assert_read_once_in_this_file` は母集団がファイル全体なので、production の読みが消えることと doc コメントに綴りが現れることが釣り合えば緑が成立する（正本は同関数の doc。いまその側を支えているのは rustc の束縛であってこの検査ではない）

## 決定

**否定形からは切り出しを取り除き、代わりに濾過層（帰属）を置く。**

要求が `P ⊇ B` である以上、**守りたい本体が母集団に入るファイルのどれかに在るなら、母集団全体は B の上位集合である**——切らなければ下界は構成から満たされ、切り詰めという事象そのものが無くなる（**本体が母集団の外へ移りうる検査ではこの前提が外れる**）。**この但し書きは弱まったが消えていない**——#1201 が母集団を 1 ファイルからディレクトリへ広げたことで「隣の子モジュールへ移る」形では外れなくなったが、ディレクトリの外（親モジュール・サブディレクトリ）へ移る形では今も外れる。**下界の根拠がファイル単位から母集団単位へ移っただけである。**#1112 はこの形で `owners_of`（出現をファイル全体から列挙し、直前の字下げ 4 の `fn` ヘッダへ帰属させる）へ移した。**代わりに引き受けるものがある**——母集団が広い分「対象が 1 つも認識されていない」は起こりうるので、canary の役はアンカーがヘッダとして実在することを名指す assert が引き継ぐ。

**切り出しを持つ形は、行の走査を `str::lines` で行い、helper 自身を LF / CRLF 両方の fixture で測る。** 終端を `find("\n    }\n")` のような部分文字列で探すと CRLF に一致せず、母集団が EOF まで伸びる（＝上の存在形が沈黙する側になる）。`str::lines` は `\n` で分割し末尾の `\r` を落とす。`include_str!` も `fs::read_to_string` も読むのは checkout された実ファイル（どちらも改行を変換しない）なので、作業ツリーの改行コードによらず固定する必要がある。同じ非対称（手元 `core.autocrlf=input` と CI の既定 `true`）は `.gitattributes` の冒頭コメントが `.githooks/**` について既に記録している。

**切り出しの helper は、同じ母集団の形を共有する検査群の単位で 1 つに閉じる。** 判断と反転条件は `ADR-source-text-probe-helper-locality` にある。

## 検討した代替案と却下理由

### 否定形から切り出しを外すだけにする（濾過層を置かない）

**却下。「切らなければ安全」ではない。** 切り出しを外しただけの `!src.contains("禁止語")` は、**同じファイルにその綴りの正当な出現が在れば永久に赤くなる**——#1112 の当該ファイルには `read_config(` が対象外の経路（`lang()`）で、`self.indexing()` が起動の入口の外で在り、加えて**検査自身が禁止語をリテラルで綴る**。永久に赤いゲートはゲートが無いのと機能的に同じである（`docs/development-principles.md`「検証の層と、層と層の隙間」の「判定を持たないツール」と同じ帰結）。**ゆえに切り出しを外すなら、代わりに濾過層が要る**——#1112 が置いたのは帰属（出現ごとに「どの関数の中に在るか」を決め、守りたい関数へ帰属するものだけを述語へ渡す）である。

### 切り出しの helper を検査ごとに書き写す

**却下。** 書き写すと母集団の壊れ方が**検査ごとに独立に起きる**——2026-08-16 実測（#1077）: 検知器 2 本のうち 1 本が CI でだけ落ち、**もう 1 本は同じ理由で「空虚に緑」だった**——ガードを消しても通る状態で、**落ちた側を追わなければ気づけなかった**。手元は 3 度の全件実行がすべて緑である。2 本が別々の状態になったのは、写しが独立に壊れたためである。#1106 は 2 本目を書くときに写し、`/simplify` の指摘で 1 つへ畳んだ（母集団を production 側へ限る理由も、書き写せば同じだけ複製される）。

**ただし crate 全域で 1 つにはならない**——切り出しはサイトの形ごとに別概念で、トップレベル関数（列 0 の `}`）・メソッド（4 スペースの `}`）・enum 宣言の走査は互いに置き換えられない。**同じ検査群に複数が同居することもある**: `egui_shell/launcher_controller/activation/tests.rs` は存在形が使う `method_body` と否定形が使う `owners_of` を並べて持つ——**極性が違えば要る不変条件が違い、ツールも分かれる**。禁じているのは写しであって数ではない。

## 受容した残余

**濾過層は、切り出しの除去と違って下界を構成では満たさない**——帰属を決めるのは行の形を読む述語であり、偽のヘッダがそれを横取りすれば禁止語は対象外へ落ちて緑になる。**残余の内訳と反証の実測は `src-tauri/src/egui_shell/launcher_controller/activation/tests.rs` の `owners_of` の doc を正本とする**（ここへ写せば、あちらを直したときこの行だけが古くなる）。
