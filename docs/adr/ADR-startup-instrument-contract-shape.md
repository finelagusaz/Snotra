# ADR-startup-instrument-contract-shape: 起動計器の契約の形（却下した 3 つの案）

- 状態: 採用
- 日付: 2026-08-09
- 文脈: #1000（起動の端から端までを刻む計器）

計器の出力とハーネスの契約をどう組むかで、**それぞれ「一見もっともらしいが false-green を
作る」案**を 3 つ却下した。`workspace/` の削除で失われる前に回収する。

## 1. 終端を 1 つのイベントにして `ok` フラグで分ける

**却下。** 当初案は登録失敗でも `startup:ready` を出し `data.ok = false` を載せる形だった。
ハーネスが `ok == true` を検査すれば足りるように見える。

**ハーネスが検査を 1 つ忘れた瞬間に沈黙で通る。** #690 / #786 が記録している型そのもので、
この issue が潰そうとしている false-green である。イベント名（`startup:ready` /
`startup:failed`）が意味を運ぶ形にし、**ハーネスは両方を終端として待つ**——`ready` だけを
待つと失敗時にタイムアウトになり、「終端が出なかった」という誤った理由で落ちて、起きたこと
（登録失敗）が読めない。

## 2. 区間の総和で「マークの取り落とし」を検出する

**却下（原理的に不可能）。** 累積タイムラインの区間和は telescoping sum であり、マークを
1 つ落としてもその区間の時間は隣へ吸収されて等式は崩れない。**実際に変異を当てて確かめた**
——`history_load` のマークを外しても恒等式は破れず、捕まえたのは「説明されない `null`」の
検査だけだった。

取り落としを捕まえるのは**キーの網羅**（`Phase` の全 variant を必ず出す）と**枝フラグ・
`reached_phase` が説明しない `null`** である。総和は基準点・単位の誤りにしか効かない。

## 3. 失敗経路の `null` を `ok = false` で一律免除する

**却下。** 失敗終端では以降の区間が `null` になるので、`ok = false` を説明者に使いたくなる。

**一律免除は失敗経路でのマークの取り落としを一切見えなくする。** かといって `reason` から
Phase を導く形は、ハーネスが対応表を持つことになり**写しが 2 部**になる（経路を足すたびに
両方を直す）。

Rust 側が `reached_phase`（実際に刻んだ最後の区間名）を出す形にした。ハーネスは対応表を
持たず、免除も一律ではない。

## 付随して確かめたこと（設計の前提）

- **検査は双方向でなければならない。** 「説明されない `null`」だけを見る形は、**スキップした
  区間に `0` を書く誤りを素通しする**——`null` と `0` を区別する設計の要なのに、片方向では
  守れていなかった（変異を書いている途中で気づき、逆向きを足したところ 2 件とも捕まった）
- **恒等式（`post_main == sum_phase + unmarked_tail`）は構成上ほぼ常に真である。**
  `unmarked_tail` を差として計算する以上、同語反復化した実装（`post_main` を部分和から作る）
  を通してしまう。外部壁時計も上限しか縛らない。**捕まえるのは単体テスト側**
  （`post_main_is_taken_independently_of_the_partial_sum`）である
