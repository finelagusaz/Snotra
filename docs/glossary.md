# 用語集

このリポジトリの文書とコメントで、意図して使い続けている語の意味を書く。読み手が知らない語でつまずかないようにするためのものである。

## 使い方

- ここにある語は、そのまま使ってよい。意味をずらして使わない。
- 新しい語が要るときは、まずその分野の標準の語を使う（判定は `docs/comment-guidelines.md`「言語（日英）」）。標準の語で言えない語を初めて書くときは、括弧で原語か一言の説明を添える。その語を 2 つ目のファイルに書くときに、ここへ足す（その語がほかのファイルに既にあるかは `git grep` で分かる）。
- ここは使う語の一覧であり、使わない語の一覧ではない。直してきた直訳語の記録は置かない。

## 語

| 語 | 原語 | 意味 |
|---|---|---|
| 正本 | source of truth | ある事実を正式に持つ、ただ 1 つの場所。ほかの場所はここを指す |
| 写し | copy | 正本の事実を、ほかの場所に書き写したもの。正本が変わると古くなる |
| 母集団 | population | 検査や列挙が、漏れなく見るべき対象の全体 |
| 述語 | predicate | 検査で、対象が条件に当たるかどうかを決める判定 |
| 照合 | verification | 写しや参照を、正本と突き合わせて確かめること |
| 分離プロファイル | isolated profile | `SNOTRA_CONFIG_DIR` が実プロファイル（`%APPDATA%\Snotra`）以外を指す起動。単一インスタンス・スタートアップ登録・既定ホットキーが実機から分かれる（`SPEC.md` §13）。スクリプトが作る検証用プロファイルは、その一種である |
| 正準形 | canonical form | 文書の節を指す決まった書き方。`` `<対象>`「<見出し>」 `` の形で、`governance:check` が照合する |
| 着地 | resolve | 正準形の参照が、実在する見出しに当たること |
| 規範（規範文書） | norm | 作業の決まりを書いた文書。ルート `CLAUDE.md`・`AGENTS.md`・`.claude/rules/`・`.claude/skills/` |
| セーフティネット | safety net | 誤りを止める仕組みの総称。hook・CI・`.githooks/`・`.claude/settings.json`・規範。対象の正本は `AGENTS.md`「条件別チェック（トリガー → 参照先）」 |
| 常時ロード | always loaded | 毎セッション文脈に入ること。ルート `CLAUDE.md` と `AGENTS.md` が当たる。`.claude/rules/` は、編集するファイルのパスに応じて読み込まれる |
| 機構 | mechanism | 散文の決まりではなく、自動で働く検査や hook |
| 検知器・検出器 | detector | 誤りがあれば赤になるテストや検査。2 つの語は同じ意味 |
| 変異・変異注入・フォールトインジェクション | mutation / fault injection | 検知器が効くかを、対象を故意に壊して確かめること。壊すのは複製に限る（`.claude/rules/safety-nets.md`） |
| カナリア | canary | 検査の前提（母集団など）が壊れたら赤になるように置いた、見張りのテスト |
| 偽陰性 | false negative | 赤になるべきところで、緑のまま通る誤り |
| 偽陽性 | false positive | 問題が無いのに赤になる誤り |
| 受容する残余 | accepted residual risk | 承知のうえで塞がずに残す欠点。残す理由とあわせて書く |
| 実測 | measured | 推論ではなく、実機や実データで測って確かめたこと |
| 適用範囲 | scope | 決まりや検査が当てはまる範囲 |
| 足場 | scaffold | 調査や測定のための一時的なコード。作るときに、撤去する時期も決める（`docs/development-principles.md`「観測と計装」） |
| fail-closed／fail-open | — | 判定できないときに、止める側を選ぶ設計／通す側を選ぶ設計 |
| 委譲先 | delegate | 作業を任せたサブエージェント |
| 対称ペア | symmetric pair | show／hide のように、片方を変えたらもう片方も見直す組 |
