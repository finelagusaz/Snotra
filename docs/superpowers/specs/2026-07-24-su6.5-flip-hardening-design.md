# SU6.5: flip 前ハードニング（計測ゲート + #652 / #643 / #648）設計

日付: 2026-07-24 / 対象: #532 Phase 2 SU6.5 / 先行: SU6（PR #651・main マージ済・retrospective は PR #653）
ロードマップ: `2026-07-21-phase2-softbuffer-migration-roadmap.md` の SU6.5 行
スコープ確定: brainstorm でロードマップ行（計測 4 項目 + #652）に **#643 / #648 を同梱**すると決定。#646 は対象外（決定 7）

## 背景と言語化

SU6.5 はロードマップ唯一の「計測 + 検証」ユニットであり、**flip（SU7）の基準 2・3・5 をここで数字と目視に接地させる**。ただし brainstorm の調査で、ロードマップ行の前提が 3 点ずれていることが分かった。

- **#652 は「SU6 の受け口と同型で移植」では動かない**。SU6 の hotkey 失敗受け口（`egui_shell/mod.rs` `register_hotkey_failure_listener`）は**意図的に wake しない**——wake を `config-applied` 一本に委ね、言語同時変更で旧言語整形になる競合窓を閉じる設計である。この成立条件は「pending 格納には必ず config 変更が随伴する」。起動時失敗（`platform-event` の `initial-hotkey-failed`）は config 変更を伴わないため `config-applied` が来ず、かつ SU5 の要石「hidden 中は `update()` が走らない」により、pending へ置くだけでは**通知が永遠に描かれない**。同じ機構が経路によって逆を向く（決定 2）
- **#628 の hidden 項目は SU5 で実質決着している**。「tao が hidden 窓へ `RedrawRequested` を配らない」は MVP スパイクではなく**製品経路（`egui_shell`）で実測済み**（`src-tauri/CLAUDE.md` egui_shell 節）。SU6.5 に残るのは裏取りであり、flip ブロッカーへの昇格はほぼ起こらない。一方で SU6 スモークが挙げた**入力レスポンス**（#628 に追記済み）は flip 基準の条文に無い未測項目である（決定 6）
- **メモリ再測には計測資産が無い**。`scripts/measure-memory.ps1` は `WorkingSet64` 軸で、採用ゲートが「共有 Edge ページを ×6 二重計上する誤軸」と結論した当のもの。しかも `package.json` / `docs/` / `.github/` のどこからも参照されない孤児（最終更新 #133）。ゲートで実際に使った PrivWS サンプラーは issue #532 のコメント（5011127487）に手順メモが残るだけでコミットされていない（決定 5）

**含まない**: #646（トースト・メイン・検索結果の 3 ウィンドウ構成への UI 再設計。決定 7）/ #650（IME 再変換・WANT・flip 非ブロック）/ #580 核心（署名付き実更新・CI 環境が要る・SU7）/ `e2e/` の後継方針決定（SU7 の受け入れ条件）。

## 決定事項

### 決定 1: サイクルの形は「実装 → release ビルド → 計測（一項目ずつ）」

ブランチ `feat/532-su6.5-flip-hardening`、PR 1 本。実装 3 件（#643 → #648 → #652）を先に通してから release を焼き、計測 G1〜G4 を回す。

**計測を後ろに置く理由**: 外観 parity（G2）は #643 の修正後でないと測る意味を持たない。先に測れば「入力欄のフォントが違う」で不合格を出し、直して測り直す往復が生じる。

**計測はバッチで回さない**。項目ごとに「手順提示 → 実測 → #532 コメントへ記録」の刻みで進める。実機作業を伴い、途中で条件を直す判断が挟まるため。

分担: 計測スクリプト・release ビルド・trace 整形・比較項目表はエージェント側。起動・目視・打鍵の実機操作は人間側（G1 の同日ペア測定、G2 の並置目視、G3(b) の打鍵）。

### 決定 2: #652 は「pending 格納 → show → wake」。wake の非対称は意図的に維持する

`register_platform_event_listener` を新設し、`main.rs` の egui ブロック（既存 `register_hotkey_failure_listener` の隣）へ登録する。payload `{event, hotkey}` の `event == "initial-hotkey-failed"` を判別する。

**登録順序は既に安全**: emit 元は `PlatformCommand::RegisterInitialHotkey` で、`main.rs` の「Must precede `setup_hotkey_listener`（RegisterInitialHotkey を送る）」コメントが egui ブロック（listener 登録）の先行を固定している。取りこぼしの窓は無い。

**順序不変条件（3 段）**:

1. **pending 格納が先** — show が起こしたフレームは reset-on-show の `notice.clear()`（`view.rs` の `reset_pending` 消費）を通ってから pending を消費する（既存順序）。逆順にすると clear と store の間にフレームが挟まりうるため、通知が消えたまま二度と出ない
2. **`show_egui_main` を呼ぶ** — WebView2 parity。ホットキーが登録できていない＝ユーザーが窓を開く手段がトレイしか無いため、能動的に見せる（原型 a06d790 の設計意図）
3. **`wake_view` を呼ぶ** — `show_on_startup=true` で既に可視なら `show()` は再描画を生まない。SU5 で `src-tauri/CLAUDE.md` へ昇格した「paint 後に状態を変えたら wake」がそのまま効く

**wake の非対称を残す**: 変更失敗（SU6 の受け口）は wake せず `config-applied` に委ねる。起動失敗は wake する。同じ pending 機構が経路で逆を向く理由をコード上に明記し、片方だけ読んで真似た改変で壊れないようにする。

**pending スロットを kind 付きへ拡張**: `EguiShellState.pending_hotkey_failure` を `Mutex<Option<(HotkeyFailureKind, String)>>` 相当へ（last-wins・2 種が同時に意味を持つ状況は無い）。文言が別キーだからである——`notice.hotkey.initial_failed` は「他のアプリが使用中の可能性があります」、`change_failed` は「元のホットキーを維持します」。

**文言**: `strings.rs::hotkey_initial_failed` を `ui/src/lib/i18n.ts` の実物から codepoint 単位で転記し（`strings.rs` の `//!` 規範）、既存 `hotkey_change_failed_matches_i18n` と同型の一致テストを添える。

**検証エスケープハッチ**: `SNOTRA_FAKE_INITIAL_HOTKEY_FAILURE=1` を設ける（`SNOTRA_EGUI_FAKE_UPDATE` と同じ流儀）。実機で `RegisterHotKey` を失敗させるのは他アプリ依存で再現性が無い。

### 決定 3: #643 は parity 解釈で閉じる（バー高さ 52px 据え置き）

**issue の前提を実物が覆した**。`ui/src/styles/global.css` の `--search-bar-height: 52px` は**固定値で `--font-size` に連動しない**。`.search-input` は `font-size: inherit` で body の `var(--font-size, 15px)` を受けるだけである。したがって WebView2 でも font_size を上げるとバー高さは 52px のまま入力欄フォントだけ拡大する。

**parity は「バー 52px 固定のまま入力欄フォントだけ追従」**。issue 本文の「バー高さを font_size 連動にする rework を伴う」は parity ではなく改善提案であり、SU6.5 では採らない。

実装は 2 点: `view.rs` の TextEdit へ `FontId::proportional(font_size)` を与える / hint を `hint_text_color` で描く。`compute_window_height` の `search_bar_height: 52.0` は据え置く。

**残余**: 極端な font_size ではバーからはみ出すが、WebView2 も同じくはみ出す（同じ壊れ方＝parity）。SPEC §11 に残余として一行記す。

### 決定 4: #648 は残り 3 点。(B) は SU6 で解消済み

(B)（`strings.rs` module doc の「起動時に一回読む」矛盾）は SU6 で是正済み（`//!` に「#648(B) で旧記述を是正」が入っている）。残りは:

- **(A)** `start_launch` 末尾に明示 `ctx.request_repaint()`（暗黙連鎖への依存を断つ 1 行）
- **(C)** `InstallFailed.message` / `ToastKind::Failed.message` の dead payload を落とす（描画未使用・詳細は trace のみ・WebView2 も generic 表示ゆえ parity 影響なし）
- **(F)** `spawn_update_check` の AppState 不在時 mode fallback を `Full` → `Disabled`（保守的既定へ）

### 決定 5: 計測ハーネスは既存スクリプトを PrivWS 軸へ置換する

`scripts/measure-memory.ps1` を書き直し、`npm run measure:memory` を付ける。新設ではなく**置換**とするのは、誤軸の孤児をリポジトリに残さないため——将来の読者がそれを使えば ×6 の二重計上を再演する。

- 指標は `Win32_PerfFormattedData_PerfProc_Process.WorkingSetPrivate`（PrivWS）を本命の単一軸に、PrivComm を参考値として併記。**`WorkingSet64` は出力しない**（誤読の源を断つ）
- 子孫合算は SU2 の実測した罠を避ける——CIM `ParentProcessId` の BFS は uint32/int のキー不一致で沈黙して 0 を返した。型を明示的に揃えたうえで、**プロセス数を出力に含めて BFS が実際に子を拾ったことを可視化する**（「測れなかった」と「0 だった」を出力で区別できるようにする）
- visible は `EnumWindows` 受動サンプラー（hide-on-blur ゆえフォーカスを奪えない）、hidden は Alt+Q 非表示 3s 後

### 決定 6: #628 は「測ってから決める」。見立てを先に固定する

hidden 停止（G3(a)）は裏取り、入力レスポンス（G3(b)）は新規実測とする。無条件の `fill_mesh` 最適化は採らない——#634（G-SYNC 実測）と SU4 の 2 プローブが確立した「設計を決める前に測る」刻みに揃える。

**見立てを先に書く**: `raster_ms=27〜44` は SU1 スパイクの 900×588（≈529k px）での値である。製品ウィンドウは幅 600・結果展開時の高さ ~300＝**≈185k px（約 1/3）**。単純比例なら 9〜15ms でフレーム予算 16.7ms の内側に入りうる。ゆえに測る価値がある（予測を固定しておかないと、出た数字を「そういうもの」として受け入れてしまう）。

落ちたときだけ `fill_mesh` 最適化（`inv_area` の乗算化 + 単色不透明・非テクスチャ mesh の fast path）を SU6.5 内で実施し、再測して閉じる。

### 決定 7: #646（3 ウィンドウ UI 再設計）は SU6.5 の対象外（否定の知識）

#646 は「トースト + メイン + 検索結果の 3 構成」への作り替えで、issue 自身が着手タイミングを「Phase 2 の SU シリーズがひと段落したら」としている。SU6.5 は **flip 基準を満たすためのハードニング**であり、parity を測る対象そのものを作り替える作業とは目的が逆を向く。SU3 brainstorm の「単一ウィンドウ維持・2 窓分割は flip 後の別 spec へ」という決定とも整合する。SU7 以降の独立サイクルとして扱う。

## テストと受け入れ

**ユニット（`cargo test -p snotra`）**:

- `hotkey_initial_failed_matches_i18n` — i18n.ts 実物との一字一句一致（Ja/En 両方・既存 change_failed テストと同型）
- pending スロットの kind 判別 — Initial / Change で異なる文言が組まれること
- `#[cfg(test)]` 可能な範囲の純粋核のみ。listener・`show_egui_main` は Win32 依存ゆえユニット対象にしない（`.claude/rules/src-tauri.md`）

**スモーク（実機・`SNOTRA_EGUI_MAIN=1; cargo run -p snotra`）**:

- `SNOTRA_FAKE_INITIAL_HOTKEY_FAILURE=1` 起動 → 窓が自動で開き、`initial_failed` 文言が NoticeSlot に 5000ms 表示される
- `show_on_startup=true` でも同様に表示される（既に可視な経路＝wake が効いていることの確認）
- `font_size=15 / 24` で入力欄フォントが追従し、hint が `hint_text_color` で描かれる。バー高さは 52px のまま
- SU5/SU6 の回帰なし（toast・overlay・config 反映）

**受け入れ条件**:

1. G1〜G4 が全て合格し、結果が #532 コメントと PR 本文に記録されている
2. 起動時 hotkey 登録失敗が egui 経路で通知され、WebView2 と同じく窓が能動表示される（#652 close）
3. 検索バーが `font_size` に追従し hint が `hint_text_color` で描かれる（#643 close）
4. #648 の (A)(C)(F) が消化されている（#648 close）
5. G3(b) が落ちた場合は `fill_mesh` 最適化まで実施し再測して合格している
