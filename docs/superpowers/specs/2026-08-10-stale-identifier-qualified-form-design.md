# G-stale-identifiers に型修飾形を見せ、外部コマンド除外を span 粒度へ落とす（#993）

status: Agreed
日付: 2026-08-10
関連: #993 ・#984 ・#991 ・#975 ・#989 ・`docs/adr/ADR-stale-identifier-detector-scope.md`

## 背景

#993 は「`G-stale-identifiers` が型修飾した形（`Engine::new_from_cache`）を見ていない」と述べ、
その実害として #984 を挙げた——`docs/comment-guidelines.md` の第一原則が模範例として指していた
関数を同じ PR が削除し、**規範の根拠だけが実在しない名前を指す**状態になった。

着手前に前提を実測したところ、**issue が名指しした穴だけでは #984 は捕まらない**ことが分かった。
本設計はその測定結果に基づき、射程を 2 つの穴へ広げる。

## 実測（複製した述語に変異を当てた。稼働中のガードは不変）

ベースラインは SSOT の関数へ直接問うた（`scanStaleIdentifiers` の戻り値）。

| 案 | 内容 | 照合 | finding | #984 の実例（`f1827b0` 版）が赤くなるか |
|---|---|---:|---:|---|
| 現行 | — | 289 | 0 | — |
| A | 修飾形は末尾セグメントを既存 3 述語で見る | 303 | 2 | **ならない** |
| B | 外部コマンド除外を行 → span 粒度へ | 318 | 4 | **ならない** |
| **C（採用）** | A + B | **337** | **9** | **なる** |

### 第 2 の穴——#984 を隠していたのは、issue が名指しした穴ではなかった

`EXTERNAL_CMD_LINE` は「同じ**行**に `gh` / `npm` / `cargo` 等のコマンドがあれば、その行の識別子は
コマンドの引数と見なす」判定である。**この判定が #984 の当該行を丸ごと除外していた**——
`f1827b0`（腐っていた時点）でも現在の版でも実測 `除外=true`。同じ行に
`` `npm run governance:check` `` が書かれているためである。

この文書は日本語の長い段落が 1 行を成すので、**段落のどこかにコマンドを 1 つ書いた瞬間、
その段落の識別子が全滅する**。判定の根拠（「コマンドの引数である」）を担保しているのは
同じ*行*ではなく同じ*バッククォート span* だった。

**A・B のどちらか一方では、#993 の撤去条件を正直には満たせない。** 満たしたことにするには
「コマンド言及を含まない fixture」を手で作るほかなく、それは**fixture だけが赤く実文書は緑**という
状態であり、`.claude/rules/safety-nets.md`「検査の入力集合を、具体対象で検算する」が名指しする罠である。

## 設計

### 1. 述語——新しい形は足さず、既存 3 本を末尾セグメントへ当て直す

`scanStaleIdentifiers` のトークン処理を次の順にする。

1. 末尾の `()` を落とす
2. `::` を含まない → 現行どおり（`/`・空白・`.` を含めば捨て、既存 3 述語で判定）
3. `::` を含む → `::` で割り、**末尾セグメントだけ**を既存 3 述語で判定

**新しい述語を足さないことが、母集団が跳ねない理由である。** 外部 API の修飾形は末尾が
単語 1 つ（`Config::validate`）か括弧つき（`Color32::from_rgb(...)`・`HistoryStore::load(top_n)`）で、
`ADR-stale-identifier-detector-scope`「却下 3: 単語 1 つの識別子も対象にする」が置いた保守性が
そのまま落とす。照合が 289 → 337 にしか動かないのがその実測である。

**型セグメント（PascalCase）は見ない。** 全セグメントを見る案は `Section::default()` を拾って
偽陽性を 1 件増やした（実測）。却下 3・「却下 6: モジュール `CLAUDE.md` を母集団へ入れる」が
守ってきた「外部の型名は語彙源をどう広げても免罪できない」がここでも効く。

**`.` の除外はトークン全体ではなくセグメントへ当てる。** 現行の `raw.includes(".")` を先に当てると、
今日唯一の本物の腐り `icon.rs::encode_batch_binary` が素通りする。

### 2. 外部コマンド除外——行から span へ

「行にコマンドがあれば行ごと捨てる」を、「**バッククォート span がコマンド名で始まるなら
その span だけ捨てる**」へ変える。判定の根拠は変わらず、粒度だけが変わる。

`ADR-stale-identifier-detector-scope`「却下 2: 偽陽性を除外リストで消す」が採った手当て——
免除リストを置かず `` `gh pr view <PR> --json closingIssuesReferences` `` と書く形——は
span 粒度でも除外されることを実測した。免除注記の機構は引き続き置かない。

### 3. 移行——finding 9 件の仕分け（すべて前例のある処置）

| 分類 | 件数 | 処置 |
|---|---:|---|
| 本物の腐り: `icon.rs::encode_batch_binary`（`docs/development-principles.md`） | 1 | SU7 で撤去済みの関数を「参照先にする」と現在形で推奨している。生きている実例へ差し替え |
| 歴史記述: `Engine::new_from_cache` ×3・`layout::results_should_show` | 4 | バッククォートを外して散文化（#975 の是正で歴史記述に採った処置と同じ） |
| 外部語彙: `closingIssuesReferences` ×2・`mergedAt`・`head_limit` | 4 | 記述の正確化（コマンド span へ畳む・出所を名指す） |

**`docs/comment-guidelines.md` の当該行は、バッククォートを外すだけでは直らない。** 同じ行は
歴史記述に加えて**現在形の射程主張**（「型で修飾した形には当たらない——`::` を含むトークンは
どの述語にも一致しない」）を持っており、本実装が入った瞬間に偽になる。**これは命題クラスの
腐りゆえ、どの機構も捕まえない**——同じ行が自ら語っている機序（#989 の並行マージで偽になった）の
再演である。`.claude/rules/governance-docs.md` の定めどおり、機構の実装の詳細を写さず正本を指す形へ
書き直す。

**検出器の自称スコープも同じ書き直しの対象である。** `scripts/governance-check.mjs` の
G-stale-identifiers 節は、冒頭で「camelCase / SCREAMING_SNAKE 識別子だけ」と述べながら、
同じブロックの後段は 3 述語を挙げている——**#975 の lowercase snake_case が冒頭から既に抜けている**。
本実装はこのブロックをどのみち触るので、修飾形の追記と同時に既存の抜けも揃える。

**#991 が書いたばかりの行を再び触る。** 矛盾ではなく、「バッククォート＝現在形の実在主張」という
規約の完遂である。外部語彙 1 件はルート `CLAUDE.md` に落ちる——規範文書ゆえ、本設計への同意が
セーフティネット変更の合意を兼ねる（2026-08-10 に取得済み）。

**本物の腐り 1 件は、この設計を採らなくても直すべきものである**（却下 6 が「母集団を狭める判断が
既知の欠陥を隠す形にしない」として採った処置と同じ向き）。

### 4. 検証

- **fixture は `f1827b0:docs/comment-guidelines.md` の当該行を凍結して使う。** 種は架空の識別子ではなく
  実在の欠陥である（`.claude/rules/safety-nets.md`「フォールトインジェクションでは、稼働中のガードを
  弱めない——複製に変異を当てる」）。緑の対は現存する `Engine::from_material` を同形で置いた行
- **2 つの穴を足ごとに測る**（同ファイル「検出器のカバー範囲は、欠落のパターンごとに検算する」）。
  述語だけ戻して緑・span だけ戻して緑・両方入って赤、の 3 セルを実測する。**片方だけの変異で
  赤くなるなら fixture が弱すぎる証拠である**
- **逆向き**——`Color32::from_rgb(...)`・`std::process::exit(0)`・`Config::validate` が
  照合されないことを測る（保守性が効いている証拠）
- 照合件数の 0 件検知は現行の `runAll` の各行がそのまま効く（母集団を変えないため）

### 5. `ADR-stale-identifier-detector-scope` へ書く残余

- **型セグメントの腐りは見えない**——型が改名されメンバ名が残った場合、末尾しか見ないので鳴らない
  （PascalCase 単語 1 つが対象外である既存設計の帰結）
- **引数つきの形は落ちる**（`HistoryStore::load(top_n)`）
- 同じトークンが 1 行に複数回あれば finding も出現ごとに出る（既存の挙動と同じ）
- 既存の各残余（`.rs` の doc コメントは母集団外・単語 1 つ・frontmatter・日本語散文ほか）は据え置き

## 受け入れ条件

1. `f1827b0` 版の当該行を凍結した fixture で赤くなり、述語だけ／span だけの変異では緑になる
2. 保守性の逆向き（外部 API の修飾形が照合されない）を測ってある
3. 移行 9 件を処置し、`npm run governance:check` が緑。うち `docs/comment-guidelines.md` の
   当該行は**射程主張の書き直しまで**含む（バッククォートを外すだけでは偽の命題が残る）
4. `scripts/governance-check.mjs` の G-stale-identifiers 節の自称スコープを、
   **修飾形の追記と既存の抜け（lowercase snake_case）の両方**について再同期してある
5. `ADR-stale-identifier-detector-scope` へ追記節（測定表・却下した全セグメント案・残余）

## 実装上の注意

- **fixture は `.test.mjs` 以外に置かない。** `VOCAB_TEST_FILE` が語彙源から外すのはその形だけなので、
  他所へ置くと fixture の `Engine::new_from_cache` が実文書を免罪する——
  `ADR-stale-identifier-detector-scope` が記録する `createObjectURL` の罠の再演になる
