# 規範の書式を文書の役割から決める（#734）

日付: 2026-08-22 ／ 対象 issue: #734「docs: 規範のメンテ」

**この文書は 5 枠の独立レビュー（Codex 外部レンズ・逆向きの監査・実測の検算・規範適合・もう 1 枠の Claude）を受けて全面改訂した版である。** 初版の裁定のうち 1 件が覆り、根拠の 4 件が差し替わった。差し替えの理由はそれぞれの節に書く。

## 目的

**規範を読んだとき、次に何をすればよいかが分かる状態にする。**

#734 は「長くなりすぎても読みにくいのでメンテする」から出発し、圧縮・重複排除・陳腐化削除・TOC の 4 つを挙げていた。本設計はそのうち生きているものを引き取り、**目的を「短くすること」から「行動が読み取れること」へ置き換える**。

### issue の 4 項の裁定

| 項 | 裁定 | 根拠 |
|---|---|---|
| 長さ | **目的を置き換える**——短くしても読めるようにはならない | 最長条項を書き直した試作で、5,012 → 4,676 バイト（−6.7%）と 4,655 → 4,850 バイト（+4.2%）に分かれた。**ただし同じ条項を 819 バイト（−84%）へ縮めた第 3 の試作も在る**（`scratchpad/734-prototype-B.md`）——採らない理由は下記「検討した代替案」の「層ごとに切り出す」が持つ |
| 重複排除 | **却下済みを踏襲する** | `ADR-governance-corpus-reduction-rejected`——**逐語の**写し（40 字以上・フェンス外）は 111 件・730,576 字に対し 22 件、生↔生は 3 件。「触る用があったときに畳めばよい、単独で企てる規模ではない」 |
| 陳腐化 | **未解消。初版の「解消済み」は誤りだった** | `src-tauri/CLAUDE.md` に `webview2-com` / `windows_core_0_61` のエイリアス依存を指示する手順が現存する。実際の依存は `windows 0.62.2` のみで、`webview2-com` は `Cargo.toml` に無く `windows_core_0_61` はその 1 行にしか無い（3 通りで確認） |

**陳腐化の裁定が覆った機序を記録する**——見落とした行は `` - `webview2-com` は… `` で始まり、**太字で始まらない**。初版が条項を「行頭 `- **`」で定義したため、走査の視野そのものに入っていなかった。`AGENTS.md`「条件別チェック（トリガー → 参照先）」の撤去の行が「『撤去した識別子の残存 0 件』を根拠にしない」と警告した型である。

### 症状の実測（2026-08-22）

**測った母集団（19 面）**: ルート `CLAUDE.md`・`AGENTS.md`・`snotra-core` / `snotra-egui-runtime` / `snotra-settings` / `src-tauri` の各 `CLAUDE.md`・`docs/` の `development-principles` / `architecture` / `hooks` / `build-commands` / `comment-guidelines`・`.claude/rules/` の 8 枚。**これは `scripts/governance/lib.mjs` の `governanceDocs`（36 件）とは別の集合である**——役割で切ったので当然だが、同じ「対象」という語が別の母集団を指さないよう、以降は「19 面」と呼ぶ。

**単位はすべて UTF-8 バイトである。** Git Bash の `wc -m` も `awk length` もこの環境ではバイトを返す。日本語主体の文書ではバイト ≒ 文字 × 2.05（実測 211,639 バイト / 103,399 文字）なので、**「800 バイト超」は体感で約 390 字である**。`ADR-governance-corpus-reduction-rejected` から引いた 730,576 は**文字数**であり、単位が違う。

- 太字で始まる箇条書き（`- **`）は 19 面で **406 本・平均 521 バイト**。1,500 バイト以上が 8 本、800〜1,499 が 44 本
- **この 406 本は規範性のある単位の一部でしかない。** 同じ 19 面に、太字で始まらない `- ` 箇条書きが 360 本 / 76,755 バイト、番号付きリスト項目が 33 本、表のデータ行が約 120 行ある。**ルート `CLAUDE.md`「最重要ルール（常に適用）」と `AGENTS.md`「条件別チェック（トリガー → 参照先）」の全行は、どちらもこの外側にある**
- 見出しの型を分類すると、**否定形 91 本だけが再現する**（独立に書いた 4 本の述語のうち 2 本が 91 と 92 を返した）。行動形・事実形・体言止めは 4 本の述語がそれぞれ 146〜178 / 31〜60 / 108〜121 に散り、**一点に収束しない**。この 3 つは語形ではなく意味で切られており、**同じツリーでも測る人が変われば違う数が出る**
- **構造の欠如が規範違反を強制していた実例**: `src-tauri/CLAUDE.md` の 4,655 バイト条項は受容残余を「4 件——上の〜・末尾の〜と、次の 2 つ」と位置参照で指している。`AGENTS.md`「検証の作法（全タスク共通）」の「数え上げは偽になる時点が確定している」に反するが、1 行に圧縮された平場では数と位置以外に指す語彙が無い

## 決定

### 役割 → 書式は、規則ではなくヒューリスティックである

役割ごとに最適な書式は違う。ただし**役割から書式が一意に決まるわけではない**——反例が実在する。「実装契約」の `docs/hooks.md` に `` **`selectChecks` に発火を足すときは、カナリアも対で足す** `` という完全な行動形があり、「運用ガイド」の `AGENTS.md` は表だけでなく順序付きのワークフロー（1〜6）を持つ。**この表は候補を出すためのものであり、条項ごとの裁定を免除しない。**

| 役割 | 書式の候補 | 面 |
|---|---|---|
| 運用ガイド・開発プロセス（常時ロード） | トリガー → 行動／参照先 | ルート `CLAUDE.md`・`AGENTS.md` |
| 編集の瞬間の手助け | `A のときは B する。C が起きたため（#NNN 実測）` | `.claude/rules/**` |
| 開発原則・判断の型 | 局面 → 立てる問い | `docs/development-principles.md` |
| モジュール固有の不変条件 | 行動形 + 射程の明示 | 各サブディレクトリの `CLAUDE.md` |
| プロダクト知識（地図） | 構造の記述 | `docs/architecture.md` |
| 改修者向けの実装契約 | 射程の宣言と、その逸脱の明記の対 | `docs/hooks.md` |
| コマンドリファレンス | 索引 + 行動形 | `docs/build-commands.md` |
| 様式規約 | 様式の規定 | `docs/comment-guidelines.md` |

**役割の出所は 1 か所ではない。** `AGENTS.md`「ドキュメント参照」が 9 面ぶんを持つが、(a) ルート `CLAUDE.md` / `AGENTS.md` 自身と `docs/hooks.md` の役割は同節に**行が無く**（`docs/hooks.md` の役割はルート `CLAUDE.md`「フック」が持つ）、(b) 同節に在る `SPEC.md` / `snotra-settings/SETTINGS-DESIGN.md` / `docs/adr/` は上表に**無い**。初版はこれを「役割を新しく定義しない」と書いたが、**書いた時点で 6 項ずれていた**——`AGENTS.md`「検証の作法（全タスク共通）」が「保証を宣言する文の隣に、保証されていない数や一覧を置かない」として #992 について記録した型そのものである。ゆえに上表は既存の役割の**引用と拡張の混合**であり、拡張ぶんは「規範の追加」の PR で明示的に足す。

### 書き換えテスト——分類ではなく操作で裁定する

条項を「規範か地図か」で**分類しない**（水掛け論になる）。代わりに:

> 条項を `A のときは B する。C が起きたため（#NNN 実測）` の形へ**実際に書き換えてみる**。

**このテストが判定するのは「書き換えられるか」であって「書き換えるべきか」ではない。** 実際、ほとんどの事実形は行動形へ変換できてしまう——`docs/architecture.md` の「行を差し替えたら in-flight は必ず失効する。これは規約ではなく機構である」は「`SearchState` の行差替え経路を変更するときは、in-flight を失効させる」へ変換でき、どちらも嘘ではない。ゆえに変換可能性だけでは裁定できず、**次の 2 つを併せて問う**。

1. **その面の役割が、読者に行動を求めるものか**（上表は候補にすぎないので、面の役割そのものへ戻って問う）
2. **書き換えると失われる保証があるか**——射程宣言のように「逸脱の明記と対で初めて真になる」形は、片方だけ書き換えると全称が実装より強くなる

初版は「`docs/architecture.md` の全 5 条項へテストを当てたところ行動が出なかった」と書いたが、**これは偽である**。見出しだけを読んで判定し、本文を読んでいなかった。`AGENTS.md`「主張は代理ではなく対象そのもので測ってから書く」に反していた。

### 対象の裁定は条項ごとに行う。面は作業の単位でしかない

以下は**作業を割り当てる単位**であって、条項ごとの裁定を置き換えるものではない。「触らない」ではなく「**行動形化の対象に入れない**」と読む——実際、下記「分割」は `AGENTS.md` と `docs/architecture.md` の両方に差分を入れる。

**行動形化を当てる面**

- `docs/development-principles.md` — 「局面 → 立てる問い」表が 10 行しかなく、91 条項を索引していない。**10 行に絞った歴史的理由は見つからなかった**（`f6972c6`・#1051 の記述に上限も選別基準も無い）ので、拡張は意図の破壊にあたらない
- `.claude/rules/**` — 28 条項のうち行動形は 5〜10 本（厳しく採るか緩く採るかで動く）
- モジュール `CLAUDE.md` × 4 — 混在。最長条項 5,012 バイト（`src-tauri/CLAUDE.md`）
- `docs/build-commands.md` — 事実形が多い（形態で 4〜10、意味で 20 本以上。**一点では測れない**）
- ルート `CLAUDE.md` — 条項が混在

**行動形化を当てない面と、その理由**（初版の理由はいずれも弱かったので差し替えた）

- `docs/architecture.md` — **#326 が「二重管理を無くすことでドリフトする面そのものを消す」根治としてモジュール表を撤去した面**であり、条項自身が「射程と、規範を守る機構は `src-tauri/CLAUDE.md`「モジュール構成」の当該条項が正本——ここに言い換えを置かない」と宣言している。行動形化はこの宣言に逆らう。**ただし長さと位置参照は別問題である**——この面の条項 5 本は平均 1,461 バイト（19 面の平均 521 の 2.8 倍）で、1,500 バイト超 8 本のうち 2 本がここに在り、位置参照（「いま除いた枝に当たらない限りにおいて」）も実在する
- `docs/hooks.md` — **射程宣言は逸脱の明記と対で初めて真になる**。「読むのは `tool_input.command` だけである」は単独では実装より強い全称で、直後の「判定の起点はコマンド位置である。ただし全判定がそこに閉じるわけではない」が支えている（#774 が意図的にこの対を作った）。片方だけ書き換えると全称が嘘に戻る。**ただし行動形の条項も混じっている**（`selectChecks` とカナリアの条項）ので、面ごと除外はしない
- `AGENTS.md` — **判定を保留する。** この面は 19 面で唯一、条項（16 本 / 5,736 バイト）より**表の方が量が多い**（数え方で ±1 行動くが、いずれの数え方でも 1.7 倍前後）。**本設計の計測はその表を一度も見ていない**。しかも `fa8e185`（#515）が表を導入したときの 1 行は平均 150 バイト・最長 243 バイトだったのに対し、現在は平均 400 バイト超・最長 985 バイトへ育っている。**#515 が本文から追い出した「注意の山」が表のセルへ戻っており**、「適合している」という判定はこの面を見られない計器から出ていた

### 行動形／事実形のずれを検知する機構は置かない

**置かないのはこの 1 種類の検知器についてである。** 書式一般を見る機構は既に稼働している（`G-folded-code-spans` / `G-folded-heading-refs` / `G-near-heading-refs` / `G-heading-refs`）ので、「書式のずれを検知する機構は無い」とは書けない。

判断の正本は `docs/adr/ADR-governance-meta-demotion.md`（`AGENTS.md`「条件別チェック（トリガー → 参照先）」が段を増やす判断の正本として名指している）と、その一部を覆した `docs/adr/ADR-governance-anchor-layer-discarded.md` である。

- **ゲート（合否を持つ検査）は作れない**——行動形と事実形は語形では割れない（否定形 91 本の「禁止」と「事実」は末尾の語形が同じ）。2026-08-22 に当てた 4 本の述語がいずれも一点に収束しなかった。**「どんな述語でも作れない」とは測っていない**——意味を読む判定は射程の外である
- **計器（合否を持たない観測）も置かない**——この repo が「ゲートにできない」と裁定したときの着地点は歴史的に「計器へ格下げ」であり（`ADR-retire-area-budget` は `G-area-instrument` を残した）、`docs/development-principles.md`「検証の層と、層と層の隙間」も「判定を持たない道具を層に数えてよい」と認めている。それでも置かないのは、`ADR-governance-anchor-layer-discarded` が「**壊れ方が沈黙である層では、欠陥が無かったのか検知できていないのかを区別する観測が原理的に作れない**」「メタ層は作りきるか捨てるかの二択である」と裁定したからである。行動形／事実形の分布は、まさに測る人が変われば違う数が出る量である

**初版が引いた根拠を 2 つ取り下げる。** (a)「形式のゲートは正当な追記にしか鳴らない」（`ADR-retire-area-budget`）——`ADR-folded-canonical-reference-detector` が「あちらは対象も却下理由も違うので同一の先例ではない」と名指しで禁じた転用だった。(b)「気づく契機が残る」——未測定の断定であり、同 ADR が同じ問いに変異注入で「**推移する**」と答えている。

### 分割

**順序が制約を持つ。** 条項の太字リードは `G-heading-refs` のアンカーそのもの（`scripts/governance/checks/G-heading-refs.mjs` が「アンカーは ATX 見出し・番号付きリスト項目・太字リードの 3 種」と宣言し、照合は正規化後の**前方一致**）である。事実形 → 行動形は頭を変える書き換えなので、着地していた参照が落ちる。**着地は実在する**——`src-tauri/CLAUDE.md` の「処置を返す純粋核の強制」「イベント駆動 wake の不変条件」「trace の presence 検査は状態の検査ではない」へ、`.rs` / `.ps1` / `.md` から複数着地することを 2026-08-22 に確認した（件数はここに書かない。書き換える PR ごとに数え直す——手順は各 PR の欄が持つ）。**この費用は仮説ではない**——`97796aa` が「旧リード文へ着地していた見出し参照 1 件を随伴修正」しており、リード 1 本で参照 1 件が壊れている。

| 順 | PR | 内容 |
|---|---|---|
| 1 | 規範の追加 | `AGENTS.md`「ドキュメント参照」へ書式を添える。同節は表ではなく箇条書きなので、成果物の形（箇条書きのまま添えるか表へ変換するか）を先に決める。**役割の行が無い 3 面ぶんは新設**し、書式を決めない 3 面はその旨を書く。「行動形」「事実形」の定義もここへ置く——本設計は `docs/superpowers/` に在り `governanceDocs` の母集団外なので、定義を生きた面へ持たないと語彙が非規範化された歴史資料に依存する |
| 2 | モジュール `CLAUDE.md` | 4 面の条項を条項ごとに裁定して行動形化。**書き換えたリードへ着地している正準形参照を同じ PR 内で随伴修正する**（`npm run governance:check` の `G-heading-refs` で数え上げる。頭を残して末尾を足す書き換えは前方一致が生きるので対象外）。長い条項を見出しへ昇格するときは **`###` 以下にする**——`##` は `sectionOf` の節を切り、`G-module-index` の順方向照合の母集団が finding を出さずに縮む。定型スロット（規範／機序／機構の射程／受容する残余／前史）は**任意**であり、持たない条項に節を作らない |
| 3 | rules と build-commands | `.claude/rules/**` + `docs/build-commands.md` + ルート `CLAUDE.md`。参照の随伴修正と `###` 以下への昇格という制約は、モジュール `CLAUDE.md` の PR と同じく当たる。`docs/architecture.md` の長い条項 2 本と履歴 1 本（過去形）、`src-tauri/CLAUDE.md` の `webview2-com` 手順の陳腐化もここで処理する |
| 4 | 索引の拡張 | `docs/development-principles.md`「局面 → 立てる問い」表を条項レベルへ届かせる。**書き換えの後に行う**——表の第 3 列は素の `##` 見出し名であって正準形ではなく `G-heading-refs` の射程外なので、先に作ると指す先が書き換えられて静かに腐る。第 3 列を正準形で書いて射程へ入れるなら順序の制約は消える |

規範を先行させるのは、以降の書き換えが「合意された書式へ寄せる作業」になり、1 本ずつ裁定を蒸し返さずに済むためである。#1164 が確立した分担（正本は `docs/development-principles.md` へ置き、常時ロード面は圧縮形と参照で分量を保つ）を、各 PR の判断材料に使う。

## 検討した代替案と却下理由

- **層ごとに切り出す**（機序・射程・残余を `//!` doc や ADR へ移し、`.md` はポインタにする）: 却下。`ADR-canonical-source-without-pointer-indirection` が同じ形を却下している——機械照合される `.md` から照合されない rustdoc へ情報が移り、「腐りを消す変更が、新しい未照合の腐り面を増やしていた」。加えて余地が小さい: 800 バイト超の条項 52 本のうち 19 本は既に正本を名指しており、最長条項は外部参照を 12 個持ったうえで 5,012 バイトある。移す先（`src-tauri/src/state.rs` の rustdoc）には E0451 / E0616 の記述が既に在り、この案は「移動」ではなく**片方の削除**になる。**ただしこの案は同じ条項を 819 バイト（−84%）へ縮める**ので、「どう書いても縮まない」わけではない
- **見出しへ昇格し、定型スロットへ展開する**: 部分的に採用（長い条項に限り、任意スロットとして）。試作 2 本で −6.7% と +4.2% に分かれ、**長さの解決にならない**ことが測れた。位置参照と数え上げが消える効果は本物なので残す
- **書式を全面で行動形に統一する**: 却下。`docs/development-principles.md`「局面 → 立てる問い」は行動ではなく**問い**を渡すのが役割に合っており、統一するとこの節を壊す
- **面単位で対象外を決める**: 却下（利用者の裁定）。面の中にも役割の違う条項が混じる。上記「対象の裁定」の面のリストは作業の割り当てであって裁定ではない

## 受容する残余

- **行動形／事実形のずれを検知する機構は無い**（ゲートも計器も置かない判断の引き受けるトレードオフ）。受け皿は `.claude/rules/governance-docs.md` の「書く約束」・レビュー・`/health-check` の意味判断である
- **裁定は意味判断であり、ぶれる。** 書き換えテストは分類の議論を減らすが、なくしはしない。実測でも、行動形・事実形・体言止めの 3 つは独立に書いた 4 本の述語のいずれでも一点に収束しなかった
- **本設計の計測は太字で始まる箇条書きしか見ていない。** 太字でない箇条書き 360 本・番号付き 33 本・表行 約 120 行は射程外であり、その中にはルート `CLAUDE.md`「最重要ルール（常に適用）」と `AGENTS.md`「条件別チェック（トリガー → 参照先）」——リポジトリで最も強い規範と、本設計が入口の実例として引いた構造——が含まれる。**ゆえに「行動形が少ない」という診断は、表と番号付きを除いた標本の性質である**
- **見出しへ昇格した条項は `- **` でなくなり、406 本の母集団から消える。** 書き換えの前後で条項数を比べても改善の証拠にならない
- **本設計の書き換えは、逐語の写しを言い換えの写しへ変換する操作である。** `ADR-governance-corpus-reduction-rejected` は「逐語の写ししか測っていない。同じ事実を別の言い回しで書いた写しはこの計測に原理的に映らない」と残余に書いており、本設計はその映らない側へ質量を移す。増分は測れない
- **`ADR-governance-corpus-reduction-rejected` の 111 件・730,576 字は独立に再現できなかった**（追跡 `.md` からも `governanceDocs` からも出ない）。本設計の「引くときは測り直す」は、この 1 件については実行できない
- **本設計の数値は 2026-08-22 時点の実測であり、単位は UTF-8 バイトである**（ADR から引いた 730,576 のみ文字数）。条項が増減すれば偽になる
- **本設計は `docs/superpowers/` に在り、`governanceDocs` と `headingRefDocs` の双方から除外されている。** ここに書いた見出し参照は CI で照合されない
- **`AGENTS.md` の適合判定は保留のままである。** 表行を測る手段を本設計は持たない
