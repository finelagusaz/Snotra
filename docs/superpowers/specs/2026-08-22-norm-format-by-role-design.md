# 規範の書式を文書の役割から決める（#734）

日付: 2026-08-22 ／ 対象 issue: #734「docs: 規範のメンテ」

## 目的

**規範を読んだとき、次に何をすればよいかが分かる状態にする。**

#734 は「長くなりすぎても読みにくいのでメンテする」から出発し、圧縮・重複排除・陳腐化削除・TOC の 4 つを挙げていた。本設計はそのうち生きているものだけを引き取り、**目的を「短くすること」から「行動が読み取れること」へ置き換える**。

### issue の 4 項の裁定（2026-08-22 実測）

| 項 | 裁定 | 根拠 |
|---|---|---|
| 1. 長さ | **目的を置き換える**——短くしても読めるようにはならない | 最長条項を書き直した試作で、字数は 5,035 → 4,676（−7%）と 4,655 → 4,850（+4%）に分かれた。長さは症状であって原因ではない |
| 2. 重複排除 | **却下済みを踏襲する** | `ADR-governance-corpus-reduction-rejected`——逐語の写しは対象 111 件・730,576 字に対し 22 件、生↔生は 3 件。「触る用があったときに畳めばよい、単独で企てる規模ではない」 |
| 3. 陳腐化（WebView2） | **解消済み** | 生きた層の `webview2` 出現 5 か所はすべて「#532 SU7 で撤去済み」と撤去を描写する文か、smoke が実際に検証している `msedgewebview2` の増分 0 |
| 4. グループ分け・TOC | **役割ごとに違う形で引き取る** | 単一の TOC ではなく、役割に応じた入口を置く（下記「役割 → 最適な書式」） |

### 症状の実測

- 条項（行頭 `- **` の箇条書き）は対象 19 面で **406 本・平均 521 字**。1,500 字以上が 8 本、800〜1,499 字が 44 本
- 見出しを語形で分類すると、**行動形**（読者が次に取る動作で終わる形。`config の読みは read_config を通す`）123（30%）・**事実形**（断定の繋辞で終わる形。`Layer 1 は best-effort である`）45（11%）・否定形 91（22%・**禁止と事実が語形では割れない**）・体言止め/問い 147（36%）
- **構造の欠如が規範違反を強制していた実例**: `src-tauri/CLAUDE.md` の 4,655 字条項は受容残余を「4 件——**上の**〜・**末尾の**〜と、**次の 2 つ**」と位置参照で指している。`AGENTS.md`「検証の作法（全タスク共通）」の「数え上げは偽になる時点が確定している」に反するが、1 行に圧縮された平場では数と位置以外に指す語彙が無い

## 決定

### 1. 役割 → 最適な書式

**役割の正本は `AGENTS.md`「ドキュメント参照」節である**（本設計は役割を新しく定義しない）。同節の各行へ、その役割の面をどう書くかを一言添える。

| 役割 | 最適な書式 | 面 |
|---|---|---|
| 運用ガイド・開発プロセス（常時ロード） | トリガー → 行動／参照先 | ルート `CLAUDE.md`・`AGENTS.md` |
| 編集の瞬間の手助け | `A のときは B する` | `.claude/rules/**` |
| 開発原則・判断の型 | 局面 → 立てる問い | `docs/development-principles.md` |
| モジュール固有の不変条件 | 行動形 + 射程の明示 | 各サブディレクトリの `CLAUDE.md` |
| プロダクト知識（地図） | 構造の記述 | `docs/architecture.md` |
| 改修者向けの実装契約 | 射程の宣言 + 表 | `docs/hooks.md` |
| コマンドリファレンス | 索引 + 行動形 | `docs/build-commands.md` |
| 様式規約 | 様式の規定 | `docs/comment-guidelines.md` |

この対応は発明ではなく**既存の実例の一般化**である。`AGENTS.md`「条件別チェック（トリガー → 参照先）」と `docs/development-principles.md`「局面 → 立てる問い」は、既に役割に合った入口を持っている。

### 2. 判定基準は分類ではなく操作である

条項を「規範か地図か」で**分類しない**——水掛け論になる。代わりに:

> 条項を `A のときは B する` の形へ**実際に書き換えてみる**。嘘にならず、B が読者の取れる行動なら書き換える。ならなければ地図・射程宣言として現状のまま残す。

検算（2026-08-22）: `docs/architecture.md` の「例外は Enter である」は書き換えると読者が何もしないため地図と裁定され、`docs/build-commands.md` の「`cargo fmt` は検査と修復で別コマンドである」は「fmt が赤いときは `cargo fmt --all` を打つ」となって嘘にならないため規範と裁定された。

### 3. 対象と対象外

**対象（役割と書式がずれている面）**

- `docs/development-principles.md` — 「局面 → 立てる問い」表が 10 行しかなく、**91 条項を索引していない**
- `.claude/rules/**` — 行動形は 28 条項中 5 本
- モジュール `CLAUDE.md` × 4 — 混在。最長条項 5,035 字（`src-tauri/CLAUDE.md`）
- `docs/build-commands.md` — 事実形 16 本
- ルート `CLAUDE.md` — 条項が混在

**対象外（役割に適合しているため触らない）**

- `AGENTS.md` — 条件別チェック表が既に入口として機能している
- `docs/architecture.md` — 地図。全 5 条項へ操作的テストを当てたところ、書き換えても読者が取る行動が出なかった（うち 1 本「検索がフレームから出た後も、検索の `Mutex` はフレームに残っていた」は**過去形の履歴**であり、条項でも地図でもない。PR 4 の中で扱う）
- `docs/hooks.md` — 実装契約。射程の宣言（「読むのは `tool_input.command` だけである」等）は「期待するな」という警告が役割で、行動形は不自然になる
- `docs/comment-guidelines.md` — 体言止めの条項見出しは「何を書くべきか」の分類ラベルであり、様式規約の役割に合っている

### 4. 検知器は置かない

書式を守る機構を新設しない。根拠 3 点:

1. **語形からは割れない**——否定形 91 本の「禁止」（`複数枠を並列で走らせたら、全枠が出揃うまで対象へ触らない`）と「事実」（`委譲はコンテキストを継承しない`）は、末尾の語形が同じである。2026-08-22 に当てた語形ベースの述語では区別できなかった。**「どんな述語でも作れない」とは測っていない**——意味を読む判定（LLM 判定器など）は射程の外である
2. **形式のゲートは正当な追記にしか鳴らない**——`ADR-retire-area-budget` が 4 観測点で欠陥検出 0 を実測し、書き手を「上限の無い面へ逃がす」副作用だけを残した
3. **気づく契機が残る**——`.claude/rules/safety-nets.md`「効いていることは、フォールトインジェクションで一度は実測する」の「足す前に『壊れたとき緑が緑のまま推移するか』を問う」に照らすと、書式のずれは読めば見える。推移しないなら機構は置かない

### 5. 分割

| PR | 内容 |
|---|---|
| 1 | `AGENTS.md`「ドキュメント参照」へ書式の列を足す（規範のみ・合意ゲート対象） |
| 2 | `docs/development-principles.md` の索引拡張——「局面 → 立てる問い」表を条項レベルまで届かせる |
| 3 | モジュール `CLAUDE.md` × 4 の行動形化。**800 字を超える条項では、見出しへ昇格して定型スロット（規範／機序／機構の射程／受容する残余／前史）へ展開する**——長さは解決しないが、位置参照と数え上げが消える（下記「検討した代替案」の 2 件目） |
| 4 | `.claude/rules/**` + `docs/build-commands.md` + ルート `CLAUDE.md`。`docs/architecture.md` の履歴 1 本（過去形）もここで処理する |

規範を先行させるのは、PR 2 以降の書き換えが「合意された書式へ寄せる作業」になり、1 本ずつ裁定を蒸し返さずに済むためである。

## 検討した代替案と却下理由

- **層ごとに切り出す（機序・射程・残余を `//!` doc や ADR へ移し、`.md` はポインタにする）**: 却下。`ADR-canonical-source-without-pointer-indirection` が同じ形を却下している——機械照合される `.md` から照合されない rustdoc へ情報が移り、「腐りを消す変更が、新しい未照合の腐り面を増やす」。加えて余地が小さい: 800 字超の条項 52 本のうち 19 本は既に正本を名指しており、最長条項は外部参照を 12 個持ったうえで 5,035 字ある。移す先（`src-tauri/src/state.rs` の rustdoc）には E0451 / E0616 の記述が既に在り、この案は「移動」ではなく**片方の削除**になる
- **見出しへ昇格し、定型スロット（規範/機序/射程/残余/前史）へ展開する**: 部分的に採用。試作 2 本で字数が −7% と +4% に分かれ、**長さの解決にならない**ことが測れた。ただし位置参照と数え上げが消える効果は本物なので、条項が長い箇所では PR 3 の中で用いる
- **書式を全面で行動形に統一する**: 却下。`docs/development-principles.md`「局面 → 立てる問い」は行動ではなく**問い**を渡すのが役割に合っており、統一するとこの節を壊す
- **面単位で対象外を決める**: 却下（利用者の裁定）。面の中にも役割の違う条項が混じるため、条項ごとに上記の操作的テストを当てる

## 受容する残余

- **書式のずれを検知する機構は無い**（決定 4 の引き受けるトレードオフ）。受け皿は `.claude/rules/governance-docs.md` の「書く約束」・レビュー・`/health-check` の意味判断である
- **裁定は意味判断であり、ぶれうる**。操作的テストは分類の議論を減らすが、なくしはしない
- **`AGENTS.md` へ列を足すと常時ロード面が増える**。面積に合否は無い（`ADR-retire-area-budget`）が、`governance:check` の計器が実測値を報告し続ける
- **本設計の数値は 2026-08-22 時点の実測である**。条項が増減すれば偽になる——判断の根拠として引くときは測り直す
- **役割の定義が変われば表が腐る**。役割の正本は `AGENTS.md`「ドキュメント参照」であり、そこを変える変更は同じ節の書式の列も同時に見る
