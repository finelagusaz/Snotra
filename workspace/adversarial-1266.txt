## 測定環境
- smoke の「文字を打つ」は SendInput でなく keybd_event(vk, 0, flags) (scripts/lib/SnotraSmoke.psm1 の Send-SnotraKey)。KEYEVENTF_UNICODE ではない → VK_PACKET を通らない。実キーボードと同じ WM_KEYDOWN → TranslateMessage → WM_CHAR 枝を通る (tao が TranslateMessage を呼ぶのは event_loop.rs:262,401,407,770)。ゆえに smoke が緑でも次は検査されない: VK_PACKET (tao 0.37.1 は KEYDOWN(VK_PACKET)+WM_CHAR を event_info 経由で KeyEvent にするので text は乗る・keyboard_layout.rs:946 は Key::Unidentified)、IME 確定、AltGr/デッドキー、Ctrl 同時押し、サロゲート、Alt+文字、focus 獲得時に押下中のキー (合成 press)。逆に VK_PACKET を使う入力 (一部のリモート/音声/AutoHotkey SendText) が実運用で通るかも smoke は保証しない。
- smoke の config (New-SnotraVerificationProfile): hotkey Alt+Q・window_width=600・show_icons=false (toast プロファイル)・auto_update="disabled"・[visual] font_size=15/bar_padding=28 (toast プロファイルのみ)。follow_cursor_monitor・ime_off_on_show は未指定 = 既定 (follow_cursor_monitor=true・ime_off_on_show=false・schema.rs:89-95) で実運用の既定と同じ。ただし起動前に *.bin (window.bin = 保存位置) を削除する (SnotraSmoke.psm1 の `Get-ChildItem *.bin | Remove-Item`) ので、position_on_target_monitor は常に「保存位置なし→中央」枝を通る (window_coordinator.rs:253-262)。research が影響として挙げた「作業領域の下端近くの保存位置」枝は smoke が一度も通らない。DPI も 100% のみ (research の実測は scale=1)。stale inset は DPI で変わる (calculate_insets_for_dpi は frame_thickness と Win11 の top=round(dpi/96) に依存) ので、125%/150% で同じ 39/9 になる保証は無い。
- target/smoke-egui/profile-toast/stderr.log は残っており読んだ。ただし TMP_ 計装行を含む (research が言う「計装は戻した」後の run ではなく計装入りの run の記録)。値は research の引用と一致 (616x61/600x22 → 616x95/600x86、show=616x82 frame=616x52)。
- 計器が測る枝と変更が触る枝のずれ: (i) bar_rect_mismatch の断言は toast シナリオにしか無い (争点4 追加)。(ii) 通常文字の入力枝は smoke が keybd_event 経由の KEYDOWN→CHAR で、本件の修正 (text_with_all_modifiers を読む) が実際に効く枝と同じ。ゆえに smoke の緑は 'z'/'c'/':'/'\' の 4 種の経路については信頼できるが、IME と合成 press の枝は検証しない。

## 最終判定
争点1: 壊せなかった
争点2: 壊せた (合成 press で Some になる・サロゲートの旧挙動は捨て・admit_key が非合成 press も抑止する)
争点3: 前半 壊せなかった / 後半 壊せなかったが機序の記述は不正確 (連結先は直前の VK_PROCESSKEY ではなく PeekMessageW 再入中の通常キー) ⚠️ 実在性は未測
争点4: 壊せた (機序の一部) — 生成時 FRAMECHANGED が配線前に撃たれる点は壊せず。「set_size で 9 に戻る」は set_inner_size が window_rect−client_rect を offset に使う (window.rs:255-262) ことと矛盾 (先行する SetWindowPos の NCCALCSIZE が直す推論)。位置が動かない初回 show では outer が 30px 大きくなりうる ⚠️ 未実測
争点5: 壊せなかった (崩れた行 0) が、行1 は PendingEventQueue で順序保証が弱まった ⚠️、行6 は機序記述が両版で誤り、行8 は確認不能 ⚠️
争点6: 壊せた (表に無い版依存の記述あり・上の一覧)
測定環境: 壊せた (bar_rect_mismatch 断言は toast だけ・smoke は window.bin を消し保存位置枝と IME/合成 press 枝を通らない・DPI 100% のみ)
