=== PROP 1: (Ascii hay, Unicode needle) => None unconditionally -- NOT BROKEN ===
Tried: read lib.rs. fuzzy_matcher_impl has TWO early returns before the (Ascii,Unicode) arm (needle.len()>hay.len() -> None; needle empty -> Some(0); equal length -> exact_match_impl), and exact_match_impl ALSO returns None for (Ascii,Unicode) (lib.rs:727). So no length-equal escape hatch.
Measured: ("abc","日"), ("a","日"), ("abc","e\u0301"), ("e","e\u0301"), ("ab","a\u0301b") hay=Ascii needle=Unicode(From) -> all None.
Subtlety (not a break): the Unicode needle here is `Utf32String::from("e\u0301")` = Unicode(['e']) (first char of grapheme only), i.e. an "NFD needle" becomes Unicode even though every grapheme is ASCII. Consequence: after the fix, NFD needle "e\u0301" never matches ANY pure-ASCII hay ("resume") -- while the OLD code also gave None there, so no change.

=== PROP 2b: "the boolean only changes when needle is also built via From" -- BROKEN ===
Evidence: a haystack-only change DOES change the boolean, in the WRONG direction (new regression), for realistic input:
  name "Re\u0301sume\u0301.docx" (macOS NFD copy) / needle "e\u0301" (NFD paste):
    old (both Utf32Str::new)  = Some(64)
    new (both From)           = Some(16)
    haystack-only (hay From, needle Utf32Str::new) = None   <-- true->false
  same for "re\u0301s": old Some(140), new Some(88), hay-only None.
  Fuzz: hay-only differs from old in 104/3,000,000 (adversarial pool) and old=true,hayonly=false in 1,748/2,000,000 (realistic pool). Examples: h=" \u3099" q=" \u3099"; h=".e\n1\u0308 1x" q="e\u0308".
Mechanism: old classifies an all-ASCII-first-grapheme NFD hay AND NFD needle both as Ascii(bytes) and byte-matches them; a hay-only fix makes hay Unicode vs needle Ascii(bytes incl. 0xCC 0x81) -> no match. So the research's "haystack-only is merely ineffective" understates: it is actively harmful. Both sides MUST move together (the research's conclusion "needle too" is right, its reasoning/claim of harmlessness is not).
Full fix (both From) vs old: realistic pool diff=22,979/2M, ALL false->true (0 true->false). Fuzz adversarial pool: full_diff=12,044/3M; needle-only (hay old, needle From) differs in 11,492 -- so nearly all changes come from the needle side, consistent with the research.
How to falsify: run the "REAL" lines in adv1276 (cargo run -q --offline --release); if hayonly != None for the Re\u0301sume\u0301 / e\u0301 pair, my finding is wrong.
