## 争点1 母集団の導出 (正規表現の漏れ)
- [壊せた] 正規表現 ^\s*\[string\]\s*\$ExePath\s*= を代表入力で実行 (PowerShell -match):
  当たる: `[string]$ExePath = ''` / `[string]$ExePath=''` / `[string]$exepath = ''` (大小無視)
  漏れる(False): `$ExePath = ''`(型無し) / `[System.String]$ExePath = ''` / 単一行の `[Parameter()][string]$ExePath = ''` /
  `param([string]$ExePath = '')`(1 行 param) / `[ValidateNotNull()][string]$ExePath = ''` / `[Alias('Exe')][string]$ExePath = ''` /
  別名 `[string]$Exe = ''` `[string]$BinaryPath = ''`。
  (属性を前の行へ置く `[Parameter()]` 改行 `[string]$ExePath = ''` の形は 2 行目が当たるので漏れない。)
  現リポジトリで実際に漏れている起動ハーネスは 0 本。scripts/*.ps1 12 本 + lib 5 本を全数確認。`$Exe` / `$BinaryPath` は無い。

  述語 (1) 自身が同じ正規表現を使うため、母集団と述語が同じ盲点を共有する (上の漏れる形で書かれた宣言は母集団からも述語からも消える)。

  対案: 補集合で縛る。非コメント行に `ExePath` のトークンを含む scripts/*.ps1 から、導いた母集団と理由つき許可リスト(run-pester.ps1 のみ)を引いて空になることを検査する。

## 争点5 未解決の疑問の反対側の論拠
- glob: 直下の論拠 — ExePath を持つ起動ハーネスは入口スクリプトで、lib/ は .psm1 とその Tests だけ。再帰だと *.Tests.ps1(5 本)が母集団に入りうる。
  今は自己ヒット無し(実測)だが、将来この検査自身の fixture や説明行が行頭 `[string]$ExePath =` を含むと自己ヒットする。
  再帰の論拠 — scripts/governance/ というサブディレクトリの先例があり、サブディレクトリに置かれた 4 本目は直下 glob では黙る。#1292 と同じ型(数え上げが外れる)の再生産。
  折衷: 再帰 + *.Tests.ps1 を理由つきで除外。直下を選ぶなら「直下以外に置かない」を守る手段(ExePath トークンを探す補集合検査)を同時に置く。
- ADR: 起こす論拠 — 既存 ADR の「4 本目に黙る死角は宣言して止める」は現役の判断として読まれ、凍結ゆえ訂正できない。
  ADR-adr-frozen-history は先行 ADR を編集せず新 ADR で覆した先例(自身がその初適用)を持つ。#1292 で「宣言して止める」が 1 サイクルで破れたこと自体が否定の知識。
  起こさない論拠 — 理由は Tests.ps1 ヘッダと issue #1293 が持つ。ADR-doc-promise-over-area-ratchet の「かぶりなく」に照らすと、書き換えるヘッダと ADR が同内容の写しになる。
  AGENTS.md は「否定の知識が生じた決定のみ」。却下されるのは「数え上げて止める」だけで、既存 ADR の却下案の反転ゆえ新 ADR の中身は実質 1 行になる。どちらも成り立つ。
