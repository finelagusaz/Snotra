[命題3] 「git diff --name-only <sha> HEAD から workspace/ を除いて空なら、sha 以降にコード変更は無い」
判定: 壊せた(rename で偽)。他の 3 形(merge・祖先でない sha・作業ツリー)は条件つき
使い捨て repo(/tmp 配下・本体には触れていない)での実測:
  1) src/x.rs → workspace/x.rs へ git mv(コードを workspace/ へ移して消す)
       既定:            `workspace/x.rs` だけ → workspace/ 除外で空 → **素通り(偽陰性)**
       --no-renames:    `src/x.rs` と `workspace/x.rs` → 正しく止まる
     既定の rename 検出が、移動元の src/x.rs を名前から消す。**`--no-renames` が必須**。
  2) workspace/x.rs → src/y.rs(逆方向): 既定でも `src/y.rs` が出るので止まる(偽陰性にならない)。
  3) 未コミットの追跡ファイルの変更: `git diff --name-only <sha> HEAD` は 0 件(作業ツリーを見ない)。`git diff --name-only <sha>`(HEAD 省略)なら出る。
     未追跡の新規ファイルは両形とも 0 件。ただし未コミットは PR のコードに入らないので、問題は「コミットしてから push」の順で別に守られるか。→ 作業ツリーが dirty でも PR は作れる。ゲートが見ない(受容できる残余として ADR に書くべき)。
  4) sha が HEAD の祖先でない(rebase / main の取り込み): `git diff <sha> HEAD` は 2 つの木の比較なので、取り込んだ他者の変更(src/m.rs)が全部出て**止まる**(偽陰性ではなく偽陽性)。復帰は run のやり直し。fail-closed 方向。main への追従 rebase が普通に起きるので、止まる頻度は低くない(⚠)。
  5) sha を解決できない(gc / 別 clone): exit 128 `fatal: bad object`。調査書の制約2「判定不能として止める」は成立する(spawnSync の status を見る必要あり)。
  6) merge commit: 木同士の比較なので間の変更は漏れない。Q2 の「merge commit を挟む履歴で漏れる形」は 2 点比較では**無い**(3 点比較 `sha...HEAD` や `git log` を使うと別)。
  7) パスの除外: 接頭辞 `workspace/` で、`foo/workspace/x.rs` のような入れ子は除外してはならない(startsWith("workspace/") でルート直下のみ)。調査書は「パスの接頭辞での除外」としか書いておらず、ルート相対であることを明記していない(⚠)。
この所見を偽にする手順: 1) を再現すればよい。`git diff --name-only --no-renames <sha> HEAD` を使えば偽にならない。
