[壊せた(部分)] 争点4a 「isCommentLine と同じ発想」
- isCommentLine は /^\s*(\/\/|\/\*|\*[\s/]|#)/。.md に当てると、見出し行の `#`、箇条書き `* x`、`//` を「コメント」と誤判定する。
  そして .md は全行が散文なので「コメントだけを拾う」発想自体が .md に使えない。さらにコード側でも
  (a) 行末コメント `code(); // 散文` は行頭判定に掛からず落ちる、(b) 文字列リテラル中の散文(エラーメッセージ・テスト名・assert 文言)は
  コメントではないが「変更で偽になる散文」に該当しうる、(c) ブロックコメント内部の継続行 ` * foo` は拾えるが `   foo`(継続でアスタリスク無し)は拾えない。
  → 「コメントか否か」で行を落とすフィルタは、issue が問題視した「切り詰め」を道具の中へ再導入する。
  docs/adr/ADR-race-check-population-tooling.md の受容する残余(落とした候補が報告に現れない・#489 型)がまさにこの形。
  研究の疑問 1 は「分類して出す」を示唆するが、「コメント判定で落とす」設計を既定から外すべき根拠として明記していない。
- 偽にする手順: 以下を isCommentLine に通す — "* 項目", "# 見出し", "foo(); // 散文" → 1,2 は true(誤)、3 は false(漏れ)。

[壊せた] 争点4b 「依存ゼロ・純関数の型をそのまま使える」
- race-boundaries の入力母集団は `git diff -U0 <merge-base>` の追加行 + 未追跡ファイル全行(parseDiff / untrackedRows / selectPopulation)。
  `--base` 必須、差分も未追跡も空なら exit 3。
  item 7 が要る母集団は「変更で偽になる散文」= **差分に現れない既存行**(変更しないファイルの doc comment・CLAUDE.md・SPEC.md)。
  つまり race-boundaries は『diff の追加行を分類する』型で、item 7 は『識別子+概念ラベルで全コーパスを引く』型。母集団の導出が
  根本的に違い、再利用できるのは「全種印字・0 件も件数・exit 2 の使用法・純関数をフィクスチャで試験」という契約の殻だけ。
  「そのまま使える」は偽。型の核(`--base`、diff 解析、SOURCE_EXT、isCommentLine)は一つも流用できない。
- 偽にする手順: item 7 を race-boundaries の selectPopulation に通して、差分に出ない既存の doc comment がヒットするか試す → 出ない。
- main() は `process.argv[1].endsWith("race-boundaries.mjs")` ガード、execFileSync("git") 依存(Node 標準のみという意味では依存ゼロだが git に依存)。

[壊せなかった] 争点6b 「Windows で git grep -F に日本語ラベルを渡すと文字化け/0 件か」
- 実測: Bash ツール(Git Bash)、PowerShell(cmd 経由でなく `git grep` 直)、Node execFileSync の 3 経路で
  `git grep -n -F -e "独立導出"` はいずれも **70 件**で一致(workspace/ 除外後も 70)。`-e "網羅性が要件"` は 6 件で、PowerShell・Bash で一致。

- 壊しきれなかった境界: (a) CRLF 化した checkout(CI の Windows autocrlf=true)で行末 \r が付くがラベルは行内なので無影響。
  (b) 概念ラベルがハード折返しで 2 行にまたがると git grep(行単位)は 0 件 — ⚠️3。
- 偽にする手順: `git grep -n -F -e "<ラベル>"` を PowerShell/Bash/Node の 3 経路で件数比較(私が行った)。差が出れば偽。出なかった。
