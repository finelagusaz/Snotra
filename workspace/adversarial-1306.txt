### 命題2 自動起動の Run 値は env を運べず、検証用プロファイルから登録した値はサインイン時に実プロファイルで起動する
判定: **壊せなかった**（ただし修飾が必要）。
根拠: snotra-core/src/autostart.rs: RUN_VALUE_NAME="Snotra"・`command_line_for` は引用符付きパスのみ。HKCU への書込みは `RegSetValueExW`（165-174 行）/`RegDeleteValueW`（200-204）の autostart.rs だけ（git grep で唯一）。呼び出しは snotra-settings/src/tabs/general.rs:44-50。SPEC §7.7（447 行）「引数は付けない」。実機の Run 値は `"C:\toolbox\Snotra\snotra.exe"`（インストール版）で、検証用 settings から登録すると **settings の current_exe の隣の snotra.exe（dev ビルド）** へ上書きされる（`main_exe_from`）ので、サインイン時に起動するのは dev exe + 実プロファイル（env 無し）。
修飾: (1) 「env を運べない」は真だが、**引数は運べる**（SPEC が禁じているだけ）。`--config-dir` 的な引数案は SPEC 変更が前提という意味で、構造上の制約ではなく方針の制約。(2) 検証用プロファイルから登録しても「プロファイルごとの値名を作っても起動しない」という research の主張は、値名とコマンドラインが別物であることから真。(3) 影響は「実プロファイルで起動」より先に、**実機（インストール版）の登録が dev exe に差し替わる**（dev exe が消えるとサインイン時に何も起動しない）点のほうが重い。
この所見を偽にする手順: Run 値が REG_EXPAND_SZ で %SNOTRA_CONFIG_DIR% を持てる値を書く設計（サインイン時にその env が存在する保証は無いので実効しないが、research の「運べない」は「サインイン時の env は当てにできない」と言い換えるのが正確）。
