#1324 反証の結果（research.md の主張を偽にしにいった記録）

凡例: 壊せた = 主張は偽、または結論を支えない / 壊せなかった = 反証できなかった / ⚠️ = 確信なし

## 結論（先に）

research.md の数え方には二重計上のバグがある。集計 script が、tool_use / tool_result を持つ行を type で絞らず数えており、
`api-request-blob` 行（リクエストの本文の写しで、過去の tool_use / tool_result をそのまま含む）を二重に拾っている。
重複を除くと、research.md の表の分母（Bash 呼び出し）と拒否数が変わり、本体の率の差は統計的に有意でなくなる。
一方、行が名指しした `git commit` / `gh` の本文の拒否（本体 5 → 0）と、委譲先の複合 git の拒否（3.0% → 1.5%）は、重複を除いても有意に残る。

## 所見ごとの結果

### 1. 2026-10-19 以前のログはほぼ残っていない（基準値 93・82 は再現できない）
- 壊せなかった。Snotra のログで最終更新が 10-19 以前のものは 0 件、10-20 が 1 件、10-24 以降が大半。
- ただし補足が要る（壊せた部分）: 「事実上 10-20〜10-31 の分」「約 12 日」は誤解を招く。ログのある日は 10-20・24・25・26・31 の 5 日だけで、10-21〜23 と 10-27〜30 のログは無い。日数で割る基準としては、暦日 12 日も活動日 5 日も、どちらを取るかで 2 倍以上動く。
- 再現できた範囲: 緩い数え方（重複込み）で 83、厳しい数え方で 81。issue の 93 との差は 12 で、10-03〜10-19 の分と整合する（その分のログは無く、検証できない）。

### 2. 集計 script の拒否判定は過不足なく数えている
- 壊せた（二重計上）。判定の述語そのものは健全だが、数える単位が重複している。
  - 原因: script は `message.content` を持つ全行を走査する。`api-request-blob` 行にも `message.content` があり、過去の tool_use / tool_result を含む。同じ tool_use の id が、assistant 行と blob 行の両方で数えられる。
  - 確かめ方: 数える行を type が assistant / user のものに絞り、さらに tool_use の id で全ファイル通しの重複排除をかけると、数が変わる（下表）。絞るだけでも、blob 由来の重複は消える。
  - ファイル間の重複（再開・分岐したセッションが履歴を写す）も別にあり、本体・試行後で Bash 128 件、拒否 2 件。
- 偽陽性・偽陰性の探索（壊せなかった部分）: 「hook の拒否文言に heredoc があるが、対応コマンドが usesHeredoc 偽」は 0 件。「usesHeredoc が真で、hook に拒まれなかった」は 0 件（全 heredoc 試行が拒否されている）。usesHeredoc の本体は試行期間中に変わっていない（変わったのはコメントの移設だけ）。#1388（11-03）は拒否の文言だけを変え、条件は変えていない。
- 拒否されなかった `<<` を含むコマンドが本体・試行前に 8 件あるが、usesHeredoc 偽（here-string 等）で、heredoc 拒否の対象外。

### 3. 「行が文脈にあったか」を instructions の中身で判定できる。unknown は Bash をほぼ打たない
- 判定方法そのものは壊せなかった。
  - 1 セッションの中で、行の有無が途中で変わる例は 0 件（285 セッション中、混在 0）。
  - 試行後の本体 34 件は全部「行あり」、試行前の本体 9 件は全部「行なし」で、worktree が古い main から切られていて行を持たなかった本体セッションは無い。委譲先で「試行後に開始したのに行なし」の 9 件は、行を持たない本体（10-31 の夜をまたいだセッション）から生まれたもの。
- 壊せた（解釈）: unknown の本体 178 件を「空・メタデータだけのファイル」とした説明は偽。実態は、harness が自動で起こす審査用のセッション（Grep / Read / 構造化出力だけを使う）で、記録は空ではなく、会話の往復もある。instructions には MEMORY.md しか載っておらず、ルート CLAUDE.md が無いため unknown になっている。Bash を 0 回しか打たない点は正しい（結論は変わらない）。
- 数の不一致: 委譲先の unknown の Bash は、research.md では 135、script の出力では 126（重複を除くと 118）。出典が違う数が混ざっている。

### 4. 1 Bash あたりの拒否率: 本体 1.29% → 0.50%、委譲先 1.45% → 1.51%、`git commit` / `gh` は試行後 0
重複を除いた表（セッションの開始時刻で区分。Bash は tool_use の id で全ファイル通しに重複排除）:

| 区分 | セッション | Bash | 拒否 | 1 Bash あたり | research.md の値 |
|---|---|---|---|---|---|
| 試行前・本体（行なし） | 9 | 1,480 | 18 | 1.22% | 2,721 / 35 / 1.29% |
| 試行後・本体（行あり） | 34 | 4,320 | 34 | 0.79% | 7,140 / 36 / 0.50% |
| 試行前・委譲先（行なし） | 55 | 1,898 | 42 | 2.21% | 3,166 / 46 / 1.45% |
| 試行後・委譲先（行あり） | 178 | 3,204 | 58 | 1.81% | 4,186 / 63 / 1.51% |
| 試行後・委譲先（行なし） | 9 | 412 | 9 | 2.18% | 673 / 9 / 1.34% |

- 壊せた: 本体の率の差は「約 6 割減」ではなく約 35% 減（1.22% → 0.79%）で、有意でもない。二項検定（前の 18 件が偶然多かった確率、片側）が p = 0.09。セッション内の相関を無視した値なので、実際はさらに緩い。
- 壊せた: 委譲先は「変化なし」ではない。2.21% → 1.85%（行あり・なし合算）で約 16% 減。ただし有意ではない（p = 0.21）。モデル別・種類別に層に分けると、general-purpose の opus で 1.39% → 0.99%、sonnet で 6.54% → 3.65%。どの層でも率は下がるが、層ごとの件数は 10〜33 件で小さい。
  - 副次の発見: 委譲先の率はモデルでほぼ決まる。sonnet は opus の 3〜6 倍で、結論は混成に左右される。
- 壊せなかった（強い所見）: 本体で、行が名指しした `git commit` と `gh` の本文の拒否は 5 件 → 0 件（research.md は 10 → 0）。名指ししない種類は 13 → 34 で、率はほぼ同じ（0.88% → 0.79%）。重複を除いても、この 5 → 0 は有意（試行後と同じ率なら 0 件の確率が p ≈ 0.001）。
- 内訳（重複除去後）: 本体・試行前は cat > file 9・node/python/sh 3・git commit 4・gh 1・その他 1。本体・試行後は cat > file 18・node/python/sh 16。つまり行は、名指しした用途（commit・gh）は止めたが、ファイルへ書く・スクリプトへ流す heredoc は減らしていない（件数は増え、率はほぼ同じ）。
- 内訳の別の見方: 試行後の本体で、拒否を 1 回以上受けたセッションは 34 件中 23 件（68%）。行があっても、多くのセッションが heredoc を試みている。
- 壊せなかった（委譲先の複合 git）: 重複を除くと、試行前 57 件 / 1,898 Bash = 3.00%、試行後 53 件 / 3,616 Bash = 1.47%（p ≈ 0.0001）。research.md の 1.83% → 1.19% より差が大きく、有意。向きは同じ。

### 5. 日数の分母では増え（3.3 → 5.8 回/日）、セッション数の分母では減る。だから手順だけでは結論が出ない
- 壊せた（日数）: 3.3 回/日は、issue の 93 回を 10-03〜10-31 の 29 日で割った値で、いまは存在しないログ（10-03〜10-19）を分子と分母に含む。試行後の 5.8 回/日は、いま残っている範囲だけの値。窓が違うものを比べている。
  - 同じ窓（残っている試行前: 10-20〜10-31 の 12 日）で比べると、research.md の数え方（重複込み）で 81 / 12 = 6.8 回/日 → 108 / 18.1 = 6.0 回/日。重複を除くと 60 / 12 = 5.0 回/日 → 101 / 18.1 = 5.6 回/日。つまり日数の分母で「増えた」とは言えず、ほぼ横ばい。「分母によって結論が割れる」という前提は、窓の取り違えが作った見かけ。
- 壊せた（セッション数）: セッション数の分母も当てにならない。委譲先 1 セッションあたりの Bash は、試行前 34.5 回、試行後 18 回（いずれも重複除去後）。委譲の粒度が細かくなっただけで、セッション数は 3 倍以上に増える。この分母は処置と無関係に動く。
- 結論: 3 つの分母のうち、較正できるのは 1 Bash あたりだけである。ただし、その差は本体で有意でなく、有意なのは「commit・gh の本文」と「委譲先の複合 git」だけ。

## 測定環境の疑い（個別に調べたもの）

- 区分の境界時刻（セッション開始時刻で切る）: 壊せなかった。instructions の中身で判定した「行あり」「行なし」は、時刻の区分と矛盾しない（食い違うセッションは 0 件）。ただし、行なしの本体 1 件（10-31 の夜をまたぐ）は、区切りの後の分が Bash 99 回・拒否 0 件で、同一セッション内の対照として使うには小さすぎる。
- ログ形式の版による違い: 壊せた。`api-request-blob` 行は、重複が出る原因で、版により有無や量が違う。試行前のセッション（古い版）は重複が多く、試行後は少ない。これが、本体の見かけの差（1.29% → 0.50%）を大きくしていた（重複込みの試行前の分母 2,721 は実体 1,480 の約 1.8 倍、試行後は 1.7 倍）。拒否の重複は試行前の本体に偏り（35 → 18）、試行後には出ていない（36 → 36）ため、率の差が膨らむ。
- モデル・Claude Code の版の交絡: 本体はほぼ全部 opus（試行前・試行後とも）。版は 2.1.310 で 10-24〜11-08 にまたがり、試行前と試行後の初期（11-01〜11-06）は同じ版。版の違いで説明できる差ではない。壊せなかった。
- 同時期に入った他の変更の交絡: ⚠️ 確信なし。
  - #1325 は、CLAUDE.md の行のほかに /implement「3b」の委譲の指示も同時に変えた。委譲先の改善は、どちらの変更によるかを分けられない。
  - #1331（0c1affc1、11-01）が CLAUDE.md を大きく縮め、#1388（11-03）が拒否文言を変えた。ただし試行後の初期（11-01〜11-02）の本体の率は、後の期間と同程度。
  - 行は、ユーザー個人の memory（MEMORY.md）とは独立。
- Bash 以外の経路（PowerShell ツール）: ⚠️ 確信なし。
  - PowerShell ツールの呼び出しは 598 回（重複込み）あり、here-string 相当は 35 回。PowerShell 側には heredoc を拒む hook が無く、heredoc 拒否としては数えられない。here-string の誤りは別の失敗（`@'` が本文に混入する等）で、この指標の外。
  - PowerShell の使用が試行後に増えた（本体で Bash に対する比が 1.9% → 3.6%、重複込みの粗い値）。Bash から PowerShell へ逃げただけの可能性は排除できない。この数は重複排除をしていない。
- worktree が古い main から切られていて行を持たなかった可能性: 壊せなかった。判定は中身で行っており、行を持たないまま試行後に開始した本体セッションは 0 件。委譲先の 9 件が該当し、「行なし・試行後」として別に数えられている（研究の表のとおり）。
- unknown の扱い: 判定に影響しない（本体は Bash 0 回、委譲先は 118 回で期待される拒否は 2 件前後）。

## 判定への含意

- 「本体の拒否率が下がった」を根拠にするのは弱い（p = 0.09、重複除去後で 35% 減）。強い根拠は 2 つ。(a) 行が名指しした commit・gh の本文の heredoc が本体で 5 → 0 になった。(b) 委譲先の複合 git が 3.0% → 1.5% になった（/implement 3b の変更と分けられない）。
- 名指ししていない用途（ファイルへ書く・スクリプトへ流す）の heredoc は、行があっても減っていない。
- 日数かセッション数かの二択は、そもそも土俵が違う。判定に使うなら、1 Bash あたり（重複除去後）にそろえ、上の表を使う。research.md の数を issue へ書き写すと、重複込みの誤った値が残る。
- 集計 script の直し方（リポジトリの外）: 数える行を type が assistant / user のものに絞る。さらに、tool_use の id で全ファイル通しに重複を除く。
