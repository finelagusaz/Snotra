### F5（命題 5 を壊せた）`git diff -U0` の変更行が `//` で始まるだけでは「コメントだけの変更」を保証できない
実験（scratchpad/dt/a.rs・rustc で実行）:
- **`\` 継続の文字列の次行が `//` で始まる**:
  ```
  let s = "abc\
      // x";        →  // y";
  ```
  変更行は `-        // x";` / `+        // y";` で両方とも `//` 始まり。実行結果は `abc// x` → `abc// y` に変わった（コードの変更）。検知器は通る。
  （raw 文字列 45 件の本文には `//` 始まりの行が 0 件。通常文字列の継続行は私は **全件を字句解析していない**。リポジトリに実在するかは未測定 ⚠️）
- 検知器が `+` の行だけを見る実装だと、コード行の純削除（`-` だけ・`+` 無し）を見逃す。`-` の行も見る必要がある。
- 逆向き（偽陽性）: 行末コメント付きのコード行の編集（`let n = 1; // old` → `let n = 1;`）は両側とも `//` 始まりでないので弾かれる。ブロックコメントの途中の行（`*` 始まり・無印）も弾かれる。
  安全側だが、偽陽性を握りつぶす運用になると検知器の信頼が落ちる。
- `///` / `//!` は `#[doc]` になる。`#[doc(hidden)]` 付きの項目は rustdoc に出ないが、rustdoc の lint（上記）は走る。
- 偽にする手順: dt/a.rs と同じ形（`\` 継続の次行を `//` で始める）をリポジトリで grep して 0 件なら実害は 0。手順は rawstr.mjs の strMultiHit の考え方だが、正規表現が粗く（3257 件の偽ヒット）使えなかった。**字句解析器が要る**（⚠️）。
