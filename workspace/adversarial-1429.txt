反証結果 issue #1429 調査メモ（pwsh 7.6.10 / npm 12.2.2 / npm script-shell 未設定=既定 cmd.exe / PowerShell の npm=C:/nvm4w/nodejs/npm.ps1 / Bash の npm=/c/nvm4w/nodejs/npm）
プローブ: scratchpad/adv の p.ps1([int[]])・q.ps1([string[]])・s.ps1([string])・r.ps1(VFRA)・package.json（命令行 `pwsh -NoProfile -File X.ps1` は package.json の smoke:manual と同形。manual-smoke.ps1 の param() に PositionalBinding 以外の束縛を変える属性は無いことを読んで確認）

1. Bash の npm で [int[]] が黙って 2510 になる — 壊せなかった（真）
   実測: Bash `npm run pi -- -Only 2,5,10` -> count=1 [2510]。cmd.exe /c npm.cmd でも同じ。pwsh -File 直でも同じ。
   メモより悪い追加事実: `-Only 1,3` -> [13]、`1,2` -> [12]（id 12/13 は実在する）= throw せず別項目を黙って走らせる。`2,99` -> [299]（不一致 throw）。機序は桁区切りカンマとして数値解析されること。
   偽にする手順: Bash で `npm run pi -- -Only 2,5,10` が count=3 を返す環境（pwsh の別版）が見つかれば偽。

2. PowerShell の npm.ps1 経由で "2 5 10" の 1 文字列になり [int[]] は変換エラー — 壊せなかった（真）
   実測: `npm run pi '--' -Only 2,5,10` -> npm notice `-Only 2 5 10`、値 "2 5 10" を Int32[] に変換できません。[string[]] -> count=1 [2 5 10]。`'2,5,10'` 引用 -> [2,5,10]。`--` 非引用 + `-Only 2,5` -> 位置引数エラー（#1296 防壁、メモと一致）。
   偽にする手順: npm.ps1 が空白でなくカンマで渡す版になれば偽（npm のバージョン依存。npm 12.2.2 限定の実測）。
   ⚠️ 未測: Windows PowerShell 5.1（powershell.exe）をホストにした場合。

3. [string[]] + `,`/空白分割で全経路同一、[string] は直接 `-Only 1,2` で壊れる — 壊せなかった（真）
   実測（[string[]] 後の分割結果）: Bash-npm ['2,5,10']、PS-npm ['2 5 10']、cmd npm.cmd ['2,5,10']、PS 直接 `-Only 1,2` ['1','2']、`'1,2'` ['1,2']、pwsh -File ['2,5,10']。いずれも `,`+空白で分割すれば同じ id 列。
   [string]: PS 直接 `-Only 1,2` は「値を System.String 型に変換できません」で壊れる（真）。`'1,2'` は通る。
   ⚠️ 注意: 分割後の int 変換はこちらの責務。"2 5 10" と "2,5,10" の混在や空要素（`2,,5`）の扱いは未測（実装側で決める）。
   偽にする手順: いずれかの経路で要素に `,`/空白以外の区切りが現れれば偽。

4. PositionalBinding=$false を保つ必要・ValueFromRemainingArguments 案と非両立 — 壊せなかった（真）
   実測: r.ps1（PositionalBinding=$false + VFRA の $Only）で `-File r.ps1 foo`（本来は位置引数拒否）-> exe=[] Only=[foo] と受理され、#1296 の防壁が消える。VFRA 無しでは `-Only 2 5` は「位置指定パラメーターが見つかりません」。
   偽にする手順: VFRA 付きでも位置引数が PositionalParameterNotFound になる設計（例: 別 param に限定）を示せば偽。※ #1296 の必要性自体は SnotraSmoke.Tests.ps1 の Describe で確認済み。

5. npm 入口の配列 param は manual-smoke -Only と visual-input-metrics -Fonts の 2 つだけ — 壊せなかった（ただし下限の主張）
   実測: package.json の pwsh 入口は全て `-File scripts/*.ps1`（-Command なし）。`grep '\[[a-z]*\[\]\]' scripts/*.ps1` の param 位置の配列は manual-smoke:10 / visual-input-metrics:33 のみ（他は関数 param か非 param）。visual-check-colors.ps1:203 の [array] は関数 param で入口ではない。
   ⚠️ 未測: [array]/[object[]]/複数行属性付き配列を完全には網羅していない（grep の型パターン依存）。33 個の param( のうち入口 10 本を個別に精査はしていない。「だけ」は grep の反証プローブ限り。

6. 現状は一部不一致 id を黙って落とし、全件不一致のみ throw — 壊せなかった（真）
   根拠（コード読み）: manual-smoke.ps1 181-187 行、`Where-Object { $Only -contains $_.id }` 後に Count -eq 0 のときだけ throw。追加: 上記 1 の 13/12 化により「一致して別項目」も実在。

測定環境の疑い（結論）: プローブの命令行は package.json と同形、npm は PS=npm.ps1 / Bash=sh スクリプト(npm) / cmd=npm.cmd を使い分けて 3 経路全測。script-shell 未設定 = cmd.exe 経由。壊せた主張は無し。
