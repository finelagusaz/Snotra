## 測定環境(smoke:egui)が通さない経路
S1 launch_settings_process の always_on_top(window.rs:100 と :158): smoke:egui は起動前に config を seed し、first-run で launch_settings_process が呼ばれたら throw する(smoke-egui.ps1 :423-433)。つまりこの 2 箇所は smoke:egui では通らない、むしろ通らないことを assert している。smoke-startup.ps1:141-144 も同様に launch_settings_process イベントを不在として扱う。→ 「smoke 緑でも挙動不変を示さない」。
  偽にする手順: smoke-egui の trace に cmd:launch_settings_process:spawned が出ることを示す。→ 出たら throw する設計。
S2 clamp_main_into_work_area(window_coordinator.rs:1043、view.rs:1266 が !pointer.any_down() で毎フレーム呼ぶ): smoke は打鍵注入のみで通りはする。ただし get_window が None なら early return で沈黙し、クランプ no-op と区別できない。作業領域外へ置く入力も無く、結果を assert しない。→ 「通るが検知できない」。
S3 check_show_bar_rect(:1186): toast ありシナリオで bar_rect_mismatch の「不在」assert のみ(smoke-egui.ps1 :957)。ヘルパーが None を返すと early return で mismatch が出ない=緑のまま推移する。検出器が発火しうるかを測っていない形。→ 本命の「計測コードが測る分岐と変更が触る分岐が違う」。
S4 hide_egui_main の placement 読み(:526): Escape で hide は通る。しかし placement の書き込み先 window.bin を smoke-egui は見ない(grep 0 件)。1 回目の get が None になっても placement=None で保存が静かに飛ぶだけで、egui_results:hide / main 可視状態の assert は緑のまま。.hide() 側(:528)だけが間接的に守られる。
S5 position_results_below_main(:1271): results の show は presence のみ assert。位置の正しさは見ない。main が引けず None でも results は show されうる(位置が違うだけ)。
S6 view の set_size(view.rs:1241): reset-on-show で毎回 set_size を撃ち、DWM 矩形 1 点(smoke-egui.ps1 :899-916)で実高を測る。→ ここは実際に守られている(None なら高さが変わらず FAIL)。唯一まともに踏む箇所。
S7 show_egui_main(:312): egui_show:done を待つので None なら FAIL。守られる。read_main_visible(:73): results gate が false になり egui_results:show が出ず FAIL。守られる。
S8 cfg(not(windows)): clamp_main_into_work_area / check_show_bar_rect の非 windows 版は no-op で get_window を呼ばない(:1130, :1209)。ヘルパーに移す直書きは cfg(windows) 側 2 箇所と共通コード 8 箇所。非 windows ではビルドされず、Windows 上の cargo では検査されない。ただしヘルパーは共通コードから使われるので dead_code にはならない。
S9 source-text テスト: view.rs の include_str!("view.rs")(view.rs:1406、icon_textures.rs:424)は ".controller.indexing()" / "read_visible_rows(" / "let input_idle = ..." を数える。get_window の綴りは対象外なので 1241 行の書き換えで落ちない。launcher_controller/activation/tests.rs の sources() は launcher_controller/ 配下のみを走査し、window_coordinator.rs / view.rs は母集団外。
