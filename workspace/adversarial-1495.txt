【命題1】「/code-review high <ブランチ名> は main...<ブランチ> をレビューする」 → 壊せた（部分的に偽）
- 展開文面（記録で確認）: 「Review target: `chore/1493-seam-contracts`」。Phase 0 は「git diff @{upstream}...HEAD（upstream が無ければ git diff main...HEAD / HEAD~1）を取る。作業ツリーに変更があるか範囲 diff が空なら git diff HEAD も含める。PR 番号・ブランチ名・パスが引数で渡されたら、その対象を代わりにレビューする」。ブランチ名を渡したときの差分の取り方は一切書いていない。解釈は主に任されている。
- 実際に主が打った diff: #1493 は `git diff 182714bc...HEAD -- . ':!workspace'`（base は sha・HEAD 起点）、#1494 は `git diff main...HEAD -- AGENTS.md .claude/skills`。どちらも `main...<ブランチ名>` ではない。しかも渡したブランチは当時チェックアウト中で HEAD と同一だった。ブランチ名がそのまま使われたこと、チェックアウトしていないブランチを渡したときの挙動は、どちらも未実測。
- 偽にする手順: チェックアウトしていないブランチ名を渡し、実際に走る git diff を見る。または記録の 1502 / 2371 行の tool_use を読む（読み済み）。
- 追加の欠陥（重要）: ローカル main は stale。今この worktree で main は 6903204e、origin/main は 9c125eaa。ブランチに独自コミットが無いのに `git diff main...HEAD --stat` は 2 files changed を出す（#1494 の変更）。つまり「main...」を対象に固定すると、他 PR の差分が混ざる。#1494 のレビューが出した指摘（ローカル main の遅れ）と同根。対象を `main` 起点で名指すのは危険。origin/main か、アンカー sha を使うべき。

【測定環境の疑い】
- code-review は harness 同梱でリポジトリの外。展開文面（Phase 0 の文）は版で変わりうる。今回の実測は 1 セッションで、2 つの呼び出しとも同じ版・同じ文面（grep で確認）。別セッションで同じ文面とは限らない。
- 結論への効き方: 「ブランチ名を渡すと main...<ブランチ> になる」を SKILL.md に断定で書くと、harness の版で偽になりうる。SKILL.md には「対象を名指す」ことと、「stale な `main` を起点にしない」という自分側の原則だけを書き、harness の内部手順は写さない（governance-docs「機構の実装の詳細を散文へ写さない」）。さらに、レビューを呼んだ後に主が、実際に走った git diff の base を確かめる一手を足すと、版ずれに強い。
- 主の記録は、1 本のセッション・既存コミット済みブランチ上の実測にすぎず、チェックアウト外ブランチ・upstream あり・stale main 以外の条件は測っていない。
