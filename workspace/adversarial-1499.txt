### 争点3: decide の CWD_CHANGE・hasSafeChain・main() を同じ正規化へ → 壊せなかった（実測で確認）
- main()（pre-bash.mjs 573 行）は tokenStart(GH_PR_CREATE, command) を decide とは別に呼ぶ。実測: decide(`gh pr create`, readVerifyState(cwd, tool=null)) → block 理由「要約の置き場を導く scripts/verify-tree.mjs を読み込めませんでした」（偽の理由）。

- hasSafeChain は内部で tokenStart(GH_PR_CREATE) を呼ぶので、raw のまま渡すと ghAt<0 → false（動的判定へ落ちる・fail-closed だが理由が別）。
- メモが落としていた点: 正規化の適用範囲。decide の入口で command 全体を norm 化すると judgeCommandShape が弱る。実測: `git push -u origin HEAD && gh pr create --body-file "C:\Users\x\y.md"` は raw では backslashPath で BLOCK、norm 済みを decide へ渡すと別の理由に変わり（`\` が消えて usesBackslashPath が発火しない）、plan/verify/git が緑なら allow になる。`git commit "--no-verify"` は norm 後 BLOCK（逆に増える）。つまり「前処理して既存の GH_PR_CREATE に通す」を decide 入口で行うのは誤り。gh 検出専用の位置関数（ghAt/hasSafeChain/CWD/main が共有する 1 つ）にだけ入れる設計が要る。この点はメモに無い → 追加すべき欠落。
- 偽にする手順: tokenStart の GH_PR_CREATE 引数を 1 箇所のラッパにして main/decide/hasSafeChain/CWD 比較が全て同じ関数を使い、judgeCommandShape は raw のままにすれば、争点3の懸念は消える（メモの主張の裏返し）。

### 争点4: 過剰検出は fail-closed だけで、正当コマンドを新たに block しない → 壊せた

### 争点5: 前処理にすれば指数爆発を招かない → 壊せなかった
