== 争点 1: 中核は成立、記述は壊せた ==
成立: upstream 無しで tip が origin/main、HEAD が古い main のとき、-d は "not fully merged" で失敗する（`--no-track` で作った A'、sha から作った A2、update-ref だけで追跡ブランチを置いた t の b1 で再現）。origin/main は upstream でない限り見られない。
壊せた点:
 (a) 「upstream があれば upstream、無ければ HEAD」は不正確。upstream の参照先が存在しない（gone）と HEAD 基準に落ちる（K: gone upstream でも HEAD に merged なら成功）。upstream があり、それに未 merge だと、HEAD に merged でも拒否される（L: "not deleting ... even though it is merged to HEAD"）。
 (b) upstream を持つと、HEAD に未 merge でも upstream に merged なら警告つきで成功する（A, B, J）。
 偽にする手順: 一時リポジトリで K（branch.X.remote=origin, merge=refs/heads/gone を config）と L（--set-upstream-to=<無関係ブランチ>）を作り `git branch -d X` を打つ。
⚠ 落とし穴（research.md に無い）: `git branch X origin/main` と `git worktree add -b X path origin/main` は、始点が追跡ブランチだと upstream を自動で付ける（G, A で確認）。この始点で作るとバグが再現せず、テストが偽の緑になる。始点は sha か `--no-track`。sha 始点の `worktree add -b` は upstream 空を実測（t の b2）。

== 争点 2: 成立（壊せず）、ただしテスト側に罠 ==
cmdRemove の git(root, ["branch","-d",…]) は本体ルートで走り、root は mainRoot（git-common-dir の親）。コードで確認。「linked worktree から打つと HEAD が変わる」対比は、私の worktree add が失敗して未実測（⚠ 未測）。
⚠ 測定環境の罠: verify-tree.test.mjs の initRepo は seed の後に `checkout -b feat/x` するので、root の HEAD は main でなく feat/x。align 版の既存テストは commitFile で repo の HEAD(feat/x) を進めるので、delegate ブランチ(seed)は HEAD の祖先になり -d が通る。つまり既存テストはバグ経路を踏まない。再現テストには「HEAD に含まれない commit を origin/main に置き、upstream 無しのブランチをその tip に置く」が要る。

== 争点 3: 概ね成立、条件つき ==
成立: --is-ancestor は祖先 rc=0、非祖先 rc=1、参照無し rc=128（実測）。origin/main が無いリポジトリは 128 → 従来どおり -d。
 実装時の条件:
 - execFileSync は 1 でも 128 でも throw する。e.status で 1（偽）と 128（origin/main 無し）を分けないと、「消さず報告」と「-d に任せる」が混ざる。
 - `origin/main` は同名のローカルブランチ・タグに曖昧に当たりうる。`refs/remotes/origin/main` と書く方が堅い（⚠ 実害は未測）。
 - 固有コミット付き（E）は -d が拒否する。受け入れ条件 2 は満たす。ただし固有コミットが root の HEAD に含まれるときは -d が成功する（正しい挙動）。
 - squash マージでは固有コミット付きの委譲先は祖先にならず残る（issue も認めている）。効くのは「コミットを作らなかった委譲先」だけ。
 - 「既存テストを壊さない」の根拠は、リモート無しで祖先分岐が 1 度も走らないこと。つまり新分岐は既存テストでは何も測れていない。新テストを足さない限り、祖先分岐が壊れても緑のまま。
 偽にする手順: 修正後、(i) 既存 initRepo（origin 無し）、(ii) update-ref で origin/main を置いた repo、の両方で `remove --delegate-tree` を走らせ、(ii) だけで消えること、固有コミット付きなら (ii) でも残ることを確かめる。祖先分岐を `false` に潰す変異を入れて新テストが落ちるかも見る。

== 争点 4: 部分的に壊れる ==
成立: clean-worktrees.mjs の孤児削除は `git branch -d` を cwd で打つ。-d の構造は同じ。
壊せた点: HEAD は「そのセッションのブランチ」であり本体の main とは限らない。セッションの HEAD が origin/main の先端（または委譲先の tip）を含めば -d は通るので、症状は HEAD が古いときだけ出る。「同じ不具合」は条件つき。「同じ修正で直る」は、判定を clean-worktrees 側にも入れたときだけ（共通化しなければ直らない）。
テスト側: clean-worktrees.test.mjs の initRepo は HEAD=main（`init -b main`）、addAgentWorktree は HEAD を始点に `worktree add -b`（upstream 無し）。新テストは、HEAD の無い commit を origin/main に置いて、その tip に worktree-agent-* ブランチを置く必要がある。
 偽にする手順: HEAD が origin/main の先端を含むブランチ（例: origin/main から切ったブランチ）上で、tip が origin/main のブランチを -d する（成功することを確認する。A の警告つき成功と同型）。
