## 命題 4: ENV_PREFIX・FLAG に引用値選択肢を足せば素通りが塞がり指数爆発しない → 壊せた（そのままでは退行する）が、爆発しない点は壊せなかった
試作（workspace/_proto/.claude/hooks/pre-bash.mjs）:
- ENV_PREFIX 値 = `(?:"[^"]*"|'[^']*'|[^\s"'])*`、FLAG 値 = `(?:"[^"]*"|'[^']*'|[^-\s"'])(?:"[^"]*"|'[^']*'|[^\s"'])*`。
壊せなかった点（塞がる・爆発しない）:
- `GH_TOKEN="a b" gh pr create`・`gh --repo "a b" pr create`・`A="a b" git pull`・`A="a b" git commit --no-verify`・`git -C "C:/my dir" pull`・`A="x y" python -c "あ"` は検出する（コーパス 86 件で差分はこの 5 種類の正しい検出拡張のみ）。
- 時間: 25 万字級の病的入力（引用が対にならない・FLAG 2 万個・ENV 5 千個・引用の混在）で元・試作とも 1〜6ms。指数爆発なし。
壊せた点:
- **退行**: 引用が対にならない値で、元は検出していたものが試作では検出しなくなる。`A=it's git pull`（pull: true→false）、`A=" git pull`（true→false）、`A=it's git commit --no-verify`（nv: true→false）、`A=it's python -c 'あ'`（needsPyEncoding: true→false）、`A=it's gh pr create`（sites 2→1）。アポストロフィを含む環境変数値は現実にありうる。fail-open 方向の退行。
  - 緩い fallback（`\S` を選択肢に足す）で直そうとすると排他でなくなり指数爆発する: `(?:"[^"]*"|'[^']*'|\S)*` は `A=` + `"a"`×20 で 676ms、×22 で 5119ms（実測）。
  - 現実的な直し: usesNoVerify/pullWithoutFfOnly では見え方との OR が退行を埋める（上の値は protoNvView/protoPullView が true）。needsPyEncoding と ghPrCreateSites は見え方側（gh は既に OR）だが、needsPyEncoding は見え方を使わないので `A=it's python 'あ'` が素通りに戻る。
- 引用値が閉じ引用の直後に文字が続く形（`A="a"b`）は試作でも検出（退行なし）。
- 偽にする手順: 試作に `A=it's git pull` を通して false を確認する（_r.mjs 相当）。爆発の件は `_s.mjs` 相当の正規表現を 1 本走らせる。

## 命題 5: ENV_PREFIX の変更は PYTHON_AT_CMD・GIT_AT_CMD の検出も広げ、向きは過剰検出だけ → 壊せた（広がるのは事実だが向きは片方向でない）
- 広がること自体は成立: 試作で needsPyEncoding(`A="x y" python -c "あ"`) が false→true、gitSegments が 0→1 件。
- 向きが過剰検出だけとは言えない: 命題 4 の退行（`A=it's python …` の needsPyEncoding true→false、`A=it's git commit --no-verify` の usesNoVerify true→false）は検出が**減る**方向。壊すのは未対の引用を含む値のとき。
- 新たに検出される形のうち、`A="x y" python -c "あ"` は真の検出（元は過小検出）で、過剰検出ではない。`A="a b" git pull` も真陽性。つまり「過剰検出だけ」は偽、「真陽性の取りこぼしが埋まる＋未対引用で後退」が実測。
- 偽にする手順: `A=it's python -c 'あ'` を HEAD と試作で needsPyEncoding に通し true→false を確認する。
