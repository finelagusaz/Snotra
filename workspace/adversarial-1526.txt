[壊せなかった 1] 「区切りを含む needle は Prefix/Substring でも区切りを含まない name/file_name に一致しえない」
  読んだもの: match_score_single_cached（Prefix = starts_with、Substring = memchr の Finder::find のバイト一致）、
  QueryPlan（norm_query_has_path_sep = contains_path_sep(norm_query)、contains_path_sep は '\' '/' '¥' の 3 つ）、
  normalize_for_match、score_one_entry の skip_name / needs_fn_score、assemble の any_name_has_path_sep（names_blob と lower_names.blob と lower_file_names.blob の 3 本を舐める）。
  反例を探した方向と結果:
  - needle の区切りバイトが haystack の別文字にまたがる: '\' '/' は ASCII 1 バイト、'¥' は C2 A5 の 2 バイト列で、妥当な UTF-8 では必ず 1 文字としてしか現れない。needle が名前に連続一致するなら、名前はその区切り文字そのものを含む。反例なし。
  - 正規化が区切りを作る/消す: needle 側は正規化「後」で判定している。haystack の lower_name は正規化後の文字列で、any_name_has_path_sep は表示名の blob と正規化後の blob の両方を見る。全角の区切り等が正規化で '\' に畳まれても、lower_names.blob() に現れて true になる（飛ばさない側へ倒れる）。反例なし。
  - kana 経路: skip_name は name/file_name の照合だけを飛ばす。primary_score が None のときだけ kana を見る構造は同じ。skip しなくても name/file_name は不一致（None）なので、kana の結果は同じ。kana_lower_names の中に区切りがあっても、skip の有無で結果は変わらない。反例なし（kana_lower_names は any_name_has_path_sep の測定対象外だが、skip の対象でもない）。
  - file_name 経路: needs_fn_score は !skip_name && ... なので、skip で fn_score = None。lower_file_names.blob と SameAsLowerName（lower_name と同一）は測定済み。反例なし。
  - tie-break/順序: スコアは「一致した候補」にしか付かず、skip は None だった照合を飛ばすだけ。一致集合が同じなら順序も同じ（TopK は ScoredEntry::Ord のみ）。反例なし。
  - 空の needle: norm_query が空なら prepare_query_plan が None。反例なし。
  - has_path_sep（生クエリ）と norm_query_has_path_sep の食い違い: 現行は外延的に一致するとコメントがある。⚠️ Fuzzy のコメントが「この条件だけは検知器を置けない」と明言している。Prefix/Substring へ広げても同じ性質。
  残った穴（論証ではなく検知器の話）:
  - 既存の等価性検知器 skipping_name_scoring_changes_nothing_over_real_index は SearchMode::Fuzzy のみ・migemo=false（new_with_migemo(entries, false) なので kana 列は空）・PATH マージ無し。Substring/Prefix へ広げても、このテストは 1 バイトも広がった分岐を通らない。
  - fuzzy_name_match_survives_when_display_name_contains_path_separator も Fuzzy のみ。広げるなら Substring/Prefix の同型を足さないと、「飛ばす条件を has_path_sep だけに緩める」変異が全モードで素通しになる。
  - sorted_prefix_fast_path_changes_nothing_over_real_index は Substring でパスクエリを打つが、比較する両エンジンが同じ skip_name を通るので、skip_name の等価性は見ていない（取り違え注意）。
  この所見を偽にする手順: name/file_name のどれかに '\' '/' '¥' を含まないのに、それらを含む正規化済み needle へ starts_with/find が真を返す (name, query) の組を 1 つ作る。合成なら Substring モードで make_entry("c:\\tool", ...) のように表示名に区切りを含めると any_name_has_path_sep が true になり、skip しない側へ倒れる（これは反例ではなく安全側）。区切りを含まない名前で一致が起きる組は、UTF-8 の性質上、存在しない。

  - wave1_from_tree の呼び出し元は new_from_tree と new_with_cached_masks の None 分岐。new_from_tree は from_material の masks = None 分岐からだけ。
