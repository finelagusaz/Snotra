【争点4】git() の失敗例外は e.stderr を utf8 文字列で持ち、main の catch は EnvError の message をそのまま出し exit 2
- 結論: 概ね壊せなかった。⚠️ 1 点だけ「常に」ではない
- 実測 (node): git が非 0 終了 → e.stderr は utf8 文字列（git() は encoding:"utf8", stdio:"pipe"）。main(432-436 行)は EnvError なら e.message を `verify-tree: ` 付きで console.error、return 2。
- ⚠️ 壊せた部分: 「失敗例外は e.stderr を持つ」は spawn 失敗では偽。cwd 不在 / git 不在は code=ENOENT で `e.stderr` が undefined（research 30 行の `e.stderr ?? e.message` が message へ落ちる、は正しい）。timeout は stderr が空文字 "" で `??` が効かない（ETIMEDOUT で実測）。resolveSha は timeout 無しで呼ぶので実害なし。git が stderr 無しで非 0 終了した場合も `""` で message に落ちず、末尾が空になる。実装は `e.stderr ?? e.message` を鵜呑みにせず、空なら message に落ちる形（`||` か trim 後の空判定）を考える余地がある。
- 偽にする手順: resolveSha の git 呼び出しに timeout を付ける、または git が無い環境で実行 → stderr が "" / undefined になる。

【争点5】テスト内で同じ git コマンドを打って得た stderr が出力に含まれる、で書けば locale に依らない
