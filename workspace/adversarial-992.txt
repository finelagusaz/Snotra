--- 4a. 発見した欠陥: isRsComment は実コードを「コメント」に誤分類する ---

`tick-probe2.mjs` の `isRsComment = (line) => /^\s*(?:\/\/|\*|\/\*)/.test(line);` は「行頭が `*`」という理由だけでコメント扱いする。しかし Rust では **デリファレンス代入文が行頭 `*` で始まる**（例: `*self.config.write().unwrap() = config;`）。これはブロックコメントの外側にある正真正銘のコードである。

独立に「ブロックコメントの開閉状態を実際に追跡する」健全な走査器を実装し（`rs-comment-audit.mjs`、本ファイルと同ディレクトリに保存済み）、`isRsComment` の判定と突き合わせた:

```
naive(isRsComment)=12423  sound(状態追跡)=12364  naiveのみに在る行(誤検出候補)=59
```

**59 行の実コードが `isRsComment` によって「コメント」として `checked` にカウントされている。** 内訳の一部（`snotra-core/src/engine.rs:251`、`snotra-core/src/history.rs` 複数、`snotra-settings/src/tabs/backup.rs:159,176` 等）はすべて確認済みの本物のコード行であり、コメントではない。

**この欠陥は現在のスナップショットでは「ヒット」を1件も生んでいない**（59行のいずれもバッククォートを含まない）ので、research.md の「6箇所・偽陽性0」という**具体的な列挙**は崩れない。しかし、**「checked の分母が汚染されている」「isRsComment は将来のコードで偽陽性を生みうる不健全な述語である」**という指摘は独立に成立する——たとえば `*b"TEST"` のような byte-string 系や、将来デリファレンス行にバッククォート付き char リテラル（`*c == '`'`のような書き方は考えにくいが、コメントで無いものが混入する経路自体は塞がれていない）が来れば、案A/Cの実装が同じ述語を流用すると誤検知しうる。**案A/Cを実装するなら `isRsComment` ではなく、状態追跡版（`inBlock` を追うもの。wrap-probe.mjs の `commentLines` や `lib.mjs` の `linesOfComments` と同型）を使うべきである。**

これを偽にする手順: `node "<scratchpad>/rs-comment-audit.mjs"` を再実行し、`naiveのみに在る行` が 0 になれば、この所見は崩れる。

--- 4b. launcher_controller.rs:2028 は「コードスパンの分解を説明している例示文」であり、性質が特殊 ---

該当行を実際に開いて読んだ:
```
/// **代償は整形と書き方への脆さで、向きは赤側である**: `let should = crate::egui_shell::…;
/// if should {` のような分解や、rustfmt が `if` とパスのあいだで折り返す形はここを赤にする。
/// 偽陽性であって沈黙ではないので受容する（直すなら綴りを短くするのではなく、当該の並びへ
/// 合わせて綴りを更新すること）。
```
これは **別の（無関係な）検査の偽陽性を「受容する」と説明している doc コメントの本文**であり、たまたまその説明文自身が「行をまたいだコードスパン」の**実例**の形をしている（意図的な例示か、単なる偶然かは断定できない）。

- **構文的には本物のヒットである**——バッククォートは実際に行末を越えて閉じていない。M4 の述語（奇数バッククォート）が「grep が壊れる」ことの代理指標である以上、構文的な意味では偽陽性ではない。
- **しかし意味的には、規約が想定する害（「識別子・コマンドを grep で辿れなくなる」）が実際に発生するケースとは性質が違う**——`let should = crate::egui_shell::…; if should {` は誰かが grep で辿ろうとする実在の識別子/コマンドの引用ではなく、パターンを説明する非実在の例示コードである。research.md の M3/M4 が「0.1%は実害に当たる」と主張するとき、この1件を「実害」側に数えるのは過大評価の余地がある——**6件中1件（16.7%）は、規約が動機として挙げた「grep が壊れる実害」の典型例とは言えない**。

**この所見は⚠️（確信度中）として扱う**——「意図的な例示だから除外すべき」という判断は編集者の意図の推測を伴い、決定的な一次証拠（コミットメッセージや ADR での明言）を見つけていない。しかし規約の趣旨（`.claude/rules/` が grep で辿る規約に依存すること）に照らすと、この行を「同じ重みの実害」として数えるのは疑わしい。
