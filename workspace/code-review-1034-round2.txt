### R2-H1. 「予算 16,700 µs は trace 2 本ぶんの間隔で超える」を、同じ bullet の実例が反証する
場所: PERFORMANCE.md:1666-1667
反証: PERFORMANCE.md:1660-1662（同 bullet の 5 行上）

書き換えで単位が「1 行あたりの費用」から「連続する 2 行の間隔」へ移った結果、この派生値の
算術が合わなくなった。**間隔は行と行のあいだにしか無い**ので、trace n 本が作る間隔は n−1 個である:

- 「trace **2 本**ぶんの間隔」= 2 本が作る間隔 = **1 個** = 10〜18 ms。16,700 µs を**超えない場合がある**。
- しかも同じ bullet の :1661-1662 が、まさにその 2 本の実例を挙げている——
  「`SearchDispatch::issue` と `SearchState::set_results` しか挟まない区間で **12 ms**」。
  12 ms < 16.7 ms なので、**bullet の主張を bullet 自身の測定値が反証している**。
- 「2 個の間隔」を意図しているなら必要なのは trace **3 本**（10〜18 ms × 2 = 20〜36 ms で常に超える）。

書き換え前は「1 本 10 ms × 2 本 = 20 ms」で算術が閉じていた。**単位を変えたときに派生値の
導出を引き直さなかった**——`AGENTS.md`「件数 N・上限パラメータ・**導出の入力**を変更」の行が
言う「変わった値を誰が消費するか」に当たる。

修正案: 「**60fps の予算 16,700 µs は間隔 2 つ（trace 3 本）で超える**」。
同じ直しが `workspace/plan.md` の「実装時の逸脱 (1)」にも要る（R2-L3）。

  宣言するのが最も強い**——読者が絶対値を使わない理由はそれで十分に立つ。
- または調停を書く: 「1 回ごとの書き込み時間は #1032 の控除計器が測っており（`:548` の 50〜96%）、
  一方で起動段の A/B では 1〜2 行の ON/OFF 差が雑音だった。**両者は未調停である**」
