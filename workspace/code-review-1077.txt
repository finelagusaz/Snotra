## Medium

### M1. SPEC.md §4.7 の新しい 1 行が自己矛盾している（SPEC.md:204）

根本原因: 「Enter・Shift+Enter・クリックは、起動もツール選択への遷移も行わない」と書いた直後に
「止めるのは不可逆な起動だけであり」と書いている。ツール選択への遷移は Escape で戻れる可逆な操作
（shift_activate:611 の enter_tool → on_escape_pressed で復帰）であり、後半の文が前半の文を否定する。
実装コメント側の「不可逆な起動だけを止める」は「行データを消さない」という意味であって
「可逆な操作は止めない」ではない。SPEC へ写す途中で射程が変わった。

修正例（1 語だけ変える）:
  止めるのは操作だけであり、行データと選択は消さない。構築が終われば……

この所見を偽にする手順: shift_activate の tools >= 2 枝で入ったツール選択ビューから Escape で
戻れないことを示す（on_escape_pressed の EscapeOutcome を読む）。戻れないなら不可逆であり矛盾は消える。

### M2. SPEC.md の「構築が終われば同じ行がそのまま使える」が実装より強い（SPEC.md:204）

根本原因: index build の完了は consume_external_pending（launcher_controller.rs:1076）の
needs_index_refresh で検知され、その場で run_search() が走る。Plain 枝は新しい索引に対する検索を

ゆえに構築後に残るのは「同じ行」ではなく「作り直された行」で、内容は変わりうるし選択は clamp される。
保証できるのは「構築中の Enter が行を壊さない・構築後にもう一度操作できる」までである。

修正例:
  構築が終われば行は作り直され、そのまま操作を続けられる

この所見を偽にする手順: needs_index_refresh が真になったフレームで run_search が呼ばれないこと、
または Plain 枝が set_results を通らずに前の行を恒久的に保つことを示す。

### 訂正 1 — H1 の「無音の no-op」は言い過ぎだった。実際はもっと悪い

execute_slash（launcher_controller.rs:439）はどのコマンドでも先に clear_search() を呼び

  見た目は成功時と区別が付かない）
この所見を偽にする手順は変更なし: 構築中に /s を打って start_index_build が走ることを trace で示す。

### 訂正 2 — W2「到達不能」に未検証の前提が 1 つ残っていたので、埋めた

### Medium — M5. SPEC.md:560 の「見た目は成功時と区別が付かない」が設定オープンには当たらない

該当箇所: 「拒否されてもクエリのクリアは走り、索引再構築ではさらに非表示も走るので、

索引再構築（/s）については正しい——成功でも拒否でも clear_search + emit_hide が走り、窓が消える。
しかし設定オープン（/o）は区別が付く:

  可視＝degraded な理由提示」と書いており、実装は「区別が付く」ことを意図している。

  区別が付かない。設定オープンでは設定ウィンドウが現れないことと status 行の構築中案内が
  唯一の手がかりになる（意図的無音・#434）

この所見を偽にする手順: 構築中でない状態で /o を打ち、設定ウィンドウが現れないことを示す
（現れるなら成功と拒否は区別が付く）。あるいは OpenSettings 枝が emit_hide を呼ぶことを示す。
