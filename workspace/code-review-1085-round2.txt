### H1. コメントの潰しと引用符の数え上げが互いを知らない 2 パスで、誤りが両方向へ出る

場所: C:/workspace/Snotra/scripts/governance-check.mjs:204-230 (blankRustComments)
      C:/workspace/Snotra/scripts/governance-check.mjs:232-245 (insideStringLiteral)
      適用は :250 と :270

根本原因（一文）: blankRustComments は文字列リテラルを知らないので文字列の中の // /*
をコメント開始として扱い、insideStringLiteral はコメントを潰した後のテキストで " の偶奇
だけを見るので、前段が食べてしまった引用符の分だけ位相がずれる——つまり各パスの数え違いが、
もう一方の判定を反転させる。

(a) 通常の Rust コードが赤くなる（実測。real.rs は実在し mod real; は本物の宣言）

| 入力（lib.rs） | 結果 |

| pub const S: &str = "/*"; ＋ mod real; | 赤（ブロックコメントが開いたまま閉じず、以降のファイル全体が潰れる） |
| 先頭 BOM ＋ mod real; | 赤（列 0 から外れる。→ L5） |

(b) 沈黙する経路が残っている（実測 4 経路。ghost.rs は宣言されていない孤児）

|---|---|
| pub const S: &str = r#"x"y / mod ghost; / "#; | 緑 — raw string の内側の " が奇数だと偶奇が合ってしまう |
| pub const S: &str = r#" / #[path = "ghost.rs"] / mod g; / "#; | 緑 — #[path] の枝（:257-266）には文字列フィルタが掛かっていない |
| pub const U: &str = "http://x"; / pub const S: &str = " / mod ghost; / "; | 緑 — (a) の位相反転が、後続の本物の文字列の中身を「文字列の外」に見せる |
| pub const Q: char = (char リテラルの二重引用符); / pub const S: &str = " / mod ghost; / "; | 緑 — 同上 |
| 対照: 複数行文字列だけ（位相反転なし） | 赤 OK（M2 の修正自体は効いている） |

つまり「M2 は塞がったのではなく狭まった」が正確な表現である。

修正例（構造で塞ぐ場合）: 2 パスをやめ、1 パスの字句スキャナにする。状態を
code / 行コメント / ブロックコメント(depth) / 文字列 / raw string(# の数) / char で持ち、
コード以外を長さと改行位置を保ったまま空白へ潰す——そうすれば insideStringLiteral は不要に
なり、#[path] の枝にも同じフィルタが自然に掛かる（上表 2 行目の原因）。実装時の罠を名指し
しておく。ここを外すとラウンド 3 で同じ議論になる:

  - char リテラルとライフタイムの区別。二重引用符の char は char、シングルクォート + a は
    ライフタイム。^ シングルクォート (バックスラッシュ. | [^シングルクォート バックスラッシュ])
    シングルクォート に当たるときだけ char 開始と見なす（現状ライフタイムは " を数えないので
    無害だが、スキャナ化すると新たな罠になる）
  - raw string の # は任意個（r"…" / r#"…"# / r##"…"##）、byte string b"…" / byte char b(char)
  - 先頭 BOM を落とす（L5）
  - #[path] の枝にも同じ潰し済みテキストを使う

受容する場合でも、上の 8 入力は .claude/rules/safety-nets.md「検出器のカバー範囲は、欠落の
パターンごとに検算する」の足そのものなので、そのまま赤いフィクスチャとして使える
（複製へ当てており、稼働中のガードは触っていない）。

任意提案（そちらの判断で・確信度は中）: 上の margin 測定（95 枚へ mod probe_zz; を足して
拾われるかを見る）は、ルート / mod.rs に絞れば 1〜2 秒でドッグフード・カナリアにできる。
「実ファイルで宣言が拾えている」ことを固定する唯一の形である。
