## 肯定的に検証した事項（逆向きの監査を含む）

### V1. `main.rs` から消えた `if !path_entries.is_empty()` ガード — 挙動不変を呼び先で検算した

削除された 3 行が守っていた不変条件は「PATH が空のとき索引の状態を一切動かさない」であり、これは**呼び先の実装によって保たれている**:

- `IndexTree::extend_with_roots`（`snotra-core/src/index_tree.rs:403-405`）は先頭に `if entries.is_empty() { return; }` を持つ。**load-bearing なのは早期 return の「位置」である**——`return` は関数末尾の `*sorted_by_path = false;`（`:431`）より前にあるので、空の呼び出しは整列の旗を倒さない。早期 return が無い（あるいは末尾の代入より後にある）実装だったら、ガードの無条件削除は「PATH が空でも整列済みの木が遅い経路へ落ちる」——結果は変わらないが性能だけ落ちる、テストで捕まらない種類の退行になっていた。
- `indexer::extend_cached_masks`（`snotra-core/src/indexer.rs:1636`）の本体は `for entry in new_entries` ひとつだけで、3 腕（`None` / `Raw` / `Collapsed`）はすべてループの内側にある。空スライスでは完全な no-op。

→ plan.md D2 の主張「`main.rs` にある現行のガードは挙動を変えずに落とせる」は**真**である。

### V2. 消した行が守っていた警告の再確立地点

`PERFORMANCE.md` の候補表から消えた行は次の警告を持っていた: 「繋いだ日に呼び忘れると**マスクだけが短くなる**。`assemble` の長さ検証は `debug_assert` ゆえ release では消える」。

`main.rs` から消えたもう 1 つの案内（「整列の旗の扱いは `IndexTree::extend_with_roots` の doc」）も失われていないが、**呼び出し点から 2 ホップ**になった（`merge_path_entries` の doc が intra-doc link で持つ）。指摘ではなく記録。

### V3. マスクと木の長さの整合が `assemble` まで保たれる

### M1. `Option<&mut CachedMasks>` は 2 つの呼び出し点での取り違えを防がない。しかも `&mut Option<CachedMasks>` を却下した記録上の理由は D1 の反転で**失効している**

場所: `snotra-core/src/indexer.rs:1695-1699`（署名）/ 呼び出し点 `src-tauri/src/main.rs:199`・`src-tauri/src/indexing.rs:114` / 却下の記録は `workspace/plan.md` D2（:34）と `workspace/research.md`（:36）

根本原因（壊れた不変条件）: 「マスクを持っているなら必ず追記する」が型で表現されておらず、`masks` が `Some` であるのに呼び出し点が `None` を渡す形が**コンパイルを通る**。

- 現署名では `indexer::merge_path_entries(&mut tree, None, path_entries)` が両呼び出し点で合法である。そのとき症状は「マスクだけが短い索引」——debug では `assemble` の `debug_assert`（`search/build.rs:184`）が鳴るが**release では消え**、再構築後の初回検索で添字外 panic → `panic="abort"` でプロセス終了になる（`merge_path_entries` の doc 自身が記す症状そのもの）。
- **新設・書き換えた検知器はこの誤りに当たらない。** 2 本はいずれも `merge_path_entries` 自身を測るもので、**呼び出し点が何を渡したか**は測っていない。「閉じたのは現存する呼び出し点」という記述は「両方が同じ関数を呼んでいる」ことしか意味せず、「誤った引数が捕まる」ことを意味しない——この 2 つを同一視しないこと。
- plan.md D2 は `&mut Option<CachedMasks>` を「drain 側が `Some` へ包んで後で `unwrap` する形になり、到達不能な panic 経路が生える」として却下した。**これは反転前の D1（drain が素の `CachedMasks` を受け取る）を前提にした記述であり、D1 が反転した時点で失効している**——現行では両呼び出し点がともに `Option<CachedMasks>` の `mut` 束縛を持つ（`main.rs:184` の `let (mut tree, initial_indexing, mut cached_masks, rescan_task) = …`、`indexing.rs:106` の `let (mut tree, mut cached_masks) = …`）ので、`&mut cached_masks` をそのまま渡せ、包みも `unwrap` も要らない。
- 素性: この形なら**「`Some` を持ちながら `None` を渡す」が書けなくなる**（渡せる値が `&mut cached_masks` の 1 つに定まる）。plan.md が挙げた代償は現行の型では発生しない。

修正例（`indexer.rs`）:

    pub fn merge_path_entries(
        tree: &mut IndexTree,
        masks: &mut Option<CachedMasks>,
        entries: Vec<AppEntry>,
    ) {
        if let Some(masks) = masks.as_mut() {
            extend_cached_masks(masks, &entries);
        }
        tree.extend_with_roots(entries);
    }

呼び出し点は `indexer::merge_path_entries(&mut tree, &mut cached_masks, path_entries)` の 2 か所へ。検知器（`build.rs:298` / `:363`）は `Some(&mut masks)` → `&mut Some(masks)` 相当、`None` → `&mut None`。

**確信度と未検証部分**: 型検査が通ることは**読解で確かめた**（両束縛が `mut` の `Option<CachedMasks>`・`as_mut()` の借用は呼び出し式で終わり後段の move / `match` と衝突しない）。**実際にコンパイルはしていない**——署名変更は 3 ファイルに跨るため、レビューで差分を作らない判断をした。採否の前に `cargo check --workspace` で確かめること。

**現状はバグではない**（両呼び出し点は正しく `cached_masks.as_mut()` を渡している）。構造的脆弱性としての Medium である。
