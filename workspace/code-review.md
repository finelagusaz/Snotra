## 発見事項（重大度順）

### H1（High）: `FLAG` の 2 通り解釈により `usesNoVerify` / `pullWithoutFfOnly` が指数時間になる（I2「線形・never hang」違反）

- **場所**: `.claude/hooks/pre-bash.mjs:49`（`FLAG`）→ `:214`（`GIT_COMMIT`）/ `:215`（`GIT_PULL`）→ `:219` / `:226`。既存の `:57`（`GH_PR_CREATE`）も同じ `FLAG` を 2 回使うため同じ性質を持つ（#482 由来で本 PR 前から在るが、**露出面が「gh を含むコマンドだけ」から「全コマンド」へ広がったのは本 PR である**）。
- **根本原因（壊れた不変条件）**: `-{1,2}\S+` は `--x` を「`-` + `-x`」と「`--` + `x`」の 2 通りに解釈でき、**どちらも同じ位置で終わる**ため、全体マッチが失敗する入力では V8 のバックトラッキングが 2^n 通りを全探索する — plan.md I2 と `docs/hooks.md:31` が要求する「全域関数（never hang）」「線形」が破れている。
- **実測**（`git ` + `--flag=v ` × n + `status`。1 トークンあたり ×2 で伸びる）:

| n | コマンド長 | `usesNoVerify` |
|---|---|---|
| 18 | 172 字 | 16 ms |
| 20 | 190 字 | 80 ms |
| 22 | 208 字 | 286 ms |
| 23 | 217 字 | 616 ms |
| 24 | **226 字** | **1237 ms** |

  `pullWithoutFfOnly` が同じ入力を独立に再計算するので `judgeCommandShape` 全体では約 2 倍。`GH_PR_CREATE` は `gh ` + 同 24 トークンで 490 ms。**n=20000 の入力では 553 秒 CPU を使って終わらず、レビュー中にこちらで kill した**（`Stop-Process` で確認済み）。
- **影響**: hook が timeout すると exit が 2 以外になり、`pre-bash.mjs:12-15` の契約どおり**非ブロッキング＝コマンドはそのまま実行される**。つまり hang は「待たされる」だけでなく **fail-open** でもあり、plan.md が「壊れたら即アウト」に挙げた 2 行（全 Bash の停止・ガードが沈黙で外れる）の両方に同時に当たる。
- **なぜ Critical ではないか**: 発火には「`git` の直後から連続する `--` 始まりトークンが 25 個以上」が必要で、実際に打ちうる形（`git --no-pager log` に長いフラグ 14 個 = 2.2 ms）では届かない。ただし上限は無く、25 と 30 の差が 1 秒と 80 秒の差になる。
- **修正例**（実測で挙動同値・44/44 一致）: `FLAG` の 2 通り解釈を消す。regex source を
  `(?:(?:--?[^-\s]\S*|--)(?:\s+[^-\s]\S*)?\s+)*`
  へ変える（`--?[^-\s]\S*` で「ダッシュの直後は非ダッシュ」を強制し、`--` 単独トークンだけ別枝で残す）。実測: n=24 で 0.08 ms・n=2000 で 0.57 ms。既存テストの 44 ケース（`usesNoVerify` 15・`pullWithoutFfOnly` 12・`GH_PR_CREATE` 17）で旧実装と**全件一致**（`--` 単独枝を落とすと `gh -- pr create` の 1 件だけ差が出るので、その枝は必要）。
- **テストの追加**: `pre-bash.test.mjs:808` の `PATHOLOGICAL` へ `git ` + `--f=v ` × 2000 を足し、**`:572` の時間上限テストを 5 述語 + `judgeCommandShape` 全体へ広げる**（現状の no-hang テストは `usesHeredoc` 1 本にしか掛かっていない。この 1 本だけを守った結果、隣の 2 述語で同じ不変条件が破れた）。

### H2（High）: `usesBackslashPath` が正規表現パターンを誤爆し、拒否文言の復帰手順が適用不能になる（I6 違反）

- **場所**: `.claude/hooks/pre-bash.mjs:165`（`BACKSLASH_PATH[0] = /[A-Za-z]:\\/`）。
- **根本原因（壊れた不変条件）**: 「ドライブレター + `:` + `\`」は「**より長い語の末尾 1 文字** + `:` + 正規表現エスケープ」と字面で区別できないため、`rg "version:\s+"` のような日常的な検索が block される — そして拒否文言は「`/` で統一してください」なので、**復帰手順に従うと壊れたコマンドになる**（I6 は「拒否は必ず復帰手順を含む」であり、規範を降ろす設計はこれに賭けている）。
- **実測 block（誤爆・5/5）**: `rg "version:\s+" src` / `grep -rn "TODO:\s" .` / `rg -n "id:\d+" src` / `cargo test | rg "result:\s"` / `sed "s:\(a\):b:"`。
- **付随する文書の誤り**: `docs/hooks.md:24` は「正規表現エスケープ（`\d`）や `find -exec \;` は巻き込まない」と書いており、前半が**偽**。`AGENTS.md`「全称表現は前提条件とセットで書く（書けないなら書かない）」に当たる。
- **修正例**（実測: 真陽性 7/7 維持・上記誤爆 6/6 解消）: 直前が語構成文字でないことと、パスらしい継続を要求する。
  `/(?<!\w)[A-Za-z]:\\[\w.$%~-]{2,}/`
  維持を確認した真陽性: `node C:\workspace\Snotra\x.mjs` / 二重引用で囲んだ形 / `cargo build --manifest-path=C:\ws\Cargo.toml` / 散文中の `git commit -m "fix: C:\path handling"` / `cd C:\ws` / 単引用で囲んだ形。
  `(?<!\w)` だけでも 4/6 が消える（残るのは `sed` の `s:` 形と `rg "a:\d"` の 1 文字接頭形）。失う真陽性は `type C:\a`（継続 1 文字）のみでテストにも実運用にも無い。
- 併せて `docs/hooks.md:24` の表現を実装に合わせて弱めること。

### M1（Medium）: `HEREDOC_FOLLOW` の `)` がシフト演算子を誤爆する

- **場所**: `.claude/hooks/pre-bash.mjs:132`（`/^[ \t]*(?:[<>|&;)]|\r?\n|$)/`）。
- **根本原因**: シフト演算子は閉じ括弧の直前に来る（`1<<n)`）ので、`)` を「heredoc 演算子の直後に来てよいもの」に含めると heredoc と shift を区別できない。ここでも復帰手順（here-string を使え）が適用不能になる。
- **実測 block（誤爆・3/3）**: `rg "value << shift)" src-tauri` / `node -e "console.log(1<<n)"` / `echo $((1<<n))`。
- **修正例**（実測: 真 11/11 維持・誤爆 3/3 解消）: `)` を落として `/^[ \t]*(?:[<>|&;]|\r?\n|$)/` にする。サブシェル内の本物の heredoc（`(cat <<EOF` … 終端行 … 閉じ括弧）は**終端行の索引側で拾う**ので落ちない（実測で確認）。`docs/hooks.md:23`「シフト演算子は除く」も同時に真になる。

### M2（Medium）: 行継続をまたぐ `--no-verify` が allow になる（fail-open・残余リストにも無い）

- **場所**: `.claude/hooks/pre-bash.mjs:75`（区切り集合に改行を含む）→ `:80` `segmentEnd` → `:199` `gitSegments`。
- **根本原因**: 行継続は「同じコマンドの続き」だが、区切り集合が改行を無条件に境界とみなすため、継続行のフラグが別セグメントへ落ちて見えなくなる。
- **実測**: bash 形（末尾 `\` + 改行）と PowerShell 形（末尾バッククォート + 改行）のどちらも `gitSegments` は `["git commit -m x \"]` しか返さず、`--no-verify` が **allow**。同じ形の `git pull` は逆に block（`--ff-only` が見えないため）で fail-closed 側に転ぶので、害は `--no-verify` の側にある。

## 3. Phase 3 — パフォーマンス検証

本差分は `search.rs` / `folder.rs` / レンダリング / アイコンキャッシュに触れないが、**全コマンドに乗る税**が新設されたので測定した。

- **典型コマンドの税**: `cargo clippy --workspace --all-targets -- -D warnings 2>&1 | tail -40`（70 字）で `judgeCommandShape` = **0.0017 ms/call**（20000 回平均）。hook プロセスの node 起動（数十 ms）に対して無視できる。**全コマンドに乗る税としては妥当。**
- **計算量**: `usesHeredoc` は候補数と長さに対して線形（実測 0.1〜4.5 ms・候補 2 万件の時間上限テストが `:572` にある）。候補ごとの `command.slice(after)` は V8 の SlicedString ゆえコピーを伴わないので、この形で正しい。

- **不要アロケーション**: `usesNoVerify` と `pullWithoutFfOnly` が `gitSegments` を各々呼ぶので走査と配列生成が 2 回起きる。典型入力で数 µs なので**最適化は不要**（H1 を直せば最悪ケースも消えるため、束ねる価値はさらに下がる）。

## 7. 追記 — H2 / 過剰検出のライブ実測（レビュー中に偶発）

本レビュー中、稼働中の hook が**レビュアー自身のコマンドを 3 度 block した**。いずれも本文で述べた誤爆クラスの一次証拠である。

1. レビュー結果を検算するための `grep` が `\` 判定で block された（パターンに `version:\|` を含めたため、`n:\` が `[A-Za-z]:\\` に当たった）。**発火したのはパスではなく正規表現の交替（`version:\|`）である**（同じコマンドには `C:.ws` というパスらしい断片も入っていたが、`[A-Za-z]:\\` に当たったのは `n:\` の側である）。H2 本体に挙げた 5 件はこの曖昧さを持たない。 H2 の誤爆クラスの発生率が「稀」ではないことの実測であり、拒否文言（`/` で統一せよ）はこの入力に対して無意味である。
2. 述語を検証する node ワンライナーが 2 度 block された。テストケース配列の中の引用内 `;` の後ろに `git commit --no-verify -m y` と書いたためで、`docs/hooks.md:33` が受容すると宣言した過剰検出そのものである。ただし**判定そのものを検証しようとする行為が止まる**という副作用は残余リストに書かれていない（回避は文字列連結で綴りを割ること）。

H2 の誤爆コーパスは 6 件（本文の 5 件 + `rg "a:\d"` の 1 文字接頭形）で、提案した修正案は 6/6 を解消し真陽性 7/7 を維持する。`(?<!\w)` のみの縮小版では 4/6 の解消にとどまる。

この 3 件は「機構へ降ろした規範が、規範を検証する作業そのものを妨げる」形の摩擦であり、#482 が根治した「バグを説明する行為を妨げる誤爆」と同じ系統に属する。H2 / M1 を直せば 1 件目は消え、2 件目は設計上の受容として残る（残余リストへ 1 行足すのが妥当）。
