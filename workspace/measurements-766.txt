## 観測手段の失格（run1 / run2 は effort の可否を測っていない）

`CLAUDE_EFFORT` は**セッション水準の環境変数**であって、サブエージェント自身の解決 effort ではない。
本体 2.1.250 の一次読み取り（検索文字列: `CLAUDE_EFFORT=e.effortLevel` を含む関数）:

    function Fxe(e){ let t={CLAUDECODE:"1", CLAUDE_CODE_SESSION_ID:e.sessionId, ...};
                     ... if(e.effortLevel!==void 0) t.CLAUDE_EFFORT=e.effortLevel; ... }
    function HJ(e){ return {sessionId:e.session_id, effortLevel:e.effort?.level, source:"harness"}; }

`HJ` の入力は `session_id` / `effort` という snake_case を持つ **hook のペイロード**である。
Bash ツール側は別経路で、`N6t`（`"CLAUDE_EFFORT"` を含む固定の env 名の一覧・検索文字列:
`"CLAUDE_CODE_TMPDIR"`）を `spawnEnvKeys()` がセッションのスナップショットへ足す形で運ぶ。

ゆえに run1（無効値 → 既定へ落ちる）と run2（`effort: low`）がどちらも `high` を返したことは、
**effort が honored されていない証拠にならない**。計器が測る枝と、変更が触る枝が違う。

未確定 1（`CLAUDE_EFFORT` が観測手段になるか）の答え: **ならない。** 未確定 2 の代替観測へ移る。

（上の行の直後に、走っていたプローブが `CLAUDE_EFFORT=high` を 1 行追記した。run2 の重複であり、
観測としては上の run2 と同一。）

## 代替観測も使えなかった（未確定 2 の答え）

`effort: low` で A/B の片側を走らせたが、**名前付きサブエージェントの完了通知にトークン使用量が
載らない**（届いたのは idle の通知だけで、`subagent_tokens` を含む形ではなかった）。所要時間は
課題の難易度と実行時の混み具合に左右され、1 本ずつの比較では分離できない。

**ゆえに「実行して外から観測する」経路は 2 つとも失格した。** 推測で埋めず、残る鎖を一次読み取りで
閉じる方へ切り替えた。

## 鎖が閉じた（構造的な確定）

検索文字列: `kind==="effort"` / `case"effort"`。

    function CFt(e){ let o; if(!e)return o; for(let t of e) if(t.kind==="effort") o=t.effort; return o; }
    function kc(e){ return CFt(e.permissionLayers) ?? fl(e.getAppState(), c(e)); }
    function c(e){ let o=e.options?.mainLoopModel; for(let t of e.permissionLayers??[]) if(t.kind==="model") o=t.mainLoopModel; return o; }

`c` が `model` を、`kc` が `effort` を、**同じ `permissionLayers` から構造の同じ走査で**解決する。
`model` の上書きが効くことは疑いがない（`code-reviewer.md` の `model: inherit` がそれである）。
`effort` は同じ配列の隣の要素として、同じ形で読み出される。

鎖の全体（すべて一次読み取り）:

1. `.claude/agents/*.md` のローダが `effort` を読み `RA()` で検証する（検索文字列: `has invalid effort`）
2. 検証を通れば agent 定義オブジェクトへ `effort` を載せる（同上の返り値）
3. spawn 経路が `{kind:"model", ...}` と並べて `{kind:"effort", effort}` を配列へ積む（検索文字列: `kind:"effort"`）
4. `kc()` がその配列から `effort` を取り出す（検索文字列: `kind==="effort"`）

## 実測で得た副次的な事実

- **agent 定義はセッション中に読み直される。** 新規に置いた `effort-probe` を `subagent_type` に
  指定した起動が通った（この session の起動時ロスターには無かった）。
- **無効な effort はロードを止めない。** `effort: bogus` の定義でもエージェントは起動した。
  ローダが値を弾いて `effort` を載せないだけで、定義そのものは生きる（shadow validator の所見と整合）。
