# 規則を全部守る読者 — 2 巡目

1. **修正C後、等式の左辺が「不着」時に組み立て不能** — Step2の「渡すパスは巡ごと・読者ごとに別にし」直後の説明、および出力節の直後注記「N・M は読者が書いたファイルの番号を数え直して立てる（不着・様式違反のクラスは件数ではなく不成立と書く）」を字面通り守ると、片方の読者クラスが不着だった巡では N または M が数値でなく「不成立」という文字列になる。しかし出力テンプレート自体は「厳守」指定で `- 1 巡目: 手を抜く読者 N 件・規則を守る読者 M 件 → **N+M = 成立 K + 降格 L + 残余 R**` という数式の形を固定しており、片方が「不成立」では加算そのものが定義できない。忠実な実行者はテンプレートの型（厳守）と、不着時は件数を書くなという禁止の両方を同時に満たせない。合格条件2・4に抵触。修正Cが作った矛盾。

2. **「残余」が巡単位の等式内と、末尾セクションとで二重に要求される** — Step1-3「上限時点で残るものを、受容する未対応リスクとして明記する」は本来「上限巡数に達した時点」だけの話だが、修正Bで等式に足された「残余 R」は出力節のテンプレート上「各巡の結果」の**巡ごとの箇条**（最終巡以外も含む）に埋め込まれている。さらにStep4「最後の巡で塞いだものは検証されないまま残る——それも受容する残余に書く」は、その巡の等式では既に成立Kとして数えた項目を、末尾の「### 受容する残余」セクションにもう一度書けと命じる。忠実に両方守ると、同一項目がある巡の等式ではK側に、文書末尾のセクションではR相当の記述として二重計上され、K+L+Rの合計が「巡ごとに独立して閉じる合計」なのか「文書全体を通じた一意の分類」なのか決められない。合格条件3に抵触。修正Bが作った矛盾（Step1-4の予算超過による残余送りとStep4の最終巡未検証残余の、二重計上）。

3. **予算超過による残余送りが「成立」の定義を崩す** — Step3「各指摘の根拠…を自分で開いて成立を確認する。成立しないものは降格し」は成立/降格の二分法を「その指摘が正しいか」だけで決めると読める。ところがStep1-4「塞ぎ1件あたりの分量予算…超えるなら受容する残余へ回す」により、内容的には成立（＝正しい指摘）と確認された項目でも、1文で塞ぎきれなければ等式上はK（成立）ではなくR（残余）に計上される。忠実な実行者は「成立の意味は妥当性の確認か、それとも実際に塞がれたことか」を等式のK/Rどちらに載せるかで毎回二重に判定を迫られ、文言はどちらが正か規定していない。修正Bが等式にRを追加したことで、この二値性の崩れが初めて数値のズレとして表面化する。

4. **「番号を並べる」規約がK・N/Mの単位を食い違わせる** — 出力節「1つの塞ぎが複数番号を覆うなら番号を並べる」は、1つの塞ぎ（＝K側の1単位）が複数の生の指摘番号（＝N・M側の複数単位）に対応しうることを認めている。したがって両読者クラスが独立に同一の抜け道を指摘した場合（合格条件4が名指しする状況）、忠実に「1つの塞ぎ」として1件にまとめてKを数えると、N+M（生の指摘件数、この場合2）に対しK+L+Rの合計が届かず、正しい報告のはずが等式不成立に見える。これはまさに合格条件4が禁じる「誤爆」であり、Step2の番号運用規約自身が引き起こす。

5. **N・Mの記号がStep1の定数と出力節の巡別変数で衝突する** — Step1は「合格条件 N 件」「上限巡数 M」として、レビュー全体を通じて不変の2つの定数を定義する。ところが出力節のテンプレートは同じ記号N・Mを「手を抜く読者 N 件・規則を守る読者 M 件」という**巡ごとに値が変わる**読者別件数として再利用している（`### 停止条件`の直下行と`### 各巡の結果`の直下行が同一出力内に併存）。忠実な実行者は「合格条件 N 件」の N と「手を抜く読者 N 件」の N が別物だと文脈から拾うしかなく、修正Cが「N・Mは読者が書いたファイルの番号を数え直して立てる」と明記して後者の用途を固定した結果、この衝突がテンプレート上でより際立つ。

6. **Step4の必須記述が合格条件3の禁止をそのまま満たしてしまう** — 合格条件3は「右辺（成立・降格・残余）に、ファイル上のどの指摘とも対応しない項目を置ける」ことを防ぐべき抜け道として挙げている。しかしStep4「最後の巡で塞いだものは検証されないまま残る——それも受容する残余に書く」、およびStep1-3「上限時点で残るものを、受容する未対応リスクとして明記する」は、いずれも読者ファイルの個別番号に対応しない**プロセスレベルの注記**（「最終巡の塞ぎは未検証」等）を受容する残余へ書くことを義務付けている。忠実にStep4を実行すると、その時点で合格条件3が塞ごうとした抜け道を規範自身が要求する形で踏むことになり、2条項（合格条件3の意図とStep4の指示）は両立しない。
