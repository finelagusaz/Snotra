# race-check SKILL.md — 忠実な実行者によるレビュー（round 2）

- **F1 [R1]** 段 (1) の禁止は「置き換え」にしか掛かっていない: 「**`main` 以外から分岐しているなら `main` を分岐元のブランチ名へ置き換える——`HEAD` や現在のブランチ自身を置いてはならない**（差分が空になり、リビジョンを明示したまま全種が 0 件になる）」。現在ブランチが `main` そのものなら**何も置き換えずに**規定どおり `git diff $(git merge-base main HEAD)` を打てる。`git merge-base main HEAD` は `HEAD` を返し、変更がコミット済みなら差分は空、`git status --short` も空 → 全種別が正直に (iii) 0 件 → 「並行境界なし（非該当）」が成立する。文書は「それを閉じるのは段 (1) の 2 コマンドを**そのまま**打つことである」と言うが、そのまま打った結果がこの穴である。

- **F2 [R1]** 「`git status --short`　# 新規ファイル（未追跡は git diff に一切現れない）」は**パス名しか出力しない**のに、段 (2) は候補を「段 (1) で得た対象に**現れるシンボル**」と定義する。未追跡の新規ファイルはシンボルを 1 つも供給せず、その中身を読めと命じる条項は段 (1)〜(3) のどこにも無い。コミットが無く未追跡ファイルだけのブランチでは `git diff $(git merge-base main HEAD)` が空 → 全種別が正直に 0 件 → 新規ファイルまるごと未検査のまま「非該当」が成立する。

- **F3 [R5]** 入口の振り分けが循環している: 「どちらでもない（人が直接起動した）| **段 (1) が空でないなら実装レビュー**。空で `workspace/plan.md` があるなら計画レビュー」。しかし段 (1) 自身が **実装レビュー**（2 つの git コマンド）と**計画レビュー**（「対象は計画の記述そのものである」）でモード別に定義されており、「段 (1) が空か」を評価するには決めようとしているモードが既に要る。どちら向きにも解けるので、「**実行者は選ばない。**」は文言として偽である。

- **F4 [R5]** 呼び出し元の場合分けが 3 行で閉じていない: 表は `/implement`・`/start-issue`・「どちらでもない（人が直接起動した）」しか持たない。**別のスキルやサブエージェントから起動された**場合はどの行にも当たらず、入口も母集団の起点も未定義 → 実行者が選ぶしかない。

- **F5** 「空で `workspace/plan.md` があるなら計画レビュー」は、plan.md が存在する限り充足不能である: plan.md が未追跡なら `git status --short` に現れ、ブランチでコミット済みなら `git diff $(git merge-base main HEAD)` に現れる——どちらにせよ段 (1) は非空になり、「**段 (1) が空でないなら実装レビュー**」が先に当たる。**計画があるときに限って計画レビューへ行けない**という決定的な誤配送であり、自由選択ではない。

- **F6 [R4]** 計画レビュー路で要求される証拠が原理的に作れない: 段 (1) は「計画が新設する記述はコードにまだ無く」と認めるのに、Step 3 は「各境界について…共有状態を変えうる経路を **grep で探す**」、出力の根拠の規律は「全判定に、**`file:シンボル` と、その判定を支える実際のコード片（該当行）の両方**」を要求する。まだ存在しないコードにファイルも シンボルも行も無く、この 2 条項は計画レビューでは満たせない → 報告を閉じられずに詰まる。

- **F7 [R2 部分]** 打ち切り禁止は命令の層では閉じている（「1 件見つけた時点で打ち切らず」）が、**証拠の層で結論の向きに非対称**である: 「並行境界なし」には「**全種別について (iii) を示し**、かつ辿る範囲（上の 3 つ）を実行したとき」が要るのに、境界を 1 件でも立てた報告に義務づけられるのは「**候補集合の各要素について**」の証拠だけで、②〜⑧ の手がかりを走らせた痕跡は何も要求されない。「**仕事量は候補の数で決まり、結論の向きでは変わらない**」は文言として偽であり、①で 1 件当てて抜ける経路は検証不能なまま残る。

- **F8 [R2 隣接]** 計画レビューでは Step 4 の 5 観点が丸ごと免除できる: 「**全面適用は差分が新設・変更した境界に限る。** 既存のまま触っていない境界は 1 行の理由（「この差分は触れていない」）で足りる」。計画レビューには差分が存在しないので「差分が新設・変更した境界」は空集合であり、全境界が 1 行免除に落ちて 4a〜4e が一つも走らない。

- **F9** 証拠形式 (ii) が適用不能: 規則は「**候補集合の各要素について**、次のいずれか 1 つを書く」だが、(ii) の条件は「**ヒットしたが候補ではない**」。候補集合の要素は定義上この条件を満たせず、満たすものは規則が量化する集合の外にある。加えて「**`[要確認]` は終端になれない**…その候補を **(i) 境界として Step 2 へ送る**」があるため、忠実に読むと `Mutex` の既存ヒット数十件がすべて (i) 境界へ昇格する。

- **F10** 同じ量化子の下で (iii) も範囲が合わない: (iii) は「**その種別に**候補が 1 件も無い」＝種別単位の証拠であって「候補集合の各要素」ではない。3 形式のうち 2 つが宣言された量化範囲に乗っておらず、忠実な読者は (i) しか書けない。

- **F11** 種別 ⑥ に (iii) の**形式**が満たせない: (iii) が書けと言うのは「**打ったコマンドとその出力**」だが、⑥ は「**独立した grep は無い**」。文書は内容の代替（「① のヒットを送信の有無で分類した結果を置く」）を与えるが、それはコマンドでも出力でもないため、要求された証拠の形は ⑥ について原理的に作れない。

- **F11a [R3 は成立しない]** 検証したが不成立: 「**候補が 0 件であること自体は正当な結論である**」と「Step 1 の候補が 0 件だった場合は「並行境界なし（非該当）」と明示する」の 2 箇所が非該当の報告経路を明示的に与える。残る欠陥は証拠の**形**（F11）と判定行の不在（F12）であって、経路そのものの不在ではない。

- **F12** 「非該当」に停止権も判定行も無い: 出力表の行は `[安全]` / `[要修正]` / `[要確認]` の 3 つだけで、`[安全]` の動作は「**全境界で**状態競合リスクなし」と境界の存在を前提にした文言である。一方で「Step 1 の候補が 0 件だった場合は「並行境界なし（非該当）」と明示する」と命じられる。忠実な実行者は 0 件のときに書くべき総合判定と停止権の帰属を決められない。

- **F13** 網羅性の否認と「非該当」の許容が矛盾する: 「**手がかりは入口であって網羅ではない。** 別名 import・再エクスポート・マクロ生成・`Builder::new().spawn` は当たらない。**0 件は「この手がかりでは見つからなかった」であって「無い」ではない**」。それにもかかわらず、まさにその手がかりの 0 件（(iii)）を全種別ぶん揃えることが「並行境界なし」の十分条件とされている。文書自身が当たらないと認める経路が、非該当の成立を妨げない。

- **F14** 候補数と行数の恒等式が (ii) および Step 4 免除と両立しない: 「**Step 1 の候補数と Step 5 のマトリクスの行数は一致させる**」（段 (2) では分割の検算根拠でもある）。しかし (ii) 母集団外の要素は Step 5 の「各境界の判定」に行を持たず、Step 4 の 1 行免除を受けた境界は 4a〜4e に `[OK]` とも `[問題]` とも書けない（免除の文言「この差分は触れていない」はどちらの記号でもない）。

- **F15** `[要確認]` の扱いが 3 条項で不整合: Step 5 のテンプレートは「総合判定: … / `[要確認: <未確認の項目>]`」を選択肢として提示し、出力表は「**[要確認]** | 終端にできない。安全側へ倒し `[要修正]` として扱う」と禁じ、Step 4 は免除された境界について「**それは `[要確認]` ではない**（ゆえに出力表で `[要修正]` へ倒す対象でもない）」と第三の状態を作る。どの記号を書けば整合するかが決まらない。

- **F16** 義務が掛かる未定義語:「段 (1) が空」の**空**（入口の振り分け全体がこれに依存するが、2 コマンドのどちらが・どの意味で空かの定義が無い）、**対象**（段 (1) では diff テキスト、段 (3) では「段 (1) の**対象ファイル**」＝パス、証拠例では `rg '\.await' <対象>` の grep 引数と 3 通りに漂う）、4a の「**値を運ばない wake**」（判定基準なし）。

- **F17** 実行に必要なコマンドが規定されていない箇所が 2 つ: 「`main` を**分岐元のブランチ名**へ置き換える」——分岐元を求めるコマンドは示されず、分岐元ブランチが削除済みなら置換先が存在しない（かつ `HEAD`・現在のブランチは禁止されているので詰まる）。「`git show $(git merge-base main HEAD):<path>`」——`<path>` の決め方が無い（廃止・移行の検査では当のパスが作業ツリーから消えていることが前提）。

- **F18** 実装より強い全称表現（いずれも前提条件なし）: 「このプロダクトのレースコンディションは…という **1 点に帰着する**」、「この規模のアプリでは辿り続ければ**必ず** `update()` に着く」、「**④ の対象外はロック取得順序・保持区間だけである**」、「**全種別について (iii) を示し、かつ辿る範囲（上の 3 つ）を実行したとき**だけである」。いずれも検算手段が示されず、最後のものは F13 と衝突する。

- **F19** 「母集団の外にあるもの」と「辿る範囲」が同一対象で衝突する: 「**同じファイルに居るだけの既存ヒット**」は母集団外とされる一方、「**呼び出し元（上流）**: **1 ホップ**」は上流を引き込む。上流が同一ファイル内の既存関数である場合、外すべきか引き込むべきかを決める条項が無い。

- **F20** Step 3 の終了条件が否定の証明になっている: 「対象コードに現れる入力ハンドラ・イベント名を grep し、**表に無い経路が無いことを示す**」。存在しないことの提示には終端が無く、どこまで grep すれば示したことになるかの規定も無い（段 (3) のような費用上限がこの Step には掛かっていない）。
