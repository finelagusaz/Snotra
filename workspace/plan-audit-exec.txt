  に従うなら参照先セルの末尾へ文を足す形になる。実装者が新しい表の行を足すと裁定と食い違う。

[軽微 7] 新 ADR 2 本の中に書いた**正準形の参照は誰も照合しない**
  `headingRefDocs`（lib.mjs:508-516）が `docs/adr/` を除外している（`ADR-adr-frozen-history`）。
  一方 ADR 内の `ADR-<slug>` 短縮引用は `adrCitationDocs` が拾うので実在照合される（非対称）。
  → ADR に書く見出し参照は腐っても鳴らない。**書くなら散文で書く**のが安全側。

[軽微 8] `.test.mjs` の扱いが検査ごとに違う（1-2 のプレースホルダ規律に影響）
  - `headingRefCommentDocs`（lib.mjs:565）は `commentFamilyOf(f) !== null` だけで絞るので
    **`*.test.mjs` を含む**（実際 `scripts/plan-review-ledger.test.mjs:2` が今日の 33 件に入っている）。
    ただし走査は `linesOfComments` が**コメント行に限る**ので、fixture の文字列リテラルは見えない。
    → **新検査のテストで危ないのは fixture ではなくテストファイル自身のコメントである。**
  - `G-adr-citations` の `nonDocSources`（G-adr-citations.mjs:61）は逆に `*.test.mjs` を**外す**が、
    非 md の腕は**行全体**を見るので `.mjs` 本体では文字列リテラルも当たる（要対処 3 と同根）。

[軽微 9] plan.md:145 の `lib.mjs:461` は `governanceDocs` の**定義開始行**で、`docs/adr/` 除外の実体は
  `lib.mjs:465` である。結論（新 ADR は `docs` 列の delta にならない）は正しい。
  `manifest`（governance-manifest.mjs:23-33）の 4 列のうち動くのは `checks` だけで、
  `+G-folded-heading-refs` が唯一の delta になる——計画の PR 本文要求は過不足ない。

[軽微 10] `pre-bash.mjs` の形の判定は **PowerShell ツールにも発火する**（本監査中に実際に踏んだ）
    BLOCKED [pre-bash] (tool_name=PowerShell): パス区切りの `\` は…
  Phase 3-1 の junction 作成（`New-Item -ItemType Junction -Path … -Target …`）は
  **パスを `/` 区切りで書く**必要がある。同様に heredoc（`<<EOF`）も block されるので、
  ADR や PR 本文などの多行テキストは Write ツールでファイルへ書いて `-F` / `--body-file` で渡す。
