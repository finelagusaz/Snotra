# plan-review #1324（独立レビュー・観点 1 と 2 のみ）

## 要対処

1. 「作業量が約 2.3 倍」は、日数の率の分母に対して偽。
   - 根拠: research.md:65 は「約 3,400 回 / 12 日 → 約 7,900 回 / 18.5 日」。総量は 3,378 → 7,936 で約 2.35 倍。
   - 一方、日数の率（回/日）の分母は日数である。1 日あたりの Bash は約 281 → 約 429 回で約 1.5 倍。
   - 文案（plan.md:30）は「作業量が約 2.3 倍に増えており、日数の率はそれを分けられない」と書く。2.3 倍だと日数の率の横ばいが「実質は大きく減った」と読める。1.5 倍なら読みが変わる。
   - 直し方は、「1 日あたりの Bash 呼び出しが約 1.5 倍」と書くか、数を ADR に書かず #1324 の表を指す。

2. 「有意に消えたのは…だけ」（plan.md:31）は全称・断定で、research.md の根拠が足りない。
   - 8 回 → 0 回は、本体 5 → 0 と委譲先 3 → 0 の合算である。有意と言えるのは本体だけ（research.md:68、p ≈ 0.001）。委譲先 3 → 0 は検定されていない。
   - 「だけ」の裏づけがない。内訳表（research.md:50-53）の「その他」は 1 → 0 で、検定していない。本体 1 Bash あたり全体の 35% 減は p ≈ 0.09 で有意ではない（research.md:62）。
   - 反証プローブ（governance-docs.md の全称条項）の処置は、前提を足すか下限に弱めるかの 2 択。例: 「検定で確かめられたのは、本体の `git commit` と `gh` の本文の 5 → 0 だけである」。
   - 「8 回 → 0 回」の括弧は残してよい。ただし、有意なのは本体の分だけだと分けて書く。

3. 追記節の写しは、書く約束（1）かぶりなく、（3）数ではなく正本を指す、に反するおそれがある。
   - ADR の既存追記（ADR-command-shape-norms-in-hook.md:49）は「判定の記録は #1324 が持つ」と明言している。追記節（plan.md:30-32）は、その記録の要旨を ADR に写す。
   - 数値（5.0 → 5.5・約半分・8 → 0・93 回・1.7〜1.8 倍）は #1324 のコメントと重複する。issue の合意手順（issue 本文の「減っていれば」の項）は、残す側では「issue に書いて閉じる」としか言っていない。ADR への追記は外す側にだけ求めている。
   - 追記に足りる理由は 2 つある。
     - ADR 49 行目の「減っていなければ外す」を読む人が、試行がまだ続いていると読む。これは古い情報の訂正である。
     - 計測の落とし穴（ログの消失・`api-request-blob` の二重計上）は、次に同じ数え方をする人への否定の知識である。
   - 推奨は縮小。判定（残す・ユーザー裁定）・日付・「数えた表と分母ごとの結果は #1324」・行が効いていない形（node / python へ流す形・委譲先）・落とし穴 2 点だけにする。率や倍率は #1324 へ寄せる。ただし、計画が追記を足すと決めた判断（plan.md:69）自体は妥当。
   - 追記を足さない案もある。ADR 49 行目だけが「試行中」の唯一の記述である。判定が「残す」なら、行は恒久になり、期限の文は意味を失う。

4. 追記節が「残す」の根拠を書いていない。
   - 合意した 2 分母のうち、日数の率は横ばい、セッションの率は約半分（plan.md:30）。「減っていれば残す」（issue）の条件を満たしたとは読めない。
   - 読者は、なぜ残したのかを文案から導けない。「ユーザーが 2026-11-18 に裁定した。名指しした commit・gh の heredoc が消え、セッションあたりの率が下がったため」といった 1 文が要る。裁定を争点にしない前提とは別に、記録としての根拠は ADR 側に要る。
