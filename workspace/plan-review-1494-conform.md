# #1494 計画の独立レビュー（計画準拠）

## 要対処

1. **D1・D2 は、委譲先が「差分のパス」を手元に持たないので、そのままでは実行できない。** `/implement` 3b が渡すのはアンカーの sha だけで、差分の基点（base）を渡さない（`.claude/skills/implement/SKILL.md` の 3b の箇条。`base` の出現は `--base` を持つ検査側だけ）。`align` の出力は `{sha, worktree, delegate_dir}` だけである（`scripts/verify-tree.mjs` の `cmdAlign` 末尾の `console.log`）。委譲先は `git diff --name-only` の基点を知らず、「触るパス」が何を指すか（コミット差分／変異注入で触る検知器／レビューで読む対象）も決まらない。決めずに足すと、「触るパスに当たる」の解釈が委譲先ごとに割れる。計画に次のどちらかを足す。(a) 主が `git diff --name-only <base>..<sha>` を渡す。パスの列挙は母集団ではなく判定の入力なので、D1 の趣旨（rule を主が列挙しない）とは衝突しない。(b) 「差分のパスと、変異注入で触るパス」と対象を明記し、基点を渡す。
2. **`paths` の照合の基準を指示に書く。** 委譲先の自分の worktree の絶対パスは `…/.claude/worktrees/agent-<id>/…` で、`.claude/` を含む。絶対パスや cwd 起点の相対でないパスで照合すると、`.claude/skills/**`・`.claude/rules/**` 系が全件に当たる誤りも、外れる誤りも起きる。照合は worktree ルートからの相対パス（`/` 区切り）で行うこと、`*.md` のような bare 名はルート直下だけで、階層を横断するのは `**/` を明示したときだけであること（メモリ `reference_claude_rules_paths_matcher.md`、2026-07-19 確認）を、指示に 1 行で入れる。実在の事例: `governance-docs.md` は `*.md` と `**/*.md` を両方持つ。`AGENTS.md`（ルート直下）は前者に、`docs/x.md` は後者にだけ当たる。これを誤読しやすい。誤読の害は計画の「異常系」のとおり悪化ではないが、読み落としは検知されない。
3. **安全側の既定を書く。** 判定に迷うときは、読む側へ倒させる。害は余分な読み込みだけで、読み落としは黙って「いまと同じ」に戻る。計画の「異常系」は読み落としを許容しているが、指示にはその向きが書かれていない。
4. **全称の反証プローブ（`governance-docs.md` の当該条項）に照らすと、D3 の「隔離した委譲先には配送されない」の射程が足りない。** 計画は測定の報告の形（2026-11-21・隔離 2 件）で書くので、これは弱い形で済む。ただ、行動形の文（「隔離した委譲先に rule を読ませるときは、委譲の指示で Read を求める」）は、未測の隔離経路（`Agent` 以外・別モデル）へも射程が及ぶ。それでも害は余分な Read だけなので許容できる。ここは対処というより、書き方の注意として残す。

## 配送の記述の整合（リスク観点 1）

`git grep -nE "自動で読み込|自動配送|自動で配送|読み込まれる|届く|配送される"` の結果（`docs/superpowers`・`docs/design`・`docs/adr`・`workspace`・`PERFORMANCE.md` を除く現役の文書）は次のとおり。

判定: **計画の「ほかを変えない」方針は妥当である。**
- 書く約束の (1)「かぶりなく書く」に沿っている。配送の事実の正本を `AGENTS.md` 冒頭の 1 か所に置き、他は一般形の記述のまま残す。例外を全部へ写すと、写しが増えて、次の測定で一斉に古くなる。
- (3)「古い情報を残さない」の判定は「存在しなくなるものへ読者を送るか」「現在形の主張が偽になるか」である。上表の 4 件（safety-nets:16・retrospective:63・comment-guidelines:5・glossary:25）は、厳密には「隔離した委譲先には届かない」例外が付く全称である。ただし、いずれも読み手が主セッション（触って届く側）であり、例外が効く読み手（隔離した委譲先）はその文を読まない。偽になる現在形の主張はあるが、読み手を誤らせる経路が無い。
- 全称の反証プローブに掛けると、「何が増えたら偽になるか」への答えは「隔離した委譲先が対象に加わったとき」である。これは前提を書き添える処置に当たる。その処置は `AGENTS.md` 冒頭の 1 文が担う（計画のとおり）。他の 4 件へ個別に但し書きを足す必要は無い。ただし、計画に「ほかの記述は、読み手が主セッションなので変えない」と 1 行、判断の根拠を書いておく（実装者が後で「更新漏れ」と誤認しないため）。
- 例外: `.claude/rules/safety-nets.md:16` だけは、`/implement` 3b の委譲先が変異注入で `scripts/**`・`.claude/hooks/**` を触る。その委譲先が safety-nets.md を持たないことは、3b の timeout の後始末の箇条（`safety-nets.md`「フォールトインジェクションでは…」を指す）が既に Read を前提にしている。偽な全称は残るが、害は 3b の箇条側で既に塞がれている。なお、D1・D2 の足す箇条は、この既存の箇条と重なる。重なりを (1)「かぶりなく」に沿わせるなら、既存の箇条を新箇条へ寄せるか、新箇条が既存の箇条を指す形にする。

ほかに見つけた現役の配送の記述はない（`snotra-core-search.md:16` の「配送される」は、ファイル編集時の配送という一般形で、同じ扱い）。

## 軽微

- 計画の A2 は「測った日付を添える」。`AGENTS.md:3` には既に「2026-11-21 にも同じ挙動を観測した」（bash で読んでも届かない側）がある。同じ日付が 2 つの別の事実に付くので、読み手は混同しうる。新文は「2026-11-21 の測定（#1494）では」と、事実の対象（隔離）を主語にして区別する。計画の D3 の文面はそうなっている。
- 計画の「実地の確かめ」（記録の Read のパスで確かめる）は、検証にならない可能性がある。隔離した委譲先は、指示に従わなくても、`safety-nets.md` を Read するかもしれない（3b の timeout の箇条が既に指すため）。足した箇条の効果を測るなら、`governance-docs.md` のように 3b の他の箇条が指さない rule が Read されたかを見る。
- `3c` の軸の違うレビューの条件判定を Step 3 で行う、という計画は妥当（前提の反転にあたる）。

## 未検証

- `paths` の照合の意味論（bare 名・`**/`・worktree 起点）の実挙動。harness ネイティブで、リポジトリ内では決定不能（メモリの記述が唯一の根拠で、公式例の転記）。`**/*.md` がルート直下にも当たるかは、本レビューでは測っていない（`governance-docs.md` が `*.md` を併記しているのは、当たらない前提の表れ）。
- 隔離した委譲先が `.claude/rules/*.md` を Read した後、本文が実際にコンテキストへ入ること（Read 自体は成功するはず。自分の worktree の `.claude/rules/` は sha に追跡されているので存在する。`git ls-tree` では確かめていない）。
- 配送されない機序（`.gitignore` の `.claude/worktrees/` に当たるパス、起点のルート外、機構の無効化）。`git check-ignore` では、`.claude/worktrees/x/.claude/skills/a.md` が `.gitignore:22` に当たることだけを確かめた。それが配送を止める原因かは未測定。
- `/start-issue` 3b・`/plan-review` の委譲先（隔離しない）で、配送が届く前提は、`workspace/research.md` の測定表（#1493 の 2 件）に依る。本レビューでは記録（`.jsonl`）を再確認していない。
