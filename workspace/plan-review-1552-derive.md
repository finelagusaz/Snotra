## (d) 不変条件

- 終了コード（推す案を 1 つに絞る）: **0 = 成立、3 = 不成立（理由をすべて印字）、2 = 判定不能**（ファイルが無い・読めない・引数の誤り・catch-all で捕まえた想定外の例外）。**0 と 3 以外はすべて判定不能として読む**（1 を含む）。理由: npm 12.2.3 / node v24.18.0 で、`npm run` は子の終了コードをそのまま返すことを確かめた（exit 3 → 3、exit 2 → 2、未捕捉の throw → 1）。モジュールが読み込めない・構文の誤り・import の失敗のように、`main` に届く前に node が落ちると、catch-all を通らずに exit 1 になる。不成立に 1 を割り当てると、この落ち方が「不成立」に見え、1c-B（`/start-issue` へ戻す）へ誤って送られる。理由の行も出ない。`scripts/merge-pr.mjs:457` も、素の exit 1 が何と取り違えられるかから番号を決めている。`verify-tree`（1 = 赤）とは番号が違うことになるが、`verify-tree` の 1 も「明示の経路でだけ返す」（`scripts/verify-tree.mjs:435-436`）ので、node が落ちたときは同じ取り違えを受け入れている。こちらでは受け入れない
- 1b への写像は全域にする: `/implement` が script を呼ぶのは、`workspace/plan.md` が在り、同一性が立ったときだけである（1a `:70`。同一性が立たなければ残骸の行へ進み、script の結果は使わない）。exit 0 → 3 つ目の条件が立つ（Step 2 へ）、exit 3 → 「未確定ゼロか承認が立たない」→ 1c-B（理由が未確定なら 5a、承認なら 5c へ戻す）、それ以外 → 1c-C（何が判定できなかったかを示して問う）。ファイルが無いときは exit 2 にする（呼び出しの前提が崩れているので）。「計画なし」の経路は、script を呼ぶ前にファイルの有無で分ける。script に「無い」専用の結果は持たせない
- plan:check が単独で検出するもの（PR ゲートでは見えないもの）: (1) 未確定の見出しが無い計画（#821。ゲートはファイル全体の `- [ ]` が 0 件なら通す）(2) 承認が無い、または形が崩れている（ゲートは承認を見ない）(3) 自己承認の記録どうしの矛盾 (4) 時機: 未確定の `- [ ]` そのものは PR ゲートでも捕まるが、実装の後になる。plan:check は Step 1 で、実装の前に止める
- fail-closed: 「確かめられなければ、あるものとして扱わない」（1a `:79`）。見出しが無い（#821）・節が無い・フェンスが閉じない・形が崩れている、はどれも 0 にならない。肯定の証拠はフェンスの外に限り、否定の証拠はフェンスの中も数える（c-3）
- 決定性: 入力はファイルのテキストだけにする。git・時計・環境変数・ネットワークを読まない。ルートは cwd から最も近い `.git` へ遡って導く（`readPlanState` と同じ。worktree では `.git` がファイルなので、`existsSync` で当たる）。`verify-tree.mjs` の `mainRoot`（本体のルートを返す）は使ってはならない。使うと worktree の `plan.md` ではなく、本体の `plan.md` を見てしまう
- 理由はすべて集める（短絡しない）。理由ごとにテストを書き、文言まで assert する（`.claude/rules/safety-nets.md`、#1319）
- 同一性は散文に残す。script はタスクの issue 番号を受け取らない（要件）
- PR ゲート（`.claude/hooks/pre-bash.mjs`）には承認の照合を足さない（要件）。ゲートは今までどおりファイル全体の `- [ ]` を数え、script は節の中だけを数える。この 2 つは意図して別の述語である（片方だけが変わる将来がある）
