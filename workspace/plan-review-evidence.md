## 2. 問い 2 — 掴まれたプロセスは誰のものか

**同一 Pester 実行の直前の It（`Tests.ps1:345`）が起動した自プロセスである。** ログから接地できる。

1. `Describe '実機配管'`（`Tests.ps1:344`）は It を 2 つ持ち、**どちらも `try` の先頭で
   `Resolve-SnotraExistingProcess -Policy Reject` を呼ぶ**（`355` と `441`）
2. 衝突した 4 反復（後 008/021/029・前 023）すべてで、**先行の It は `[+]` で pass している**
   （例: `repro-after\…\iter-008\pester.log` の
   `[+] 生成した seed を本体が parse して… 1.42s`）＝`355` の時点で生存プロセスは 0 件
3. 先行の It の `finally`（`Tests.ps1:380-382`）は `Stop-Process -Force` を呼ぶだけで終了を待たない
4. `Get-Process` に現れるプロセスは増えることはあっても勝手に湧かない。**2 つの `Reject` の間に
   起動されたプロセスは先行の It のものだけ**である

→ **反復再現ハーネスに固有の要素（`-FailureGraceMs` / `SNOTRA_PESTER_TRACE_DIR`）は
この経路に 1 つも関与しない。`rust-check` の 1 回きりの実行にも同じ確率で届く。**
実測の遭遇頻度は **60 反復中 4 件**（`実機配管` Describe は 1 実行につき 1 回走るので、分母は
「Pester 実行 60 回」と読める）。**ただしこの 4 件はすべて計器つきの反復に在る**（§3）——
衝突の**経路**は計器と無関係だが、**率は他の数字と同じく計器つきの条件下のものである**。
`rust-check` での期待値としてそのまま使ってはならない。

→ exists=True value=''                    （変数は残る）

- **Rust** `input.rs:34` — `std::env::var_os("SNOTRA_EGUI_INPUT_TRACE").is_some()` は

## 6. 所見

### 要対処

1. **`repro-pester-flake.ps1` の env 復元が空文字の変数を作り、2 反復目以降の全測定を計器つきにしている。**
   根拠: §3。`[Environment]::SetEnvironmentVariable($name, $null, 'Process')` を自分で実行して
   `exists=True value=''` と子プロセスへの継承を確認した。**この 1 行が、道具自身の
   「率を測る回と機序を測る回は別の回にすること」という規律を無効化していた。**
   直す先は復元側（`Remove-Item Env:$name` 相当へ）と読み手側（空文字を偽に落とす）の両方。
   `config.rs:695` が同じ判断の手本である。

2. **`summary.md` の ⚠️ が `$InputTrace`（意図）だけを見ており、env の実態を見ていない。**
   根拠: §3.1。両 run とも「計器なし」を名乗る `summary.md` が出ており、
   **この文書だけを読んだ下流は 25/30 → 8/30 を無条件に比較できる数字だと読む。**
   受け入れ条件 3 の方向（残った trace の中身から測る）が正しい。

3. **単一インスタンス衝突は `rust-check` に届く。** 根拠: §2。ハーネス固有の要素を含まない経路で、
   実測 6.7%（60 反復中 4 件）。**#872 本文の失敗表にこの assertion は 1 行も無い**ので、
   過去 7 件の記録のうち何件がこれだったかは分類し直すまで分からない。
