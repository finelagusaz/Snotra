方針は案 A（ユーザー裁定・2026-07-28）。`init` が slug 集合を `workspace/plan-review/ledger.json` へ保存し、`verify` は引数を取らずにそれを読む。**打ち直す機会そのものを消す**のであって、打ち直しを検査するのではない。

## 不変条件

- **I1: `verify` の母集団は `ledger.json` であって argv ではない。** `verify` は `--slug` を**拒否**する（無視しない）——両形を許すと弱い形が残り、issue の穴が「引数が効かないだけ」の形で生き延びる。**これがこの変更の失敗様態である。**
- **I2: 母集団を得られない全形が exit 2。** 台帳不在 / parse 不能 / shape 不正 / 0 件 / 形不正スラグ。**空配列へ倒さない**（0 件中 0 件実在で緑になる経路を作らない）。exit 1 は「母集団に対する不着」に予約済みで、母集団が取れないことと不着は別事象である。
- **I3: `init` の非冪等 `mkdirSync`（`recursive` 無し）は観測点として残る。** 台帳の書き込みはその**後**に置く——順序を入れ替えると、削除が silent fail した回に前サイクルの台帳が残ったまま上書きされ、観測点が意味を失う。
- **I4: このスクリプトが書くのは、自分が検証した識別子だけである。** 呼び出し側が渡したバイト列（レビュー内容）は決して書かない。成果物の中身を受け取る口（`--write` / `--report-to` 等）を足してはならない——オーケストレーターが `Write` を持たない理由（自作自演で実在確認を通せてしまう）を、スクリプト経由で回復させないため。
- **I5: `ledger.json` は `readLedgerDir` の母集団に入らない。** 入ると毎回「命名逸脱」で不着 1 件が立ち、`verify` が常に赤になる。**台帳を `.md` にしてはならない。**
- **I7: 台帳は 2 つになるが、SSOT は 1 つである。** ファイル `ledger.json` が**機械の母集団**、会話の表は**カバレッジ論証**（レイヤーの分割根拠と、`plan.md` の変更ファイルを覆っているかの検算——ファイルには入らない情報）。**両者の一致を完全性の証拠にしてはならない**（`AGENTS.md`「検証の作法（全タスク共通）」の「派生コピー同士の一致を完全性の証拠にしない」。ここを曖昧にすると **#831 の失敗クラスを 1 段上で再生産する**）。両者が溶接される唯一の瞬間が `init` である。
- **I6: `classifyEntries` の「命名逸脱」ブランチを、この PR で弱めない。** 母集団が会話（打ち直せるが偽造されない）からファイル（スカウトが書ける）へ移るため、この分岐が**新しい理由で** load-bearing になる——台帳を縮めても他人の `*.md` が命名逸脱で不着になり exit 1 で止まる。

### 失敗・異常終了時の振る舞い

| 事象 | 結果 | 根拠 |
|---|---|---|
| `init` が `mkdir` 後・`writeLedger` 前に落ちる | 台帳なし → 次の `verify` が exit 2 | fail-closed（I2） |
| 台帳を人・エージェントが消す／壊す | `verify` が exit 2 | I2 |
| 台帳を縮める（スカウトによる改竄） | 残った `*.md` が命名逸脱 → exit 1 | I6 |
| `init` を 2 度走らせる | `rm -rf` → 作り直し → 台帳を新規作成。冪等 | — |
| `verify` を `init` なしで走らせる | exit 2（復帰手順つき） | I2 |
| `verify --slug x` を打つ | exit 2（復帰手順つき） | I1 |

### 自己破壊ハザード（実装・検証時の制約）

`LEDGER_DIR` は `process.cwd()` 基準（`scripts/plan-review-ledger.mjs:177`）で、`init` は `rmSync(dir, {recursive:true, force:true})`（`:180`）を打つ。**リポジトリルートで `init` を打つと、進行中のラウンドのスカウト成果物が丸ごと消える。**

ここで 2 つの規範が衝突する——「新設した検証経路は報告前にその経路自体を実行する」（`RETROSPECTIVE.md`）と「検査対象を変更しながら検査を走らせない」（ルート `CLAUDE.md`「サブエージェント委譲と worktree」・#489）。**解決は cwd を一時ディレクトリにすること**であり、手打ち・自動テストの両方に適用する。

## テスト方針

- 判定本体は入力注入の純関数に保ち、`scripts/plan-review-ledger.test.mjs` がフィクスチャで両方向（赤・緑）を押さえる（既存 19 件と同じ形）。
- **機構が効いていることは、フォールトインジェクションで一度は実測する**（`.claude/rules/safety-nets.md`）。種は **#831 の欠陥そのもの**（`verify --slug` で母集団が縮む）を蒔き、新実装が exit 2 で捕まえることを測る。
- プロセス級 e2e は cwd を一時ディレクトリにする。**リポジトリルートを cwd にした e2e を書いてはならない**——`npm test` が誰かの plan-review ラウンドを消す。
- CI は ubuntu + windows の両方で走る（`.github/workflows/ci.yml`）。`mkdtemp` とパス区切りを両 OS で通す。
- 検証コマンドは `docs/build-commands.md` の SSOT に従う（`npm test` / `npm run governance:check`）。**どちらも手で走らせる**——`selectChecks` は対象 4 ファイルすべてに `[]` を返す（直接実行で実測）。

## SPEC.md 更新要否

**不要。** `SPEC.md` はユーザー観測可能な契約（状態遷移・IPC・スコア計算・設定キー・データフォーマット）を持つ。本変更はエージェント運用の内部機構であり、アプリの挙動に一切触れない。`ledger.json` は永続形式だがユーザーデータではなく、毎ラウンド `rmSync` で消える作業ファイルである（version バンプ・後方互換の対象外）。

## 受容する残余（PR 本文へ書く）

1. **台帳の改竄と成果物削除の同時実行は塞がらない。** スカウトは `general-purpose` ゆえ `Bash` / `Edit` を持ち、書き込み範囲はプロンプト契約でしか縛れない（`/plan-review` SKILL.md の「受容する残余」と同じ理由・構造では表現不能）。ただし**今日の「打ち直す」より高コストであり、退行ではない**。
2. **`.claude/rules/safety-nets.md` の `paths` は `scripts/plan-review-ledger.mjs` を含まない**（実測: `.claude/hooks/**` `.githooks/**` `.claude/settings.json` `.github/workflows/**` `.claude/rules/**` `.claude/skills/**` `scripts/governance-check.mjs` の 7 件）。**次にこのスクリプトだけを直す人には、フォールトインジェクション義務が配送されない。** 足すのが妥当に見えるが、`paths` の変更はエージェント設定の変更であり**ユーザーの合意が要る**（ルート `CLAUDE.md` 最重要ルール 2）。本 PR の必須変更には数えず、PR 本文で提案する。
3. **`init` を打たないセッション再開では、前ラウンドの台帳と成果物が対で残って緑になりうる。** 塞ぐには台帳へラウンド番号や `plan.md` のハッシュを持たせることになるが、`/start-issue`「5a」が「収束判定に要る状態はすべて `plan.md` に置く」と定めており、**台帳を第 2 の状態面にするのは方針と衝突する**。塞がない。
