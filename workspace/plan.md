# 計画: #1409 egui_shell のコメントの経緯を、いま守っている約束の形へ書き直す

## 目的

`src-tauri/src/egui_shell/` のコメントにある経緯（変化の語り・作業単位の名指し）を、いま守っている約束の形へ書き直す。約束にならない作業記録は消す。コードは変えない。`scripts/smoke-egui.ps1` は別 PR（ユーザー裁定・`research.md`「issue の要約」）。

## 受け入れ条件

1. **台帳が母集団を覆う**: 基準 sha（0265463c）で `workspace/tools/candidates.mjs` が出す `.rs` の候補行がすべて、`workspace/ledger/<file>.md` のどれかのブロックに属し、分類（残す／縮める／書き直す／消す）と理由を持つ
2. **作業単位の副ラベルが残らない**: 変更後の egui_shell で、`PR [A-Z]`・`codex #`・`SU\d`・`決定 \d`・`#\d+ F\d`・`段 \d+` の前の「旧・」・`state-check 発見`・`Task \d` に当たるコメントは、台帳で「残す」と判定され理由があるものだけ
3. **コードが変わらない**: 23 ファイルすべてで、コメントを落とした Rust のトークン列が基準 sha と一致する（比較器は変異で検知能力を確かめ済み）
4. **新しい主張を足さない**: 書き直した文の主張は、元のコメントにあったか、台帳の「根拠」欄にコードの `file:シンボル` を挙げて確かめたものだけ
3b. **ソーステキスト検査の needle が動かない**: `view.rs` の `assert_read_once_in_this_file`・`icon_textures.rs` の `include_str!` 検査・`activation/tests.rs` の `sources()` 系検査が探す needle 文字列の、ファイルごとの出現数が基準 sha と一致する（コメントに needle を足すと件数検査が赤、`contains` 検査は将来ゲートを消しても黙って緑になるため）
5. **体裁**: 追加行のバッククォート数は偶数。コードスパンが行をまたがない
6. カテゴリ A（fmt・check・clippy・`cargo test -p snotra`・`cargo doc`）と F（`npm run governance:check`）が green
7. 消さなかった形と理由が ADR に残る（次に整理する人が残りを消し漏れと読まないため。#1411 の `ADR-comment-pointer-trim-scope` と同じ役割）

| 分類 | 当てる形 | 処置 | 実例 |
|---|---|---|---|
| 残す | `回帰テスト:` の守る性質と出自・日付つきの実測・現在の不変条件を支える過去の行為の 1 文・フレーム内の前の値（「旧色」「旧幅」「旧 state」）・変異の説明 | 変えない | `activation/tests.rs:787`（移した先でゲートが落ちる退行＝変異の説明） |

| 書き直す | 旧実装との対比・移設の記録のうち、今の制約を運んでいるもの | 制約を現在形で書き、`(#NNN)` を添える。旧の姿の描写は消す | `view.rs:714`「以前は `interactive` が 2 項…」→「`interactive` と再フォーカスは同じ 1 つを読む。別々に書くと片方だけ足した条件が食い違う（#700）」 |
| 消す | 作業記録だけで、今の制約を運ばないもの | 消す。`#NNN` も要らなければ消す | `view.rs:1561-1566`（テストを移した記録） |

- **`#NNN` の無い名前の対応表**（敵対的調査 3）: `PR A′`（`PR A` も同じサイクル）→ `#671`・`SU<n>`／`SU5 要石`／`codex #<n>` → `#532`（副ラベルは消す）・`Task <n>` → 消す（SU5 plan の内部番号）・`spec 決定 3`（`view.rs:654`）→ `#802`。表に無い名前は、`git log -S '<名前>'` で導入コミットを引いて番号を決め、台帳の根拠欄に書く
- **誤検出は語でなく 1 件ずつ判定する**: 「旧 state」「旧 token」はフレーム内の前の値で「残す」。「旧色」（`view.rs:264`・`:1807`）は過去の不具合の語りで判定対象。「旧幅」は hide を跨いだ値で、経緯ではない
- **外が写している箇所**: `SPEC.md:198`↔`layout.rs:123`・`ADR-show-path-derives-bar-rect`↔`window_coordinator.rs:1209`・`config_watcher.rs:247`↔`view.rs:1561`。外は触らない（範囲外・ADR は凍結）。コメント側を書き直すのはかまわない。食い違いは ADR の「受容する残余」へ書く
- **needle の綴り**: コメントで needle と同じ綴りを足さない・消さない（受け入れ条件 3b）
- **Phase 1 の追補**（`workspace/ledger/results_window.rs.md` 末尾）: 「旧 〜」は同じ処理の中の前の値なら残し、消えた型・関数を指すなら消す。`決定 N`・`案 N` は `git log -S '<語句>' -- <file>` の最古コミットの PR 番号へ。消えたシンボル名は ADR が持つなら落としてよい。経緯の段落が今は偽の現在形の主張を含むなら消す。名指しを足すなら grep で主張どおりかを確かめて根拠欄へ
- **書き直しの上限**: 元のコメントに無い主張を足さない。足すなら台帳の「根拠」にコードの位置を書く。迷ったら「縮める」か「残す」へ寄せる
- **回帰検出器の宣言は消さない**: 「この行は移設の回帰検出器になる」（`view.rs:892`）型は、検出する性質を現在形で書く（「偽なら起動直後の打鍵が捨てられている」）
- **却下案の比較**: 既存 ADR が持つなら `ADR-<slug>` を指して比較を消す。持たないなら、却下が課す制約だけを残す（新しい ADR へ比較を移すのは、この PR の範囲外）
- **段番号**: 段番号は振り直さない（`ADR-blur-grace-single-field-state-machine`）。「旧・段 14/34」の 5 か所（`view.rs:407,669,672`・`hide_request.rs:86`・`lifecycle.rs:280`）は欠番の説明として「残す」
- **コメント間の逐語引用**: ほかのコメントの語句を「」で引く箇所は、引かれる側と同じブロック群として同時に直す（例: `view.rs:407` と `:669-672`）
- **規約の他の条項**: 触った段落には規約全体が当たる（適用範囲）。ただし今回の書き直しの対象は経緯だけで、ほかの違反（指すだけの参照など）を見つけても台帳の「範囲外メモ」に書くだけにする
