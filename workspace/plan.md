# 計画 — issue #1495 implement の軸の違うレビューを出力の母集団に入れ、対象を固定する

## 目的と受け入れ条件

目的: `/implement`「3c」の軸の違うレビュー（`/code-review high`）を、実施したかどうかが報告から読める形にし、レビューの対象を作業ツリーの状態に依存しないものに固定する。

受け入れ条件（issue #1495 から）:

- A1「出力」節の母集団の記述と表が、3c の軸の違うレビューを含む
- A2 3c の項目が、`/code-review` へ渡す対象を名指している
- A3 `npm run governance:check` が通る

## 設計の決定

- D1（Q1）対象は、チェックアウト中の作業ブランチ名にする（`/code-review high <作業ブランチ名>`）。PR 番号は Step 5 の前なので使えない。差分の git コマンドは `code-review` を実行する主エージェントが選ぶので（`workspace/research.md`「敵対的調査（3b）の反映」）、3c に「差分は `git fetch` のあと `origin/main...HEAD` で取る（ローカルの `main` は古いことがある）」を添える。`code-review` の内部手順は写さない
- D2（Q2）条件が立たなかったときの根拠には、3 条件それぞれの判定を 1 行で書く（例:「(1) 委譲の所見をすべて採った (2) 安全機構・回復機構を足していない (3) 規範・ADR の前提を変えていない」）。一言では「該当なし」と「確かめていない」を区別できない
- D3「出力」節の母集団の記述を「3a の check スキル全件と 3b の委譲と 3c の軸の違うレビュー」にし、表の見出しも同じにする。既存の箇条「レビューの母集団は、3a の列挙と一致する」は、check スキルの列挙の同期を求めるもので、軸の違うレビューは check スキルではない。この箇条の主語を「check スキルの行は」に狭めて、偽にならないようにする
- D4 表の軸の違うレビューの行には、対象（ブランチ）・件数・直した件数・残した件数を書く（委譲の行の書き方にそろえる）
- D5 3c の「ラウンドの結果を `plan.md` の消し込みへ 1 行で書く」に、軸の違うレビューを通したときも同じ形で 1 行書くことを足す（独立導出の波及先。書かないと `workspace/` の撤去後に、通したかどうかが PR 本文にしか残らない）
- D6 3b の `git diff --name-only main...<sha>` と `.claude/agents/code-reviewer.md` の `git diff main...<sha>` は、ローカルの `main` を起点にしたまま変えない（範囲外。読み過ぎの向きにしか働かない。#1501 の `/code-review high` でも nit として残した）。軸の違うレビューだけを `origin/main` 起点にするのは、こちらはレビューの所見そのものが他の PR の差分で汚れるため（読み過ぎで済まない）
