## 目的

`docs/comment-guidelines.md` を、コメントを書く瞬間に読める形にする。何を書いてどこに置くかの判断を、問い 1 つと置き場の表に集める。規約自身が抱えている経緯は、規約から外す。

## 受け入れ条件

1. 「第一原則」の冒頭が、問い「この行を単純にされたら、何が壊れるか」と、答えごとの置き場の表である（テストが落ちる → テスト名／落ちないが壊れる → その行の直上に、いま成り立つべき前提・不変条件として／何も壊れない → 書かない／どう至ったか → コミット・PR、コメントには `#NNN`）。「約束」は語として使わない（「書く約束」として別の意味で使われている・`.claude/rules/governance-docs.md` ほか。Step 2b の指摘）
2. 理由と精密事実の置き方を 2 つに分けて書く。**理由**は守る行の隣に書き、道案内の参照で済ませない。**精密事実**（1 か所にしか置けない値・契約）は正本を 1 つ決めて `` [`X`] `` か正準形で指す（3b F6）。「短く保つ」の「同じ主張が別の面に既に在るなら指す」と「名指しと正本の指名」の冒頭も、この線に合わせて「精密事実は指す」と書く（今の文面は理由まで指してよいと読める・Step 2b の指摘）
3. 規約の本文に、条項ができた経緯（「#NNN で〜した」「かつて〜だった」「この条項は自分で古くなった」）を書かない。`#NNN` は条項の出所を辿る手がかりとしてだけ残す
4. 外から指されている見出しと、指されている中身を残す（3b F2）:
   - 見出し: 「第一原則: コメントは理由を書く」（全形のまま）・「短く保つ」・「名指しと正本の指名」・「rustdoc の様式」・「日本語の折返し」・「言語（日英）」・「歴史メモの様式」
   - 中身: 第一原則の「書いてよい例外」（一意性の宣言・誤読の予防として名指しする形）・名指しの面ごとの表・測定値に出所を添える理由・判定 (A)/(B)
5. 規約から外した否定の知識のうち、どの ADR にも無いものを新しい ADR が持つ
6. ファイル名だけで規約の中身を述べる 3 か所（`AGENTS.md:16`・`CONTRIBUTING.md:13`・`docs/development-principles.md:72`）が、縮めた後も真である（3b F3）
7. `npm run governance:check` が green（見出し参照の着地・本文のパスと識別子の実在）

## ADR に移すもの

規約から外す否定の知識のうち、ADR が無いもの（2026-11-07 に `git grep` で確認）:

- 行数・文字数の上限を置かない（#1185 の非目標）
- doc の欠落を lint で deny 化する案を採れない（workspace 全体で 305 件が該当・2026-08-16 実測）。挿入位置を既存アイテムの後ろに取れば構造的に起きない
- 禁則処理の規則を置かない（`.rs` のコメント 8030 行で違反候補 0 件・2026-08-08 実測）
- 訳語の判定から「定着語」を外していた扱いをやめた（直訳語が規範文書に入ると保護され、#1251・#1252・#1307 の整備が届かなかった）
- `//` のインラインコメントで角括弧の名指しを禁じた規則を解いた（commit e440c64f。禁止の後も 18 件中 12 件が書かれた）。実装のとき commit 本文を読んで、数と理由を一次資料で確かめてから書く

今回のサイクルで却下した案:

- 規約の表を router（`.claude/rules/comments.md`）に直接置く: `ADR-comment-guideline-delivery-by-pointer` 却下 1 の第一の理由（面積上限）は `ADR-retire-area-budget` で失効したが、`.rs` を触るたびに全文を読み込ませる費用と、人間向けの入口（`CONTRIBUTING.md`）が `.claude/` 配下になる問題は残る。フェーズ 1 では見送る

- 経緯だけを消して節の構成を残す: 「経緯は `#NNN` へ」「リファクタを生き延びるか」が 3〜4 か所に重複したまま残り、書く瞬間の問いが 1 つにならない
- 「遠くを指さない」を一般則にする: `.rs` の正準形参照 140 件と `` [`X`] `` の名指しが一斉に違反に見える。理由と精密事実を分けた（3b F6）
- 問いに機械検査を付ける: 「何が壊れるか」は意味の判定で、正規表現では測れない（散文の数え上げの検知器を測って却下した先例: `ADR-comment-guideline-delivery-by-pointer` 却下 4）

ADR 化済みで、規約から外しても知識が残るもの（指すだけ）: 1 段落 1 行の撤回と rustfmt の `wrap_comments`（`ADR-folded-code-span-detector`）・模範例の消失と述語の陳腐化（`ADR-stale-identifier-detector-scope`）・測定値の置き場（`ADR-measurement-canon-in-code-doc`）。
