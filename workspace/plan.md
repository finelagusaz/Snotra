# 計画 — #1321 merge:pr の事後検証の待ちを 3 段すべてに掛ける

## 目的

マージ直後の反映の遅れで、正常なマージが exit 3 になるのを防ぐ。事後検証の 3 段（宣言した issue の状態・`merged:` の検算・`closed:` の検索）を 1 回分の**観測**としてまとめ、「すべて揃う」か「待ちが尽きる」まで観測を繰り返す。

## 受け入れ条件

1. 観測 1 回で、3 段をすべて引く。揃う条件は次の 3 つがすべて成り立つこと
   - 宣言した issue がすべて `CLOSED`
   - `merged:>=<mergedAt>` に当の PR が現れる
   - `closed:>=<mergedAt>` に宣言した同リポジトリの issue がすべて現れる
2. 揃わなければ `SEARCH_RETRIES` の間隔で待って観測し直す。尽きたら最後の観測で判定する
3. **依存の順を保つ**（敵対的調査の穴 A）: 最後の観測で検算が通っていなければ、`closed:` の検索を信用しない。この場合、宣言外の close も「索引が未反映」も所見に出さず、「検算が通らない」だけを出す
4. **宣言外の close は待ちの判定に入れない**: 揃ったあと（または尽きたあとで、検算が通り、宣言した issue が `closed:` に揃っている観測）で 1 回だけ判定する
5. `SEARCH_LIMIT` への到達は、待たずにその場で打ち切る（いまどおり exit 3）
6. 出力に「観測 N 回・待ち計 S 秒」を載せる（exit 0 でも 3 でも）。索引の遅れの実測を、次の実マージから溜めるため
7. 終了コードの意味は変えない。0 = 揃った、3 = 尽きた・打ち切った・想定外
8. `SEARCH_RETRIES` を `[5_000, 10_000, 15_000]`（計 30 秒）にする。待ちが掛かるのは揃わないときだけで、正常な場合の費用は観測 1 回で済む。マージ直後の引き直し（:240）は先頭要素（5 秒）を使い続け、値は変わらない

## テスト（偽の実行器）

- 2 件宣言のうち 1 件だけが、1 回目の観測で OPEN・2 回目で CLOSED（#1313 の実形）→ exit 0、観測 2 回、待ち 5 秒
- 1 回目の観測で `merged:` に PR が現れず、2 回目で現れる → exit 0
- 3 段とも尽きるまで揃わない → exit 3、観測 4 回、待ち計 30 秒、所見に揃わなかった項目が並ぶ
- 検算が最後まで通らず、`closed:` に宣言外がある → exit 3。所見は「検算が通らない」だけで、宣言外は出さない（穴 A）
- 揃っていて宣言外の close がある → 待たずに（観測 1 回で）exit 3
- `SEARCH_LIMIT` への到達 → 待たずに exit 3（既存テストの意図を保つ）
- 既存のテストはすべて意図どおり緑のまま（件数の変化は、足した分だけ）

3. SKILL の 1 句

## 不変条件と異常系

- マージ後の例外は、いまどおりすべて exit 3（`describe` で文字列化する）
- 観測の途中で gh が失敗したら、その場で exit 3（待たない）。gh の失敗は反映の遅れではない
- 待ちの総量は 30 秒を超えない
