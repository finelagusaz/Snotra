# 計画 — issue #1533 背景の作業を残した委譲先の worktree が、Step 4 の remove でロックに拒まれて残る

## 目的

委譲先の worktree が、Step 4 の `remove --delegate-tree` で消えるようにする。消えなかったときは、そのことがセッションの終わりの報告に出るようにする。

採る候補は、1（発生源で断つ）と 3（拒まれたときの出力と報告）である。2 と 4 は採らない（理由は「採らない候補」）。

## 受け入れ条件

- `/implement`「3b. 委譲へ渡すもの」が、委譲先に「背景の作業の完了を待ってターンを終えない」ことと、その代わりの回し方を指示している。
- Step 4 の「ロックされている」の行が、#1533 で実測した機序と合っている。打ち直しで待つ指示が消え、残ったことを「出力」の片づけの欄に書く指示がある（plan-review で wrap_up の recap から改めた）。
- `verify:tree remove --delegate-tree` がロックで拒むとき、出力にロックの理由（git の `locked` 行の残り。harness なら `claude agent agent-<id> (pid N)`）が出る。「委譲先がまだ動いているか」の推測は出さない。テストが理由の表示を断言する。
- 次の実サイクルで、背景の作業を使わない委譲先の worktree が remove で消える（PR 本文のチェックリストに置く。計画の中では測れない）。
- `npm test` と `npm run governance:check` が通る。

## 不変条件と異常系

- ロックされた worktree では、`.delegate/` を消さない（先に消すと、報告だけ失って worktree が残る）。exit は 1 のまま。
- `.delegate/` の外に変更があるときの拒否は、ロックの判定より先に行う（今の順序を変えない）。
- `locked` 行に理由が無い（`git worktree lock` を `--reason` なしで打った）ときも、拒否は同じに働く。
- `ADR-implement-verification-tool-tree` の前提（`.delegate/` を worktree の中に置き、意図して dirty にする）は変えない。
