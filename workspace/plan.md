## 未確定（すべて解消済み）

- [x] **1. 逐次 1 パスは並列 16 に勝てるか** → **勝てない。** 上の判定表のとおり 2.33〜3.34 倍遅い。
  **事前の予測（6 倍削減 vs 16 倍ペナルティ）は結論だけ当たり、機序は 2 つとも外れていた**
  ——実測は単価の削減 1.29 倍 / 並列度の利き 3.01 倍である。裏取りのため A 側を単スレッドでも
  測る列を足した（この 1 列が無ければ「単価は削れたが並列度に負けた」と誤って記録していた）
- [x] **2. マッチ不能な部分木を丸ごと飛ばせるか** → **飛ばせない。測定ではなく論証で決着した。**
  パスマッチは部分文字列検索であり、親で照合状態が 0 に戻っても子孫は自分のセグメントの
  途中から新たに一致を開始できる。「この部分木には決して一致が現れない」と言える条件が
  存在しない。spike はこの前提（スキップ無し）で書いてある
- [x] **3. 照合状態の型・所有者・寿命** → **消滅**（製品実装へ進まないため決める対象が無い）
- [x] **4. マッチしたエントリのフルキーをどう供給するか** → **消滅。** ただし判定の根拠として
  効いた——1 パスが組み立てを省けるのはマッチしなかったエントリだけで、`c:\users\` の
  96,482 件では後段で組み立てが戻る。並列化で救う案の天井（1.29 倍）を無効にする論点である
- [x] **5. 非 ASCII の長さ変化（ß → ss）を自動機がどう扱うか** → **消滅。** spike は非 ASCII を
  素通しして単価の**下限**を測った（下限で負けるなら正しく作っても負ける）。実データの
  非 ASCII は 1.7% で、件数の突き合わせは両側一致した
