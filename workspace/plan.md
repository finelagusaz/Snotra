# 計画 — #1314 `/implement` の本文から経緯を外す

## 目的

`.claude/skills/implement/SKILL.md` の本文を「何をするか」に寄せる。経緯（事件の再話・issue 番号の列・機構の死角の説明）は、既に在る所（ADR・PR 本文＝main の squash commit）を指す。規則・射程の条件・設計の理由の 1 文は残す。

## 受け入れ条件

1. **規則を 1 つも落とさない。** 判定は、組み直し前後の集合差（バッククォート語・`ADR-*`・`#NNN`・太字句）を 1 件ずつ裁いた表で行う。消えた語ごとに「経緯なので消した（在る所）／規則なので残した」を書く
2. **見出しの文言を 1 つも変えない**（生きた参照: `「3a. 委譲の前に」`・`「3b. 委譲へ渡すもの」`・`「Step 4 — 仕上げ」` ほか。research.md の表と敵対的調査の追加分）
3. 他文書が散文で依存している文を逐語で維持する: 行 110 末尾「注入するのはこのエージェントだけである: 主エージェントは同じ木へ注入しない」、行 127 の太字「この Step を出るのは、…すべて通ったときである。」
4. 行 18 の較正（Fable 5.1 以降・#1230）は残す（`.claude/rules/safety-nets.md`「規範（ドキュメント・スキル・チェックリスト）を足すとき」）
5. 末尾に、`/race-check` に倣った経緯の所在の 1 段落を置く（「改修するときに読む——実装で従うのは本文である」）
6. `npm run governance:check` が緑

1. 組み直し前の集合を採る（`git show main:.claude/skills/implement/SKILL.md` からバッククォート語・`ADR-*`・`#NNN`・太字句を抽出）

3. 組み直し後の集合を採り、`comm` で差を出し、1 件ずつ裁いて表にする。正準形 `X「Y」` の抽出は Git Bash の `grep -o` で行わない（多バイトが壊れ、12 件中 2 件しか出なかった・独立導出の実測）。Grep ツールか `rg -o` を使う。**識別子の差は散文の条件を見ない**ので、独立導出の A〜K（規則を担う文 11 件）を検収表として、新版で 1 件ずつ在ることを確かめる

## 不変条件と異常系

- 見出しを変えれば G-heading-refs が赤にする（敵対的調査で実測済み）。ただし `docs/adr/` からの参照（「1a」「出力」「Step 3 — …」）は走査の外なので、検査は守らない。見出しを変えないこと自体を受け入れ条件にしている
- 逐語で依存されている文（受け入れ条件 3）は、どの検査も見ていない。集合差の表で、その文が残ったことを名指しで確かめる
