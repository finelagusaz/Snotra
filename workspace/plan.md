# 計画 — issue #1494 委譲先に、触るパスの rules を Read で読ませる

## 目的と受け入れ条件

目的: worktree に隔離した委譲先（`/implement` 3b）にも、触るパスに当たる `.claude/rules/` の本文が届くようにする。配送の挙動の記述（`AGENTS.md` 冒頭）を、測った事実に合わせる。

受け入れ条件:

- A1 `/implement`「3b. 委譲へ渡すもの」の指示に、自分の worktree の `.claude/rules/` から触るパスに当たる rule を Read で読む箇条がある
- A2 `AGENTS.md` 冒頭の配送の文が、worktree に隔離したサブエージェントには配送されないことを述べ、測った日付を添えている
- A3 `/start-issue` 3b・`/plan-review` は変えない（隔離しない委譲先には、Read で配送が届き、`AGENTS.md` も届く）
- A4 測定結果が #1494 のコメントに残っている
- A5 `npm run governance:check` が通る

## 設計の決定

- D1（Q1）読ませる rule は、主が列挙せず、委譲先に各 rule のフロントマターの `paths` で判定させる。主が列挙すると、列挙しなかった rule が黙って落ちる（`.claude/rules/governance-docs.md`「規則を具体化するとき、閉じた形を開いた禁止の列挙へ替えない」と同じ理由）
- D2 読ませるのは、自分の worktree の版である（アンカーの sha の版。主の作業ツリーの版ではない）
- D1 の具体（計画準拠レビューの要対処 1〜3 を反映）。新しい箇条に次を書く
  - 「触るパス」は、差分（`git diff --name-only main...<sha>`）のファイルと、変異注入で書き換えるファイルである。委譲先は sha を持つので自分で出せる（`.claude/agents/code-reviewer.md` も `git diff main...<sha>` を使う）。主から一覧を渡さない
  - 照合は worktree のルートからの相対パス（`/` 区切り）で行う。絶対パスは `.claude/worktrees/agent-<id>/` を含むので使わない
  - 当たるか迷ったら読む（読み過ぎの害は Read 1 回だけ）
- D4 3b の既存の箇条（timeout の後始末で `.claude/rules/safety-nets.md` の節を指す）は残す。新しい箇条は「どの rule を読むか」の一般則、既存の箇条は「timeout のときにどの節に従うか」の名指しで、役が違う
- D5 配送を述べる他の現役の記述（`.claude/rules/safety-nets.md` 冒頭・`.claude/skills/retrospective/SKILL.md`・`docs/comment-guidelines.md`・`docs/glossary.md`）は変えない。隔離という例外が付く全称だが、読み手の多くは主セッションである。隔離した委譲先も 3b の箇条に従って `safety-nets.md` などを読むが、その時点で Read を済ませているので、「触ると自動で配送される」を読んでも誤った行動にはつながらない（委譲レビュー ラウンド 1 の L2 で根拠を直した）。前提の書き添えは `AGENTS.md` 冒頭の 1 文が担う（全称の反証プローブの処置「前提を書き添える」）
- D3（Q2）`AGENTS.md` 冒頭には、測定の報告と行動形を 1 文ずつ足す。報告: 2026-11-21 の測定（#1494）では、worktree に隔離したサブエージェントには、ファイルツールで触っても配送されなかった。全称にしない、機序を書かない（`workspace/research.md`「敵対的調査（3b）の反映」）。行動形: 隔離した委譲先に rule を読ませるときは、委譲の指示で Read を求める。手順の本文は `/implement` 3b が持つ
