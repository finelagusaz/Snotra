# 計画 — issue #1497 文書だけの変更で implement Step 3 に何を求めるかを決める

## 目的と受け入れ条件

目的: 文書だけの変更で、`/implement` Step 3 の委譲（レビュー・変異注入）に何を求めるかを決め、変異注入を省いたときに「省いた」のか「対象が無い」のかを報告から区別できるようにする。

受け入れ条件（issue #1497 から）:

- A1 文書だけの変更で Step 3 をどう進めるかが `/implement` に書かれ、「出力」節の表にその場合の書き方がある
- A2 hook・スクリプトなど、文書の形をした実行物（`.mjs` など）を「文書だけ」に含めない
- A3 `npm run governance:check` が通る

## 設計の決定

- D1（Q1）委譲は省かない（いまの `/implement` のとおり、どの変更でもレビューは委譲先が行う）。変えるのは変異注入の扱いだけである。根拠: 「出力」節の「時間・手間を理由に値を選ばない」と、safety-nets の「規範が妥当かどうかは…独立したレビューが後から明らかにする」。このセッションの文書の PR でも、各 PR の初回ラウンドで指摘が出て、うち 2 本は High だった（`workspace/research.md`「敵対的調査（3b）の反映」）
- D2（Q2・組み替え）「文書だけか」は判定しない。判定するのは「変異注入の対象があるか」である。対象があるのは、差分が次のどれかに当たるとき: 検知器（テスト・hook・検査・スクリプト）を足す・変える／検知器の入力の構造を変える（G-* 検査が読む表・見出し・フェンス、`verify:tree` が回すフェンス、harness が読むフロントマター・設定など）／検知器が何かを捕まえると主張する文を足す・変える。どれにも当たらなければ「該当なし」で、その根拠に当たらないことを書く。迷ったら対象があるものとして扱う。検知の主張を足した・変えた場合に注入する先は、差分の文書ではなく、主張の根拠にした検知器の複製である（`.claude/rules/governance-docs.md` の「有効性の主張は、何を注入し、どの母集団を測って、どう出たかの報告に置き換える」と同じ）。スクリプトや `.mjs` は検知器か実行物なので、この判定で自然に「該当なし」から外れる（A2）
- D3 変異注入が「該当なし」の差分でも、差分が手順・コマンド・ツールの挙動を述べるなら、委譲先は「実地の確かめ」を行う。使い捨ての複製（一時リポジトリ・一時ディレクトリ）で、述べられた手順を書いてあるとおりに打ち、主張どおりかを確かめる（#1501 の rules の配送、#1503 の git 手順と retrospective の範囲がこの形で効いた）。手順を述べない差分（言い回し・説明だけ）では、実地の確かめも「該当なし」とする
- D4（Q3）「出力」節の委譲の行には、変異注入の結果か、該当なしの根拠（D2 のどれにも当たらない理由）と、実地の確かめの結果（何を打ったか、または該当なし）を書く。3c の plan.md への 1 行の記録も、「生き残った変異の数」の代わりに同じ形で書く
- D5（Q4）入口での変更の種類の判定とは合わせない。Step 1 の入口判定は計画の有無・同一性・承認を見るもので、変更の種類は見ない。この issue は Step 3 の中で閉じる

## 不変条件と異常系

- 「時間・手間を理由に値を選ばない」を保つ。「該当なし」は、差分に変異を当てる対象が無いことを根拠にする
- 検知器・その入力の構造・検知の主張に触れる差分は、文書であっても変異注入の対象から外さない（D2）
- 判定に迷ったら、対象があるものとして扱う（変異注入を求める側へ倒す）

## テスト方針と検証コマンド

- 文書だけの変更。`npm run verify:tree '--' run --sha <sha> --categories E,F`
- `/implement` Step 3 の委譲: レビューと読み合わせ。この PR 自身に足した手順を当てる（差分は手順書の文で、検知器・その入力の構造・検知の主張に触れないので変異注入は該当なし。手順・コマンドを述べる差分も無いので実地の確かめも該当なし、の見込み）。足した箇条を、#1491（検知の主張を直した例）・#1500〜#1503・フロントマターの `allowed-tools` を変える架空の差分・G-* 検査が読む表を変える架空の差分に当てて、判定が一意に決まるかをたどる
