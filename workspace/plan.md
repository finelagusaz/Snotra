# plan — issue #504: 故障注入をライブの `.githooks/` から複製へ移す

## 方針（一行）

差し替え点は**テストファイルではなく `core.hooksPath`** である。使い捨て repo を `.githooks` の**複製**へ向ければ、ライブを読むだけで故障注入が成立する。issue の候補 1（テストへ引数を足す）も候補 2（worktree を切る）も要らない。

**恒久変更は `AGENTS.md` の一文だけ。** 受け入れ条件 1（「実際に一度やって示す」）は使い捨てサンドボックスでの実測で満たし、PR 本文へ記録する。

## 初版から反転した判断（`/plan-review` Step 2b・独立導出）

初版は「故障注入テストを `githooks.test.mjs` へ恒久化する」としていた。**独立導出がこれを否定し、検算の結果その指摘が正しい**と判断した。3 つの根拠が独立に同じ結論を指す:

1. **規範の文言**: `AGENTS.md:60` は「故意に壊して検知されることを **1 度**確かめる」。恒久化は要求されていない。先例 #482 もメモリ内コピーへの ad-hoc 変異で実証し、テスト化していない。
2. **`AGENTS.md`（#500）「カナリアで守るのは沈黙する経路だけでよい」**。`enableHooks()` を使う 13 テストはライブの `.githooks` を回すので、ライブが壊れれば `expectBlocked` が必ず throw する（実測 M3・`research.md`）。**loud に落ちる経路に見張りを足すのは、コストを払って何も買っていない。** 初版はこの規則を「変異テストを 4 本に増やさない」根拠に使いながら、1 本目に適用し忘れていた。
3. **手口は既にテストされている（決定打）**。`githooks.test.mjs:229`+`:250`（V10）が `cpSync(HOOKS_DIR, …)` で複製を作り、複製の `pre-commit` を `#!/bin/sh\nexit 0\n` へ置換し、`core.hooksPath` を複製へ向けている。**追加しようとしたテストは、V10 が毎回実行している機構の手書き重複**だった。

初版が残した正しい判断（両方向 assert・`enableHooks()` をライブのまま残す・env 差し替えを採らない）は、いずれも「テストを足さない」に吸収される。

## 実装（単一フェーズ）

### `AGENTS.md` L60 の該当文を差し替える

**変更前**:
> ただし**稼働中のガードを弱めて測ってはならない**——**判定がソース述語なら**、ライブのファイルではなく**複製に変異を当てる**（#482 で既定 `exitCode = 2` を 0 へ反転する編集は classifier が拒否した。ソースをメモリ上でコピーし 3 通りの変異を当てて、カナリアが全て捕まえることを実証した）。

**変更後**:
> ただし**稼働中のガードを弱めて測ってはならない**——ライブのファイルではなく**複製に変異を当てる**。判定がソース述語なら、ソースをメモリ上へコピーして変異を当てる（#482 で既定 `exitCode = 2` を 0 へ反転する編集は classifier が拒否した。3 通りの変異をカナリアが全て捕まえることを実証した）。**判定が実 git 操作でも規則は同じである**——hook ディレクトリを一時ディレクトリへコピーし、使い捨て repo の `core.hooksPath` をコピーへ向けて、コピー側を壊す（`core.hooksPath` は任意の絶対パスを取るので、ライブの `.githooks/` を壊す必要はない。手本は `.githooks/githooks.test.mjs` の V10）。**「判定がソース述語なら」のような条件節を読んではならない** — 変わるのは複製の作り方だけで、規則は無条件である（#504。この条件節を免除と読み、ライブの `pre-commit` を無害化して測った）。

**この改稿が満たすもの**:

- **条件節の除去**: 「判定がソース述語なら」が #484 のわたくしに「実 git を回す検査は適用外」と読ませた。`/plan-review` トリガの廃止（#495）と同型の**条件性含意**であり、免除条件は免除を必要とする当人が判定する。
- **二分岐の明示**（独立導出 §6-4）: ソース述語 → メモリ内コピー、実 git → 一時ディレクトリへのコピー。分岐を書かないと、規則を守る読者が「メモリ内コピーはそのまま使えない」→ ライブ改変へ逃げる（#484 の再演）。
- **既存事例での検算**（`AGENTS.md`「新設した規約は、既存の全事例に当てて検算してから書く」）: #471（型エラー注入・ライブを弱めない）／#482（メモリ内コピー）／#488・#489（規範への読者注入）／#497／#500（カナリアへ偽セクション注入）／設計文書 §6 の V1〜V10。**無条件化して破れる既存事例はゼロ。** 唯一破っていたのが #484 であり、それが本 issue である。

## 不変条件

1. **ライブの `.githooks/**` は 1 byte も変わらない。** 検証: `git diff --stat` に `.githooks/` が現れないこと。
2. **`enableHooks()` はライブを向いたままである。** 複製へ差し替えれば `githooks-selftest` は「複製が正しい」ことしか言わなくなり、この PR が塞ぐはずの false green を別の場所に作る。
3. **恒久カナリアの loud 性を損なわない。** `expectBlocked` 系 13 テストは、hook が沈黙すれば必ず throw する（`BLOCKED` を stderr へ書くのは `_lib.sh` の `die()` だけ・実測 M3）。本 PR はテストを 1 行も触らないので、この性質は保存される。
4. **失敗時の挙動**: 本 PR はドキュメント 1 ファイルの変更であり、実行時の状態・リソース・フラグを導入しない。
