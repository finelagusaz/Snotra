# 計画: #1408 コードのコメントから、ジャンプで足りる道案内の参照を減らす

調査は `workspace/research.md`、反証は `workspace/adversarial-1408.txt`。範囲はユーザー判断で「参照の削減」に絞った（構造の断定の見直しは行わない）。

## 目的

`.rs` のコメントにある「（`X` の doc）」型の参照のうち、指す側が X を実際に使っていて、道案内か出所の印にしかなっていないものを消す。読者は定義へジャンプすれば読める。消すことで、指された doc が「そこに書いてある」という約束から外れ、書き換えやすくなる。

## 受け入れ条件

1. 候補（下の「候補の母集団」）を 1 件ずつ判定し、判定（消す／残す）と理由を `workspace/judgements.tsv` に残す
2. 「消す」と判定したものだけを消す。消したあとの文が、参照なしで読める（括弧だけが残る・文が途切れる、などが無い）
3. 変更は `.rs` のコメントだけである。コメントを除いたトークン列が、変更の前後で一致する（下の「検知器」）
4. カテゴリ A（fmt・clippy・test・`cargo doc`）と E・F が green

## 候補の母集団

`.rs` のコメント行と、その次行（折返し）から、次の形を拾う。

- `` `X` の doc `` / `` `X` の `//!` `` / `` `X` の `///` ``（現行の抽出）
- `` [`X`] の doc `` などのリンク形（3b F1 で 63 行）
- 「の」と「doc」が折返しで別行になった形（3b F1 で 22 行）

除外（範囲の外）: `.md`・スクリプトのコメント（issue が `.rs` のコードを条件にしている）、「理由は `X`」型の理由の所在の宣言（3b F1）、指す側のファイルのコードが X の名前を一度も使わないもの（ジャンプの経路が無い）。

抽出のスクリプトは scratchpad に置く（`ref-purpose.mjs` を広げる）。リポジトリには入れない。

## 判定の規則（消すのは、次をすべて満たすとき）

1. **X を、その参照が効いているブロックで実際に呼ぶ・使う。** ファイル単位の名前の一致では足りない。読んで確かめる（3b F2）
2. **X がこのリポジトリの中にある。** 外部 crate（egui・epaint・egui_kittest など）の doc は残す
3. **参照は道案内か出所の印である。** 次のどれかなら残す:
   - 精密事実（値・契約・式）の正本の指名（「正本は」「値は」など）
   - テストが何を固定するかの宣言（「X の doc が挙げる例外を、ここが固定している」）
   - X の doc の文言を逐語で引いている（「」で括った引用。出所を消すと、出所の無い引用になる・3b F3）
4. **コメントの中にある。** 文字列リテラル（`assert!` のメッセージなど）は触らない（3b F3）
5. **同じ括弧・同じ行に、別の参照（正準形の見出し参照・ADR 引用・`#NNN`）があれば、X の部分だけを消す**（3b F3）

消したときに文が成り立たなくなる場合（「（`X` の doc）。」だけの行など）は、括弧ごと消し、前後の文を最小限つなぐ。理由を書き足さない（写しを増やさない）。

## 検知器（コメントだけの変更であること）

Rust の字句を、コメントを落として並べ、変更の前後で比べる scratchpad のスクリプト（`rust-code-tokens.mjs`）。区別するもの: 行コメント・ブロックコメント（入れ子）・文字列（エスケープと継続行）・raw 文字列（`r#"…"#`）・byte 文字列・char リテラルとライフタイム。出力はトークン列（空白を畳む）。

- 自分で確かめる: 3b F5 の文字列継続行の変異（`"abc\` の次行 `// x";` を `// y";` に変える）と、コード 1 行の削除を、検知器が差として出すこと。コメントの中身だけの変更を差として出さないこと
- 足場の撤去: scratchpad に置くので、リポジトリには入らない

## 変更するファイル

候補を含む `.rs`（判定の結果で決まる。3b の時点の上位は `src-tauri/src/egui_shell/window_coordinator.rs`・`view.rs`・`results_window.rs`・`snotra-core/src/indexer/cache.rs`・`layout.rs`）。コメント以外は変えない。

触らないもの: `.md`・スクリプト・指されている側の doc の中身（構造の断定の見直しは範囲外）・文字列リテラル。

## 不変条件と異常系

- コード・文字列・テストが読むソースの断片は変えない（検知器と `cargo test`。ソースを文字列で読むテストが 4 本ある・3b F4）
- doc コメントの折返しの中でバッククォートを落とさない（`cargo doc` の `invalid_html_tags` などが赤になる・3b F4）
- 正準形の見出し参照・ADR 引用を同じ行から消さない（`governance:check` が照合件数の減りで知らせるわけではないので、`judgements.tsv` の規則 5 で守る）

## テスト方針と検証コマンド

- `npm run verify:tree` のカテゴリ A・E・F
- 検知器: main の版と HEAD の版で、変更した全 `.rs` のトークン列が一致すること
- 変異注入は `/implement` の委譲先が行う（検知器がコードの変更・文字列継続行の変更を捕まえること、`cargo doc` がバッククォートの欠けを捕まえること）
