## 目的

`scripts/governance/checks/G-stale-identifiers.mjs` の `productionOnly` を削除し、**それを名指している生きた層の記述から偽の前提を落とす**。

**これはデッドコードの削除ではなく、撤去の取りこぼしの回収である**（`research.md` §3b・`git log -S` で実測）。この関数は #793 の G12（config 値の到達性検査）のために書かれ、#897 の G12 撤去で呼び出しが 0 になり、#1093 が隣接だけを理由に現在地へ運んだ。`AGENTS.md`「機構・層・ファイル群を撤去する」が言う「撤去した層の語彙」の残余（#1155 / #1157 と同クラス）に当たる。

## 不変条件と異常系

- **禁止は機械が守る。** `#[cfg(test)]` 切り落としを `G-heading-refs` の `.rs` の腕へ持ち込むと `lib.test.mjs` の「種 3」が赤くなる（`research.md` §2e で実測）。書き換えはこの機構に触れない
- **書き換えは「識別子を消すだけ」で終えてはならない。** 消すだけだと `lib.mjs` に「`#[cfg(test)]` 相当を入れてはならない（非対称は意図）」という**相手方を探せない警告**が残る。将来の保守者が grep して 0 件を見て「腐った警告」と判断し、**警告ごと削除する**経路が開く——それは規範の消失であり、**種 3 はコメントを消しただけでは落ちない**。ゆえに禁止を**変換の名**（例: 「`#[cfg(test)]` 以降を落とす変換を…入れてはならない」）で書き直す
- **`:90-94` からは、次の 2 つを落とさない。** ここは、ヘッダが `:61` / `:141` / finding メッセージ `:188` で 3 度使う「**production の**ソース」という語の**唯一の訂正**である（実際に production を支えているのは `VOCAB_TEST_FILE` というファイル名の形だけで、`.rs` のテストコードは語彙に入っている）:
  1. Rust 側の 3 つの形（`#[cfg(test)] mod` の中身 / `<crate>/tests/*.rs` / `src/**/tests/*.rs`）が語彙を寄付しうること
  2. **`#[cfg(test)]` 以降を落とす変換を入れても閉じるのは 1 つ目だけ**という測定結果と、「全セルで finding が 1 件も動かなかったので採らなかった」という却下理由
- **`.mjs` のコメント内の識別子は、どの検査も見ない**（`research.md` §2d）。散文化漏れは沈黙する。ゆえに 4 か所を**同じ差分で**処理し、完了は `git grep productionOnly` の全件振り分けで判定する
- **ただし同じコメントは `G-heading-refs` の `.mjs` の腕に入っている**（`headingRefCommentDocs`・#1138）。見られていないのは識別子だけで、**正準形の見出し参照は照合される**。**正準形を 1 物理行に保つこと**——文言に合わせて JSDoc の段落を折り返すと #1156 の検査（物理改行で折れた参照）が赤くなる。**編集後の赤はまず折れた参照を疑う**
- **「受容する残余」を正準形へ格上げしない。** `ANCHOR_SPECS` の第 3 スペックは JSDoc の継続行（` *  **X**`）には当たるが、行コメントの箇条書き（`// - **X**`）は行頭が `/` なので当たらない。独立導出が `collectAnchors` を実ファイルへ当てて実測し、`G-stale-identifiers.mjs` のアンカー 5 件がいずれも JSDoc 側で「受容する残余」が**アンカーになっていない**ことを確認している。`:112` / `:152` の「受容する残余」は**バッククォート無しの素の「」のまま**にする（正準形にするとパスは解決してアンカーが無く、G-heading-refs が恒久的に赤くなる）
- 異常系: 削除で語彙源から 1 語が消える。母集団文書に `` `productionOnly` `` があれば finding へ転ぶ——**今日 0 件**（`research.md` §2a で実測）だが実装後にもう一度測る
