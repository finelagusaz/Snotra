## issue の要約

`docs/comment-guidelines.md`「日本語の折返し」は「文途中で物理改行を入れない（1 段落 1 行）。適用は新規に書くコメントと、その変更で触った段落だけである」と定める。#984 のサイクルで目視では守れず、**新規・touched の段落に 26 件**の違反があり、**直す編集自身が 2 件持ち込んだ**。issue は `npm run governance:check` へ `G-<name>` を 1 本足すことを提案し、判定の骨格（差分から追加行を取る → 文末らしい文字で終わらない行 → 表・箇条書き・フェンスを除外）と既知の性質（太字スパンまたぎ・語の途中・母集団は新規/touched のみ）を挙げている。撤去条件は規約の「折返しは機械が持たない」の一文を「整形器は持たないが検査は持つ」へ更新すること。

## 選択肢（この issue の実体はここの分岐である）

### 案 A — issue の提案どおり、差分ベースの `G-` 検査を `checks/` へ足す

- **`checks/` 初の git 依存の検査になる。** 今日の `checks/` は snapshot 純粋で、`git` を触るのは `lib.mjs` の `check-ignore` と、`checks/` の外にある `dependents.mjs` だけである。
- **CI に base が無い（実測）。** `.github/workflows/ci.yml` の `governance-check` job は `actions/checkout@v7` を `fetch-depth` 指定なし（＝depth 1）で使い、`node scripts/governance-check.mjs` はその直後に走る。base を持つのは後段の `governance manifest delta` step だけで、そこも `git fetch --depth=1 origin "$BASE_SHA"` の**浅い**取得である（merge-base は取れない）。**案 A は workflow の変更を含む。**
- **fail-open が「壊れたとき緑が緑のまま」に当たる。** 差分ベースでは `checked: 0` が main 上の正常状態なので、`{findings, checked}` の証跡では「`git diff` が黙って失敗した」と「変更が無い」を区別できない。`git` の失敗は必ず赤にする必要がある。
- **base ref を CI で解く必要がある**（shallow clone だと merge-base が無い）。`.github/workflows/` の `governance-check` job の fetch-depth を先に読む。
- **M2 の数がそのまま費用になる**——中央 19 件。既存 3151 件のうち touched になった分が毎 PR で赤になる。

### 案 B — `dependents.mjs` の形で post-edit の reminder にする（合否を持たない）

- 母集団（新規・touched）が構造的に一致し、#984 の失敗の瞬間（**直す編集自身が 2 件持ち込んだ**）にその場で鳴る。
- 誤検出の費用が低い（exit code を動かさない）。
- **ただし中央 19 件は読まれない。** `dependents.mjs` が `LISTED = 3` で切っているのと同じ問題が、はるかに高い頻度で起きる。ほぼ毎編集で鳴る reminder は無視されるようになり、**鳴っていることが「見た」を意味しなくなる**。

### 案 C — 「1 段落 1 行」ではなく**害の側**を機構化する（`G-folded-code-spans` 相当を新設）

- 全ツリー snapshot 走査でよい（差分・base ref・fail-open の問題がすべて消える）。
- 既存 6 箇所を畳めば **0 件から始まり、以後の再発を赤にする**。偽陽性 0。
- **2 つの実測された害の両方が機構を持つ**状態になり、#1156 が作った非対称が解消する。
- **却下 3 の裁定を覆すことになる**（前提の変化＝#1156 を理由に）。ADR へ追記が要る。
- **issue の動機そのものには答えない。** #984 の 26 件は M3 の分布からして大半が「害の記録が無い素の折返し」であり、案 C はそれを 1 件も捕まえない。

### 案 D — 機構を足さず、規約側を実測に合わせて縮める

- 「1 段落 1 行」を、根拠のある 2 条（コードスパンを跨がせない・正準形の参照を折らない）へ縮め、素の散文の折返しは許す。
- **M2 が示すのは「規約が守られていない」だけでなく「規約が実践と乖離している」ことでもある**——`G-folded-heading-refs.mjs` 自身のヘッダ（2026-08-20 に書かれた）が段落を折っている。機構を書く側が守っていない規約である。
- `.claude/rules/safety-nets.md` の「足す前に『壊れたとき緑が緑のまま推移するか』を問う——推移しないなら置かない」に照らすと、素の折返しは**気づく契機が残らない**（誰も困らない）ので、機構を置く根拠が弱い。

## 技術的制約（どの案でも効く）

- **`.rs` のコメント行だけを取る導出が今は無い。** `COMMENT_FAMILY`（`lib.mjs`）に `.rs` は入っておらず、`refScanLines` は `.rs` を散文側（`linesOutsideFences`＝全行）に落とす。これは #925 以来の意図的な母集団であり、**同じ変更で動かしてはならない**（検査対象を変更しながら検査を検証しない・#489）。コメント行への絞り込みは新設の述語として持つ。
- **`parseHunks`（`dependents.mjs`）は再利用できるが `HEAD` 固定である**。base を引数化するなら、あちらの呼び出し点を壊さないこと。
- **検査は `checks/` 直下に `<id>.mjs` と `<id>.test.mjs` の対で置く**（`registry.mjs` が走査して `id` / `run` の export を要求する）。`checks/` の外に置いたものは「検査 N 件」に数えられない＝合否を持たない、が機構上の担保である。
- **フォールトインジェクションで一度は実測する**（`.claude/rules/safety-nets.md`）——複製へ折返しを 1 件植えて赤になることまで確かめる。
- **`.rs` のコメント行の抽出は状態追跡で書く**（3b 所見 4a）。行頭の記号を見る正規表現は Rust のデリファレンス代入文を拾う（実測 59 行）。
- **検査を 1 本足すと構造母集団が動く**（#1088）。`scripts/governance-manifest.mjs` の `KEYS` に `checks` が入っているので、**PR 本文で宣言しないと `governance manifest delta` step が落ちる**。
- **`.ps1` / `.psm1` にはコメント作法の生きた規範が一つも無い**（`G-folded-heading-refs.mjs` のヘッダが宣言している）。M4 のヒット 6 件のうち 2 件はそこに在るので、母集団を広げるなら「規範が無い面で機構だけが赤を出す」ことを検査のヘッダで宣言する必要がある。
