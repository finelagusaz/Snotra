# 調査: issue #988 — `//` インラインコメントの intra-doc link 形

**結論（先出し）**: issue の中核前提は、issue 提出（2026-08-08）より後の #1176（`e440c64f`・2026-08-25）が**明示的に反転させている**。`//` でのリンク形の一般的な禁止は解かれており、issue が課した「8 件を 0 件にする」という到達目標はもう正本に支えられていない。生きて残るのは (b)——「保証の要る参照を doc コメント側へ移す」——の側だけであり、その母集団は 20 件のうちの一部である。

## issue の要約

`//` のインラインコメントに書いた `` [`X`] `` は rustdoc が読まないので着地が検査されない。角括弧は「`cargo doc` が確かめている」外見を持つため誤った安心を与える。2026-08-08 時点で 8 件（すべて `snotra-core`）。一括置換せず 1 件ずつ (a) 素のバッククォートへ落とす / (b) doc コメントへ移す を判断する。8 件を 0 件にしてから検知器の採否を決める。

### 4. 着地しない参照が 2 件ある（3b が反証し、自分で裏を取った）

**初稿の「腐った参照は 0 件」は誤りだった。** 述語が最終セグメントの定義検索だったため、「名前はツリーに在るが、そのコメントが在るファイルのスコープに無い」形を落としていた。3b が `columns.rs:137` の `` [`IndexMaterial`] `` を一時的に `///` へ昇格させて `cargo doc` を走らせ、`unresolved link to 'IndexMaterial'` を実測した。

スコープを見る述語で 20 行を測り直し、疑いの出た 3 件を `use` 宣言の逐語で裁定した。

| 位置 | 参照 | 裁定 |
|---|---|---|
| `indexer/columns.rs:137` | `` [`IndexMaterial`] `` | **着地しない**——定義は親 `indexer.rs`。`columns.rs` の `use` は `super::AppEntry` だけ |
| `indexer/cache.rs:634` | `` [`DerivedColumns::into_cached_masks`] `` | **着地しない**——`cache.rs` は `super::columns::{CachedLower, CachedMasks}` を引くが `DerivedColumns` を引かない |
| `search/scoring.rs:287` | `` [`PathStore`] `` | 着地する（**述語の偽陽性**）。`use super::{ ... PathStore ... }` が複数行に折れており正規表現が拾えなかった |

修飾を伴う 2 件も逐語で確かめた。`binfmt.rs:174` の `` [`crate::indexer::index_built_at_in`] `` は `indexer/cache.rs:327` の `pub fn` を `indexer.rs:25` が再エクスポートしており、パスが通る。`path_store.rs:277` の `` [`Self::sorted_prefix_len`] `` は `impl PathStore`（127〜325 行）の内側にあり、同名の field（124 行）と `pub(super) fn`（308 行）が在る。

**残る 18 参照について、着地を妨げるものを見つけていない。** ⚠️ ただし `Self::sorted_prefix_len` は field と method が同名であり、rustdoc が曖昧さを警告する形かどうかは測っていない——(b) を選んだ場合の確認項目にする。

**この 2 件の害は潜在的である。** `//` は rustdoc が読まないので現在は何も壊れておらず、`cargo doc` は緑のままである。効いてくるのは (b)——doc コメント側へ移す——を選んだ瞬間であり、そのとき `use` を足すか完全修飾へ書き換えるかの作業が同時に要る。**(b) の判定に直接効く事実なので、triage の入力として使う。**

## 技術的制約

- ADR は凍結された歴史であり、黙って書き換えない
- `.claude/worktrees/` を含む `grep -r .` は追跡外のファイルを混ぜる。母集団は crate ディレクトリを明示して取る
- コメント規約の冒頭が「既存コメントの一括書き直しは本書のスコープ外」と宣言しており、新条項の射程は新規・触った箇所に限られる
- `use super::{ ... }` は複数行へ折れる。import の有無を 1 行の正規表現で測ると偽陽性が出る（上の 4 で実際に 1 件出した）
