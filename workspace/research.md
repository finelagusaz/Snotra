# 調査: #1408 コードのコメントから、ジャンプで足りる道案内の参照を減らす

測定は 2026-11-08・main（#1410 マージ後）。抽出は scratchpad の `ref-purpose.mjs`（`X` の doc / `X` の `//!` / `X` の `///` の形を、`governance:check` と同じ走査元 `allHeadingRefDocs` + `refScanLines` から拾う）。

## issue の要約

- 「（`X` の doc）」の形の参照は、指された doc の中身まで変えにくくし、しかも検査が照合しない
- あるべき姿: 指す側のコードが X を使っていて道案内しかしていない参照は消す。理由が指す側で要るなら、その行の隣に書く。1 か所にしか置けないもの（測定値など）を指す参照は残す。指されていた doc から構造の断定（「唯一の」「N 箇所ある」など）を外す
- 規範: `docs/comment-guidelines.md`「第一原則: コメントは理由を書く」（#1407 で縮めた版。理由は守る行の隣、精密事実は正本を 1 つ決めて指す。書いてよい例外に一意性の宣言）

## 事実

### 参照の母集団（279 件）

| 指す側と X の関係（名前の一致で判定） | 件数 | うち目的の語なし |
|---|---|---|
| 同じ `.rs` のコードが X の名前を使う | 157 | 90 |
| `.rs` だが、コードは X の名前を使わない | 49 | 30 |
| `.rs` 以外（`.md`・スクリプト） | 73 | 23 |

- 目的の語は「理由・なぜ・ため・根拠」「経緯・#NNN・実測」「正本」「契約・不変条件・前提」「詳細・参照・にある」の有無で分けた近似
- 「コードで使う」はファイル単位の名前の一致で、呼び出しの関係ではない

### 「コードで使う × 語なし」90 件を読んだ所見

全件を目で読んだ。形は大きく 4 つに分かれる。

1. **引用（主張を手元に書き、出所として X を添える）**: 「X が起きる（`MainScale` の doc）」「受け取りは行を複製しない（`RowsSnapshot::rows` の doc）」。主張は手元にあり、括弧は出所の印。X は同じコードが使うので、読者は定義へ飛べる。issue が消す対象の中心
2. **委ね（中身を手元に書かず、X が持つと言う）**: 「前後関係は `drain_folder` の doc が持つ」「意味と限界は `heap_trace.rs` の `//!`」「分かれ方は `read_bar_anchor` の doc」。理由そのものが遠くにある形。issue の「理由が指す側で要るなら隣に書く」に当たるか、精密事実の正本の指名かを 1 件ずつ判定する
3. **外部の doc**（egui の `Visuals::ime_composition`・`egui_kittest` の `Harness::step`・`epaint::TextureId::Managed`）: リポジトリ外の仕様の出所。ジャンプ先が手元に無いので消さない
4. **テストが何を固定するかの宣言**（`layout.rs:1256`「`fit_middle_by_measure` の doc が挙げる唯一の例外を、ここが固定している」）: テストの検証意図であり、規約の「テストコードのコメント」に当たる。消さない

### 指されている doc の中の構造の断定

- 指されている `.rs` の doc は 147 ブロック・1,671 行
- 数・「唯一」・「だけである」を含む行は、正規表現の近似で多数ある（`pointee-docs.mjs` の STRUCT）。読むと大半は**一意性の宣言**（「起動経路が通る唯一の入口」「判定式の正本はここ 1 か所」）で、#1407 の規約では書いてよい例外に当たる
- 規約が禁じる形（今の姿の数え上げ）に当たりそうなもの: `window_coordinator.rs` の `hide_egui_main` の doc「世代 bump だけは 2 箇所ある」・同 `show_egui_main` 周辺「呼び出し元は `show_egui_main` だけである（#749 で実測）」・`lifecycle.rs`「フレーム内の入口は `reset`（段 3）と `observe`（段 16–17）の 2 つだけである」など。一意性の宣言との境界が 1 件ごとに違う

## 技術的な制約

- `.rs` のコメントを触るので、カテゴリ A（fmt・clippy・test・`cargo doc`）が該当する。挙動は変えないので C・D は該当しない
- 参照を消すと、`cargo doc` が見ていた intra-doc link が減ることがある（`[`X`]` の形を消した場合）。減ったこと自体は赤にならない
- 指されていた doc の中身を直すとき、別の箇所がその中身を逐語で引いていれば、その引用が偽になる（検査は見ない）

## 敵対的調査（3b）の反映

出力: `workspace/adversarial-1408.txt`。採否:

- **F1 採る**: 抽出は取りこぼす。rustdoc リンク形 `` [`X`] の doc `` が 63 行、「の」と「doc」が折返しで別行になった形が 22 行ある。「理由は `X`」型の委ねは 31 行。→ 候補の母集団を広げる（リンク形・折返し形を含める）。「理由は `X`」型は、範囲の外とする（道案内ではなく理由の所在の宣言であり、消すか隣へ書くかは理由の中身次第で、#1407 の規約に沿って触ったときに直す扱い）
- **F2 採る**: ファイル単位の名前の一致は、呼び出しの関係を示さない（`window_coordinator.rs:356` の `window_width` は config のフィールド、`view.rs:316` の `active_range_chars` は別 crate）。→ 消す条件は、その参照が効いているブロックで X を実際に呼ぶ・使うことを**読んで確かめる**ことにする
- **F3 採る**: 4 分類は網羅的でない。文字列リテラル内（`assert!` のメッセージ・`cache/tests.rs:384,451,859,910`）、同じ行に正準形参照や ADR 引用を持つもの（`indexing.rs:146`・`view.rs:1270`）、doc の文言を逐語で引くもの（`view.rs:367,2100`・`frame_stages.rs:7`・`cache.rs:365`・`cache/tests.rs:936`）がある。→ 判定の規則で除外する
- **F4 採る（但し書き）**: 参照を消しても `cargo doc`・`governance:check` は赤にしない。ただし折返しの書き換えでバッククォートを落とすと `invalid_html_tags` などで赤になりうる。ソースを文字列で読むテスト（`icon_textures.rs`・`view.rs` の `assert_read_once_in_this_file`・`indexing.rs` の `start_index_build` 本体の検査・`activation/tests.rs`）がある。→ カテゴリ A の `cargo test` と `cargo doc` を回す
- **F5 採る**: 「変更行がすべて `//` で始まる」では、文字列の継続行（`"abc\` の次行が `// x";`）を見逃し、コード行の純削除も見逃す。→ コメントを除いたトークン列を比べる検知器にする（文字列・raw 文字列・char とライフタイム・ブロックコメントを区別する字句解析）
- **F6**: `.rs` の走査元は全件入っている。母集団に文字列リテラルが混ざる点は F3 で扱う
