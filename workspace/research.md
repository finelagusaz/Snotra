# research — issue #765: `/implement` の出力に Step 4 の受け口が無い

## issue の要約

`/implement`「出力」の報告項目は 3 つ（入口判定・最終検証結果・コミット）で、Step 4（4a の check スキル・4b の `code-reviewer`）の結果を書く枠が無い。4b は「Critical または High の発見事項は修正してから次に進む」と義務づけているのに、**実施した回と素通りした回が報告から区別できない**。#764 の受容する残余からの繰り越し。

## 前提の是正 — issue 後半の指摘は既に古い

issue は「項目 2 が `check, clippy, test` と 3 種だけを名指しし、カテゴリ A〜F を覆っていない」を併記するが、**この文言は #764 自身（`880be34`）で既に直っている**。

- `git log -S"check, clippy, test" -- .claude/skills/implement/SKILL.md` → `39fe33e`（導入）と `880be34`（除去）の 2 件のみ
- `git show 880be34` の該当 hunk: `2. 最終検証結果 — check, clippy, test の出力（Step 3）` → `2. 最終検証結果 — 実行したカテゴリとその出力、および**実行できなかったカテゴリ（D 等）と人間へ引き渡す目視項目**（Step 3）`

`docs/superpowers/specs/2026-07-27-opus5-skill-tuning-design.md`「受容する残余」が修正前の文言のまま書かれ、それが issue へ写された。

**ただし同型の残余は生きている**: 現行の母集団は「実行したカテゴリ」＝**書き手が選んだもの**であり、「該当しなかった」と「該当したのに落とした」が区別できない。#764 の総括パターン 2（義務の係り先が自分で選ぶ分類になっていると、書き手が義務を消せる）に当たる。ユーザー確認により、この残余も同じ変更で直す。

## 既存パターン（報告テンプレートの正準形が 2 つある）

issue が「同じ失敗様態を繰り返し塞いでいる」と指す 2 箇所は、**そのまま流用できる形**を持つ。

- `/health-check`「Check 7 — MEMORY.md 参照の実在性」の判定は**三値**であり、「異常あり」「異常なし」「見ていない」を同じ記号で書かないと明記する（`[Skipped] 検証不能` を「不在」と書くことを禁じる）
- `/plan-review`「Step 3 — 結果の統合と報告」の配送欄は**台帳の全エントリを 1 行ずつ**書かせ、不着は「独立レビュー不成立（＝検証されていない。問題が無かったのではない）」と書かせる

いずれも**母集団を先に閉じ、各要素に必ず 1 つの値を割り当てる**形。これが #764 の総括パターン 3（記録テンプレートの有無が実施の有無の唯一の観測点）に対応する既存解である。

## 技術的制約

- **`.claude/skills/**` に PostToolUse 検査は割り当てられていない** — 編集後の沈黙は「何も走らなかった」であり合格ではない。`npm run governance:check`（カテゴリ F）を手で実行する必要がある
- **AREA_BUDGET（G10 面積 ratchet）は掛からない** — `scripts/governance-check.mjs:536-538` が「対象外は意図的である: skills 本文…」と明記。常時ロード面に載るのは skill の `description` のみで、本変更は `description` を触らない
- **`/norm-review` が必須** — `.claude/rules/safety-nets.md`「セーフティネットが『規範』の場合、フォールトインジェクションとは『回避しようとする読者』である」が `.claude/skills/` の変更で起動を要求する。同スキルは停止条件（合格条件・上限巡数・**塞ぎ 1 件あたり 1 文の分量予算**）を**着手前に決めて計画に書く**ことを Step 1 で要求する
- **序数参照の巻き込みは無い** — 「出力」項目への外部からの序数参照を `.claude/` / `AGENTS.md` / `CLAUDE.md` / `docs/`（`superpowers/` 除く）で grep して 0 件。`CLAUDE.md:74` と `docs/adr/0004` は `/implement`「4b. code-reviewer エージェント」を**正準見出し形**で指しており、見出し自体を変えなければ影響しない（G11 の照合対象）
- **ただし内部の名前参照は 1 件ある** — `:123` の「最終検証結果とコミットの各項目は、該当経路では生成物が存在しない」。項目を足すなら**同じ変更でこの列挙に追加する**（#764 が序数→名前へ直した箇所であり、名前列挙も同じく取りこぼす）
