# 調査 — issue #1497 文書だけの変更で implement Step 3 に何を求めるかを決める

## issue の要約

`/implement`「3b. 委譲へ渡すもの」は委譲先に変異注入を求め、「出力」節は省いた検査を「未実施（理由: 省いた）」と書かせる。文書だけの変更では変異を当てる対象が決まらず、`.claude/rules/safety-nets.md`「規範（ドキュメント・スキル・チェックリスト）を足すとき」は「規範へフォールトインジェクションを当てる専用の手順は置かない」と定めている。文書だけの変更で Step 3 の委譲に何を求めるか、「文書だけ」を何で判定するかを決めて書く。hook・スクリプトなど文書の形をした実行物（`.mjs` など）は「文書だけ」に含めない。

## このセッションの実践（2026-11-21・文書だけの PR 4 本）

4 本とも、委譲のレビューは回し、変異注入は「該当なし」（根拠は safety-nets の上の条項）として進めた。

- 委譲のレビューは、文書だけの変更でも毎回、実害のある指摘を出した（#1503 では、`/retrospective` の diff を 2 点形にした主の修正が、マージ後に自分の変更を消す後退だったことを、使い捨てのリポジトリの実測で示した）
- 委譲先は、文書の手順を使い捨てのリポジトリで実際に打つ「実地の確かめ」もした（#1503 の git 手順、#1501 の rules の配送）。変異注入の代わりに、文書が述べる挙動を実測する形である
- #1491・#1492（このセッションより前）は、委譲のレビューを回さず、検証欄は E・F だけだった

## 敵対的調査（3b）の反映

出典: `workspace/adversarial-1497.txt`

- 採る（B1・B2）: 上の表の「指摘（直したもの）」は直していない件を含む（#1500・#1502 で Low を 1 件ずつ残した）。「毎回実害のある指摘」は言いすぎで、実害の記録があるのは #1500 と #1503（High 2 ずつ）。言えるのは「各 PR の初回ラウンドで指摘が出た。うち 2 本は High」まで
- 採る（B3）: 文書の形をした実行物の列挙は閉じない。SKILL.md の `description`、rules の `paths`、agents のフロントマター、`@AGENTS.md` のインポート、PR・issue テンプレート、`labels.yml`、表・見出し・フェンスを入力に読む G-* 検査など。この基準だと #1500（description とテンプレートを変えた）は「文書だけ」から外れる。→ 「文書だけ」を列挙で定義しない
- 採る（B4）: `verify:tree` が回すのはカテゴリ A・C・E・F の最初の `bash` フェンス（B はコマンドなし、D は handoff、行末のコメントは落とす）。フェンスが実行物であることは変わらない
- 採る（B5・設計の組み替え）: 「文書だけなら変異注入の対象が無い」は無条件には言えない。文書は G-* 検査の入力であり、「この検査が捕まえる」と主張する文を足す変更もある（#1491 は、src だけを改名する変異で `cargo build -p` が緑になることを実測して AGENTS.md を直した）。safety-nets の条項は「専用の手順は置かない」と言うだけで、「該当なし」とは言っていない。→ 判定するのは「文書だけか」ではなく「変異注入の対象があるか」にする。対象が無いのは、差分が検知器を足さず・変えず、検知器の入力の構造を変えず、検知の働きを主張する文も足さないときである
- 採る（B6）: Q1〜Q4 は既存の文書でほぼ決まる。「出力」節の「時間・手間を理由に選ばない」と safety-nets の「独立したレビューが後から明らかにする」から、委譲のレビューは残し、変異注入は条件つきで該当なし。Q4 は、入口（Step 1）に変更の種類の判定は無く、Step 3 で閉じれば足りる
- 採る（測定の偏り）: 標本 4 本は同じセッションの開発プロセス文書で独立でない。効いたのは手順（git・harness の挙動）を述べる文書を実測したとき。→ 「実地の確かめ」は、差分が手順・コマンド・ツールの挙動を述べるときに限る
- ⚠️ 採らない（B7・B9）: #1491・#1492 が委譲レビューを回していないのは本文の沈黙からの推測／#1503 の後退が主の修正によることは PR 本文からは読めない（このセッションの記録では主の修正である）。どちらも結論に効かない

## 再利用できる既存のパターン

- 3b の「該当するかの判定は、拡張子ではなく、変更が触れるコードパスの意味で行う」— 「文書だけ」の判定にも同じ考え方を当てられる
- 「出力」節の値の語彙（実行 / 該当なし / 実行不能 / 未実施）。変異注入の「該当なし」は、根拠を書けば値として既にある

## 技術的な制約

- `.claude/skills/**` はセーフティネット。マージは合意してから
- 「出力」節は時間・手間を理由に値を選ぶことを禁じている。「該当なし」は、変異を当てる対象（検知器）が差分に無いことを根拠にする必要がある
- 文書の形をした実行物がある: `docs/build-commands.md` のカテゴリのフェンス（`verify:tree` が回す）、SKILL.md のフロントマター（`allowed-tools`・`disable-model-invocation` など harness が読む）、`.claude/settings.json`、`package.json` の scripts
