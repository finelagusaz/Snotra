### Medium 1 — `docs/architecture.md:228` の flush 枝の主張に、実装が持つ 2 つの例外が無い

**場所**: `docs/architecture.md:228`（「**flush へ倒れる Enter は同期 `engine.search` の錠待ちと
走査を負う**」）／根拠は `src-tauri/src/egui_shell/launcher_controller.rs:1457-1464`

**根本原因**: flush 枝は無条件に `engine.search` を呼ばない。壊れている不変条件は
「flush へ倒れること ⇒ 錠待ちと走査を払うこと」であり、実装は

    let searched = if query.trim().is_empty() || indexing.get() {
        None
    } else {
        self.app_handle.try_state::<crate::AppState>().map(|state| {
            let mut engine = state.engine.lock().unwrap();
            engine.search(&query)
        })
    };

と 2 つの carve-out を持つ。どちらも到達する:
- **空クエリ**: 全消しの直後は `Debouncer::on_input` が `armed` を立てるので
  `is_unsettled` は真（`search_state.rs:643-645`）、`interp("")` は `Plain`。
  ゆえに `should_flush_on_enter` は真になり、flush 枝へ入って `None` で抜ける
- **`indexing` 中**: 索引再構築中の打鍵 → Enter が同じ並びを通る

帰結として、次の一文「**#1038 が広げたぶんの Enter は #1076 以降、走査待ちを新たに負う**」も
索引再構築中には成り立たない（#1038 が広げた窓に入った Enter でも、`indexing` なら錠を取らない）。

**修正例**: flush の肢へ限定条件を足す。
「**flush へ倒れる Enter は同期 `engine.search` の錠待ちと走査を負う**」→
「**flush へ倒れる Enter のうち、クエリが空でも `indexing` 中でもないものが、同期 `engine.search` の
錠待ちと走査を負う**（残り 2 つは行の同期クリアだけで、錠を取らない・`on_enter` の該当分岐が正本）」。
次文も「その広がったぶんの Enter は #1076 以降、**同じ限定のもとで**走査待ちを新たに負う」とする。

**場所**: `docs/architecture.md:228`（「**flush へ倒れない Enter は錠を一切待たない**」）
