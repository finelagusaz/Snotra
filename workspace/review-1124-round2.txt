## Q2. 「取得側と実行側が同じ答えになる」は正確か — 言い過ぎになっていないか

**言い過ぎです。** しかも「loose な表現」よりもう一段強い問題があります
——**この文が述べる同時発生は起こりえません**。詳細は R2-3。要点だけ:

取得側が空 `Vec` を返すと `self.state.results()` が空になり、`execute_instant_selected` の
**入口**（`launcher_controller.rs:496-498` の `let Some(sel) = self.state.results().get(index) else { return; }`）
で先に return します。つまり実行側の `read_config(.., || None)` には**到達しません**。
「取得側の答え」と「実行側の答え」が両方求まる場面が存在しないので、
それらが「同じ」かどうかを比べる状況自体が無いのです。
（AppState の不在は単調です——`.manage` 済みの state が外れる経路は無いので、
「表示時は在り、実行時は不在」という交差も生じません。）

## Q3. 「算出もされない」は実装と一致するか — 実装詳細を書きすぎていないか

**一致はしています。書きすぎです。** 詳細は R2-4。3 つの理由:
(1) 利用者から観測できない、(2) `SPEC.md` は第 1 層（意図）で実装事実は第 2 層（コード）の担当、
(3) **検査できない**——「算出しなかったこと」を測るテストは書けず、現に 1 件も無い。
そして **削っても記録は失われません**（Q4 と同じ話なので下でまとめて扱います）。

## Q4. Low 4 の削除で失われた情報は再確立地点を持っているか

**判断は成立します。ただしリードが挙げた 2 つの根拠のうち、実際に効いているのは別のものです。**

- **`SPEC.md` §19.2 の同期** → 「`action` から算出する派生値」としか書いておらず、
  **非算出を記録していません**。効いていません。
- **`matching_results_prefers_description_over_display`** → 固定するのは
  「`path` に description が入る」ことだけで、**display が算出されないことは測っていません**。
  効いていません（原理的に測れません）。

**実際に再確立している 1 つは、Low 3 の修正が書いた doc 文**です
（`snotra-core/src/instant.rs:338-339`）:

> `[display_text]` の算出を `description` 空の枝に置いてあるのは、**非空なら出来上がった
> 文字列をその場で捨てることになる**からである（#1124 以前はそうしていた）。

これは **層も正しい**（`docs/comment-guidelines.md`「配置基準（3 層）」の doc コメント＝

## R2-3 Low【不正確】「取得側と実行側が同じ答えになる」は、起こりえない同時発生を述べている

**場所**: `src-tauri/src/egui_shell/launcher_controller.rs:920`

**根本原因**: 壊れた不変条件は `docs/comment-guidelines.md`「第一原則」の

型も違います（`Vec<SearchResult>` と `Option<InstantAction>`）。

（起動できない行を表示する）が消えたのは事実です。誤っているのは、その理由づけだけです。

```rust
// 空へ倒せば、起動できない行がそもそも出ない。
```

## 2. R2-6 Low【新規】R2-1 / R2-2 の修正が、位置の主張を 1 つ新しく持ち込んだ（しかも偽である）

**場所**: `snotra-core/src/instant.rs:1043`

```rust
/// `is_folder` が true だと→キーが `path`（URL や `exe args`）をディレクトリとして
/// 展開しにいく（ガードの連言は `execute_instant_selected` の直前にある）。
```

**括弧の中が偽である。** 実測:

- → 展開ガードの連言（`&& sel.is_folder`）は **`launcher_controller.rs:1293`**、
  これを含む関数は **`on_nav_keys`（:1274 で定義）**
- **`execute_instant_selected` は :495 で定義** されている

**798 行離れた別の関数**であり、「直前」ではない。**時間順で読んでも偽である**——
:1293 のガードが通す先は :1296-1298 の `navigate_folder` / フォルダ突入であって
`execute_instant_selected` ではない（両者は Enter/クリックと → キーで**別の入口**を持つ）。

**根本原因**: 壊れた不変条件は `docs/comment-guidelines.md`「第一原則」の書かないもの
「**コードが決めている構造の事実**——経路の数、分岐の列挙、**呼び出し元**、到達可能性」。
**位置の主張はこの型の最たるもの**で、関数を 1 つ挟むだけで偽になり、
`cargo doc` も `clippy` も `G-stale-identifiers`（`.rs` は母集団外）も検査しない。

**注目すべき点**: これは round 1 の Medium 1（機序の誤帰属）と**同じクラスの 3 巡目**である。
1 巡目「アイコンをゲートする」（偽）→ 2 巡目「ゲートは 2 つだけ」（維持できない全称）→
3 巡目「直前にある」（偽）。`review-frameworks-not-rounds` が言う
「**自分の修正差分が対象だと同じ枠組みは収束しない**」がそのまま出ている。
**収束させる書き方は「他ファイルの位置・数・関係を書かない」ことである**——
`is_folder` / `is_error` が**何を通す/通さないか**という肯定的な記述だけで自足しており、
どこに在るかは読者が `sel.is_folder` を grep すれば 1 行で分かる（分断が解消したので今は効く）。

**修正例**: 括弧を丸ごと削る。

```rust
/// `is_folder` が true だと→キーが `path`（URL や `exe args`）をディレクトリとして展開しにいく。
```
