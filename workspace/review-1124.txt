# 争点として渡された 3 点の裁定（自分で測った）

## 争点 1: `filter_instant_commands` の pub → private

**裁定は正しい。crate 外に消費者は居ない。**

- リポジトリ全体（`target/` 除外）を grep → `filter_instant_commands` は
  `snotra-core/src/instant.rs` の **同一ファイル内 7 箇所のみ**（`//!` 1・定義 1・`matching_results`
  からの呼び 1・テスト 5 呼び）。`snotra-settings` / `snotra-egui-runtime` / `src-tauri` に **0 件**。
- **コンパイラでも確かめた**: `cargo build --workspace` / `cargo clippy --workspace --all-targets`
  が緑。private 化して落ちなかったことが、crate 外に消費者が居ないことの機械的な証拠である。
- **公開面の収支も確認**: `matching_results` が pub に増え `filter_instant_commands` が private へ
  落ちたので、**到達性の検出器を持たない pub fn の数は増減 0**（plan の主張どおり）。
  かつ `display_text` は最初から private ゆえ純増ではない。

## 争点 2: fallback を `Config::default().instant_commands` → `Vec::new()`

**裁定は正しい。しかも「実行側と整合する」より強い理由がある。**

**(a) 到達性 — 到達する経路は無い。2 つの独立した根拠で確かめた。**

1. `src-tauri/src/main.rs:258` の `.manage(app_state)` が `:263` の `.setup(..)` **より前**に
   ある（実測）。ゆえに setup 以降 `try_state::<AppState>()` は None を返さない。
2. `run_search_with` の呼び出し元は `run_search`（:856）と打鍵の changed エッジ
   （:1387 / :1395 / :1403）**のみ**で、いずれも egui フレームの中にある。
   `src-tauri/CLAUDE.md`「ウィンドウ生成の制約」が「setup ブロックの実行中は wry plugin の
   on_event が回らないため、**egui フレームは 1 枚も走らない**」と明記している。
   つまり **フレームが 1 枚でも走る時点で .manage は既に済んでいる**。

**(b) 実行側との整合 — 整合している。かつ本差分は非対称を「解消」している。**

- 実行側は `|| None`（launcher_controller.rs:514）＝「見つからない」。
- **変更前は非対称だった**: 取得側が既定の g / gh を**表示**し、その行で Enter を押すと
  実行側は `|| None` へ落ちて egui_instant_error を trace して何もしない。
  すなわち「**表示はされるが実行できない行**」が出る構成だった。
- 変更後は両側とも「何も無い」へ倒れ、**表示と実行の帰結が一致する**。単なる整合ではなく、
  到達したときに誤る分岐の修正である（ADR-config-default-fallback-references の
  「直したのは症状ではなく、到達したときに誤る分岐である」と同型）。
- 副次: **src-tauri から「Config 全体を建てる fallback」が絶滅した**。
  `Config::default()` を grep すると残るのは `config_watcher.rs`（load 経路・fallback ではない）と
  `#[cfg(test)]` だけで、read_config の fallback は全件が狭い `*Config::default()` になった。

## 争点 3: `launch.rs` の DTO テスト 3 件の撤去

**失われた不変条件は「1 件だけ」で合っている。そしてその 1 件の削除は正しい。**

- 旧 `instant_dto_display_url` が固定していた「description が非空でも display を算出する」は
  **DTO のフィールドが常に埋まっていることの検査**であり、利用者から見える挙動ではなかった
  （`launcher_controller` がその値を捨てていた）。DTO の消滅とともに主張の対象が消えている。
  `SPEC.md` §19.2 の同期も済んでいる。**正しい削除である。**
- 旧 3 件の残り 2 件（Exec+args / Exec-args 無し）は移植先の同名テストが逐語で維持。
- **移植先が増やしたもの**: `_prefers_description_over_display` /
