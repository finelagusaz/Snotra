## 4. ご質問への回答

### (1) 修正で新しい現在形・数え上げ・双条件を作っていないか

- **双条件: 0 件。** :246-248 は「潰すと赤になる」＝赤の側で定義しており、正しい向きである
  （しかも変異 C で追試できた）。
- **他 crate の現在形: 0 件。** snotra-core 側から src-tauri の保持・引きの**現在の**挙動を主張する文は
  無くなった。
- **ただし過去形の側に 1 件（Medium A）。** 「現在形を消したか」だけを見ると合格に見えるので、
  ここが今回いちばん見落としやすい所でした。

### (2) `visible_icon_keys` の doc は誤解を招かないか（`icon_key` への帰属を落とした裁定）

**足りていると判断します。** 根拠は 3 つ:

1. 当該 doc は「絞らない」で終わっていない——**「この関数は導出が返したキーをそのまま集める」**が
   続く。つまり「何が集まるかは導出が決める」と明示しており、「エラー行のテクスチャが保持される」と
   読み切ることはできない（読者は導出を見に行く必要があると分かる）。
2. その導出の正体は**同じファイルの 30 行上のブロックコメント**（:72-79）が持ち、そこは
   「**導出が決めるのは「どのキーか」だけではなく「そもそもキーを持つか」でもある**——列挙失敗行が
   アイコンを持たないことも…この導出が担う（#1134）」と、まさにこの疑問へ直接答えている。
   **同一ファイル内で完結しており、参照の跳躍は 1 回だけ**である。
3. 帰属文を両方の関数 doc に置くと、ブロックコメントを含めて**同じ事実が 3 か所**になる。
   今回の差分自身が「同じ事実の 2 つ目の表現を残さない」を理由に `continue` を撤去した以上、
   doc 側だけ 3 重にするのは筋が通らない。

補足（所見ではありません）: 「行の性質でここを絞らない」は、**エラー行が実際には落ちる**現在の姿と
一瞬だけ緊張して読めます。それを解いているのが続く 1 文なので、**その 1 文は削らないでください**
（削ると本当に誤読可能になります）。
