## 争点 1 — 禁止 9 件 vs 原案 1 件

### 1-A. まず、依頼された「1 件で足りる論証」を可能な限り強く組み、そして**それは成立しなかった**

構築を試みた 1 件案の柱は 3 本ある。順に、どこで折れたかを書く。

**柱①「回帰とは撤去したコードが戻ることであり、戻る形は `ctx.set_visuals` である」**
——#900 の本文が「**戻すと同じバグが再発する**」と書くとおり、守る対象は履歴のある 1 つの形である。
`ctx.global_style_mut` は `src-tauri` に一度も書かれたことがない（`research.md` 測定 2・
`plan-review` §2 の型解決経由の 0 件測定）。**未来の推測より、起きた事実の方が根拠として強い。**

**→ 折れた理由**: 柱①は「1 件で足りる」ではなく「1 件は必ず要る」しか導かない。
残り 6 件を**足さない**理由になるには、6 件が高くつく必要がある。それが柱②だった。

**柱②「エントリが増えるほど沈黙経路が増える」**
——`clippy.toml` の不正パスは `-D warnings` 下でも exit 0、crate 名の書き損じは診断すら出ない
（`research.md` 測定 7・`plan-review` §5-R1、いずれも実測）。エントリが 9 本あれば
書き損じの機会も 9 倍になる。

**→ 折れた理由（これが決定的）**: **`research.md` 測定 3 が、私の主張の反証そのものである。**
7 パスを置き 7 行を注入した**単一の `cargo clippy` 実行**が、7 件すべての `error` を行番号つきで
出している（`research.md:73-80`）。すなわち **7 件の生存確認の費用は 1 件の費用と同じ 1 コマンドであり、
限界費用はほぼゼロ**である。「1 件ずつ測る手間が 9 倍」という直感は、この一次証拠に当たると消える。
私はこの premise を捨てる。

**柱③「lint は壁ではなく道標であり、迂回する者には `#[allow]` がある」**
——`#[allow(clippy::disallowed_methods)]` は `-D warnings` 下でも完全に抑止する（`plan-review` §5-R3 実測）。
`ctx.options_mut(|o| o.dark_style = …)` も素通りする（同 §5-R2・計画も受容残余として認めている）。
ゆえに**この機構が捕まえるのは事故だけであり、意図的な迂回は最初から捕まえられない**。
事故として起きうるのは、履歴のある `ctx.set_visuals` である。

**→ 折れた理由**: 柱③は正しいが、**結論が逆向きにも効く**。捕まえるのが事故だけなら、
事故として打鍵されうる名前をすべて閉じるのが正しい。`ctx.set_global_style` /
`ctx.global_style_mut` は egui 自身の doc が「Mutate the currently active `Style` used by all
subsequent popups, menus, etc.」と説明する**素直な第一候補**であり
（`context.rs:2111-2136`・自分で読んだ）、`ctx.set_visuals` を禁じられた人が次に手を伸ばす形として
十分に現実的である。**「そう書く人間は実在しない」は、ここでは書けない。**

**ゆえに「1 件で足りる」は構築できなかった。** これも結論として報告する。

### 1-B. では 9 件が正しいかというと、正しくない。**費用は件数ではなく「正当化の装置」にある**

計画が 9 件のために背負っているものを数え上げる。

| 背負っているもの | 出所 | 7 件にすると |
|---|---|---|
| 選別規則「API の名前ではなく visuals を書けるかで選ぶ」の明文化 | `plan.md:27-30`・コメント点 1（`:96-98`） | **不要**。1〜7 は名前が自明に同族 |
| `set_debug_on_hover` を落とす理由の段落（4 行） | `plan.md:49-54` | **不要**。選別規則を立てなければ候補に上がらない |
| `context.rs:3564-3568` / `:3187-3200` の再照合 | `plan.md:245` | **不要** |
| 注入時の `let c = ui.ctx().clone();` という迂回 | `plan.md:124-126`（**「`ui` を別に借りる 8・9 のために」と明記**） | **不要**。1〜7 は `ctx` の借用を割らない |
| 「9 件を個別に測る」という受け入れ条件の重み | `plan.md:16` | 1 コマンドで 7 error（測定 3 が先例） |

**つまり 8・9（`style_ui` / `settings_ui`）の 2 件だけが、計画の分量のかなりの部分を単独で牽引している。**

### 1-C. `style_ui` / `settings_ui` を削るべき決定的な根拠 — **egui 自身の doc**

`plan-review` は「`&mut Ui` を取る＝ pass の中で呼ぶ前提の API だから、正当な使用がほぼ無く
禁止しても失うものが無い」と、これを**含める**側の補強に使った（同 §1.4-A）。
**この読みは誤りである。**`&mut Ui` を取るのは、これらが**ウィジェットを描くための API** だからである。

```rust
// egui-0.35.0/src/context.rs:3563-3568（自分で読んだ）
/// Edit the [`Style`].
pub fn style_ui(&self, ui: &mut Ui, theme: Theme) { … }

// 同 :3186-3188
/// Show a ui for settings (style and tessellation options).
pub fn settings_ui(&self, ui: &mut Ui) { … }
```

判定の問いは「その呼び出しを書いた人は #751 の誤りを犯しているのか、それとも
**意図したことをしているのか**」である。1〜7 を書く人は global style を書きたい＝ #751 の誤りを犯している。
**`style_ui` / `settings_ui` を書く人は、egui 組み込みのスタイル編集パネルを画面に出したいのであって、
global style の書き込みは副作用である。** 禁止すればそれは**偽陽性**になり、解消手段は
`#[allow(clippy::disallowed_methods)]` しかない。**それは §5-R3 が「機構を完全に無効化する」と
実測した逃げ道そのものを、正当な理由で打鍵させる訓練になる。**

失われる守り: **ほぼゼロ**。デバッグパネルを足した人が、そのフレームでスタイル編集の反映が
1 フレーム遅れることに気づかない、という不都合だけが残る。#751 の欠陥（config の色が旧色で残る）は
再現しない——config の色は inspector から来ないからである。

**この切り出しは他の判断から独立している。** 禁止を 7 件にせよ 1 件にせよ 9 件にせよ、
この 2 件は落として構わない。

### 1-D. 7 件が「閉じた集合」であること

1〜7（`set_visuals` / `set_visuals_of` / `style_mut_of` / `set_style_of` / `global_style_mut` /
`set_global_style` / `all_styles_mut`）は、名前と doc から自明に同族である。

**ただし「これで全部である」という母集団の導出は本レビューの一次証拠ではない**——
`research.md` 測定 1（`context.rs:2080-2230` の読解）と `plan-review` §1.1（`impl Context` が
`context.rs` に閉じることの grep）に依る。**私が自分で読んだのは `:2110-2150` と `:3562-3568` /
`:3185-3200` だけ**であり、そこでは doc が「Mutate the currently active `Style` …」と
**目的を明示している**ことを確認した。ここから 1 件でも抜くと
「なぜこれだけ抜いたのか」を書く義務が発生する——**7 は、説明を要しない最小の閉包である。**
`research.md` 測定 1 がこの 7 件を独立に導いており、測定 3 が 7 件の発火を実測している。

**争点 1 の結論: 7 件。**

## 争点 2 — `view.rs` を触る必要があるか → **無い。Phase 4 を丸ごと削る**

計画は `view.rs:16-17` の

> **`ctx.set_visuals` は `src-tauri/src/` の全域 grep で 0 件である**（#751 で撤去・現在の pass に届かないため）

へ「`clippy.toml` がその 0 件を保つ」旨を 1 句足そうとしている（`plan.md:152-159`）。削ってよい。

**理由 1 — この文は真のままであり、直す必要が無い。** 計画自身が「字義としては真のまま」と認めている
（`plan.md:154`）。#900 は文書の**追加**を 1 か所（`src-tauri/CLAUDE.md`）しか求めていない。

**理由 2 — 主張されている守りが、検算すると立たない。** 計画の懸念は
「次の読者が機構の存在を知らないままこの行を消したり戻したりしうる」（`plan.md:155-156`）である。
2 つに分けて当てる。
- **消す**（`//!` の 1 行を削除する）→ 何も壊れない。この行は観測の記録であって、
  依存している機構は無い。
- **戻す**（`ctx.set_visuals` を書く）→ **clippy が止める。** それが本 issue で作るものである。
  しかも `set_visuals` はどの候補集合にも入るので、この守りは件数の議論と独立に成立する。

**すなわち追記が守るものは無く、失われる守りはゼロである。**

**理由 3（副次的だが大きい）— 削ると、計画が段落を割いて管理している手順上の危険が丸ごと消える。**
`plan.md:113-118` は Phase 2 と Phase 4 の順序について、

> 注入の撤去は `git checkout -- src-tauri/src/egui_shell/view.rs` で行うため、**Phase 4 の `//!` 追記より前に
> 済ませなければ、その追記が黙って巻き戻る**

という危険を管理している。**`view.rs` を成果物から外せば、この危険は存在しなくなる**——
`view.rs` への書き込みは注入だけになり、`git checkout --` は常に正しい撤去手段になる。
`git status --short` の期待値も**ちょうど 2 ファイル**（`clippy.toml` / `src-tauri/CLAUDE.md`）と
issue 原案に一致する。

**理由 4 — かぶり。** `.claude/rules/governance-docs.md`「書く約束」(1)「かぶりなく」。
「clippy が禁止を機構で守る」という主張の置き場所は `clippy.toml` の `reason` と
`src-tauri/CLAUDE.md` の 1 文で 2 か所あり、3 か所目を作る理由が無い。

## 争点 3 — `clippy.toml` のコメント 5 点のうち、どれが「推論で辿り着ける」ゆえ不要か

判定基準は `.claude/rules/governance-docs.md`「書く約束」(2)「**推論で辿り着ける事柄は書かない**」に加え、
**「このファイルを将来編集する人が、ある具体的な誤りを避けるために必要か」**とした。

**この争点は争点 1 の下流にある**——点 1・点 2 の分量は 9 件案が牽引しており、7 件にすると自動的に縮む。

| # | 計画の点（`plan.md:96-105`） | 判定 | 理由 |
|---|---|---|---|
| 1 | **なぜ 9 件か**（root `Ui` の snapshot 機序・選別は名前ではなく「visuals を書けるか」） | **削る** | 7 件案では選別規則そのものが不要（1-B）。機序は `reason` 文字列と #751 の番号が運ぶ。**同じ機序は `src-tauri/CLAUDE.md` と `view.rs:22-24` に既にあり、3 度目の写しになる**（「かぶりなく」） |
| 2 | **含めなかったもの**（`set_debug_on_hover` / `options_mut` / `set_theme` / `set_fonts`・4 群） | **1 行へ縮める** | `set_fonts` は**削る**——フォントであって style でないことは名前から自明で、しかも `font_stack.rs:192` に実使用があるので、足した人は即座に赤を踏む（**誤りが大声で自己訂正する**）。`set_debug_on_hover` は選別規則ごと**削る**。**残すのは `options_mut` の 1 行**（唯一の実在する抜け道で、意図的な除外だと知らなければ「漏れ」と読まれ、次の人が足して正当な用途を巻き込む）。⚠ `set_theme` は判断が割れる（下記 未検証-3） |
| 3 | **`snotra-settings` は巻き込まれない**（package スコープ・creation closure ゆえ欠陥を持たない） | **削る** | **`clippy.toml` が package スコープであることは clippy の上流仕様であり、`src-tauri/clippy.toml` というパスを見た人が推論で辿り着く。** 測定が要ったのは**書く側**であって**読む側**ではない。`snotra-settings` の正当性の説明もこのファイルの読者の関心ではない（あちらのコードを読む人はここを開かない） |

| 5 | **ルート `clippy.toml` を後で置いても遮蔽される**（マージされない） | **削る（軽微）** | **必要とする人がこのファイルを読まない。** ルートに `clippy.toml` を新設する人は、`src-tauri/clippy.toml` を開く動機を持たない。届かない場所へ書いた警告は面積だけを消費する。⚠ 完全な確信は無い（下記 未検証-2） |

**結果**: コメントは「沈黙経路 1〜2 行」＋「`options_mut` は素通りする（受容残余）1 行」＋
「`style_ui` / `settings_ui` は inspector ゆえ意図的に除外 1 行」の**計 3〜4 行**に収まる。
`reason` 文字列（条件つき文言）が残りを運ぶ。
