### 調べたが「削れない」と結論したもの — A2（テストの doc の逆参照）

チームリードの問い「issue が申告した 4 箇所から増えた分は本当に同じ変更で直す必要があるか」への回答。**`:61`（削れる #2）と A2 は答えが逆になる。**

A2 の現在の doc は「一致は今まで規約でしかなかった（**`snotra-egui-runtime/CLAUDE.md` が受容した残余**）」と書いている（`window_coordinator.rs:698-700` 実測）。A3/A6 が当の CLAUDE.md の bullet を書き換えた瞬間、**この括弧は存在しない記述を指す**。

つまり **A2 を触らないことは「射程を守る」ではなく「6 つ目の stale な主張を作る」**である。#825 が消そうとしている欠陥クラスそのものを、同じ PR が新しく 1 件生むことになる。**同じ変更で直すのが正しい**——research.md が「写しの網は 4 頂点ではなく 5 頂点」と結論した部分は妥当である。

### 1 を「費用が高い」ではなく「構造的に採れない」まで詰める

`.json` を採りつつ生成物・ロックファイル・未追跡物だけを外す方法は**無い**。

- `scripts/governance-check.mjs` 冒頭の契約は「**免除注記の機構は設けない**」（`:14` 実測）。`VOCAB_TEST_FILE` が許されているのは `.test.<ext>` が**ファイル名の形**だからで、`-lock.json` + `gen/` + `test-results/` は**リストである**。ADR-stale-identifier-detector-scope 却下 2 が退けたものそのものになる
- 同契約は「**決定的（ネットワーク・時刻・環境変数に非依存）**」とも定める（`:12` 実測）。`test-results/.last-run.json` は `.gitignore:34` に在り、`snapshot` の walk（`WALK_EXCLUDE_NAMES` = `.git`/`node_modules`/`target`/`dist`、`WALK_EXCLUDE_PREFIXES` = `workspace`/`.claude/worktrees`/`.superpowers`）から**外れていない**。**正確に言うと、今日この 1 件で判定が割れることはない**——寄付するのは `failedTests` ただ 1 語で、それを書いた文書は 1 つも無い（実測）。**問題は潜在的な契約違反のほうである**: 語彙の母集団が「その環境で誰かが何を走らせたか」に依存する状態が新設され、CI と手元で母集団が一致しなくなる。しかも e2e は #532 SU7 で撤去済みで、これは**誰も保守していない置き土産**である
- ADR が定める原則「**語彙を寄付してよいのは『現に動いている実装』だけである**」に、`package-lock.json`・`src-tauri/gen/schemas/*.json`・`test-results/*.json` はどれも当たらない

**`.yml` は同じ線の反対側に立つ**——`.github/workflows/*.yml` は追跡され、人が書き、CI が実際に実行する。線は拡張子ではなく「**追跡され手で書かれた実装か / 生成物・未追跡物か**」であり、その線で `.yml` は通り `.json` は通らない。

（公平を期すと、`.yml` も `TAG_NAME` / `GITHUB_ENV` / `GITHUB_OUTPUT` / `TAURI_SIGNING_PRIVATE_KEY` という **GitHub 提供の外部語彙**を、新設する SCREAMING_SNAKE 述語とまさに同じ形で寄付する。これは受容してよいが、**ADR へ受容残余として書くべきである**——B12 に項目が無い。）

## 設計判断への異論

### 1. 「正本 1 + 参照 n」の向きが、機械照合の向きと逆である

計画は正本を `snotra-egui-runtime/src/renderer.rs` の rustdoc に置き、`snotra-egui-runtime/CLAUDE.md` からは「正本は `renderer.rs` の `CLEAR_COLOR` の doc」と指す。**照合の実態はこうなる**:

| 書く場所 | 書く内容 | 機械照合 |
|---|---|---|
| `renderer.rs` の rustdoc（正本） | `src-tauri/src/egui_shell/window_coordinator.rs` へのパス参照 | **無い**（`governanceDocs` は `.md` のみ・計画自身が認める） |
| `CLAUDE.md`（参照側） | 「正本は `renderer.rs` の doc」 | `renderer.rs` の**実在**のみ（`REF_EXTENSIONS` に `rs` を含む・`:30` 実測）。doc の**中身**は誰も見ない |

**機械照合される場所（`.md`）に、照合されないポインタ（「あの doc を見よ」）を書き、照合されない場所（rustdoc）に、照合されうる情報（テストのパス）を書いている。** 逆である。

`CLAUDE.md` に `src-tauri/src/egui_shell/window_coordinator.rs` を**直接書けば**、パスの実在は G-references が守る。テストを別ファイルへ移した瞬間に CI が名指しで落ちる——これは「正本 1 + 参照 n」構造が一切与えない保証である。

**この推奨は受け入れ条件を書き換えない。** 計画の受け入れ条件 3 は「他 4 箇所はそこ**か機構そのものを指す**参照になっている」と書いており、`src-tauri/src/egui_shell/window_coordinator.rs` を直接書くことは**まさに「機構そのものを指す」**である。平坦化は AC3 を満たす。

**より単純な解を推す**: 参照構造を作らず、**両所で事実を正しく述べ、両所がテストのパスを直接書く**。この issue が消そうとしている欠陥は「**事実が古くなったこと**」であって「事実が 2 箇所にあること」ではない。実際、`CLEAR_COLOR` の一致は `AGENTS.md` の言う「事実の写し」——同じ**判断**を 2 度書くこと——ではなく、**同じ機構を 2 つの読者層（crate の実装者と crate の利用者）へ告げること**である。参照へ倒すと、`CLAUDE.md` を読む人が答えを得るのに 1 ホップ増え、その 1 ホップは機械が守らない。

（計画の「正本を `renderer.rs` に置く根拠」——値を変える人が必ず定数の定義位置を開く——は妥当で、私はそこに異論を持たない。異論は「他所を参照へ**倒す**」部分だけである。）

**この 1 件は実装者の判断ではなくユーザーの裁定に属する。** issue #825 の本文が「**どれが正本かを決めてから残りを参照へ倒す**必要がある」と方法まで指定し、`AGENTS.md`「文書に事実の写しを増やす変更 → 正本を 1 か所に定め他は参照へ」を名指しで引いているからである。私の根拠は機構の側（照合の向きが逆）にあり十分だと考えるが、**issue 起票者が明示した方法に反対する提案**なので、実装者が黙って平坦化してよい類ではない。

### 2. 外部語彙の扱いが、D 軸と M 軸で非対称である

計画は M 軸（モジュール `CLAUDE.md`）を却下し、その理由を「偽陽性 3 件（`WM_SETCURSOR` / `MARKER_DONT_FOCUS` / `numFonts`）はいずれも**ソースのコメントにしか現れない外部語彙**である」と述べる。**正しい判断である。**

ところが同じ計画が、D 軸で現れた外部語彙（`GITHUB_TOKEN` = GitHub Actions の提供物、`CLAUDE_PROJECT_DIR` = Claude Code harness の提供物）に対しては、**語彙源の母集団を広げて免罪する**という逆の手当てを採っている。同じ性質の問題に 2 つの原理を当てている。

一貫させるなら、外部語彙の手当ては **(i) 文書側の書き方で外す**（`ADR-stale-identifier-detector-scope`「その後」節が `closingIssuesReferences` に対して採った形。「これは回避ではなく記述の正確化である」と明記されている）か、**(ii) その外部語彙の定義ファイル自体が「現に動いている実装」なら、そのファイルを名指しで語彙源に入れる**かの 2 つである。どちらも母集団を**名指しの粒度**で動かす。一括で拡張子を足す案が異質なのは、**免罪の範囲が「今そこに何が置かれているか」に委ねられる**点にある。

### 3. 「#489 は PR 分割の規則ではない」という計画の判断には同意する

issue コメントの「#489 に従い単独 PR が要る」を過読みと退けた点は妥当で、削る方向の判断として正しい。**ただし 2 PR に分ける判断そのものは維持すべきである**——理由は #489 ではなく、計画が別に挙げている「Phase A の事実訂正が Phase B の測定結果に人質を取られない」であり、こちらは十分な根拠である。#819 案 (A) を Phase A へ置いて `docs/development-principles.md` の同一節へ寄せる判断も、コンフリクトを構造的に消すので支持する。
