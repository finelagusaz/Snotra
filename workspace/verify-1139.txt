実測: 実ツリーの .rs 101 件すべてについて、元の cfg.src 判定と crate 名前方一致とで
      scopedFindings の出力を突き合わせた → 差分 0 件。cfg.src の外だが crate 名で拾われる .rs は

帰結: (1) cfg.src 判定は正しさの門ではなく費用の最適化であり、doc がそう書いていない。
      (2) edit-findings.test.mjs:48-53 の「判定対象外: tests/ 配下の .rs は母集団の外
      （cfg.src が src/ に閉じている）」は、名乗った理由ではなく帰属フィルタのおかげで緑になる
      ——cfg.src を crate 名前方一致へ退化させても赤くならない（= この行を守る検知器は存在しない）。

      境界の理由として書いているので非対称に見える。

      (prev === undefined || !/[A-Za-z0-9._/\-]/.test(prev)) を条件へ AND する。
      直さない選択も妥当だが、その場合は doc に「見るのは末尾側の境界だけである（先頭側は
      <何か>/<rel> の形がメッセージに現れないので不要）」と非対称を名乗らせる。

  露出が 0 である以上、これは挙動の欠陥ではなく doc の精度の問題である。**修正しない**という判断も
  成り立つ——ただしその場合は「今日の索引 token の形に依存している」と doc が名乗るべきで、
  依存を書かないまま無条件の断定を残すのが一番よくない（次に索引へ完全パスを書いた人が
  この doc を根拠に前方一致へ簡略化しうる）。確信が持てないのは「条件を書き足すこと自体が
  また別の現在形の主張（今日の索引 token の形）を doc へ持ち込む」点で、
  この連鎖をどこで止めるかは規範の運用判断である。

⚠️-7【同じ主張が 3 か所に在る】
  「前方一致でも出力は変わらない」は edit-findings.mjs の //!・ADR・workspace/plan.md の 3 か所に
  書かれている。plan.md は /implement が消す作業バッファなので実害は小さいが、Medium-4 を直すなら
  3 か所とも直す必要がある（AGENTS.md「文書に事実の写しを増やす変更」の「取りこぼすのは写しを直す
  当のコミットが典型」）。**PR 本文も数え上げの母集団に含める**（squash で commit message になるが
  grep には入らない・#1056）。実測していないので ⚠️ に置く——PR 本文は読んでいない。

⚠️-8【Medium-5 の読み方】
  「今はどの層も見ていない」の直前の文脈は索引の話なので、文脈込みで読めば真である。
  私が広すぎると判断したのは、この文が ADR の「受容する残余」に隣接して置かれ、
  そこだけ引用されうるからである。severity を Medium としたのはその理由で、Low と読む余地もある。
