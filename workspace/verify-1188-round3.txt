## 2. 偽にできた 3 件

### F-C2 — 「`matchAll` は内部で複製するため `lastIndex` を持ち越さない」（`lib.mjs:174`）

**種別**: 機序の断定（全称ではないが、安全性の根拠として使われている）

**偽にする手順**: `HEADING_REF.lastIndex` に 0 以外を注入してから `matchAll` を呼ぶ。
持ち越さないなら結果は lastIndex に依存しないはず。

**実測**（入力 `` `a.md`「X」 `b.md`「Y」 ``）:
```
 元の lastIndex=0  → matchAll: a.md,b.md
 元の lastIndex=12 → matchAll: (なし)          ← **複製は lastIndex を継承している**
 matchAll 後の元の lastIndex = 12               ← 書き戻しはしない
 exec を 1 回: a.md → lastIndex = 9
 その直後の matchAll: b.md                      ← a.md を取りこぼす
```

**判定**: **偽。** `String.prototype.matchAll` は正規表現を複製するが、**`lastIndex` は複製へ引き継ぐ**。
持ち越さないのは「元へ書き戻さない」方だけである。

**なぜ重いか**: この一文は直後の「`test` / `exec` で共有すると、消費者どうしが互いの `lastIndex` を踏む」の
**根拠**として置かれている。実際には **`exec` が 1 度でも走れば、その後の `matchAll` も取りこぼす**——
doc の機序を信じた読者は「matchAll 側は免疫がある」と読み、まさに doc が防ぎたい失敗へ歩く。
**結論（「`matchAll` からだけ使う」）は正しく、根拠だけが誤っている。**

**直し方の案**: 「`matchAll` は複製へ `lastIndex` を**引き継ぐが元へ書き戻さない**ので、
`matchAll` だけを使う限り消費者どうしは互いを踏まない。**`exec` / `test` を 1 度でも混ぜると
以降の `matchAll` も取りこぼす**」。

「`findings` が 1 → 0」を「内側の findings がすべて消える」と書けば数え上げが消える。

## 5. 出口の判定

**偽にできた主張は 3 件ある**（F-C2 / F-C7 / F-C9）。ゆえに「1 つも無い」とは言えない。

ただし性質を分けて読んでほしい:
- **実装の挙動を誤って書いた主張は 0 件**——宣言する死角 5 項はすべて実測と一致し、
  ADR の帰結（移行コスト 0・性能・却下理由・受容する残余）も 11 項すべて偽にできなかった。
- 偽になった 3 件は **(a) 機序の説明**（C2）**(b) スコープの名札**（C7）**(c) 主語の取り方**（C9）で、
  いずれも**書き換えれば真になる**——実装を変える必要は無い。
- 3 件とも **1 文の中の 1 語**（「複製するため」「全追跡ファイルで」「参照は」）が原因である。

**⚠️ 巡を終えることについての所見**（確信度中）: 3 件のうち C7 は**ラウンド 2 の R2-1 と同じ型**
（数に誤ったスコープ／定義が付く）であり、**同じ括弧の中で 2 度続けて起きている**。
