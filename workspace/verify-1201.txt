## 3. 指摘

### Critical — 0 件

沈黙して空／欠けた母集団を返す経路は、3 本の検査に関しては見つからなかった。
`read_dir` / `DirEntry` / `read_to_string` は `expect` で赤、フィルタで黙って落ちる経路
（下記 High-3）が在っても、起動の入口 3 本は `sole_file_with` が 0 枚で赤にするため
沈黙にはならない（(o)/(o2) で両方向を実測）。

### High

**H1. `launcher_controller.rs:42-43` の散文が偽になったまま残っている（差分の取りこぼし）**
```
//! **起動の入口を `activation.rs` から動かす前に、そのファイルの `//!` を読むこと**——
//! ソーステキスト検査の母集団がそこに縛られている（理由と死角の正本は `activation.rs` の `//!`）。
```
「母集団がそこに縛られている」は #1201 が消した当の前提である。しかもこの行は読者を
`activation.rs` の `//!` へ**送る導線**であり、送り先はいま正反対（「その規範は要らなくなった」）を
書いている。`src-tauri/CLAUDE.md` と `activation.rs` の `//!` は直したのに、**親モジュールの
`//!` だけが漏れた**——皮肉なことに、この親モジュールは tests.rs の `//!` が
「母集団に入らないもの」として名指している当のファイルである。

**H2. `sole_file_with` の doc「2 枚以上になる形は、実は散文からしか作れない」は偽**（変異 (n) で実測）
E0592 は**同一型の inherent メソッド**の重複にしか出ない。自由関数・別型のメソッド・trait impl は
どれもコンパイルが通り、`src.contains("fn on_enter(")` は 2 枚を数える。実測では
`folder_nav.rs` へ自由関数 `fn on_enter(_hint: u8) {}` を足すだけで 2 本の検査が赤になった。
向きは赤（誤爆）なので**穴ではない**が、doc はこの前提から
「ゆえにここが赤にするのは doc コメントや文字列リテラルへ綴りが入った場合であり、**その 1 形で
足りる**」と結論しており、**結論の根拠が偽である**。実際の誤爆面は「兄弟に同名の何かを置くこと」
まで広い（`on_enter` / `activate_or_execute` / `shift_activate` はどれも一般名である）。

**H3. `sources` の doc 見出し「# 失敗はすべて赤へ倒す」「3 経路とも `expect` で panic させる」に
4 経路目が入っていない**
```rust
.filter(|entry| {
    entry.file_type().is_ok_and(|t| t.is_file())   // ← Err のとき黙って落とす
        && entry.file_name().to_string_lossy().ends_with(".rs")
})
```
`is_ok_and` は `Err` で `false` を返すので、`file_type()` が失敗したエントリは
**沈黙して母集団から欠ける**。同じ形で、`.rs` で終わる**シンボリックリンク**も
（std の `DirEntry::file_type` はリンクを辿らないので `is_file()` が false）沈黙して落ちる。
向きは「狭まる」で、3 本の述語にとっては `sole_file_with` が受け止めるため無害だが、
**doc は「すべて」「3 経路とも」と書いており実装より強い**。当リポジトリの
`AGENTS.md`「検証の作法」の「全称表現は…何が増えたらこの文は偽になるか」に直接当たる。

### ⚠️（確信の持てない／裁定を仰ぎたい所見）

**⚠️1. tests.rs の doc の大半は、どの機械検査も見ていない**（変異 (h) で実測）
`#[cfg(test)] mod tests;` ゆえ rustdoc は tests.rs をドキュメント化しない。壊れた
`[\`no_such_symbol_xyz\`]` を植えても `cargo doc` は exit 0・診断 0 行だった。#1201 は
tests.rs へ約 150 行の doc（`[\`sources\`]` / `[\`sole_file_with\`]` / `[\`owners_of_all\`]` /
`[\`method_body\`]` …）を新設しており、その intra-doc link は**誰も検算していない**。
見出し参照（正準形）だけは governance:check が見る（変異 (h2) で確認）。
**#1201 が作った欠陥ではなく既存の性質**だが、この差分で露出が大きく増えたので申し送る。
（メインの依頼が「今回 doc コメントを大量に書き換えているので cargo doc を必ず含めよ」だったが、
**その cargo doc は書き換えた doc のほとんどを見ていない**、というのが実測の答えである。）

**⚠️2. `owners_of_all` の「ファイルごとに呼ぶことが不変条件である」に検知器が無い**
（変異 (j)/(j2)/(j3) で実測）。連結形へ戻しても現在のツリーでは緑で、赤にするには
`folder_nav.rs` の `//!` へ禁止語を植える必要があった。doc の機序主張は A/B で裏づけられたが、
不変条件そのものは散文契約である。**塞ぐべきかは裁定を仰ぎたい**——塞ぐ道具
（連結を型で表現不能にする等）は検査対象より複雑になり、`owners_of` の残余節が
同じ判断を「塞がない」側で記録しているので、**死角として宣言するだけで足りる可能性が高い**。

**⚠️3. tests.rs の `//!`「母集団に入らないもの」の 2 項列挙は、腐る時点が確定している**
```
//! **母集団に入らないもの**——名指せないなら測っていない: **このファイル自身**（`activation/`
//! サブディレクトリに在り、`read_dir` は再帰しない）と、**親モジュール …**（ディレクトリの外）。
```
`activation/` へファイルを 1 枚足せば「このファイル自身」は不足になる。同じ文書の
line 553-554 に**腐らない書き方**（「`read_dir` が返すのは直下のエントリだけで、ディレクトリは
フィルタで落ちる」）が既に在り、冒頭の列挙はその派生コピーである。当リポジトリの
「正しい直し方は数を直すことではなく、列挙をやめて正本を指すことである」に当たる。

**⚠️4. 母集団が「黙って狭まる」変異は落ちない**（変異 (o) で実測）
`.rs` フィルタを `"n.rs"` へ狭めて母集団を `activation.rs` 1 枚（＝#1201 以前）に戻しても
3 本とも緑だった。`owners_of_all` の doc は「**下界（`P ⊇ B`）は構成から満たされる**」と書くが、
「構成から」が保証しているのは**ファイル内で切り詰めが起きないこと**であって、
**そのファイルが母集団に入っていること**ではない。後者を持っているのは `sources()` ではなく
アンカーごとの `sole_file_with` である（(o2) で、アンカー保持ファイルを落とす狭まりは赤に

射程を 1 文で明示するのが妥当かどうか、裁定を仰ぎたい。

**⚠️5. `sources` の doc「ファイルごとに配れば 3 つとも起こりえない」・死角(1) の「倒れ方は 3 通りで、
沈黙するのは 1 形だけである」はどちらも閉じた全称**
前者は構造ではなく呼び出し側の契約に依存する（⚠️2 と同根）。後者は inline `#[cfg(test)]` の
倒れ方を 3 通りに数え上げているが、母集団は「将来書かれうる inline test の形」なので
数え上げは原理的に閉じない。どちらも向きは無害で、書き方の問題である。

**⚠️6. `files.sort_by` は load-bearing でない**（変異 (l) で実測）
逆順にしても 14 本すべて緑。doc は「[\`sole_file_with\`] の一意性 assert と**合わせて**」と
書いているので過大主張ではないが、防御的な余剰であることは記録に値する。

**⚠️7. `docs/adr/ADR-source-text-probe-helper-locality.md` の「文脈」節が、
