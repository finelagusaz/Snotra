### High

**H1. `launcher_controller.rs:42-43` の散文が偽になったまま残っている（差分の取りこぼし）**
```

//! ソーステキスト検査の母集団がそこに縛られている（理由と死角の正本は `activation.rs` の `//!`）。
```
「母集団がそこに縛られている」は #1201 が消した当の前提である。しかもこの行は読者を
`activation.rs` の `//!` へ**送る導線**であり、送り先はいま正反対（「その規範は要らなくなった」）を
書いている。`src-tauri/CLAUDE.md` と `activation.rs` の `//!` は直したのに、**親モジュールの
`//!` だけが漏れた**——皮肉なことに、この親モジュールは tests.rs の `//!` が
「母集団に入らないもの」として名指している当のファイルである。

**H2. `sole_file_with` の doc「2 枚以上になる形は、実は散文からしか作れない」は偽**（変異 (n) で実測）
E0592 は**同一型の inherent メソッド**の重複にしか出ない。自由関数・別型のメソッド・trait impl は
どれもコンパイルが通り、`src.contains("fn on_enter(")` は 2 枚を数える。実測では
`folder_nav.rs` へ自由関数 `fn on_enter(_hint: u8) {}` を足すだけで 2 本の検査が赤になった。
向きは赤（誤爆）なので**穴ではない**が、doc はこの前提から
「ゆえにここが赤にするのは doc コメントや文字列リテラルへ綴りが入った場合であり、**その 1 形で
足りる**」と結論しており、**結論の根拠が偽である**。実際の誤爆面は「兄弟に同名の何かを置くこと」
まで広い（`on_enter` / `activate_or_execute` / `shift_activate` はどれも一般名である）。

**H3. `sources` の doc 見出し「# 失敗はすべて赤へ倒す」「3 経路とも `expect` で panic させる」に
4 経路目が入っていない**
```rust
.filter(|entry| {
    entry.file_type().is_ok_and(|t| t.is_file())   // ← Err のとき黙って落とす

```

**doc は「すべて」「3 経路とも」と書いており実装より強い**。当リポジトリの
`AGENTS.md`「検証の作法」の「全称表現は…何が増えたらこの文は偽になるか」に直接当たる。

**限定しない「狭まること自体」は後者の水準の検査 2 本を確実に含んでしまう。**

正確に書くなら「ファイル集合の母集団が狭まる形のうち、**アンカーを保持するファイルが
落ちないもの**を見ている検査は無い」。

## 6. 【真】 `sources()` 内の `Result` の数え上げ

**4c392ae8 の本文を読み直して全呼び出しを列挙した**（前ラウンドの結果を写していない）:

| 呼び出し | 戻り値 | 扱い |
|---|---|---|
| `std::fs::read_dir(dir)` | `io::Result<ReadDir>` | `unwrap_or_else(panic!)` |
| `ReadDir` の Item（`entry`） | `io::Result<DirEntry>` | `unwrap_or_else(panic!)` |
| `entry.file_type()` | `io::Result<FileType>` | `unwrap_or_else(panic!)` |
| `std::fs::read_to_string(&path)` | `io::Result<String>` | `unwrap_or_else(panic!)` |
| `concat!` / `env!` | マクロ | Result ではない |
| `entry.path()` | `PathBuf` | 〃 |
| `path.display()` | `Display` | 〃 |
| `file_type.is_file()` | `bool` | 〃 |
| `entry.file_name()` | `OsString` | 〃 |
| `.to_string_lossy()` | `Cow<str>` | 〃（**下記の注**） |
| `.ends_with(".rs")` | `bool` | 〃 |

**偽にできなかった。** 4 つで尽きている。

**注（S6 を偽にはしないが、隣に在る形）**: `to_string_lossy()` は `Result` を返さないが
**沈黙して不正 UTF-8 を U+FFFD へ置換する**唯一の経路である。ファイル名が不正 UTF-8 でも
拡張子はどれも ASCII なので `ends_with(".rs")` の判定は変わらず、影響は
`sole_file_with` の失敗メッセージに出る名前の見え方だけである。**「`Result` を返すもの」
という文の射程の外なので S6 は真のままである**——射程を「黙って情報が変わる経路」まで
広げるなら 5 つ目になる、という関係。
